# 第 05 课（S03）：怎样比较才接近未来使用

## 本课要解决什么问题

**第一次做或基础还不稳：从 [入门支持：逐步做一遍](SUPPORT.md) 开始**。里面有现成配置、完整命令、一条手算、输出核对和报告提示，不要求先写代码。完成这条路径及自己的检查，就覆盖下面的必做任务；提高与拓展均为选做，不必重复做两套流程。

模型将用于熟悉窗口的未来日期，还是一个从未用于训练的新窗口？本课保持模型类型不变，比较时间、分组和随机划分，检查它们究竟在回答哪个问题。

你将提交自己的任务说明、程序生成的比较表和逐条记录，以及解释选择的报告。报告必须同时回答两个不同的使用问题：继续服务已有窗口的未来日期，和服务从未用于训练的新窗口。你要说明两种用途各自更接近哪种划分，并用训练编号、验证编号、共有窗口数和 MAE 支持判断。然后选择一种你真正准备支持的用途，设计一项**可能让你修改或暂停原建议**的检查；运行前先写清什么结果会让你改主意，运行后再引用结果作决定。AI 可以帮助提出方案、编程和解释，但不能用一段流畅说明代替实际比较。出错时按报错核对字段；不会操作文件时先查 [第一次运行指南](../docs/FIRST_RUN.md)，可以从原始小数据重新开始。

## 本课要学会什么

| 通用术语 | 学完后能做什么 |
|---|---|
| 训练、验证与测试 | 说明每部分数据的用途 |
| 时间划分 | 用较早记录学习，评价较晚记录 |
| 分组划分 | 避免同一对象在训练和新对象评价中重复 |
| 随机划分与用途 | 用多个随机种子检查一次随机划分是否稳定，不按最低 MAE 挑划分方法 |
| 数据泄漏 | 找到正常预测时拿不到的输入，并说明为什么低误差不能采用 |

先读 [LEARN.md](LEARN.md) 的情境和小计算，陌生词再查 [术语表](../docs/TERMINOLOGY.md)。不要求预先会算法推导；本课读懂计算与比较，比背下英文名更重要。

## 90 分钟安排

0–12 分钟：结合一条样本说明两个未来用途；12–28 分钟：运行起始配置并核对编号、分母和一项 MAE；28–48 分钟：比较时间与分组方案，填写两个用途的证据表；48–66 分钟：先写改变建议的条件，再完成日期或多随机种子检查；66–75 分钟：解释泄漏反例、反面证据和选择限制；75–90 分钟：参加 A 版概念检查、AI 学习、B 版检查并提交。入门路径提供操作支持，但所有学生都要完成用途比较和证据解释。

到第 30 分钟仍未找到结果时，先完成入门指南的手算检查，并将命令和报错给教师；不要跳去做提高任务。环境按课前安排准备，必要时修复后补跑，不把手算冒充程序结果。

## 完成步骤

### 1. 从用途开始，运行原始实验

在 `report.md` 先写使用者、用途和预计结果。在学生仓库根目录运行，也就是能看到 `scripts/` 与 `lesson-05/` 的目录。只识别 `python3` 的电脑，把命令中的 `python` 换为 `python3`。

```bash
python scripts/course.py start 05
python lesson-05/analysis.py --output lesson-05/artifacts/original
```

程序读取本课 `data/base.json` 和 `config.json`。先看终端的中文比较，再打开本课 `artifacts/original/comparison.csv`，核对每个方法的名称和统计样本数；`records.csv` 用于逐条核对，`summary.json` 保存完整结果。文件、字段和参数对应见 [数据说明](data/DATA.md)。

### 2. 核对一项计算，再比较两个使用问题

先在报告中写下两个用途，而不是只选一个：“预测已有窗口的后续日期”和“预测训练中没有出现的新窗口”。这两个问题都合理，但答案不应相同；用途决定怎样解释划分，不能由最低 MAE 反过来决定用途。对每个用途先写预计采用的划分，并写一个当前证据可能失败的原因。例如，时间划分仍然只检查已经出现过的三个窗口；分组划分的验证记录来自 B 窗口，不能自动代表所有新窗口。

打开 `comparison.csv`，核对 `train_n`、`n` 和 `shared_sites`。时间验证使用 12 条训练与 6 条验证；分组验证使用 A 的 6 条训练、B 的 6 条验证，共有窗口数为 0。在报告中为两个用途各填一行：使用对象、对应划分、训练编号、验证编号、共有窗口数、MAE，以及这行证据仍没有覆盖的情况。两个用途可以得到不同建议，不要把它们压成一个“全局最好”的划分。

下面的副本将主要划分改为 `group`。程序仍列三种开发比较，但 `metrics` 改为保存你指定方案，不代表它一定最好。请在报告中并排填写 time 和 group 两行的训练数、验证数、共有窗口数和 MAE，再说明它们回答的用途是否相同。正常 MAE 和 `leaked_mae_demo` 是两个不同实验；后者使用了事后小票，不能采用。

把 `config.json` 另存为 `lesson-05/config-trial.json`。下面是可以完整复制的示例副本；JSON 使用英文双引号、逗号和冒号。它是操作起点，不是所有人必须选择的方案。

```json
{
  "seed": 7,
  "evaluation_split": "validation",
  "split_strategy": "group",
  "train_through_day": 4,
  "validation_through_day": 6
}
```

运行：

```bash
python lesson-05/analysis.py --config lesson-05/config-trial.json --output lesson-05/artifacts/trial
```

### 3. 作出自己的选择，设计一次检查

先用 `records.csv` 手算 time 方案的一项 MAE：把 A05、A06、B05、B06、C05、C06 六条验证记录的 `absolute_error` 相加，再除以 6，并和 `comparison.csv` 核对。然后检查你指定划分的训练和验证编号，确认第 7–8 天测试行没有进入任何开发比较；分别说出为什么不能用事后小票、为什么不能按最低 MAE 选划分。

最后选择下面一项检查。**运行前必须写清什么结果会让你保留、限制或暂停原建议**；如果无论出现什么结果你都不会改变结论，这项检查就没有真正检验你的判断。

- **改变时间边界：**把 `train_through_day` 改为 2 或 3，观察时间方案的训练编号、验证编号、分母和 MAE 如何变化。新的 MAE 使用了不同验证记录，不能写成同一样本上的性能提升。运行前写一个可检查的改变条件，例如“验证日期不再对应准备用于预测的日期”或“MAE 超过使用者事先给出的分钟上限”；若没有现实上限，就如实比较结果和限制，不在看完分数后临时编一个界限。
- **检查随机划分波动：**选择至少三个不同 `seed`，保存每一次 random 行的训练/验证编号与 MAE，报告最小值、最大值和差值。不能只保留最好的一次；若结论依赖某一个种子，应暂停用单次随机结果作主要证据。

保持第 7–8 天测试行不动，并写下修改前的预计。无论选择哪项，都要引用一个支持原建议的结果和一个削弱原建议的结果。

AI 可以帮你提出不同解释和实现改法。至少一项选择要真正影响比较，不仅把示例改写成自己的话。允许换问题、数据和实现，但要说明为什么仍需要本课知识；不要只改字段名称却保留原结论。进一步运行请使用新输出目录，避免覆盖旧证据。

### 4. 保留比较，确定本课建议

本模块默认使用验证集作开发比较。请保留测试数据；本课不要求为了得到一个“最终分数”而提前查看它。

把本课要保留的参数写回 `config.json`，运行 `python scripts/course.py run 05` 生成主目录结果。程序的 `example_only` 仍表示起步计算，不会替你选择模型、写建议或把作业改成已完成。最后分别写出“已有窗口的未来日期”和“新窗口”两条建议，再指出你本次实际选择支持哪一条。原方案可胜出，失败也可成为有依据的结论。

### 5. 核对提交文件

将 `report.md` 的提示替换成自己的回答，在 `contract.json` 填写任务说明，再把 `submission.json` 的 `status` 改为 `complete`。六个任务字段、结果保存和提交命令见 [本模块操作说明](../docs/FOUNDATIONS.md)。不要更改清单里的课号。

```bash
python scripts/course.py check 05
```

清单默认包含主结果的 JSON 与 CSV。报告引用的原始和试验结果、配置副本也要一起保留。`artifacts/` 被 Git 忽略，提交时需要显式加入；具体命令和验证方法在模块说明中。检查通过不等于文件已经上传。

## 必须提交什么

提交程序与配置、`summary.json`、`comparison.csv`、`records.csv`、任务说明和报告；保留报告引用的配置副本、原始与试验输出，以及对应运行命令。不要手填程序结果来代替计算。

报告回答：我在研究哪两个使用问题；什么是输入和标签；比较是否使用了正确的编号、分母与数据；什么结果原本会使我改变建议；实际检查得到了什么；一条支持证据和一条反面证据分别是什么；最后为何保留、限制或暂停。

## 不同起点怎么做

### 入门支持（Support）：跟着详细步骤完成核心任务

使用 [SUPPORT.md](SUPPORT.md) 和已准备的 `config-start.json`、`config-support.json`。先核对一行，再做一项比较，最后选择一个有理由的改动并解释。可以请教师或 AI 解释操作，不要求自己从零实现算法。**入门支持不是低分任务，是否完成取决于比较和解释，而不是代码量。**

### 必做任务（Core）：比较用途、证据和限制

分别描述已有窗口未来日期和新窗口两个用途；核对时间、分组两种划分的训练与验证编号、共有窗口数和 MAE；手算一项 MAE 并说明分母；解释小票字段为什么泄漏；先写改变建议的条件，再改变一个日期条件或运行至少三个随机种子重新检查；分别给出一条支持证据与反面证据。使用入门路径完成这些要求后，不再额外做一次“Core 作业”。

### 提高任务（Upgrade）：检查波动与分组差异

用至少五个随机种子保留全部结果，计算随机划分 MAE 的最小值、最大值和平均值，并说明波动与新窗口评价是两个问题；再比较 time/group 的验证对象差异。不挑最好的一次，也不把不同验证对象的 MAE 排成单一名次。

### 换数据重测（Transfer）：用新数据重新检查

换成重复设备或用户的数据，按实际用途重新划分对象与日期。更换字段或任务时一并调整程序和评价，不只改名称。

### 自选拓展（Open extension）：探索本课之外的问题

研究同时有时间和对象变化时如何验证，说明每个比较能区分什么。以上选做项不替代必做任务，也不要求全部完成。

## 运行限制

使用 Python 3.10 以上与已安装的 NumPy，本课 24 条人工教学样本，普通 CPU 即可；约 8 GB 可用内存，单次运行目标不超过 3 分钟、从头重跑目标不超过 5 分钟。必做实验不联网、不调用付费模型；AI 学习和在线概念检查的接入或补做另按教师安排。人工数据只能支持本次机制练习，不能证明真实人群、行动效果或 AI 能力。
