# S03 · 怎样测试才像将来的使用

## 本课要解决什么问题

维护团队准备用历史记录训练预测办法，却还没明确要预测老设备的未来，还是从未出现的新设备。随机分开各行可能在测试里保留同一设备的其他记录，也可能把未来信息混入训练。你要为一个明确使用场景设计评价，并展示另一种划分会回答什么不同问题。

请交划分方法、记录编号、模型比较结果和评价结论。分数降低不等于实验失败；如果更真实的测试揭示限制，说明可以服务哪些对象，哪些还不能承诺。

### 由你选择的用途与方案

使用者可选负责已有设备的维修组，或负责新设备接入的团队；也可自拟同时涉及新对象与未来时段的用途。由你决定拆分的单位、时间范围、开发办法及哪些字段可用。不能仅为得到高分而挑划分。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **训练、验证与测试（training / validation / test）**：分别用于形成办法、作出选择和检查选定方案。
- **按时间划分（temporal split）**：用较早记录学习、较晚记录评价，模拟未来使用。
- **按对象分组（group split）**：同一对象全部留在一侧，评价对新对象的能力。
- **数据泄漏（data leakage）**：把使用时不可得的信息带入训练或选择，造成过于乐观的结果。
- **泛化（generalization）**：关注方案对目标新记录是否仍有效，目标不同需要不同评价。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—14分钟明确将来服务谁；14—27分钟画两种划分；27—51分钟运行与核对编号；51—66分钟追查泄漏；66—75分钟限定结论；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 查看 data/base.json 中时间与对象标识；先在 report.md 预计随机、时间、分组划分可能有什么差异。
2. 按目标修改 config.json 的现有划分选项，运行实验并保存每组记录编号；若接口不足，可让AI修改程序。
3. 追踪一条记录在训练和评价中的位置，核对预处理是否也只使用训练资料。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-05/analysis.py
```

默认结果保存为 `lesson-05/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`split_strategy` 选择划分方式，`train_fraction` 控制训练资料比例；先按用途选择，再查看分数。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-05/analysis.py --output artifacts/S03-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 选择将来的使用对象与时刻，画出数据使用顺序，说明哪些数据用于开发、哪些留作最后检查。
2. 执行至少两种有解释意义的划分，比较对象重叠、时间关系、样本量和结果；不把不同问题强行排为同一榜单。
3. 核查一列特征的生成时刻，演示一种泄漏或不合适划分如何改变评价。
4. 最后检查前写清评价方法；检查后如继续修改，把已看过的数据标明为开发资料，更新可支持的结论。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

可重建的划分程序及记录编号；两种划分的用途说明和结果；一个泄漏或重复对象案例；对未来使用的限定建议。合格标准是评价能回答你声明的问题，不以最低误差为准。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

选择已有设备或新设备中的一种用途，使用现有划分程序并核对实际编号。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

设计同时限制时间和对象的评价，解释可用样本减少后的不确定性。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一个做预测的时刻或对象群，再检查原划分能否沿用。

### 自选拓展（Open extension）：提出本课问题之外的新探索

用自己的重复测量数据设计评价，先说明对象标识与取得时刻。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
