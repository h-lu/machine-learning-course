# 第 31 课（S29）：换一个场景，原来的方案还能用吗

## 本课要解决什么问题

前五课处理校园设备请求。本课把同一套路由作品交给社区图书馆：新的使用者会说“读者证”“馆藏”“在架”和“续借”，但仍要把请求送到查规则、查数量、算费用或人工处理。旧方案不能因为在原场景有效就直接采用。

**第一次做时从 [入门支持](SUPPORT.md) 开始。** 你要先重新写明新使用者、用途、数据和评价，再在同一批 8 条图书馆请求上实际运行原方案与适配方案。提交共同分母、改变的请求、一项未覆盖条件和是否采用的建议。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 场景迁移（transfer） | 把已有方案用于新的使用者、数据或用途。 |
| 分布变化（distribution shift） | 新场景出现原数据中少见或没有的说法和请求比例。 |
| 任务重新定义 | 在新场景重新写清输入、输出、使用者和错误后果。 |
| 公平比较 | 原方案和适配方案使用同一批新场景请求、同一参考标注和同一分母。 |
| 未覆盖条件 | 当前数据没有测试的情况，报告应明确不能判断。 |

学完后，你应能说明“在新数据上重跑”与“引用旧场景分数”为什么不是一回事。

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–18 分钟 | 重写图书馆场景的使用者、输入、输出和错误后果 |
| 18–35 分钟 | 运行原方案和适配方案，核对 6/8 与 8/8 |
| 35–52 分钟 | 追踪 T01、T02 的词语如何改变路线 |
| 52–68 分钟 | 新增一条未覆盖条件，先预计再运行 |
| 68–75 分钟 | 写采用、限制试用或停止的建议 |
| 75–90 分钟 | 完成 A 版概念检查、AI 学习、B 版检查并提交 |

## 完成步骤

1. 先在 `contract.json` 和 `report.md` 写明新任务。`contract.json` 中，`user` 写社区图书馆服务人员和读者，`question` 写把文字请求送到哪条处理路线，`data_source` 写课程编写者制作的 8 条开发请求加 1 条自设计检查，`metric` 写原 8 条的路线正确数/8、加入检查后的正确数/9，并单列个人信息和预约请求，`split_plan` 写本课只用开发数据、最后评价留到下一课，`initial_expectation` 写看结果前的预计。涉及账户、个人信息或真实预约的请求必须转人工。
2. 从仓库根目录运行：

   ```bash
   python scripts/course.py start 31
   python lesson-31/analysis.py --config lesson-31/config-start.json --output lesson-31/artifacts/start
   ```

3. 打开 `records.csv` 的 T01 和 T02。原方案没有专门处理“读者证”和“馆藏可借册数”，适配方案增加了图书馆常用词。手算原方案 `6/8=0.75`、适配方案 `8/8=1.00`。这只说明给定 8 条人工请求。
4. 打开现成的 `config.json`，在 `added_request` 中只改一条你认为会影响采用建议的开发请求。`id` 用新编号，`condition` 说明新条件，`text` 是程序真正读取的文字，`expected_route` 只能是 `retrieve`、`inventory`、`calculator` 或 `human`。先根据用途写参考路线理由和预计输出，再运行：

   ```bash
   python scripts/course.py run 31
   ```

   若新请求暴露失败，保留失败；不要事后改参考路线迎合程序。`summary.json` 的 `provided_comparison` 仍是原来 8 条的 6/8 与 8/8，`comparison` 则包含你新增的第 9 条；两个分母不能混用。
5. 报告说明原方案来源、适配修改、新证据、未覆盖条件和建议。原方案可以在证据不足时保留，适配方案也可以限制试用。

## 必须提交什么

- 图书馆场景的任务说明、最终配置、`summary.json` 和 `records.csv`。
- 原方案与适配方案在同一 8 条请求上的分子、分母和差异请求。
- `config.json` 中自己新增并实际运行的新场景请求及其预计和实际结果。
- 至少一个未覆盖条件，以及它为何限制结论。
- 采用、限制试用或停止的建议，并说明需要继续收集什么证据。

## 不同起点怎么做

### 入门支持（Support）：从两个新词完成迁移比较

按 [SUPPORT.md](SUPPORT.md) 核对 T01、T02，再加入一条新请求。它完成同一核心任务。

### 必做任务（Core）：重新定义并在新场景重测

所有人都要在新请求上同时运行原方案和适配方案，不能引用设备场景旧分数代替。

### 提高任务（Upgrade）：按条件分组

分别报告新名词、费用、个人信息和有副作用请求的结果，检查总分是否掩盖关键失败。

### 换数据重测（Transfer）：再换一个机构

把任务改为实验室预约或社区服务，只选择一个新使用者条件，重新写参考路线并说明来源。

### 自选拓展（Open extension）：设计小规模试用

写出试用人群、人工复核比例、停止条件和新证据收集方式，不直接承诺全面采用。

## 运行限制

课程给出的数据是 8 条中文文字请求，学生再增加 1 条自设计检查；这些都不代表真实图书馆规定。课程数据没有英语、语音或真实含糊政策；自设计一条英语请求也不等于覆盖了英语场景。程序离线运行，不执行预约、修改资料或导出信息。
