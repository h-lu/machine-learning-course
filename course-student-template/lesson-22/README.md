# 第 22 课（S20）：什么时候应该调用工具，而不是继续生成

## 本课要解决什么问题

上一课的一步基线会用固定值直接回答。库存会变化，费用也必须按明确公式计算；固定值偶尔答对，并不能证明它知道当前事实。本课实际调用两个离线工具：库存查询和逾期费用计算，并检查工具名、参数、状态、返回值和单位。

你要把透明一步基线与工具结果放在相同 5 条开发请求上比较，运行一个无效参数，再增加或修改一个会改变比较结果的开发条件。提交实际工具日志、带单位手算、失败处理和有条件的调用建议。程序失败时保存命令与报错，先按 [入门支持](SUPPORT.md) 手算 W03，修复后补跑。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 工具调用（tool call） | 程序用工具名和参数请求一次可检查的查询或计算。 |
| 参数（argument） | 传给工具的具体输入，例如设备名或逾期天数。 |
| 返回值（return value） | 工具实际产生的状态、数值和单位。 |
| 参数校验（input validation） | 执行前检查类型、范围和允许值。 |
| 失败处理（error handling） | 失败时停止、有限重试或转人工，不静默复用旧值。 |

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–15 分钟 | 区分固定估计与当前查询，手算一笔费用 |
| 15–35 分钟 | 运行库存和费用工具，逐列核对日志 |
| 35–50 分钟 | 用相同分母比较一步基线与工具 |
| 50–68 分钟 | 运行无效参数并增加一个自己的数据条件 |
| 68–75 分钟 | 写调用、停止和转人工规则 |
| 75–90 分钟 | 概念检查与提交 |

## 完成步骤

1. 在学生仓库根目录运行：

   ```bash
   python scripts/course.py start 22
   python lesson-22/analysis.py --config lesson-22/config-start.json --output lesson-22/artifacts/invalid-minus-2
   ```

2. 先打开 `tool_calls.csv` 的 W03。参数是 2 天，数据规定 2 元/天，所以 `2 天 × 2 元/天 = 4 元`。核对 `tool_ok=True`、`tool_value=4`、`tool_unit=元`；一步基线按 1 元/天只得到 2。
3. 打开 `summary.json`。5 条都是自动处理请求，因此两条方案的自动正确率分母同为 5。默认结果中一步基线正确 1/5，工具为 5/5；这只是当前小数据，不证明工具永远正确。
4. 起点还会运行 `days=-2` 的无效调用。它应返回错误且没有数值。再运行只把天数改成 31 的现成对照：

   ```bash
   python lesson-22/analysis.py --config lesson-22/config-support.json --output lesson-22/artifacts/invalid-31
   ```

5. 做一项会改变实际比较的开发检查。把 `data/base.json` 复制为 `data/mine.json`，增加一条库存或费用请求，并同步增加明确的数据来源和参考值。例如增加一项库存恰好为 1 件的设备，会让一步固定值在这条记录上也正确。先预计两个方案的正确数怎样变化，再运行：

   ```bash
   python -m json.tool lesson-22/data/mine.json
   python lesson-22/analysis.py --data lesson-22/data/mine.json --config lesson-22/config-start.json --output lesson-22/artifacts/mine
   ```

   这是新的开发情境，不是为了迎合旧输出修改标签。若工具失败，报告状态和无结果，不能沿用旧值。
6. 把采用配置写入 `config.json`，在报告说明什么时候分数相同仍值得调用工具。运行 `python scripts/course.py run 22`，更新提交清单，再执行检查。

## 必须提交什么

- 实际配置、程序、`summary.json` 和 `tool_calls.csv`。
- 一笔写清天、元/天和元的手算，或一条库存参数、件数和返回状态核对。
- 一个无效调用和一个自己增加的开发条件，包含预计与实际变化。
- 一步基线与工具的共同分母比较、失败处理、调用与人工条件。

## 不同起点怎么做

### 入门支持（Support）：按现成调用核对参数与返回值

按 [SUPPORT.md](SUPPORT.md) 完成 W03、一个库存请求和两个无效天数检查。

### 必做任务（Core）：作出工具调用决定

比较实际结果，核对单位和失败，并运行一个会改变结果的自设计条件。

### 提高任务（Upgrade）：检查“成功但不合理”

为 `ok=true` 的返回值增加单位或范围检查，构造一个状态成功但数值不合理的开发案例。

### 换数据重测（Transfer）：换一种可确定计算

可以使用教室容量或打印费用，但要给数据来源、参数、单位、有效范围和失败规则。

### 自选拓展（Open extension）：增加只读外部工具

保存真实请求、时间和返回；必做任务仍须能离线完成。

## 运行限制

工具只读取人工库存表并执行本地乘法，不修改真实库存、账户或预约。普通 CPU 数秒内完成，不需要网络。本课只能支持给定工具和数据上的结论。
