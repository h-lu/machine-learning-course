# S20｜同一个模型，怎样选择输出

## 本课要解决什么问题

为一个明确的输出用途选择解码策略，例如用几个活动符号为学习小组生成不同的日程候选；也可以换成自己的用途。你更需要稳定格式、少重复，还是多种候选？本课保持模型分数不变，比较输出选择怎样改变结果。提交多次运行的对比、失败输出和采用理由。若输出稳定却没有完成任务，或多样性来自无效内容，就修改策略、增加校验或暂停使用。

起步程序从同一个教学词元转移分数表生成短序列，实际运行温度、候选截取和多次抽样。它不是大模型文本生成；短序列可用于研究重复、结束与多样性，不能证明真实创作或问答质量。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **贪心解码（greedy decoding）**：每一步选当前概率最大的词元，便于得到确定结果，但不保证整段输出最优。
- **温度（temperature）**：调整概率分布的尖锐程度，从而影响随机抽样。
- **候选截取（top-k / top-p）**：分别保留固定数量或累计概率达到标准的高概率词元，限制抽样范围。
- **随机种子与任务指标（random seed / task metric）**：种子帮助重跑；任务指标判断输出是否有用，不能只看多样性。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一个能用小序列检查的输出用途，例如生成合法操作序列或产生若干不同候选。先写允许格式、长度或禁用重复的理由，再确定主指标；可以认为确定性的规则生成器更合适。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-22/analysis.py
   cp lesson-22/config.json lesson-22/config-trial.json
   cp lesson-22/data/base.json lesson-22/data/trial.json
   ```

3. **做出有理由的比较。** 保持分数表和输入相同，比较贪心与一种采样策略，或两种有明确用途差别的采样策略。用多个种子生成一批输出；分别检查有效比例、重复情况和长度，不从最好看的一个样本得结论。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-22/analysis.py --config lesson-22/config-trial.json --data lesson-22/data/trial.json --output lesson-22/artifacts/trial
   ```

4. **核对数字和含义。** 查看截取前后的候选概率，解释哪些词元不再可能出现。核对“不同输出”是否只是多了无效符号；分清结束词元停止和达到长度上限被迫停止。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自定义一条输出规则或一种容易出现循环的转移，然后运行两种策略，找出表面多样但任务失败，或稳定重复却没有完成目标的序列。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 交代固定分数来源、两种策略与随机种子、有效输出的正确数和总数、失败序列，以及选择该策略的使用条件。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-22/analysis.py --config lesson-22/config-trial.json --data lesson-22/data/trial.json --output /tmp/ml-s20-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

在固定分数下比较两种解码方法；检查一批输出的有效性与重复或长度；实际运行自设失败条件；以任务用途作决定；从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先用默认词表，把“是否出现结束词元”作为一个检查，再自己选择另一个与用途有关的条件。AI 可汇总，学生核对几个原始序列。

### 提高任务（Upgrade）：增加一种能改变判断的比较

比较温度与候选截取的相互影响，或加入逐步格式校验，检查多样性与有效性怎样取舍。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一套序列规则或转移表再跑一次，判断此前最好的策略是否仍合适。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做使用固定小词表；每种策略生成不超过 200 条、每条不超过 64 个词元的短序列。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
