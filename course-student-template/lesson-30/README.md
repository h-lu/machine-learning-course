# 第 30 课 · 不知道转移规律，怎样从尝试中学习

## 本课要解决什么问题

让一个小代理从环境反馈学习动作价值，例如让送件机器人在模拟地图中试出路线；你也可以自己选择仿真任务。判断在有限尝试预算下，它是否比规则更值得使用。你要区分训练时探索与评测时执行，并检查高回报是否真能完成任务。提交多种子学习结果、策略轨迹和奖励变化测试。学得慢、表现不稳或只会刷奖励时，保留失败并修改训练、目标或采用决定。

起步程序在本地小网格里真实运行表格 Q 学习：多个训练种子各自训练，冻结后的策略再用独立评测种子选择其他合法起点，比较成功、回报和步数截断；另检查额外奖励引起的行为变化。它没有测试未见地图。学习更新只使用实际交互，不能提前读取最佳动作。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **动作价值（Q-value）**：估计在某状态选一个动作后能得到多少未来回报。
- **时序差分更新（temporal-difference update）**：用新观察到的奖励和下一状态估计，修正原来的价值。
- **探索与评测（exploration / evaluation）**：训练需要尝试；评测要明确是否保留探索，并与实际使用策略一致。
- **学习率、折扣与奖励设计（learning rate / discount / reward design）**：分别影响更新幅度、未来权重和追求的目标，不能混作同一个调参旋钮。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一个允许仿真试错的任务，确定成功、失败与尝试预算。决定你接受平均表现还是要求大多数训练重复都能成功；额外奖励必须解释为什么可能帮助学习，又可能诱导什么行为。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-30/analysis.py
   cp lesson-30/config.json lesson-30/config-trial.json
   cp lesson-30/data/base.json lesson-30/data/trial.json
   ```

3. **做出有理由的比较。** 比较规则或规划参照与训练后的策略；用相同预算运行多个种子，并把训练回报和评测成功率分开。说明评测是否关闭随机探索，以及为什么这对应预期使用。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-30/analysis.py --config lesson-30/config-trial.json --data lesson-30/data/trial.json --output lesson-30/artifacts/trial
   ```

4. **核对数字和含义。** 从一条转移手算一次动作价值更新，特别检查到达终止状态时不继续加未来价值。查看策略轨迹是否完成目标，不能用训练回报增长替代任务成功。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自己设计一种奖励或环境变化，例如反复经过某格可以拿分。分别记录回报和是否到达目标，实际验证学习器会不会靠循环取得高分；再比较修改后的行为。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 保存学习预算、种子、训练与评测方式、一次更新的数字、多次结果和失败轨迹；说明继续训练、改奖励、保留规则或停止使用的理由。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-30/analysis.py --config lesson-30/config-trial.json --data lesson-30/data/trial.json --output /tmp/ml-s28-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

运行真实交互学习与一个参照；复核一次 Q 更新；比较多个种子并区分训练和评测；实际运行奖励或环境失败案例；依据任务成功作决定并从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先用小网格和给定参数，只追踪一个状态动作对怎样变化。AI 可以解释表格，你要核对奖励与终止处理。

### 提高任务（Upgrade）：增加一种能改变判断的比较

比较探索率变化、学习率计划或另一种表格方法，检查收益是否来自更大交互预算。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一张地图或新的奖励后再跑一次，区分直接使用旧策略与重新训练；不要把重新训练结果写成零成本迁移。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做状态不超过 100 个，每次训练不超过 1,000 回合，每回合设置步数上限；在多个种子间平均分配预算。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
