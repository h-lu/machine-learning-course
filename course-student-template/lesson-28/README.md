# 第 28 课（S26）：一个好分数会不会鼓励错误行为

## 本课要解决什么问题

本课继续改进同一个设备服务台助手。助手可以自动回答，也可以把高风险请求交给人工。若只奖励“马上给出答案”，自动回答每条请求会得到高分；若把稍后发现的错误和伤害计入，同一行为可能变得很差。

**第一次做时从 [入门支持](SUPPORT.md) 开始。** 你将沿 8 条请求的轨迹比较“全部自动回答”和“高风险转人工”两种处理策略。起点和候选只改变延迟后果的权重，状态、请求和人工等待成本保持一致。提交逐步轨迹、两种分数下的排序和一个自己设计的状态或奖励检查。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 状态（state） | 作选择时可用的信息；本课包括风险等级和人工队列长短。 |
| 奖励（reward） | 用数值表达希望系统鼓励什么；它是设计选择，不是自然存在的真理。 |
| 延迟奖励与回报（delayed reward and return） | 奖励可能在动作后稍后出现；回报是当前和后续奖励的累计，例如把自动答复后的修正一并计入。 |
| 奖励函数设定不当（reward misspecification） | 奖励漏掉重要后果，使高分行为偏离实际用途。 |
| 轨迹（trajectory） | 按顺序保存状态、动作、即时分数和稍后后果的一组记录。 |

学完后，你应能从一条轨迹重算总分，并指出排序改变来自奖励定义还是助手预测改变。

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–15 分钟 | 用一条高风险请求画出即时和延迟后果 |
| 15–32 分钟 | 运行延迟后果权重 1 的起点并核对 Q02 |
| 32–52 分钟 | 只把权重改为 4，比较两种策略的排序 |
| 52–68 分钟 | 改一个状态字段或一个奖励参数，检查结论是否稳定 |
| 68–75 分钟 | 写用途、限制和继续收集的证据 |
| 75–90 分钟 | 完成 A 版概念检查、AI 学习、B 版检查并提交 |

## 完成步骤

1. 从仓库根目录运行：

   ```bash
   python scripts/course.py start 28
   python lesson-28/analysis.py --config lesson-28/config-start.json --output lesson-28/artifacts/start
   ```

2. 打开 `trajectories.csv` 的 `Q02` 两行。`fast_auto` 自动回答，`risk_aware` 根据可见风险决定是否转人工。分别找出即时分数、延迟伤害和长期分数。
3. 手算候选权重 4 下 Q02：自动回答的结果分为 1，延迟伤害为 -4，合计 -3；人工复核的结果分为 1，再减 0.5 的等待成本，合计 0.5。单位是本课定义的“分”，不是真实金钱或满意度。
4. 先预计权重变大后哪个策略会在长期分数中胜出，再运行：

   ```bash
   python lesson-28/analysis.py --config lesson-28/config-support.json --output lesson-28/artifacts/support
   ```

   打开 `summary.json`，比较 `speed_score` 和 `long_term_score`。请求和行为策略没变，变化来自评价包含的后果。
5. 将支持配置复制到 `config.json`，只做一项个人检查：删除 `state_fields` 中的 `risk`，或只改 `human_delay_cost`。先写预计，再运行最终配置，说明缺少状态信息或改变成本怎样影响行为与结论。

## 必须提交什么

- 最终 `config.json`、`summary.json` 和 `trajectories.csv`。
- Q02 的逐项手算，明确即时分、延迟分和总分。
- 两种策略在即时分数与长期分数上的共同分母和排序。
- 一项状态或奖励变化检查，以及它是否改变你的建议。
- 对奖励定义的限制：哪些真实后果仍未被本课分数表示。

## 不同起点怎么做

### 入门支持（Support）：从一条轨迹完成核心比较

按 [SUPPORT.md](SUPPORT.md) 核对 Q02，再运行权重 1 与 4。使用支持材料与其他学生采用同一完成标准。

### 必做任务（Core）：检查分数是否支持真实用途

所有人都要比较即时和长期评价，完成一项单因素状态或奖励检查，并写出采用建议。

### 提高任务（Upgrade）：检查分组后果

分别统计高风险和低风险请求的长期分数，判断总体分数是否掩盖高风险失败。

### 换数据重测（Transfer）：加入一种新的延迟后果

复制数据并加入一条“立即成功、稍后需要人工纠正”的请求，说明为何给定延迟分，再重跑。

### 自选拓展（Open extension）：提出多目标报告

把正确处理、人工等待和严重后果分开报告，不急于压成一个总分，说明最终选择由谁作出。

## 运行限制

这是确定性表格模拟，不是强化学习算法实现，也不证明真实助手会采取相同行为。运行只需 Python 标准库和普通 CPU。AI 可以帮助提出漏掉的后果，但不能替你决定奖励代表什么。概念检查需按课堂安排联网。
