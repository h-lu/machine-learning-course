# S26｜怎样把连续决策写成一个环境

## 本课要解决什么问题

把一个连续做选择的流程写成可运行的小环境，例如走到目标、安排补货或决定何时维护。你要判断状态是否包含下一步需要的信息，奖励是否真的鼓励使用者想要的结果。提交环境说明、两条轨迹和一个状态或奖励漏洞。规则不合理时，先修环境再讨论最优策略。

起步环境是小网格，状态由位置编号表示，动作是上下左右，碰墙原地停留，到目标或危险格结束。程序实际运行轨迹与折扣回报，并展示合并状态后的信息丢失。你可以重新解释或修改环境，但要让状态、转移和奖励一起对应新的问题。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **状态与观测（state / observation）**：状态包含预测下一步所需的信息，观测是实际能看见的部分，两者可能不同。
- **动作与转移（action / transition）**：动作改变环境，转移规定会到哪里、发生什么。
- **奖励与回报（reward / return）**：奖励评价一步，回报汇总一段过程；容易计数的奖励可能偏离真正目标。
- **马尔可夫决策过程与折扣（Markov decision process，MDP / discount）**：在充分状态下用当前状态和动作描述下一步；折扣控制后续奖励的权重。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择使用者想完成的流程，并说明一步代表多长时间。确定可见信息、允许动作、终止条件与真正成果；如果某种信息看不见，不能直接把它送进策略然后声称现实可用。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-28/analysis.py
   cp lesson-28/config.json lesson-28/config-trial.json
   cp lesson-28/data/base.json lesson-28/data/trial.json
   ```

3. **做出有理由的比较。** 写出一个普通移动、一个撞墙或无效动作、一个终止转移。比较两条策略轨迹，并逐步计算回报。若你采用库存等自定义问题，可以替换入口程序，保持小型离线环境。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-28/analysis.py --config lesson-28/config-trial.json --data lesson-28/data/trial.json --output lesson-28/artifacts/trial
   ```

4. **核对数字和含义。** 找两个观测相同但后续可能不同的状态，检查缺少的信息是什么。再核对奖励是否把“完成目标”与“多做动作”混在一起；程序结束和任务成功也要分别计数。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自己构造一个状态遗漏或奖励漏洞，例如只显示距离不显示障碍方向，或重复领取中间奖励而不完成任务。实际运行一条轨迹，展示原来的定义怎样鼓励错误行为。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 用文字或表格说明状态、观测、动作、转移、奖励与终止；保存两条轨迹和回报；解释漏洞、修改后行为，以及环境适用的条件。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-28/analysis.py --config lesson-28/config-trial.json --data lesson-28/data/trial.json --output /tmp/ml-s26-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

明确 MDP 定义；运行两条轨迹并核对回报；实际揭示一个状态或奖励缺陷；修改定义或说明无法修复的限制；从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先把小网格解释为机器人送件，逐步记位置与奖励。AI 可画地图，你要判断地图中哪些内容是机器人真实可见的。

### 提高任务（Upgrade）：增加一种能改变判断的比较

增加随机转移、有限电量或历史信息，检查状态是否仍足够，以及状态数量增加多少。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一个流程再跑一次，例如由路径问题换成含库存的补货；不要只换格子名称而保持不合理的转移。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做状态不超过 100 个、动作不超过 5 个，每条轨迹最多 200 步；全部是本地仿真。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
