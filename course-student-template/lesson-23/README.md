# 第 23 课（S21）：固定流程还是由模型选择下一步

## 本课要解决什么问题

固定流程按预定顺序检查条件，容易核对但可能多做无关检查；模型路由先用一个小型分类器选择路线，动作更少，却可能选错或在陌生请求上过度确信。两种流程遇到工具失败时都还需要读取反馈、决定是否重试，并在完成后停止。

本课把一次条件检查、一次模型路由决定、一次检索、一次工具调用或一次交人都记为 **1 个动作**。你要比较相同 6 条开发请求上的自动处理、自动错误、转人工和动作数，追踪 W09 的“首次超时—有限重试—成功停止”，再故意关闭完成停止条件，观察无意义重复。路由器是课程数据训练的多项式朴素贝叶斯分类器，不是语言模型或自主智能体。第一次操作卡住时直接按 [入门支持](SUPPORT.md) 的完整路径执行。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 固定流程（fixed workflow） | 按预定顺序检查条件并执行匹配路线。 |
| 动态路由（dynamic routing） | 根据当前输入由已训练模型选择路线。 |
| 环境反馈（environment feedback） | 工具的成功、失败和值会影响下一步行动。 |
| 停止条件（stopping condition） | 完成、转人工、达到重试或动作上限时结束。 |
| 动作预算（action budget） | 本课以同一定义的动作数限制流程；不是实际货币成本。 |

置信度阈值只改变是否自动执行，不会重新训练模型。转人工表示结果尚未观察，必须与自动错误分开报告。

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–15 分钟 | 统一动作单位，区分固定流程与模型路由 |
| 15–35 分钟 | 运行起点并追踪 W09 的失败、重试和停止 |
| 35–50 分钟 | 比较两种流程的自动结果、人工量和动作数 |
| 50–65 分钟 | 关闭完成停止条件，定位重复动作 |
| 65–75 分钟 | 自选阈值、重试或失败请求，先预计再运行 |
| 75–90 分钟 | 概念检查与提交 |

## 完成步骤

1. 在学生仓库根目录运行：

   ```bash
   python scripts/course.py start 23
   python lesson-23/analysis.py --config lesson-23/config-start.json --output lesson-23/artifacts/stop-on-completion
   ```

2. 先打开 `action_trace.csv`，筛选 W09。固定流程先执行条件检查，模型流程先执行一次 `model_route`；两者的首次费用工具调用都得到课程模拟超时，随后只重试一次，成功后停止。数出两条流程各自的动作数和重试数。
3. 打开 `route_decisions.csv` 的 W07，四条路线概率之和约为 1。最高路线概率不等于端到端正确概率。再读 `status`、`sent_to_human` 和 `stopped_reason`。
4. 打开 `summary.json`。起点中固定流程共 22 个动作，模型路由共 13 个动作；两者都有 1 次工具失败和 1 次重试。自动正确率只以实际自动处理数为分母，转人工另报。
5. 运行只把 `stop_when_complete` 从 `true` 改成 `false` 的对照：

   ```bash
   python lesson-23/analysis.py --config lesson-23/config-support.json --output lesson-23/artifacts/repeat-after-completion
   ```

   每条已自动完成的请求会多执行一次相同检索或工具调用。两种流程各出现 4 次完成后重复；结果没有变好，动作数分别增至 26 和 17。
6. 从起点另存 `config-mine.json`，只改一项：把 `confidence_threshold` 调高、把 `max_tool_retries` 改为 0，或把 `failure_request_id` 改成同批另一条工具请求。先预计自动数、转人工数、重试和停止原因，再运行。提高阈值后转人工不记为自动错误；重试为 0 时，W09 首次失败后应转人工。
7. 把采用设置写入 `config.json`，在报告给出完成条件、重试上限和最大 8 动作的理由。运行 `python scripts/course.py run 23`，更新提交清单并检查。

## 必须提交什么

- 起点、重复对照和个人单因素配置的 `summary.json`。
- `route_decisions.csv` 与 `action_trace.csv`；逐步解释 W09。
- 固定与模型路线各自的自动处理数、自动正确/错误、转人工数、动作数、失败和重试数。
- 个人条件变化前的预计、实际轨迹、停止条件与采用限制。

## 不同起点怎么做

### 入门支持（Support）：沿 W09 完成失败与停止检查

按 [SUPPORT.md](SUPPORT.md) 数动作、重试和完成后重复，不需要重写分类器。

### 必做任务（Core）：同时评价效果、人工量和动作预算

追踪模型决定与工具反馈，比较完成停止开关，并运行一项会改变轨迹的个人设置。

### 提高任务（Upgrade）：改变训练覆盖

只增加一条路由训练例子，保持阈值和停止规则不变，检查哪类概率与实际动作改变。

### 换数据重测（Transfer）：换一种请求表达

改写相同意图，检查小模型路线、置信度和人工量；说明关键词表示的限制。

### 自选拓展（Open extension）：比较另一种路由模型

保存训练数据、实际模型输出和动作轨迹；固定 if 规则不能冒充模型自主选择。

## 运行限制

小型分类器和人工请求均在普通 CPU 本地运行，单次数秒，不需要网络。本课只说明这个受限流程在给定请求上的行为，不能推广为真实智能体能力。
