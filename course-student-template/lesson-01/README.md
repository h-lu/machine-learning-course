# C01 · 让别人重跑你的第一次预测

## 本课要解决什么问题

你会第一次把一小份数据交给程序，让程序对一个还没有看到的结果做预测。预测就是：根据现在已经知道的输入，估计以后会出现的结果。机器学习项目最容易出错的地方，往往不是程序完全不能运行，而是读错了列、把答案提前放进输入，或者只保存了一张漂亮的结果截图，别人却无法重新算出这个结果。

本课的使用者是一位接手你项目的同学。他需要回答四个问题：

1. 一行数据代表什么？
2. 哪些字段在作出预测时已经知道，哪个字段是后来才知道的结果？
3. 程序输出的数字是怎样算出来的？
4. 换一台电脑，别人能不能按你的说明得到主要结果？

你会使用随课的合成数据。合成数据是为了教学而生成的记录，不是真实机构的业务数据。你可以选择“估计下一次需求”或“发现与平常不同的记录”这样的用途，也可以根据字段说明提出自己的用途。先把用途说清楚，再决定要预测什么；不能先看见一个分数，才倒过来编一个用途。

预测不准并不等于作业失败。你需要指出一条具体的错误或限制，说明它会怎样影响你的用途，再决定继续试用、修改办法，还是暂时不用。程序遇到报错时，保留报错文字和已经核对的部分，修好后再运行。

## 本课要学会什么

- **输入和结果**：输入是作出预测时已经知道的信息；结果是之后才会知道、需要拿来核对的值。机器学习里常把输入叫作特征（feature），把要预测的结果叫作标签（label）。本课先学会分清这两类信息。
- **预测值和实际值**：预测值是程序事先给出的估计，实际值是事情发生后记录下来的值。两者相差多少，才是误差；预测值不是保证，也不是“准确率”。
- **简单起点（baseline）**：用一个很简单的办法给出结果，例如把过去几天的平均数当作下一天的预测。它不是最终答案，而是一个可以比较的起点。
- **环境与依赖**：环境是运行程序所需要的 Python 版本和软件包；依赖是程序额外使用的软件包。把它们写清楚，接手者才知道怎样准备电脑。
- **可重新运行**：别人应能找到数据、程序、运行命令和软件版本，重新得到主要结果。这叫可复现（reproducible），意思是结果有清楚的来路。

先读[学习材料](LEARN.md)，再开始实验。学习材料会用很小的数字解释这些词，不要求你先记住英文缩写。

## 90 分钟安排

- **0–15 分钟：看数据。** 打开 `data/DATA.md` 和 `data/base.json`，找出一行代表什么、哪些列是输入、哪些列是结果。
- **15–30 分钟：手算一次。** 用三条小记录算出一个简单预测，把每一步写在 `report.md` 的“预计结果”里。
- **30–50 分钟：运行程序。** 运行起步程序，打开结果文件，把一条记录从输入追到输出。
- **50–65 分钟：设计一次出错检查。** 删除一列、改一个字段，或者输入一个不符合要求的记录，观察程序怎样反应。
- **65–75 分钟：重新运行。** 在新的输出目录运行，核对记录数和主要数字，修改最初的判断。
- **75–90 分钟：学习和提交。** 完成 `ml-check` 的本课 A 版、AI 学习和 B 版，并补齐报告和提交清单。

可以让 AI 解释代码、生成修改建议或帮你计算。你仍要自己核对字段、分母、数字和结论；不要把 AI 猜出的数字当成程序实际运行的结果。

## 完成步骤

### 1. 先看数据，再写任务

从学生仓库根目录打开：

- [字段和生成说明](data/DATA.md)
- [原始记录](data/base.json)
- [任务说明](contract.json)
- [报告](report.md)

在 `contract.json` 中填写：

- `question`：你要预测什么？结果出来后谁会怎样使用？
- `user`：谁会看这个预测？
- `data_source`：数据从哪里来？一行记录代表什么？
- `metric`：你准备怎样计算预测好不好？如果只是检查程序，说明你要核对哪些数字。
- `split_plan`：哪些记录用来形成简单办法，哪些记录留到最后检查？如果本课的起步程序已经给出划分，照实说明。
- `initial_expectation`：运行前先写下你预计会看到的结果和原因。

### 2. 运行起步程序

```bash
python3 lesson-01/analysis.py
```

如果你的电脑命令叫 `python`，可以把 `python3` 换成 `python`。程序会把结果写入 `lesson-01/artifacts/summary.json`。这是教学起点，不是评分答案。

打开结果文件，先看这几处：

- `data.rows`：程序读到了多少行数据；
- `metrics`：程序在评价资料上算出的数字；
- `comparison`：换一种简单预测办法后，数字怎样变化；
- `stress_test`：输入缺少一项时，程序是否拒绝了它；
- `provenance`：实际用了哪个数据文件、配置文件和运行环境。

从 `details` 中挑一条记录，写出“输入是什么、实际结果是什么、预测值是什么”。如果不能用文件中的数字逐步说明，就先不要写结论。

### 3. 设计一条容易出错的输入

默认配置会复制一条记录并删除 `x2` 字段，检查程序是否能发现必需输入缺失。你也可以修改 `config.json` 中的 `missing_field`，但要说明为什么选这一列。

```bash
python3 lesson-01/analysis.py --output artifacts/C01-demo
```

`--output` 后面是新的结果目录。比较两次结果时，写清楚每次使用了什么设置。错误输入可以保存在 `lesson-01/` 目录中，但不要覆盖原始数据。

### 4. 完成必做任务（Core）

每个人都要完成下面四件事：

1. 用一句话写清楚“谁要根据预测做什么”，并选择一个能支持这句话的检查数字。
2. 手工核对一条记录，说明输入、实际结果和预测值的关系。
3. 设计一条会让简单办法出错的输入，判断这是程序故障，还是这个办法本身的限制。
4. 在新的输出目录重新运行，核对行数和主要数字，并修改第一次写下的建议。

最后按[仓库首页的环境说明](../../README.md)在干净环境重新运行。别人应能按你的命令得到主要结果。如果运行失败，报告中写出完整命令、报错和你已经核对的部分；不要用估计数字代替运行结果。

## 必须提交什么

请提交以下内容：

- `contract.json`：填好的任务、使用者、数据、检查数字、资料划分和预计结果；
- `report.md`：手算过程、程序输出、错误输入、第一次建议和修改后的建议；
- `analysis.py`、`config.json`：实际运行的程序和设置；
- `artifacts/` 中支持报告的 `summary.json` 或其他结果文件；
- `submission.json`：报告路径、结果路径和运行命令，并把 `status` 改为 `complete`。

合格的作品不要求预测分数漂亮。别人要能重新算出主要数字，并看懂你发现的错误会不会妨碍所选用途。自动检查只检查文件、字段和路径，不能替你判断一个用途是否合适。

## 不同起点怎么做

### 入门支持（Support）：先把过程跑通

直接运行起步程序，选择一条记录做手算。只修改 `missing_field`，观察程序怎样报告缺少输入。可以请 AI 逐行解释代码，但要把自己的核对写进报告。

### 必做任务（Core）：完成一次可复核的预测

完成“完成步骤”中的四件事：说明用途，核对一条记录，设计错误输入，重新运行并修改建议。你可以保留简单办法，也可以据证据决定暂时不用。

### 提高任务（Upgrade）：比较两个简单办法

增加一个合理的简单预测办法，例如比较历史平均值和“沿用最近一次结果”。用同一批评价资料比较，并解释两种错误对用途的影响。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

准备一小份含义相同的新记录，重新运行程序。说明哪些结果保持不变，哪些结果改变，以及你是否需要限制原来的建议。

### 自选拓展（Open extension）：探索另一个用途

换一个使用者和行动，但先重新说明一行数据代表什么、输入何时可得、结果出来后要做什么。不能只把同一个分数复制到新用途。

## 运行限制

本课数据约 180 行、文件约 40 KB。必做任务只使用仓库内的离线数据、普通 CPU 和约 8 GB 可用内存，不需要 GPU、网络下载或付费 API。单次运行目标不超过 3 分钟，从原始数据重新运行目标不超过 5 分钟。

如果你替换数据或增加依赖，请在报告中写明数据怎样得到、每行代表什么、依赖怎样安装，并保留一个不需要联网的必做版本。数据只是教学样例，不能据此声称真实机构或真实人群的表现。
