# 第 01 课：怎样把一个想法变成可运行的作品

## 本课要解决什么问题

排队取餐时，同学想知道大约还要等几分钟。本课用“前面有多少人”作输入，运行一条简单预测规则，再核对一个具体结果。数据由课程人工编写，不是真实食堂记录。

**本课主线：一行数据 → 输入特征 → 规则给出预测 → 和实际值比较**。不需要先会算法、JSON 或命令行；概念随例子学习，文件操作按步骤完成。

你可以让 AI 帮助读代码、写代码和提出改法。需要提交程序、运行结果和简短报告；AI 给出的代码或解释不等于已经运行。遇到错误先查文件位置和参数，不会操作时请教师协助，环境故障不因此扣分。

## 本课要学会什么

| 知识点 | 学完后能做什么 |
|---|---|
| 样本与数据集 | 说明一行是一次排队经历，几行合起来是数据集 |
| 特征与标签 | 区分开始排队时知道的人数，与结束后才知道的实际等待时间 |
| 回归与预测值 | 知道预测分钟数是回归任务，预测不等于保证 |
| 规则与模型训练 | 区分事先写定参数，与根据数据学习参数 |
| 可复现性与输入检查 | 核对一条计算，保存运行条件，检查不合理的输入 |

先读 [LEARN.md](LEARN.md)，其中解释这些术语并给出小例子。遇到文件操作再查 [第一次运行指南](../docs/FIRST_RUN.md)，不用先学会 Python、JSON 或背完整术语表。

## 90 分钟安排

前 20 分钟理解问题、术语与一条计算；接着 35 分钟运行并修改；用 20 分钟核对结果、测试新输入并写报告；最后 15 分钟完成概念检查与提交。软件环境和个人仓库在课前准备。

## 完成步骤

### 1. 运行原例，确认结果真的产生了

在能同时看到 `lesson-01` 和 `scripts` 的学生仓库根目录打开终端。电脑只认 `python3` 时，将所有命令的 `python` 换成 `python3`。位置或依赖不确定时先按 [第一次运行指南](../docs/FIRST_RUN.md) 检查。

```bash
python scripts/course.py start 01
python scripts/course.py run 01
```

第一条将学习状态改为“进行中”，第二条运行程序。输入是 `lesson-01/data/base.json` 和 `lesson-01/config.json`；输出是 `lesson-01/artifacts/summary.json` 和 `lesson-01/artifacts/predictions.csv`。运行成功后终端显示两份文件的位置。

### 2. 从 CSV 中核对一条预测

CSV 是每行一条记录、用逗号分隔各列的表格文本，可用文本编辑器打开，不要求安装表格软件。第一行是列名。找到 `train-03`，按下表读这一行：

| 列名 | 含义 | 原例中的值 |
|---|---|---|
| `queue_length` | 前面的人数，输入特征 | 2 人 |
| `actual` | 实际等待时间，标签 | 4 分钟 |
| `prediction_rule` | 人工规则的预测值 | 5 分钟 |
| `absolute_error_rule` | 预测与实际相差多少，取非负值 | 1 分钟 |

默认规则是“预测分钟数 = 1 + 2 × 排队人数”，所以 `1 + 2 × 2 = 5`。预测 5，实际 4，**绝对误差**为 `|5−4| = 1` 分钟。`summary.json` 用字段名保存汇总；本课先核对这一条，不要求读懂其中全部指标。

### 3. 选一个会影响结果的改动

先在 `report.md` 写下改什么、预计会怎样。可以修改每增加一人需要的分钟数、固定等待时间，或借助 AI 改写规则。不是必须找出一个更好的模型。

例如，把 `lesson-01/config.json` 另存为同目录的 `config-trial.json`，只将 `rule_slope` 从 `2.0` 改为 `1.5`。完整副本应是：

```json
{
  "seed": 7,
  "rule_intercept": 1.0,
  "rule_slope": 1.5,
  "stress_queue": 10,
  "evaluation_split": "train"
}
```

`rule_intercept` 是固定分钟数，`rule_slope` 是每增加一人增加的分钟数；其他字段暂时保留。保存文件，再运行：

```bash
python lesson-01/analysis.py --config lesson-01/config-trial.json --output lesson-01/artifacts/trial
```

新结果位于 `artifacts/trial/`，不覆盖原结果。仍核对 `train-03`，先自己算新预测，再对照新的 CSV。用一条样本更接近实际值，不能证明所有样本都更好。

### 4. 自己选择一个新输入检查

在配置副本中把 `stress_queue` 改为你想检查的人数，说明为什么选它，再运行上一步的完整命令。终端会显示这个新人数的预测；汇总中的 `stress_test` 保存同一次检查。

本例已记录的人数只有 0–3 人。人数 6 是合法输入，但超出这个区间；人数 -1 则不合理。没有新人数对应的实际等待时间时，只能检查计算和输入，不能计算预测误差。`null` 表示暂时没有这个值，不是误差为 0。

若要试负数等无效输入，另存 `config-invalid.json`，使用单独的输出目录：

```bash
python lesson-01/analysis.py --config lesson-01/config-invalid.json --output lesson-01/artifacts/invalid-check
```

明确报错是输入检查的结果，不代表得到了有效预测。记录报错及原因，之后恢复合法配置。不要把旧目录的文件误当作这次新结果。

### 5. 保存自己的工作并提交

将最终保留的合法参数写回 `lesson-01/config.json`，再次运行：

```bash
python scripts/course.py run 01
```

填写 `report.md` 和 `contract.json`，再把 `submission.json` 的 `status` 改为 `complete`；六个任务字段的解释、JSON 格式和第 01 课的完整提交命令见 [第一次运行指南](../docs/FIRST_RUN.md)。不要直接粘贴其他课次的标签或文件名。

```bash
python scripts/course.py check 01
```

检查只确认提交文件存在，不能替教师判断内容。提交时要用指南中的 `git add -f` 加入结果文件；普通 `git add` 会忽略 `artifacts/`。报告引用了试验副本时，也要保存并提交对应配置和结果。

## 必须提交什么

程序和最终配置、实际生成的 `summary.json` 与 `predictions.csv`、自己的报告、已填写的任务说明及提交清单。报告至少说明一条样本的含义、一条预测的计算、自己的选择与输入检查，以及目前不能证明什么。

本课先跑通流程并核对，第 02 课为同一问题加入模型比较。结果中的 `example_only` 表示这是示例程序的输出，不是你的完成状态；不要手改它。C01 不计平时分，但要完成入门练习。

## 不同起点怎么做

入门支持：从给定规则开始，让 AI 解释一条计算；仍需自己选参数或新输入并核对。提高任务：换一个预测数值的问题，解释特征、标签和单位，并相应修改程序。不按代码长度或模型数量评价。

## 运行限制

需 Python 3.10 以上及已安装的 NumPy，课前准备方法见第一次运行指南。数据只有 8 条，普通 CPU 即可；实验不调用模型服务、不需要显卡，单次运行目标不超过 3 分钟。AI 辅助和 Gitea 概念检查另按教师安排；网络不可用时先做本地实验，再补做相应环节。
