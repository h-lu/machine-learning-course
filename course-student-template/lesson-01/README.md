# 第01课（C01）：把真实记录变成可解释的预测规则

## 本课要解决什么问题

共享单车分析员希望从当时已知的信息估计一个小时的租借总次数。你要构建一个**计算过程清楚、别人能重算、能说明何时失准的预测规则**。你可以选择关注哪些小时、由谁使用结果，但须说明预测时已知哪些信息。本数据支持给定实际当小时天气的条件估计，没有未来天气预报、单站库存或干预记录。

你决定研究什么、规则怎样写、怎样找失败。作品可保留简单规则、修改它、缩小用途或暂不采用。首个可开始动作是打开 [数据字典](data/DATA.md) 并选一条开发期记录（训练或验证记录，不含最后测试记录），说明输入与想估计的量；默认程序可帮你读数据。卡住时按需查 [SUPPORT](SUPPORT.md)，保留报错，先用学习页人工例题继续，明确尚未运行再补跑。本课为已授课内容增强，不追改旧要求或成绩。

## 本课要学会什么

| 概念 | 你应能做的判断 |
|---|---|
| 样本与数据集 | 说明一行记录代表什么，区分人数、次数、库存 |
| 特征与标签 | 指出使用时可用的输入和预测后核对的实际值 |
| 回归与预测 | 追踪一条数值预测，计算有符号与绝对误差 |
| 人为参数与训练 | 说明参数来源，区分AI编程与模型从标签拟合 |
| 可复现与输入检查 | 保存运行条件，检查非法或超出已知范围的输入 |

[LEARN](LEARN.md)有完整的小表例题、提示逐步减少的练习和常见错误；正式项目的编号、参数和解释由你决定。

## 课堂任务

教师给情境、核心关系和另一个情境的示范；随后自主构建、核对、改进同一作品，最后按教师通知完成既有课堂选择题。基础支持、标准任务和提高任务是同一作品的不同深度，不是三份重复作业。较快者继续研究敏感性或建议条件。

## 完成步骤

下面是作品应回答的问题，**可以按自己的分析路线组织，并借AI构建代码**。

- **选用途与输入**：谁要看预测？什么时间能知道哪些字段？选择一种简单规则形式及参数，写选择理由与运行前预计。参数可由人设定或用自己选的训练记录解释，不能拿验证答案逐条决定规则。
- **构建并追踪**：让程序在真实验证记录产生预测。自己选三条记录，留下输入→规则→预测→实际→误差的完整追踪，至少一条暴露规则不足。不强制使用同一批编号。
- **自己设计检查**：选择一个会影响实验或建议的条件变化，例如改变规则某项、比较不同小时或检查输入边界。先写为什么这个检查能帮助判断规则的不足，再实际运行或检查；给组内条数或明确没有标签的限制。只改一个因素便于解释，但若有多项改变必须说清。
- **提出有限建议**：选保留、修改、缩小使用或暂停；用实际记录支持它，同时提出其他可能解释和仍缺的数据。C01不要求增加多个训练算法；复杂不自动更好。

你的两项实质决策至少包括：**用途/规则怎样确定**和**失败条件/检查怎样设计**。换一个合理选择应会改变实验或建议，而不是只换输出文件名。

所有命令在学生仓库根目录执行（能看到lesson-01、mlcourse、scripts、requirements.txt）。`analysis.py`是可编辑起点：默认只读取并核对数据，必要时给出基线，运行不会自动完成你的项目。共享`mlcourse/bike_course.py`保留可选例子，也可以借AI自己写读取、规则、拟合、分组与评价代码；不要求必须沿用它的菜单。方法应保持在本课已有概念范围，必要时请AI解释一条输入的计算，不突然引入不理解的新算法。

```bash
python3 lesson-01/analysis.py
```

默认只保存数据审计和开发数据预览，不能作为完成标准项目的全部证据。先看预览的instant/datetime，认出记录单位，再自行构建规则与检查。你可以修改analysis.py，或新写脚本并更新提交命令。

## 必须提交什么

提交自己的规则追踪与失败记录（[report.md](report.md)仅提供可改结构的提示）、真实程序/配置、三条自选追踪、自己的检查证据、有依据建议和运行清单。证据须能对应真实编号，解释参数来源、单位与分母；不能只交截图或默认示范。

目录工具与程序可由AI协助，但关键选择及结果解释由你承担。保存报告引用的数据版本、代码、配置、完整命令、逐条预测与汇总。

`contract.json`保存任务说明，字段名不改，填写六个空字符串（各字段的含义见 [SUPPORT](SUPPORT.md#卡点我想保存自己的作品)）；`submission.json`是提交清单，把`run`改为你自己的可重跑命令、`artifacts`列为实际证据文件，完成后将`status`改为`complete`。示范或基线文件齐全不等于项目完成。

`python3 scripts/course.py check 01`只检查文件，CI（自动检查）重新运行命令，检查清单中的结果文件是否逐字节一致，不替你判断推论；未列入清单的对照仍须保存并给独立命令。用`git add -f lesson-01/artifacts`保存可能被忽略的产物。

C01不计平时分，入门完成和概念检查仍按原办法。

## 不同起点怎么做

**基础支持（Support）**：需要时查看学习页的其他情境的完整例题及卡点说明，先做可核对的最小流程；标准作品仍保留你的用途、规则和检查选择。

**标准任务（Core）**：完成上述作品与证据，不要求固定规则、编号或建议。

**提高任务（Upgrade）**：围绕同一作品选择规则敏感性、不同条件的失败或使用建议之一，研究参数变化在哪些记录上改变结论；不以更多重复报告加深任务。

**迁移与课后挑战（Transfer / Open extension）**：重新定义一个其他数值预测场景的记录单位与可用输入，说明为什么不能直接搬用单车参数；或找温度相近而需求不同的记录，提出后续可检验问题。

## 运行限制

标准任务使用共享的真实 [UCI Bike数据](../data/bike/LICENSE_AND_SOURCE.md)，17,379行、17列，CC BY 4.0。训练 `<2012-07-01` 13,003行；验证 `[2012-07-01,2012-10-01)` 2,208行；最后2,168行测试留到第08课，前七课不评价它。缺少的165个小时记录不能补成0需求；casual和registered相加等于cnt，禁止把这两列作输入。

实验离线；Python 3.10以上与NumPy即可，普通CPU约8GB内存，无显卡或付费依赖。环境已在本机Python3.14/NumPy2.5验证，不代表每台学生电脑具备同一环境。完整说明见 [ENVIRONMENT.md](../ENVIRONMENT.md)。下面命令用python3，学生沿用自己的python或py启动命令即可。AI辅助与课堂选择题按教师安排联网。运行时间只反映程序计算；项目完成还需选择、检查与解释。
