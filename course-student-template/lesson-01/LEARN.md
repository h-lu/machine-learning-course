# 第01课 · 一条预测是怎样算出来的？

假设你在食堂排队。前面有2个人，你想知道还要等几分钟。有人给出一个简单办法：

**预计等待时间 = 1 + 2×前面的人数。**

把2代进去，得到5分钟。这个5是预测，还不是实际等待时间。等轮到你接受服务时，才能知道预测得准不准。

本课就从这样一条规则开始：先看清它用了什么信息，算一次预测，再检查哪里会出错。最后把同样的思路用到共享单车记录中。

## 1. 一行数据记录了什么？

下面是一张人工编制的排队小表，用于手算，不是正式项目数据。

|记录|前面的人数|事后实际等待（分钟）|
|---|---:|---:|
|p|2|4|
|q|3|9|
|r|0|2|

这里从开始排队计时，到轮到自己接受服务时结束；下面的“实际等待”都采用这个定义。

每一行记录一次排队经历，叫作一个**样本（sample）**。这些记录放在一起，组成**数据集（dataset）**。同一个人排队两次，也可以留下两条记录，所以记录数不一定等于人数。

在这个问题里：
- 前面的人数是预测时已经知道的输入，叫作**特征（feature）**。
- 实际等待时间是我们想估计、事后才知道的结果，叫作**目标值（target）**，训练时也常称**标签（label）**。
- 用规则算出的等待时间叫作**预测值（prediction）**。

预测分钟数、租借次数这类数值的任务，叫作**回归（regression）**。如果改问“会不会等超过10分钟”，输出就变成“会”或“不会”。这叫分类（classification）。第3课会学习怎样检查这类判断。

## 2. 顺着一条记录，把计算走完

先看记录p。预测时只读“前面2人”，不能先看实际等了4分钟再决定预测。

1. 代入规则：1+2×2=5分钟。
2. 等结果发生后，读到实际等待4分钟。
3. 用预测减实际：5−4=1分钟。这次高估了1分钟。

对另两条也这样算：

|记录|预测的计算|预测（分钟）|实际（分钟）|预测−实际|绝对误差|
|---|---|---:|---:|---:|---:|
|p|1+2×2|5|4|1|1|
|q|1+2×3|7|9|−2|2|
|r|1+2×0|1|2|−1|1|

“预测−实际”保留正负号：正数表示高估，负数表示低估。只想知道偏离了多少时，去掉正负号，得到**绝对误差（absolute error）**。

把三条绝对误差加起来，再除以3，得到**平均绝对误差（mean absolute error，MAE）**：

**MAE=(1+2+1)÷3=4/3≈1.33分钟。**

这句话的完整意思是：“在这三条记录上，预测平均偏离实际约1.33分钟。”它不是准确率，也不能代表另一批尚未检查的记录。

## 3. 规则里的1和2从哪里来？

本例的1和2是人为指定的，没有通过数据训练。

1是**截距（intercept）**：前面没有人时，规则仍预测要等1分钟。2是**斜率（slope）**：前面每多1人，预测增加2分钟。模型里的这些数叫作**参数（parameter）**。

用训练数据来确定参数，才叫作**训练（training）**或**拟合（fitting）**。让AI写出一段计算代码，并不意味着参数已经经过训练。下一课会比较人为规则和从数据得到的模型。

现在可以先试着改规则。若把2改成1.5：
- p预测1+1.5×2=4分钟，恰好符合实际。
- q预测1+1.5×3=5.5分钟，离实际9分钟反而更远。

因此，只凭一条记录改善，不能说整套规则变好了。比较时要在同一批记录上重新计算。

## 4. 两道练习，先自己算

第一道有提示：前面1人，实际等6分钟。用原规则先算1+2×1，再分别写出预测−实际和绝对误差。

第二道自己完成：前面4人，实际等7分钟。写出预测、误差方向和绝对误差。

核对时检查三件事：是否用了原规则；误差是否按“预测−实际”计算；最后是否写了分钟。如果遇到新输入却还没有实际结果，只能给预测，暂时不能计算误差。没有实际结果，不等于误差为0。

## 5. 回到共享单车，先别急着写模型

正式数据每行汇总整个单车系统在某一个小时的情况，不是一位用户、一个站点或一辆车的记录。目标字段 `cnt` 表示这个小时记录的租借次数，不是单站库存。

例如，`hr=8` 表示8点这个小时；`temp` 是经过缩放的温度数值，不能把`temp=0.5`读成0.5摄氏度。使用哪个字段，先到[数据字典](data/DATA.md)确认它的含义和单位。

项目把历史记录分成不同用途：训练记录用来确定规则参数，验证记录用来检查规则。第2课再详细区分它们；现在先按项目已有的日期范围取记录，不打开最后的测试部分。

本课允许你选择一个简单规则。先选一条训练或验证记录，按下面的顺序写在报告里：

**记录编号 → 预测时知道的输入 → 规则和参数来源 → 预测次数 → 实际cnt → 误差。**

历史表里已经写着cnt，是为了让我们事后核对。不能用它来决定同一条记录应该预测多少。`casual`和`registered`相加正好等于cnt，也不能把这两个答案组成项当成合法预测输入。最后一段测试记录留到第8课，前七课不拿它来挑方案。

本数据没有未来天气预报。如果使用当小时实际天气，结论应写成“已知这些天气条件时的租借次数估计”，不能直接说成“前一天就能作出的预测”。

## 6. 程序运行之后，先检查什么？

在学生仓库根目录运行：

```bash
python3 lesson-01/analysis.py
```

这里的根目录是能看到`lesson-01`、`mlcourse`和`scripts`的目录。默认程序先检查数据并提供开发期预览，不会自动替你选好规则、完成项目。

先在预览中找到`instant`（记录编号）和`datetime`（日期时间），认出这是一条什么记录。再用你写的规则算预测，挑一条用计算器复算，确认程序与手算一致。具体输出文件的位置和报错处理见[操作帮助](SUPPORT.md)。

预测可以保留小数，它表示估计值，不是已经发生了半次租借。若你决定把负预测改成0，或把结果取整，要把这条处理规则记下来，对所有评价记录一致使用。

## 7. 怎样找到规则的不足？

先找一条误差较大的真实记录，再问一个具体问题。例如：“温度相近的两个小时，租借次数是否仍可能差很多？”把两条记录的编号、输入和结果并排看。

如果确有这种情况，可以说单靠温度还不够；但不能因此认定差异一定由工作日、天气或某个活动造成。这些只是需要继续核查的解释。

还要区分两种输入：
- 负的排队人数是无效输入，应提醒检查。
- 很大但非负的人数可以代入算式，却可能超出已有记录的范围，缺少可靠性证据。

同样，单车表中缺少的165个小时不能补成0次租借。“没有记录”和“记录了零次”是两回事。

## 8. 完成到什么程度？

按自己的进度推进同一份作品，不用重复交三份报告。

- **基础完成：**读懂并手算排队例子；认出一条真实记录的输入、目标和预测；能解释误差方向。暂时做不到的项目步骤写明，继续借助操作帮助完成。
- **完整完成：**按[本课任务页](README.md)写出自己的规则，追踪三条真实记录，完成一项有理由的失败检查，并保存代码、运行命令和有证据的建议。基础练习不替代这些原有项目要求。
- **扩展练习（选做）：**只改变规则中的一个参数，在同一批记录上比较。先预计哪些记录可能改善，再检查实际结果；分别找出改善、未改善的记录；若某一类没有出现，说明这一点，不为了凑结果改变数据。

最后试着回答：“别人拿到我的数据、代码和参数，能不能重算出这些结果？”这叫**可复现性（reproducibility）**。可复现让人能够检查你的工作，但一个用错输入的程序也可能稳定地产生错误结果，所以还要检查它是否回答了正确的问题。
