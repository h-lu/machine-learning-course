# 第 21 课（S19）：怎样把任务拆成模型、程序和人的协作

## 本课要解决什么问题

校园设备服务台会收到借用期限、库存、逾期费用和账户操作等不同请求。一个步骤直接给数字虽然简单，但数字错了时很难判断是规则、资料还是计算出了问题。本课把同一件作品拆成“选择路线—查资料或调用工具—形成结果—必要时转人工”，并保存中间产物。

你要比较两条实际运行的方案。**一步基线**使用公开的固定规则直接回答，不查资料或工具；**分步流程**会读取当前资料、库存或费用函数。一步基线未覆盖的新输入会明确记为 `not_covered`，不会自动算错。提交两条方案的结果、一个逐步轨迹、一个自己设计并运行的边界请求，以及采用或限制使用的建议。运行失败时保存命令与完整报错，先按 [入门支持](SUPPORT.md) 的小表继续理解，修复后补跑。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 工作流（workflow） | 按顺序连接多个步骤，后一步实际读取前一步的输出。 |
| 输入输出约定（input/output specification） | 写清字段、单位和缺失值含义，避免相邻步骤误读。 |
| 中间产物（intermediate artifact） | 路线、资料编号、工具返回值等可以单独核对的结果。 |
| 确定性计算（deterministic computation） | 同一输入和配置得到同一结果，适合查表和公式计算。 |
| 人在回路（human-in-the-loop） | 请求需要权限、制度判断或系统没有覆盖时，由人继续处理。 |

完成后，你应能沿一条请求说明每步输入与输出，并区分“自动答错”“没有覆盖”和“转给人后结果尚未知”。

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–15 分钟 | 读一步基线规则，画出 W01 的两条处理路线 |
| 15–35 分钟 | 运行初始开发批次并核对 W01、W02 |
| 35–50 分钟 | 比较自动正确、自动错误和转人工数量 |
| 50–68 分钟 | 换到后一批开发请求并加入自己的边界请求 |
| 68–75 分钟 | 写采用、限制使用或停止建议 |
| 75–90 分钟 | 概念检查与提交 |

## 完成步骤

1. 在学生仓库根目录运行：

   ```bash
   python scripts/course.py start 21
   python lesson-21/analysis.py --config lesson-21/config-start.json --output lesson-21/artifacts/initial
   ```

   成功后先打开 `traces.csv`。W01 中两条方案都回答 7 天，但只有分步流程保存了 `loan-student-current`；W02 中一步基线固定回答 1 件，分步流程从库存表得到 2 件。
2. 打开 `summary.json`。初始 6 条中有 4 条实际自动回答、2 条按参考路线交人。自动正确率的分母是 4，不是 6；人工完成后的结果没有观察，不能把转人工直接写成正确或错误。
3. 运行后一批**开发请求**：

   ```bash
   python lesson-21/analysis.py --config lesson-21/config-support.json --output lesson-21/artifacts/later
   ```

   W07–W12 在后续课程还会继续使用，所以它们是既有开发证据，不是最终测试。比较两批中一步基线的固定规则何时碰巧正确、何时失败。
4. 将 `data/base.json` 复制为 `data/mine.json`，增加一条边界请求。按 [数据说明](data/DATA.md) 补齐路线所需字段，先写预计，再运行：

   ```bash
   python -m json.tool lesson-21/data/mine.json
   python lesson-21/analysis.py --data lesson-21/data/mine.json --config lesson-21/config-start.json --output lesson-21/artifacts/mine
   ```

   你的请求应让两条路线至少有一个中间值或结果发生变化。可以设计固定默认值恰好适用的情况，也可以使用公开规则没有匹配的表达，或检查资料与权限边界。路线必需字段仍要按数据说明填写完整。若显示 `not_covered`，报告覆盖数，不把它塞进错误分母。
5. 把采用批次写入 `config.json`，在 `report.md` 保留预计、实际轨迹和条件化建议，再运行 `python scripts/course.py run 21`。完成后更新 `submission.json` 并执行 `python scripts/course.py check 21`。

## 必须提交什么

- 可运行的程序、最终配置、自己新增的数据和实际输出。
- `summary.json`、`traces.csv`，以及 W01 或另一条请求从输入到中间产物再到结果的解释。
- 两条方案的覆盖数、自动正确数/自动处理数、自动错误数和转人工数。
- `report.md` 中的边界请求、采用或限制使用建议、任务说明和提交清单。

## 不同起点怎么做

### 入门支持（Support）：跟随完整路径完成同一个核心任务

按 [SUPPORT.md](SUPPORT.md) 核对 W01、W02，再添加一条请求。使用支持路径不限制成绩。

### 必做任务（Core）：比较可检查的直接方案与分步方案

实际运行两条方案，追踪一条请求，报告覆盖和处理状态，并运行一个会改变轨迹的自设计请求。

### 提高任务（Upgrade）：改变拆分位置

把资料选择和数值抽取合并或拆开，记录中间产物、故障定位难度和动作数怎样变化；不要用代码行数代替流程成本。

### 换数据重测（Transfer）：换一组服务请求

重新定义使用者、字段、路线、参考值和人工条件；旧数据上的比例不能沿用。

### 自选拓展（Open extension）：接入真实模型候选

可以让课前准备的本地模型提出路线，但要保存模型、输入、配置和实际输出，并与确定性起点公平比较。

## 运行限制

Python 3.10 以上、标准库、12 条人工开发请求，普通 CPU 数秒内完成，不需要网络、显卡或付费服务。本课验证流程拆分和中间产物，不证明真实服务台或语言模型效果。
