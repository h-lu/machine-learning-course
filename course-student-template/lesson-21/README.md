# 第 21 课 · 一句话怎样变成词元和概率

## 本课要解决什么问题

选一类你希望语言模型处理的短文本，例如同学询问借书规定时输入的专名、日期和限制条件；也可以选择自己的文本。检查它怎样被拆分、保留多少内容，以及下一词元的概率怎样得到。本课要找出会影响任务的文本表示问题。提交拆分对照、概率复核和截断案例。遇到生僻词、重要条件被截断或低质量输出时，说明缺的是文本覆盖、上下文还是模型知识，再决定怎样处理。

起步程序使用只有少量词元的教学词表，按最长匹配切分文本，再从固定转移分数表计算下一词元概率和困惑度。这不是生产分词器或大语言模型。配置中的 text 用来换短文本，context_length 控制保留长度；默认保留末尾词元，长度不足时会丢掉开头内容。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **词元与分词器（token / tokenizer）**：词元是模型处理的文本单元，可能是字、子词或其他片段，不等于日常说的一个词。
- **词表与未知词元（vocabulary / unknown token）**：词表决定教学分词器能表示哪些片段；不同真实分词器处理陌生文字的方式不同。
- **上下文窗口（context window）**：模型一次能使用的词元数量，重要信息可能因长度限制丢失。
- **分数、概率和困惑度（logit / probability / perplexity）**：分数经过归一化得到概率；困惑度概括已知目标的预测难度，不直接评价事实是否正确。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选一种文本需要，例如含专名的借阅咨询、带数值条件的规则或中英混写。决定必须保留哪些信息，选择词元覆盖、截断后条件完整性或目标词元概率作为本课检查，不能只凭词元少就判定更好。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-21/analysis.py
   cp lesson-21/config.json lesson-21/config-trial.json
   cp lesson-21/data/base.json lesson-21/data/trial.json
   ```

3. **做出有理由的比较。** 准备意思相近但写法不同的短文本，查看拆分和未知项。再用相同的分数表复核一组概率。你可以自建词表或切分规则，但若比较困惑度，要说明词元单位是否相同。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-21/analysis.py --config lesson-21/config-trial.json --data lesson-21/data/trial.json --output lesson-21/artifacts/trial
   ```

4. **核对数字和含义。** 手算两个输出分数的归一化，确认概率和为 1。把截断前后文字并排读一遍，指出使用者需要的条件是否还在；词元计数不能替代语义检查。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自己写一条容易受截断影响的输入，例如把“仅限周末”放在开头，再接上超过保留长度的文字，或加入词表没有的姓名。实际运行，检查不同文本是否被压成相同的未知词元序列。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 展示至少两种写法的词元与覆盖情况、一次概率计算、一个丢失关键信息的例子，以及调整长度、改写输入或换工具的理由。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-21/analysis.py --config lesson-21/config-trial.json --data lesson-21/data/trial.json --output /tmp/ml-s19-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

检查同义写法和陌生文字；解释一组分数如何得到概率；运行一条截断或未知词元失败输入；说明困惑度不能支持哪些结论；从新目录重跑并保存决定。

### 入门支持（Support）：用较小的起点完成同样的判断

先围绕给定词表改写一条短句；用 AI 帮助计算概率，你核对真正丢掉了哪段意思。

### 提高任务（Upgrade）：增加一种能改变判断的比较

比较另一个可离线使用的真实分词器，并说明词表、字节回退和特殊词元的差异；跨分词器不直接比较原始困惑度。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一份文本或语言再跑一次，例如由短中文句子换成产品编号和中英混写，重新评估覆盖与长度。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

起步词表只有 10 个词元，分数来自人工转移表；必做文本总量控制在 100 条短句以内。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
