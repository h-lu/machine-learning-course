# 第 04 课（S02）：收到的数据能代表全部记录吗

## 本课要解决什么问题

值班人员要整理 8 条已经发生的排队记录，为以后预测等待时间准备数据。表里同时放着实际等待记录、按人数得到的估计值、第二位记录者的标注，还有尚未上传的实际结果。

本课先回答三个问题：截止当前日期，哪些实际标签已经收到？未知值能不能填成 0？两份标注不一致时应该复核什么？本课不训练模型，也不按平均数最小选择“最好方法”。

第一次接触缺失标签或标注复核时，直接按 [入门支持](SUPPORT.md) 完成。第一项任务只需辨认 B02 一行中的三个数。

## 本课要学会什么

| 概念 | 学完后你能做什么 |
|---|---|
| 目标值与标签来源 | 区分实际等待、代理估计和第二份标注 |
| 缺失标签与标签覆盖率 | 区分未知和真实的 0，并写清均值与覆盖率的分母 |
| 标签延迟 | 区分排队发生日期和标签上传日期 |
| 标注分歧 | 比较同一记录的两份标注，按明确容差安排复核 |
| 选择偏差 | 判断已收到的记录是否可能不能代表全部八条 |

这些词和数字例子见 [LEARN.md](LEARN.md)。不需要先会模型训练或统计推导。

## 90 分钟安排

- 0–15 分钟：辨认 B02 的实际记录、代理估计和第二份标注。
- 15–30 分钟：运行第 4 天起点，手算已知均值与覆盖率。
- 30–50 分钟：把观察日改为第 7 天，比较哪些标签新到达。
- 50–65 分钟：只改一个容差或日期，完成个人检查。
- 65–78 分钟：写复核建议、限制和运行记录。
- 78–90 分钟：按教师通知完成概念检查和提交。

## 完成步骤

命令都在学生仓库根目录运行，也就是能同时看到 `scripts` 和 `lesson-04` 的文件夹。电脑找不到 `python` 时，整套命令统一改用 `python3`。

### 1. 先写统计对象

打开 `report.md`，写清本批固定包含 A、B 两个窗口第 1–4 天已经发生的 8 条记录。我们要统计的是实际等待分钟数，不是代理估计。再写下预计：截至第 4 天，是否所有标签都已上传？

### 2. 运行第 4 天起点

```bash
python scripts/course.py start 04
python lesson-04/analysis.py --config lesson-04/config-start.json --output lesson-04/artifacts/original
```

程序读取 `data/base.json` 和 `config-start.json`。成功后按顺序查看：

1. `artifacts/original/records.csv`：每条记录的来源、可见状态和数值；
2. `artifacts/original/comparison.csv`：不同统计办法的汇总；
3. `summary.json`：配置和完整说明，需要时再看。

### 3. 手算两个不同分母

在 `records.csv` 找 `visible=True` 的 A01、A02、A04、B02。第 4 天已收到的实际等待是 1、3、7、9 分钟：

```text
已收到标签的均值 = (1 + 3 + 7 + 9) ÷ 4 = 5 分钟
标签覆盖率 = 已收到标签数 ÷ 本批记录数 = 4 ÷ 8 = 50%
```

均值分母是 4，因为只对已知实际值求平均；覆盖率分母是 8，因为本批一共有 8 条。未知值不能填 0。

再找 A04：第一份实际记录为 7 分钟，第二份标注为 10 分钟，相差 3。默认规则是差异**超过** 2 分钟才标记分歧，所以 A04 需要复核。

### 4. 只把观察截止日改为第 7 天

`config-support.json` 只把 `observation_day` 从 4 改成 7。先预计会新收到哪些标签，再运行：

```bash
python lesson-04/analysis.py --config lesson-04/config-support.json --output lesson-04/artifacts/trial
```

比较 `original` 与 `trial` 的 `records.csv`。新增可见的是 A03、B01、B03；B04 仍未知。记录仍是原来的 8 条，只是可用标签从 4 条增加到 7 条。均值变化不能写成排队服务在这几天变快或变慢。

### 5. 做自己的单一改动

从 `config-start.json` 另存为 `config-mine.json`，只选择一个改动：

- 改 `disagreement_minutes`，检查 A04 是否仍被标记；或
- 改 `observation_day`，检查截止该日已经收到哪些标签。

下面是只改变容差的完整示例。你可以把它复制为 `config-mine.json`，也可以只修改起点配置中的一个数字：

```json
{
  "seed": 7,
  "observation_day": 4,
  "later_day": 7,
  "disagreement_minutes": 3.0
}
```

先在报告写预计，再检查 JSON 并运行：

```bash
python -m json.tool lesson-04/config-mine.json
python lesson-04/analysis.py --config lesson-04/config-mine.json --output lesson-04/artifacts/my-check
```

成功后查看一条具体记录和一个带分母的比例。改变容差只会改变分歧标记，不会修改两份原始分钟数，也不能让标签自动变得正确。

### 6. 保存报告和提交文件

报告需要说明标签来源、两个分母、日期对照、个人检查、具体复核建议和限制。填写 `contract.json` 六个字段，把最后保留的设置写回 `config.json`，实际完成后再把 `submission.json` 状态改为 `complete`。

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

检查通过只表示文件齐全。报告引用的起点、对照和个人检查都要连同配置与结果保存；具体 Git 步骤见 [操作与提交说明](../docs/WORKFLOW.md)。

### 7. 完成概念检查

按教师通知进入第 04 课场次，依次完成 A、学习、B 和反馈。学习阶段只展示本课知识点和学习说明；你可以带着页面中的问题向外部 AI 提问，再自己判断新情境。网络或场次未切换时记录问题并联系教师，不要重复提交。

## 必须提交什么

- 程序与最终配置；
- `records.csv`、`comparison.csv` 和 `summary.json`；
- 起点、日期对照和个人检查所用的配置与输出；
- 已填写的 `contract.json`、`report.md` 和 `submission.json`。

报告必须包括：实际记录、代理估计和第二份标注的来源；均值和覆盖率的算式；日期改变后哪些记录新到达；自己的单项检查；一条具体复核计划；当前数据不能代表什么。

## 不同起点怎么做

### 必做任务（Core）：核对来源、分母和日期

完成第 4 天起点、第 7 天对照、一次个人检查，并根据原始记录提出复核建议。

### 入门支持（Support）：按 SUPPORT.md 完成

[SUPPORT.md](SUPPORT.md) 从 B02 一行开始，提供完整命令、手算、第一份要看的文件和卡住时的处理。它已经覆盖必做任务，不需要再交另一份 Core。

### 提高任务（Upgrade）：按窗口检查覆盖率

分别计算 A、B 窗口的标签覆盖率，并说明小样本和窗口／时段重合带来的限制。

### 换数据重测（Transfer）：换成延迟上传的成绩

区分真实零分与尚未上传的成绩，重新说明统计对象、均值分母和覆盖率分母。

### 自选拓展（Open extension）：检查辅助标注

在能够核对原始来源的小数据上比较人工提取与 AI 辅助提取，保留原始记录、输出和抽查结果。没有真实调用就不能写成 AI 实测。

## 运行限制

需要 Python 3.10 以上、NumPy 和仓库内的 8 条人工数据。普通 CPU 可离线运行，不需要显卡、付费 API 或下载模型。单次运行目标不超过 3 分钟。在线概念检查另需网络；本课结果不能证明真实食堂或真实 AI 服务的效果。
