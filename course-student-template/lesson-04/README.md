# 第 04 课（S02）：这份数据和标签代表谁、代表什么

## 本课要解决什么问题

值班人员收到八条已经发生的排队记录，想知道能否用它们准备等待时间预测的数据。表里既有实际记录，也有估计值和没上传的标签。你要先分清来源，再报告“已经知道什么、还缺什么、应该复核什么”。**本课检查标签，不训练新模型，也不按平均等待最短挑方案。**

**第一次做或操作还不熟：从 [入门支持](SUPPORT.md) 开始。**第一项只需找到四条已收到的标签并算平均值。指南包含现成配置、命令和核对位置；完成这条路径及自己的检查，就覆盖必做任务，不用重复做两套流程。

最后提交程序结果、自己的报告和任务说明。可以让 AI 帮助解释、编程或提出抽查办法。运行出错时先按报错核对文件；软件暂时不能运行，就用学习卡的小表继续手算，注明未运行并在修复后补跑。

## 本课要学会什么

| 知识点 | 能用本课记录说明什么 |
|---|---|
| 目标值与代理标签 | 实际等待记录和按人数估计的值为什么不是一回事 |
| 缺失标签与标签覆盖率 | 未收到与真实零值的区别；均值和覆盖率各除以什么 |
| 标注分歧与复核 | 比较哪两列，怎样判断超过容差，怎样保留争议 |
| 选择偏差 | 哪些窗口或时段更少出现在已收到的记录中 |
| AI 辅助标注与独立核对 | 抽查什么原始依据，为什么不能只让生成标签的模型自证 |

先读 [LEARN.md](LEARN.md)，理解一行数据再运行；术语按需查阅，不要求预先背英文或掌握算法推导。

## 90 分钟安排

0–20 分钟：读情境并核对一条记录；20–30 分钟：运行起点并找到四条已知标签；30–55 分钟：运行现成对照，做一次自己的检查；55–75 分钟：整理比较、建议和提交文件；75–90 分钟：A 题 4 分钟、AI 学习 5 分钟、B 题 4 分钟，最后 2 分钟确认提交并按教师安排查看反馈。

这是教学安排，不是已经测得的完成时间。到第 30 分钟仍卡在软件操作的同学，先完成入门指南的手算，并把命令和报错交给教师处理；不要跳到选做任务。

## 完成步骤

### 1. 先写统计对象，再运行起点

在 `report.md` 写下：本次检查的是 A、B 窗口第 1–4 天已经发生的八条记录；准备统计实际等待，而不是估计值。再写一句你预计哪些标签可能尚未收到。

以下命令均在学生仓库根目录运行，那里有 `scripts` 和 `lesson-04`。只识别 `python3` 的电脑，将 `python` 换成 `python3`。操作不熟时查 [第一次运行指南](../docs/FIRST_RUN.md)。

```bash
python scripts/course.py start 04
python lesson-04/analysis.py --config lesson-04/config-start.json --output lesson-04/artifacts/original
```

程序读取本课 `data/base.json`。先打开 `artifacts/original/records.csv`，看 `id`、`visible`、`observed_minutes`；再看 `comparison.csv` 的 `available_only` 行。`summary.json` 保留完整结果，暂时不需要读懂所有字段。

### 2. 核对分母和一条分歧

`visible=True` 表示截至第 4 天结束已经收到标签。找出 A01、A02、A04、B02，先自己算已知均值和覆盖率，再对照学习卡。均值不是除以全体八条。

找 A04，比较 `observed_minutes` 与 `review_minutes`。差异超过容差才标为分歧；缺第二份标注的记录不参与配对统计。比较表中的填零行是错误示范，代理值行不是全体实际等待的统计，不能按最小均值排名。

### 3. 保留起点，做一个只改日期的对照

先预计推迟截止日会增加哪些已知记录，再运行已准备的 `config-support.json`。它只把 `observation_day` 从 4 改为 7，其他字段不变：

```bash
python lesson-04/analysis.py --config lesson-04/config-support.json --output lesson-04/artifacts/trial
```

比较两次 `records.csv` 的编号和可见状态。仍是同一批八条记录，不是第 7 天另采了八条。截止日均值变化不能解释为服务变快或变慢。字段、分母和日期规则见 [数据说明](data/DATA.md)。

### 4. 选择一次有理由的个人检查

把 `config-start.json` 另存为 `config-mine.json`。可以只改变 `disagreement_minutes`，例如研究容差 1 或 3 分钟是否会改变 A04 的标记；也可以只把 `observation_day` 改成第 5 或第 6 天，研究多收到哪些记录。先写理由和预计，不同时改日期与容差。

下面是只改容差的**示例配置**，可以完整复制；自己的选择不必相同：

```json
{
  "seed": 7,
  "observation_day": 4,
  "later_day": 7,
  "disagreement_minutes": 3.0
}
```

```bash
python -m json.tool lesson-04/config-mine.json
python lesson-04/analysis.py --config lesson-04/config-mine.json --output lesson-04/artifacts/my-check
```

核对一条记录和一个比例。即使结果没变，也解释为什么。提出一条具体复核建议，例如“先查 A04 的加入队伍与取餐时间”，不要只写“让 AI 再检查”。想换数据或实现的同学仍要保留这些判断。

### 5. 写建议、重跑并提交

本课没有训练集／测试集切换。`later_day` 是额外演示的截止日，不是最终测试集；它不得早于 `observation_day`。不要使用 `--split`。

把准备保留的设置写回 `config.json`，保留起点、对照和个人检查的配置与输出。将报告提示替换成自己的回答，填写 `contract.json` 的六项任务说明；完成实际工作后才把 `submission.json` 的 `status` 改为 `complete`。

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

`example_only` 是程序结果的示例标记，不要改它来冒充完成。清单检查不等于内容合格或已上传；[入门指南](SUPPORT.md) 给出 `git add -f` 保存结果的命令，[模块说明](../docs/FOUNDATIONS.md) 解释六个任务字段。

最后按教师指定的 Gitea 场次完成 A→学习→B→反馈，具体操作见入门指南；源码更新不会自动更换线上题库。

## 必须提交什么

提交程序与配置、`summary.json`、`comparison.csv`、`records.csv`、任务说明和报告，以及报告引用的配置副本和输出。不要改原始结果数字。

报告至少包含：目标与标签来源；一个有明确分母的计算；日期对照；一项个人检查及复核建议；数据尚不能代表什么。运行信息集中写一次，不用每个问题重复列文件。

## 不同起点怎么做

### 入门支持（Support）：按现成材料完成核心判断

按 [SUPPORT.md](SUPPORT.md) 找到指定记录、手算、运行对照，再选一个设置说明理由。可以使用现成程序、教师或 AI 帮助，不因使用支持设置分数上限。

### 必做任务（Core）：所有路径共同的完成标准

区分目标、代理与缺失；核对已知均值和覆盖率；比较一条标注分歧；完成日期对照和一项自己的检查；给出有依据的建议。入门路径已经包含这些内容，不另交一份 Core 作业。

### 提高任务（Upgrade）：有余力再检查代表性

按窗口分别计算覆盖率，挑选需要补标签或复核的记录，说明理由。A 与午间、B 与晚间在本例重合，不据此分开断言窗口和时段的影响。

### 换数据重测（Transfer）：换情境再核对

换成延迟上传的测验成绩，保留真实零分和缺失的区别。更换字段时一起调整程序与说明，不能只改列名。

### 自选拓展（Open extension）：实际尝试辅助标注

用一小份能够核对来源的数据比较人工提取和 AI 辅助提取，记录输出与复核结果。需要的服务由教师安排，不要求付费；没有真实调用就不能写成 AI 实测。以上三项为选做，不必全部完成。

## 运行限制

Python 3.10 以上、已安装的 NumPy，八条人工教学样本，普通 CPU 即可。必做程序离线运行，不需要 GPU 或付费服务；AI 学习和在线概念检查另需教师安排网络。单次实验目标不超过 3 分钟，从头重跑目标不超过 5 分钟，实际耗时以运行记录为准。数据只用于练习，不能证明真实食堂或 AI 服务的效果。
