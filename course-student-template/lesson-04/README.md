# 第 04 课（S02）：收到的数据能代表全部记录吗

## 本课要解决什么问题

值班人员正在整理 8 条已经结束的排队记录，准备把它们用于以后预测等待时间。每条记录可能同时出现三种数：直接观测到的目标值、根据其他信息推算的代理值，以及第二位记录者独立得到的复核值；有些直接观测标签还没有上传。你需要先弄清楚每个数是怎样得到的，再决定哪些数可以用于当前统计。

本课围绕一个实际问题展开：如果只看截至某一天已经收到的标签，我们看到的结果能不能代表全部记录？为回答这个问题，你会区分未知值和真实的 0，分别计算已知标签的均值与标签覆盖率，比较不同日期收到的标签，并为有分歧的记录安排复核。本课不训练模型，也不把“平均数更小”误当成更好的方法，因为当前首先要检查的是数据是否完整、来源是否可靠。

如果你第一次接触缺失标签或标注复核，请直接沿着 [入门支持](SUPPORT.md) 操作。支持材料会从 B02 这一行开始，告诉你先看哪个字段、命令在哪个目录运行，以及每一步成功后应当检查什么。完成后提交报告、最终配置，以及起点、日期对照和个人检查生成的结果表。命令报错时请保留完整报错和已经生成的文件，再按 SUPPORT 的“卡住时怎么办”继续；不要手工修改程序生成的结果表。

## 本课要学会什么

| 概念 | 学完后你能做什么 |
|---|---|
| 目标值与标签来源 | 区分目标值（实际等待时间）、代理值和独立复核值 |
| 缺失标签与标签覆盖率 | 区分未知和真实的 0，并写清均值与覆盖率的分母 |
| 标签延迟 | 区分排队发生日期和标签上传日期 |
| 标注分歧 | 比较同一记录的两份值（直接观测值和独立复核值），按明确容差安排复核 |
| 选择偏差 | 判断已收到的记录是否可能不能代表全部八条 |

这些词和数字例子见 [LEARN.md](LEARN.md)。不需要先会模型训练或统计推导。

## 90 分钟安排

- 0–15 分钟：辨认 B02 的直接观测值、代理值和独立复核值。
- 15–30 分钟：运行第 4 天起点，手算已知均值与覆盖率。
- 30–50 分钟：把观察日改为第 7 天，比较哪些标签新到达。
- 50–65 分钟：只改一个容差或日期，完成个人检查。
- 65–78 分钟：写复核建议、限制和运行记录。
- 78–90 分钟：按教师通知完成概念检查和提交。

## 完成步骤

命令都在学生仓库根目录运行，也就是能同时看到 `scripts` 和 `lesson-04` 的文件夹。电脑找不到 `python` 时，整套命令统一改用 `python3`。

### 1. 先写统计对象

打开 `report.md`，先用自己的话写清楚这次统计的对象：A、B 两个窗口在第 1–4 天已经发生的 8 条排队经历，以及我们真正想统计的目标值（实际等待时间）。这里的代理值只能作为辅助信息，不能直接替代目标值。然后写下你的预计：第 4 天结束时，8 条记录的直接观测标签是否已经全部上传？后面运行得到的结果要和这个预计进行比较。

### 2. 运行第 4 天起点

```bash
python scripts/course.py start 04
python lesson-04/analysis.py --config lesson-04/config-start.json --output lesson-04/artifacts/original
```

这条命令会读取 `data/base.json` 中的原始教学数据和 `config-start.json` 中的起点设置，并把结果写入指定目录。`records.csv` 和 `comparison.csv` 在运行前并不存在，它们会在下面的命令成功后出现在 `lesson-04/artifacts/original/`；不要到 `lesson-04/data/` 里寻找它们。看到“结果写入”后，按下面的顺序查看文件，这样不容易把原始记录、汇总数字和完整配置混在一起：

1. `artifacts/original/records.csv`：每条记录的来源、可见状态和数值；
2. `artifacts/original/comparison.csv`：不同统计办法的汇总；
3. `summary.json`：配置和完整说明，需要时再看。

### 3. 手算两个不同分母

打开刚生成的 `artifacts/original/records.csv`，找到 `visible=True` 的 A01、A02、A04、B02。`visible=True` 的意思是“截至本次观察日已经收到直接观测标签”，并不表示这条记录一定正确。第 4 天收到的目标值是 1、3、7、9 分钟，因此可以这样核对两个不同的分母：

```text
已收到标签的均值 = (1 + 3 + 7 + 9) ÷ 4 = 5 分钟
标签覆盖率 = 已收到标签数 ÷ 本批记录数 = 4 ÷ 8 = 50%
```

均值分母是 4，因为只对已知目标值求平均；覆盖率分母是 8，因为本批一共有 8 条。未知值不能填 0。

再找 A04，比较它的直接观测值和独立复核值：前者为 7 分钟，后者为 10 分钟，相差 3 分钟。默认规则规定只有差异**超过** 2 分钟才标记为标注者间分歧，所以 A04 会被标记出来。这里的“标记分歧”只是提醒你回到原始记录复核，并不表示程序已经判定哪一个数正确。

### 4. 只把观察截止日改为第 7 天

`config-support.json` 只把 `observation_day` 从 4 改成 7，其他设置保持不变。运行前先写下预计：哪些记录会因为标签上传日不晚于第 7 天而变为可见？然后运行：

```bash
python lesson-04/analysis.py --config lesson-04/config-support.json --output lesson-04/artifacts/trial
```

比较 `original` 与 `trial` 的 `records.csv`，你会看到 A03、B01、B03 新增为可见，而 B04 仍然未知。记录总数仍是原来的 8 条，只是统计时可用的直接观测标签从 4 条增加到 7 条。因此，均值从 5 变为约 6.143 分钟，说明可见子集发生了变化；它不能证明排队服务在这几天变快或变慢，因为这些排队经历本来都已经结束。

### 5. 做自己的单一改动

从 `config-start.json` 另存为 `config-mine.json`，只选择一个改动：

- 改 `disagreement_minutes`，检查 A04 是否仍被标记；或
- 改 `observation_day`，检查截止该日已经收到哪些标签。

下面是只改变容差的完整示例。你可以把它复制为 `config-mine.json`，也可以只修改起点配置中的一个数字：

```json
{
  "seed": 7,
  "observation_day": 4,
  "later_day": 7,
  "disagreement_minutes": 3.0
}
```

先在报告写预计，再检查 JSON 并运行：

```bash
python -m json.tool lesson-04/config-mine.json
python lesson-04/analysis.py --config lesson-04/config-mine.json --output lesson-04/artifacts/my-check
```

成功后先打开 `lesson-04/artifacts/my-check/records.csv` 查看一条具体记录，再打开同一目录下的 `comparison.csv` 查看一个带分母的比例。改变容差只会改变“是否标记为分歧”，不会修改两份原始分钟数，也不能让标签自动变得正确。报告中要写出你预计的变化、实际看到的变化，以及这项检查仍然不能回答什么问题。

### 6. 保存报告和提交文件

报告需要说明标签来源、两个分母、日期对照、个人检查、具体复核建议和限制。`contract.json` 的 `split_plan` 在本课不是训练/验证/测试划分，而是写清第 4 天起点、第 7 天日期对照和最后保留的观察截止日；`metric` 写均值、标签覆盖率和标注分歧怎样计算。填写六个字段，把最后保留的设置写回 `config.json`，实际完成后再把 `submission.json` 状态改为 `complete`。

```bash
python scripts/course.py run 04
python scripts/course.py check 04
```

检查通过只表示要求的文件已经齐全，并不替你判断结论是否合理。报告引用的起点、日期对照和个人检查都要连同各自的配置与结果保存，这样别人才能重算你的数字；具体 Git 步骤见 [操作与提交说明](../docs/WORKFLOW.md)。

### 7. 完成概念检查

按教师通知进入第 04 课场次，依次完成 A、学习、B 和反馈。学习阶段只展示本课知识点和学习说明；你可以带着页面中的问题向外部 AI 提问，再自己判断新情境。网络或场次未切换时记录问题并联系教师，不要重复提交。

## 不同起点怎么做

### 必做任务（Core）：核对来源、分母和日期

先完成第 4 天起点和第 7 天日期对照，再只改一个设置做个人检查。最后根据原始记录和来源字段提出一条具体的复核建议，并在报告中说明两个分母为什么不同。

### 入门支持（Support）：按 SUPPORT.md 完成

[SUPPORT.md](SUPPORT.md) 从 B02 一行开始，提供完整命令、手算、第一份要看的结果文件和卡住时的处理。它已经覆盖必做任务，不需要再交另一份 Core。

### 提高任务（Upgrade）：按窗口检查覆盖率

如果你已经能独立完成必做任务，可以把整体覆盖率拆开看。分别计算第 4 天和第 7 天 A、B 窗口的标签覆盖率，并列出每个窗口的已知数、总记录数和分母。然后使用 `record_source`、`clock_quality` 找出一条虽然已有数字、但仍应优先复核的记录，写清楚你的优先级依据。最后回答：整体覆盖率从 50% 提高到 87.5% 后，能不能直接说明 A、B 两个窗口同样可靠？必须用分组数字支持你的判断。

### 换数据重测（Transfer）：换成延迟上传的成绩

把同样的检查换到“成绩延迟上传”的情境中：区分真实的 0 分和还没有上传的成绩，然后重新说明统计对象、均值分母和覆盖率分母。重点是迁移本课的判断关系，而不是照抄排队数据中的数字。

### 自选拓展（Open extension）：检查辅助标注

如果你想继续探索，可以在能够核对原始来源的小数据上比较人工提取和 AI 辅助提取。请同时保存原始记录、提取输出和抽查结果，并说明抽查覆盖了什么、没有覆盖什么；没有真实调用时，只能写成设计或模拟，不能写成 AI 实测。

## 运行限制

需要 Python 3.10 以上、NumPy 和仓库内的 8 条人工数据。普通 CPU 可离线运行，不需要显卡、付费 API 或下载模型。单次运行目标不超过 3 分钟。在线概念检查另需网络；本课结果不能直接代表真实食堂或其他数据来源的表现。

> 数据提醒：运行生成的 `records.csv` 还会显示 `record_source` 和 `clock_quality`。它们不是等待分钟数，而是帮助判断先复核哪条记录的来源信息。先读 B04 和 A03 的这两列，写下它们为什么更需要说明。
