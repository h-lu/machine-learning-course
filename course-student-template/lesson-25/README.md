# 第 25 课 · 有了引用，回答就可信吗

## 本课要解决什么问题

把小知识库检索结果组织成可核对的回答，例如帮助同学查借书期限和适用条件；也可以换成自己的数据与读者。决定什么时候给出答案，什么时候说明证据不足。你要检查回答中的每个主张是否真的被当前数据支持。提交逐条证据核对、回答与拒答的比较，以及一条失效案例。找到了引用却支持不了结论时，缩小回答、补证据或拒答。

起步程序先检索短文，再直接摘取原文并附文档编号，实际检查相似度、版本和拒答。它是抽取式问答，没有调用大语言模型生成答案。你可以研究证据链和拒答设计；若加入生成模型，必须另存真实输出并逐条核对。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **检索增强生成（retrieval-augmented generation，RAG）**：先找数据，再让生成模型依据数据回答；检索和生成可能分别出错。
- **证据支持与忠实性（grounding / faithfulness）**：检查回答是否能从给定数据得到，而不是只检查有没有引用标记。
- **可回答性（answerability）**：判断现有有效数据是否足以回答当前问题。
- **拒答（abstention）**：证据不足时明确说明不能回答，同时评估拒掉可回答问题的损失。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一种读者需要的回答，例如当前流程、历史政策或设备说明。决定一条答案需要哪些证据，错误回答和拒答各会造成什么后果。可以选择只返回原文而不合成一句答案。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-25/analysis.py
   cp lesson-25/config.json lesson-25/config-trial.json
   cp lesson-25/data/base.json lesson-25/data/trial.json
   ```

3. **做出有理由的比较。** 在同一组查询上比较相似度标准、返回段落或回答方式。把结果分为找到正确数据、给出有支持的答案、拒答三层；一层分数高不能替代下一层检查。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-25/analysis.py --config lesson-25/config-trial.json --data lesson-25/data/trial.json --output lesson-25/artifacts/trial
   ```

4. **核对数字和含义。** 逐句标注答案依赖哪段原文，核对版本、对象和条件。分别统计可回答问题中漏答的比例，以及无答案问题中仍作答的比例。相似度只用于排序或筛选，不等于答案正确概率。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 设计一个需要组合两段条件的提问，或把有效文档换成内容相似的旧版。实际运行并检查引用是否支持完整结论；直接摘录也可能摘到无关内容。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 保存查询、实际返回数据、答案与引用、逐句支持判断、拒答计数和失败案例；说明采用抽取、生成、仅检索还是停止自动回答的理由。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-25/analysis.py --config lesson-25/config-trial.json --data lesson-25/data/trial.json --output /tmp/ml-s23-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

比较两种回答或拒答设置；区分检索错误与回答不被支持；核对一个完整答案的证据；实际运行无答案或版本失败案例；从新目录重跑并修改决定。

### 入门支持（Support）：用较小的起点完成同样的判断

先检查一条短回答，把每个数字和条件对应回原文；再加入一条数据中没有答案的问题。

### 提高任务（Upgrade）：增加一种能改变判断的比较

加入重新排序或已有离线生成器，检查是否改善证据支持；即使答案更流畅，也保留逐句核对。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一份数据或读者要求再跑一次，例如从查单条规则换成比较两个版本，重新定义足够证据。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做使用短小本地语料与人工向量，不需要语言模型服务；总量不超过 1,000 个段落和 100 条查询。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
