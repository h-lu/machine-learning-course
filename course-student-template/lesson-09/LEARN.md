# 从模型假设到泛化证据

## 为什么复杂模型会给出不同答案

模型不是从数据中“发现唯一真相”，而是用一种关系形式概括记录。直线模型写成 `预测 = 截距 + 斜率 × 输入`，假设输入每增加 1，预测变化量保持不变。二次模型多出“输入的平方”一项，允许变化速度随输入改变。多一个项意味着更高的**模型复杂度**，也意味着它能适应更多形状。

复杂度不是好坏标签。如果真实关系确实弯曲，直线会遗漏结构；数据很少或噪声很大时，更复杂的模型也可能追随偶然变化。

## 一个带单位的小例子

某模型对 3 条验证记录的处理时间预测分别为 6、10、15 分钟，真实值为 5、12、14 分钟。绝对误差是 1、2、1 分钟，因此：

```text
MAE = (1 + 2 + 1) / 3 = 1.33 分钟
```

分母是 3 条验证记录，不是训练记录数。MAE 越小表示平均偏差越小，但看不到误差方向，也不能保证每条记录都更好。

训练 MAE 描述模型对参与拟合的记录表现；验证 MAE 用未参与拟合的记录估计**泛化**。若复杂模型训练误差大幅降低、验证误差却变差，要怀疑它是否过度适应训练数据。这里只先学习区分两类证据；系统诊断放在 S12。

## 训练范围外的预测

**外推（extrapolation）** 是对训练输入范围以外的值预测。例如训练中细节项为 0–10，而新记录为 15。直线仍会机械延长直线，二次模型会按弯曲速度延伸；公式能计算，不等于现实关系仍成立。

若范围外输入没有真实标签，两个模型预测差 14 分钟只能说明假设产生了重要分歧。正确做法是标记证据缺口、限制自动使用，并收集相应范围的真实结果。

## 常见误区

- “训练误差最低，所以模型最好”：忽略了未见数据。
- “复杂模型验证分数更好，所以任何输入都能用”：验证只覆盖实际样本范围。
- “范围外没有报错，所以预测可信”：程序可计算和现实有证据是两件事。
- “斜率说明增加细节会造成处理时间增加”：观察预测关系不自动证明因果关系。

## 何时适用，何时不够

当输入和目标是数值、用途明确、评价范围接近已见数据时，简单与复杂模型的同条件比较很有用。如果重要输入无法取得、数据范围太窄、标签单位不一致，先修正问题或数据；堆更复杂模型不能补上缺失证据。

## 换情境判断

设备数据只包含温度 10–35°C。二次模型在验证集略好于直线。现在要预测 70°C 时的故障时间。你可以报告两个模型的数值差异，但能否据此自动停机？写出缺少的证据和一种安全处理办法。
