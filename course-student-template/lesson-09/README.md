# 第09课（S07）：同样的信息，线性模型和浅树怎样拟合

## 本课要解决什么问题

继续估计共享单车在一个小时里的租借次数。例如，已知这个小时是工作日、气温是多少，能估计出有多少次租借吗？

这节课比较两种做法：线性模型把各项贡献加起来；浅树先按条件把记录分成几组，再用所在组的平均租借次数作预测。两者看到的信息完全相同，我们要看它们在哪些情况下估计得更准。

这里假设已经知道这个小时的实际天气。因此，做出来的是“给定这些信息后的估计”，不能直接当作提前一天的调度预测。

## 本课要学会什么

- 说明训练怎样从有冲突的观测中选出系数。
- 把截距和各项贡献相加，核对线性模型的一次预测。
- 沿条件找到树的末端分组，核对组内训练均值。
- 用相同输入字段、训练记录和评价记录比较模型。
- 区分“平均误差变小”与“已经够实际使用”。

## 课堂任务

先选一个你关心的情形，例如“工作日早晚高峰”或“周末下午”。也可以从前课或本课结果中发现问题再检查；如果是看过结果后才选的，要在报告里说明。用相同原始字段和记录，比较线性模型与浅树；再看你关心的那组记录，而不只看总体平均。自选一条真实记录，分别算线性各项之和、沿树的条件找到预测，解释误差与限制。

你来决定重点情形和主要评价指标；再决定两方共同使用的字段，或树最多分几层。这些选择要有理由，并能影响实验或建议。 AI可帮助写代码、计算和分析；要核对关键数值，不能只交默认输出。也可以自拟其他路线，但要保留真实数据、相同的比较条件和一次预测的计算过程。用来调整方案的数据，不能再被称为“从未看过的最终测试”。

平均少错一些，还不能说明已经够实际使用。若没有事先说明能接受多大误差、判断错了有什么代价，结论应是“比较中改善了，还需用途证据”，不能只凭MAE的大小说能用或不能用。

## 完成步骤

在学生仓库根目录运行；已有环境是Python 3.10+和NumPy。

如果不知道从哪里开始，先读[四条记录的小例](LEARN.md)，再运行下面的比较程序。它会训练线性模型和浅树，并用同一批验证记录检查误差。训练记录用来选模型里的系数或分组条件；验证记录不参与训练，用来比较、修改方案。

```bash
python3 lesson-09/analysis.py --compare --output lesson-09/artifacts/first-comparison
```

完成后打开 `lesson-09/artifacts/first-comparison`：

- `summary.json`：先看两种方法的 MAE，即每小时预测与实际相差多少次租借的平均值。数值小表示这批记录上平均误差小。
- `records.csv`：查看每个小时的实际值、预测值和误差。同一个编号 `instant` 会有两行，对应两种模型；不要把两行当成两个不同小时。
- `trace.json`：查看一条记录的线性预测怎样相加、树怎样一步步分组。按[操作帮助](SUPPORT.md)换成你想检查的记录。

如果这个结果目录已有文件，换一个新的目录名再运行，不覆盖旧结果。运行成功只是得到比较起点：还要完成自己的选择、核对和解释。只运行不带 `--compare` 的命令会得到均值参照，不能代替两模型比较。

阅读和实验顺序由你安排；[HINTS](HINTS.md)解决具体卡点，[EXERCISES](EXERCISES.md)检查能否换一个例子解释。

## 必须提交什么

一份作品要包含：问题与两项重要选择、一条真实记录的计算、同记录的两方案比较、失败检查、建议和限制。填写contract.json，保存报告、代码、配置和结果；把submission.json的run改为自己的命令，artifacts列齐该命令生成的结果。只运行起点尚未完成任务，不另交额外报告或AI对话日志。

沿用v2-l09-final和revision标签，[提交流程](../docs/WORKFLOW.md)与[评分](../docs/ASSESSMENT.md)不变：完成25、代表作品25、期末50，每六课取最好五次。课末A独立判断→AI学习→B换情境，按参与计分，不按正确率扣完成分。

## 不同起点怎么做

先用完整小例看懂关系，再用可选程序或自己实现的方法完成比较。较快者可在同一作品多查一个分组或设置，但不要同时改许多条件后猜原因。有证据地保留原方案也合理。
