# 第 09 课（S07）：简单模型与复杂模型各自假设了什么

## 本课要解决什么问题

**第一次做或不确定从哪里开始：直接打开 [入门支持](SUPPORT.md)，先运行现成配置。** 你会为咨询人员预测一条记录需要多少处理时间，并比较直线模型与弯曲模型。两种模型都能输出数字，但它们对“细节项增加时，处理时间怎样变化”作出了不同假设。

本课要用训练集拟合模型，用验证集比较方案，并查看一个超出训练范围、尚无真实处理时间的输入。你要提交程序结果、一次分钟误差手算、模型选择和使用边界。运行失败时保留命令与报错，先按支持页的小表继续核对，修复后再补跑。

## 本课要学会什么

| 标准术语 | 学完后的表现 |
|---|---|
| 模型假设 | 说明直线和二次曲线分别假设了怎样的输入—输出关系 |
| 模型复杂度 | 说明多一个弯曲项带来了什么表达能力和成本 |
| 训练表现 | 用训练数据上的误差描述模型对已见数据的拟合情况 |
| 泛化 | 用验证集检查模型在未参与拟合的记录上是否仍然有效 |
| 外推 | 识别训练范围以外的输入，并把预测写成待验证假设 |

本课不要求背模型清单。你需要回答：复杂模型在同一验证集上的改善，是否足以支持它的额外假设和使用成本？

先读 [LEARN.md](LEARN.md) 的直线、MAE 和外推小例子；陌生词再查 [术语表](../docs/TERMINOLOGY.md)，不必先背完整术语表。

## 90 分钟安排

0–15 分钟理解用途、输入和 MAE；15–30 分钟运行起点并核对一条绝对误差；30–50 分钟比较两种复杂度；50–65 分钟改变一个范围外输入并写建议；65–75 分钟整理提交；75–90 分钟完成 A 版概念检查、AI 学习和 B 版检查。

第 30 分钟仍没有结果时，先用 SUPPORT 中 R21 的数字手算，明确记录“程序尚未运行”，再把报错交给教师。手算帮助继续学习，但不能冒充程序实验。

## 完成步骤

### 1. 先运行同条件比较

在学生仓库根目录，也就是同时看得到 `scripts/` 和 `lesson-09/` 的目录运行：

```bash
python scripts/course.py start 09
python lesson-09/analysis.py --config lesson-09/config-start.json --output lesson-09/artifacts/start
```

程序读取 `data/base.json`，只用 `split=train` 的 20 条记录拟合模型。成功后先打开 `artifacts/start/comparison.csv`，确认 `evaluation_split` 为 `validation`，再比较两行的 `train_mae_minutes` 与 `evaluation_mae_minutes`。MAE 是平均绝对误差：先算每条预测与真实处理时间相差多少分钟，再对验证集 8 条记录取平均。

### 2. 核对一条记录，而不是只抄总分

打开 `records.csv`，找到 R21 的两行。分别用 `|actual_minutes - predicted_minutes|` 重算 `absolute_error_minutes`，写清单位是分钟。再找一条复杂模型误差更大或改善较小的记录，避免把平均改善误解成每条都改善。

### 3. 改一个设置，检查假设的边界

把 `config-start.json` 复制成 `config-mine.json`，只改 `outside_detail_count`，选择一个大于训练最大值 10 的整数。运行：

```bash
python -m json.tool lesson-09/config-mine.json
python lesson-09/analysis.py --config lesson-09/config-mine.json --output lesson-09/artifacts/mine
```

打开 `outside_check.csv`。这里没有真实处理时间，两个预测相差很大只能说明模型假设分歧，不能说明其中一个更准。报告写下你预计哪种模型变化更快、实际是否符合预计，以及现实中还要收集什么记录。

### 4. 测试前作出选择并保留证据

根据验证 MAE、逐条误差、可解释性和范围外风险，先选择 `simple_linear` 或 `candidate_complex`。允许保留简单模型，也允许采用复杂模型；关键是说明可以支持的数据和情境。起点与个人输出保留验证证据，不要覆盖。

把最终设置写回 `config.json`，并将 `evaluation_split` 改为 `test`；记录选择后运行 `python scripts/course.py run 09`。这时主 `artifacts/comparison.csv` 的 `evaluation_split` 应为 `test`。不能看完测试结果后重新挑模型；若改了方案，这次测试就成为开发证据，需要新的未见数据再评价。在 `report.md` 分别引用验证和测试输出路径。

### 5. 完成提交检查

填写 `contract.json` 的六个任务字段，把 `submission.json` 的 `status` 改为 `complete`，再运行：

```bash
python scripts/course.py check 09
```

检查通过只说明文件存在；教师还会看你的手算、测试前选择和结论边界。

## 必须提交什么

提交 `analysis.py`、最终配置、任务说明、`report.md`，以及 `summary.json`、`comparison.csv`、`records.csv`、`outside_check.csv`。同时保留报告引用的 `config-mine.json` 和对应输出。

报告回答：预测给谁使用；一行数据代表什么；两种模型各自假设什么；R21 的误差怎样算；验证结果怎样影响选择；范围外检查缺少什么证据；最终采用、保留还是暂停哪一方案。下一课会继续讨论怎样把预测用于行动，但会使用另一份已经准备好的概率数据；不能把本课的分钟预测文件当成下一课的直接输入。

## 不同起点怎么做

### 入门支持（Support）：跟着一条可执行路径完成必做任务

使用 [SUPPORT.md](SUPPORT.md) 和现成配置，从运行、手算到单因素检查逐步完成。使用支持材料不降低成绩，也不需要再重复一套 Core。

### 必做任务（Core）：比较假设并限定使用范围

在同一数据划分和 MAE 下比较简单与复杂模型，核对一条记录，检查范围外输入，并在看测试结果前选择方案。

### 提高任务（Upgrade）：检查复杂度是否值得

将 `candidate_degree` 改为 3，比较二次与三次候选的训练和验证 MAE，并说明新增复杂度是否带来稳定价值。

### 换数据重测（Transfer）：换一个有自然边界的数量

把“细节项数”换成“附件数”或其他非负计数，重新说明训练范围、单位和范围外输入；不能只改字段名称。

### 自选拓展（Open extension）：估计选择对成本的影响

为模型维护或人工复核设一个明确成本，说明多小的 MAE 改善才值得采用复杂方案。这是选做，不替代必做比较。

## 运行限制

Python 3.10 以上、NumPy、36 条人工合成记录，普通 CPU 单次通常不足 1 秒；约 8 GB 可用内存即可。实验离线运行，不调用付费服务。人工数据只用于学习模型假设与评价流程，不能证明真实咨询业务中的处理时间规律。
