# S24｜哪些请求可以交给语言模型

## 本课要解决什么问题

为一个有明确权限的小助手设计使用方式，例如帮同学查公开规则但不能修改账户；也可以自己选择用途。决定哪些请求能直接处理、哪些要复核、哪些应拒绝。你要同时看有用请求是否完成和不允许的动作是否被拦住。提交可运行的比较、一次注入或越权测试，以及试用或停止使用的理由。遇到失败时，停止该动作并修复权限路径，不靠更强硬的提示句代替检查。

起步程序在教学请求表上比较关键词过滤和显式动作允许列表，并检查输入扫描长度的影响。它只做本地文本与权限判定，不执行真实外部动作，也不包含语言模型。通过这些样例不构成实际系统安全认证。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **提示注入（prompt injection）**：输入或检索资料夹带要求系统改变原任务的指令，需要识别其来源。
- **最小权限与允许列表（least privilege / allowlist）**：系统只拥有完成任务需要的能力，动作由明确规则决定是否允许。
- **输入接口约定（input schema）**：约定请求字段和类型，避免内容被误当作有权限的指令。
- **应用评价与恢复旧版本（application evaluation / rollback）**：同时检查有用性、失败后果和处理成本，出问题时按预定办法停止动作或恢复旧方案。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 定义一个助手的使用者、可读资料和可做动作，例如查询公开说明但不能改账户。自己列清允许、需人工复核和不允许的请求，并确定误拒正常请求与放行越权动作的后果。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-26/analysis.py
   cp lesson-26/config.json lesson-26/config-trial.json
   cp lesson-26/data/base.json lesson-26/data/trial.json
   ```

3. **做出有理由的比较。** 比较关键词过滤与显式权限检查，或加入你自己的简单方案。让允许请求和不允许请求都进入评价；检查内容来源能否改变动作权限，记录拒绝率与错误放行的实际计数。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-26/analysis.py --config lesson-26/config-trial.json --data lesson-26/data/trial.json --output lesson-26/artifacts/trial
   ```

4. **核对数字和含义。** 逐项追踪请求内容、请求动作和最终许可决定。拒绝原因是否来自权限规则，还是碰巧含有一个关键词？检查扫描长度是否让末尾条件被漏读；字符数不能直接当作真实服务的费用或时延。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 在本地副本加入一条伪装成系统说明的输入，要求完成任务之外的动作；再加入一条包含相同词语但实际合法的请求。实际运行，检查错误放行和误拒是否同时被发现。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 说明助手能做什么、权限在哪里检查、两条路线的有用性与错误放行、失败输入和修复结果；根据这些局部证据决定继续离线试验、限制试用或停止使用。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-26/analysis.py --config lesson-26/config-trial.json --data lesson-26/data/trial.json --output /tmp/ml-s24-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

定义具体权限；运行两条处理路线；同时检查合法请求和越权请求；实际完成一次注入式输入与合法近似输入的对比；写出停止动作或恢复旧方案的办法；从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

从只读查询助手开始，保留两个允许动作和一个禁止动作。AI 可以帮你生成请求，但权限与后果由你确定。

### 提高任务（Upgrade）：增加一种能改变判断的比较

在已有授权的沙盒中加入真实本地工具调用和审计记录，检查权限是否在执行动作前独立验证。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一个权限需求不同的助手再跑一次，例如从查说明换成提交预约草稿；重新设计可以自动完成的动作。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做只执行本地字符串与规则检查，不连接账户、不发送消息、不修改外部系统。请求总数控制在 500 条以内。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
