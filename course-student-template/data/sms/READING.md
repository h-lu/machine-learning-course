# 英文与短信缩写阅读支架

|原文常见写法|供人阅读的释义|需要保留的区别|
|---|---|---|
|ham / spam|正常短信 / 垃圾短信|语料标签，不是程序执行动作|
|u / ur / r|you / your或you are / are|ur要结合上下文，不能一律替换|
|txt / msg / pls|text / message / please|缩写可能影响词表覆盖|
|claim / prize / reward|领取 / 奖品 / 奖励|出现这些词不保证为垃圾|
|free / rate / charge|免费 / 费率 / 收费|free可能是空闲，也可能是免费|
|urgent / reply / stop|紧急 / 回复 / 停止|别实际回复、拨打或访问联系方式|
|train / dev / finalholdout|训练 / 开发 / 最终留出|角色取决于信息是否参与选择|
|TP / FP / FN / TN|真阳性 / 假阳性 / 假阴性 / 真阴性|阳性指spam；action=1是交复核|
|BCE / IDF / L2|二元交叉熵 / 逆文档频率 / 二范数|分别是损失、词项权重、向量长度/正则|
|logit / sigmoid|实数得分 / 转成0至1概率的函数|阈值在概率之后使用|

先用ID在train或dev定位原文，写“原文—自己理解—不确定词义”，可让AI帮助解释。不要向AI发送个人短信。解释文本不传入模型；保持原文SHA不变。模型看到的标点、数字、缩写和可能截断的信息，都应与报告中的追踪对应。需要机器翻译时，保存为另一份实验输入，冻结翻译方法并使用相同划分与评价条件。
