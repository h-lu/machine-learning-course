# S05 · 复核名额应该给谁

## 本课要解决什么问题

值班团队每天只能复核有限数量的记录，希望尽量找到真正需要处理的对象。模型给出了分数，却没有决定查多少、漏掉谁、哪些情况交给人工。你要选择一种复核目标，制定能在容量内执行的规则。

请交规则、复核人数、误报漏报结果和建议。容量不足或分数不可信时，可以缩小用途、调整人工安排或停止自动筛选；不能只交一条看起来漂亮的曲线。

### 由你选择的用途与方案

可以为风险排查团队优先减少漏报，也可以为资源紧张的审核组减少无效复核；还可自拟目标。你决定阈值、排序取前若干条或分段人工处理，确定代价与接受标准；任何新容量或成本假设都要写明。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **精确率与召回率（precision / recall）**：分别看建议复核中有多少真的需要，以及真正需要者找到了多少。
- **阈值（threshold）**：把分数转成行动的分界，不一定是0.5。
- **基础率（base rate）**：真正需要处理者在全部记录中的比例，影响复核的有效程度。
- **概率校准（calibration）**：被预测为相近风险的对象，其实际比例是否与概率相符。
- **人工复核与暂不判断（human review / abstention）**：对信息不足或代价特殊的情形另行处理，仍要计算所需容量。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟明确复核目标；12—27分钟核对两个分母；27—51分钟比较阈值与容量；51—66分钟检查群体与边缘案例；66—75分钟选择和重跑；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 先写预计提高阈值会改变哪些数量，再运行 config.json 中的候选设置。
2. 从 data/base.json 抽出几条记录，手工核对一次复核名单与两种比例的分母。
3. 修改规则或容量假设，保留最后检查前使用的版本；在 report.md 解释是否改了原建议。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-07/analysis.py
```

默认结果保存为 `lesson-07/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`threshold`、`capacity` 和 `false_negative_cost` 分别对应分界、可用名额与漏报代价。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-07/analysis.py --output artifacts/S05-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 选择用途与复核容量，先写评价办法及接受标准；明确误报漏报分别会发生什么。
2. 用开发资料比较阈值或排序规则，计算每种规则的复核人数、找到数量、遗漏数量和相关损失。
3. 检查一种重要群体或基础率变化，并查看分数能否当作概率理解。
4. 设计一条接近规则分界或信息不足的输入，说明如何处理；最后用未参与选择的记录检查选定规则。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

可执行的复核规则；同一批记录上的人数和错误比较；容量与群体检查；一条边缘输入及处理办法；采用、限用或暂缓建议。合格标准包括人数算得对且方案能实施。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

使用已有分数，不必重训模型；完成容量、比例和一条边缘记录的完整判断。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较概率校准前后的行动结果，或检查群体分配取舍。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换基础率不同的数据再跑，重新评估阈值与名额。

### 自选拓展（Open extension）：提出本课问题之外的新探索

设计包含人工暂缓判断的规则，并计入人工工作量。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
