# 第07课 · 只能再取得少量真实结果，应该选哪些记录？

模型表现不好时，多一些数据可能有帮助。但预算有限，并不是所有记录都能立即取得真实结果。

假设你已经知道一些记录的真实结果，也就是标签；预算只够再取得两条记录的标签。是随机选，还是优先选目前很少见的情况？这一课要比较两种选择怎样改变数据，以及改变后预测是否真的改善。

## 1. 先看一个晴雨天小例

下面是人工例子，不是单车策略的实际结果。

初始有6条已经知道真实结果的记录：晴天4条、雨天2条。还没看标签的记录里，两类都有。现在只允许补看2条。

|选择办法的一次结果|新增晴天|新增雨天|合并后的晴天|合并后的雨天|
|---|---:|---:|---:|---:|
|随机选择，这次恰好选到两条晴天|2|0|6|2|
|优先补目前较少的雨天|0|2|4|4|

从候选中选部分记录，叫作**抽样（sampling）**。可供选择的集合叫作**候选池（candidate pool）**；允许补看多少真实标签，叫作**标注预算（labeling budget）**。

第二种办法让两类数量一样多，但这只说明计数均衡。如果现实里晴天本来就多，两类各一半并不等于更有代表性；误差是否下降，也还没有计算。

## 2. 为什么必须先选，再看标签？

假如先看到某条记录的真实cnt，发现加进去能降低误差，再把它选入，就已经利用了本来需要付出预算才能获得的答案。

正确顺序是：

**保存选择规则 → 仅用可见输入选编号 → 保存编号 → 揭示所选标签 → 重新训练 → 用相同验证集评价。**

这里的“揭示”就是读取所选记录原来隐藏的cnt。

本课使用已有真实数据模拟这个过程，叫作**标注预算回放（label-budget simulation）**。原CSV其实包含答案，课堂约定在选择时不查看它们；这不是技术保密，也不是实际采集了新数据。

## 3. 单车任务里的各部分怎样分？

只从训练期的13,003条记录中建立初始已标注集与候选池，二者编号不重叠。验证和测试记录都不能进入候选池。

例如，初始已知240条标签，再选120条不同记录，最终有360条可用于训练。这些数只是举例，自己的预算按项目设计说明。

先给选样程序一份不含标签的清单，可以包括：
- instant：记录编号；
- dteday：日期；
- hr：小时；
- workingday：是否工作日。

不能给cnt，也不能给相加就能得到cnt的casual、registered。其他字段只有在设定的选择时点已知，才允许使用。保存这份清单和最终选中的编号，才能检查是否先选后看。

## 4. 怎样设计一个简单的覆盖策略？

可以按“小时hr、是否工作日workingday”组合分组。例如(hr=8, workingday=1)表示工作日8点，是一个组；(hr=8, workingday=0)是另一个组。

看看初始已标注记录在哪些组较少，再优先补这些组。若多组同样少，或组内候选不止一条，也要在看标签前规定并列顺序。一次选多条时，还需说明每选一条是否更新组计数；这两种办法可能选出不同名单。

例如，某组只有两条训练标签10、30次，组均值是20次。使用按组均值预测时，落入这组的记录都预测20次。

如果新揭示的该组标签为50，组均值就从(10+30)÷2=20变为(10+30+50)÷3=30。它是否改善验证误差，还要看验证记录的实际结果，不能只凭均值改变判断。

如果某组完全没有已知标签，就不能求该组均值。可以事先规定**回退规则（fallback rule）**，例如使用当前已取得标签的总体均值。这个备用值也不能由验证答案计算。

覆盖策略只是一个候选。为判断它是否有帮助，应与从同一个候选池随机选同样多记录的办法比较。两者要共用初始集、预算、模型与验证记录，否则无法清楚解释差异。

## 5. 随机结果会变化，怎样报告才公平？

一次随机抽样可能恰好抽得不错，也可能恰好较差。可以使用事先规定的多个**随机种子（random seed）**重复比较，并保留全部结果，不只报告最好的一次。

每次至少检查：
1. 是否选了预算允许的数量？
2. 编号有没有重复，是否都来自候选池？
3. 是否排除了初始已标注记录与验证、测试记录？
4. 训练只用了共同初始标签和本方案新选的标签吗？
5. 两方案是否在同一批验证记录上评价？

反复使用同一个验证集，不会增加独立测试的数量。这些结果仍用于改进方案，不能说成做了多次独立测试。

## 6. 多了数据，哪些结论仍不能下？

**代表性（representativeness）**关注所选记录能否支持对目标总体的判断，不能只靠各组数量相等来保证。

**标签质量（label quality）**关注真实结果本身是否可靠。若原交易记录是10次，AI生成了20次，生成数字不能代替新的真实观察。合成记录可以测试程序，不应冒充新采集证据。

Bike训练中天气类别4仅有3条。即使重新分配标注预算，也不能凭少量记录保证严重天气下的可靠性，更不能补出根本不存在的新城市、新站点数据。

因此报告最好分开写：
- 训练可见组数或各组记录数怎样改变；
- 同一验证集的平均绝对误差（mean absolute error，MAE）怎样改变；
- 哪些情境仍缺足够数据。

## 7. 运行程序前，先检查它实际做了什么

默认代码只检查文件、预览数据结构，不会自动选样、揭示标签或比较策略，也没有可直接调用的`select`命令。

按[任务页](README.md)组织自己的步骤。先完成一个预算下的两方案比较，再考虑增加预算。把记录数与模型误差画在一起，可以得到**学习曲线（learning curve）**，用来观察数据增加时误差怎样变化；曲线必须来自实际计算，不能按预期手画成下降。

## 8. 练习与不同完成程度

- **基础完成：**复算晴雨天小表，解释“数量更均衡”“更有代表性”“预测更准”为什么是三个不同判断。
- **完整完成：**按原项目要求完成先选后揭示的预算比较，保存可见字段、所选编号、训练来源及相同验证条件下的结果。
- **扩展练习（选做）：**在其他条件固定时比较两个合理预算。事先预计哪些组会补到记录，再检查实际覆盖和误差是否同步改变；若没有同步改变，提出一个需要继续验证的解释。

如果总体MAE下降，但少见小时依然没有数据，可以写：“本次验证总体误差下降，但尚无证据说明少见小时也改善。”把成果与未知分别说清楚，就是本课的重点。
