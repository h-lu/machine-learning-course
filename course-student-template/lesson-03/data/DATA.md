# S01 数据、参数和结果说明

本课用人工编写的 24 条排队记录。不是个人真实数据，也不是 AI 服务的实际输出。S01/S03/S04 的核心编号与标签相同；S06 另隐藏部分人数。这里先学预测与提醒的区别，跨课比较仍要核对数据版本。

## 一行记录是什么

`base.json` 是文本文件，顶层 `rows` 是记录列表。三个虚构窗口各有 8 条；例如 `B05` 表示窗口 B、第 5 天的一次排队，不是 5 个人。

| 字段 | 含义与单位 | 是否进入本课默认预测？ |
|---|---|---|
| `id` | 样本编号，如 B05 | 否，用来对应记录 |
| `queue_length` | 开始排队时前面的人数，非负整数 | 是，唯一特征 |
| `wait_minutes` | 排队结束后知道的实际等待分钟数，非负 | 是标签，不是预测输入 |
| `period` | 午间或晚间 | 否，供分组检查 |
| `site` | 窗口 A、B、C | 否 |
| `day` | 第几天 | 用来说明已给定的数据划分，不作特征 |
| `split` | 数据用途 | `train`=训练集，`validation`=验证集，`test`=测试集 |

第 1–4 天是 12 条训练样本；第 5–6 天是 6 条验证样本；第 7–8 天是 6 条测试样本。本课只读验证结果。训练标签总和为 88；均值基线预测 `88/12`。回归参数也只用训练样本拟合；验证或测试标签只用于核对预测，不参与拟合。

## 配置先改哪一项

`config-start.json` 是入门起点，`config-support.json` 只把提醒阈值从 8 改为 10。它们都已准备好。先运行，再把起点另存为 `config-mine.json` 做个人检查；最终保留的设置写入 `config.json`。

| 参数 | 含义 | 本课操作 |
|---|---|---|
| `alert_minutes` | 预测大于或等于多少分钟时提醒；单位为分钟，不是概率 | 首次个人试验只改它；可为 0 或正数 |
| `stress_queue` | 额外测试的新人数，非负整数；没有对应标签 | 可以另做一次只改人数的检查 |
| `primary_model` | `baseline`、`rule`、`linear` 指定主要汇总对象 | 先保持 `linear` 也可以；所有方法仍会计算，不是自动采用决定 |
| `rule_intercept` | 人工规则的固定等待分钟数，默认 1 | 非负数；提高任务可改 |
| `rule_slope` | 每增加 1 人，规则预测增加的分钟数，默认 2 | 非负数；不决定回归系数 |
| `evaluation_split` | `validation` 或 `test`，只改变评价对象 | 本课保持 `validation`，不打开最后测试 |
| `seed` | 保留的随机种子字段，默认 7 | 本课无随机步骤，改变它不会改变预测；仍需为非负整数 |

不要复制其他课的整份配置，不要随意增添字段。未知字段、负人数、非整数人数等会明确报错。每次 CLI 运行都执行拟合；只改提醒阈值不会改变训练数据、拟合方法或得到的回归系数。

## 先看逐条记录，再看比较表

`records.csv` 每一行是“一个方法对一个样本”的结果。三种方法各对同样 6 条验证样本预测，共 18 行。计算某种方法的 MAE 时只用它的 6 行，不能除以 18 或 24。

| 列 | 怎么读 |
|---|---|
| `id`、`method` | 同时匹配样本与方法；例如 B05 + rule |
| `actual` | 真实等待分钟数 |
| `prediction` | 预测等待分钟数 |
| `absolute_error` | 两者差的绝对值，单位分钟 |
| `alert` | True=发提醒，False=不提醒；比较的是预测与阈值，不是真实值与阈值 |

`comparison.csv` 汇总各方案。`method_name` 是中文名，`n` 是每种方法评价的样本数，`mae` 是平均绝对误差，`alerts` 是提醒条数。要核对各方法的编号相同，不能只看 `n` 相同。

`no_action` 特指“不提供预测，也不发提醒”，没有对应预测行；它的 MAE 空白／`null` 是未定义，不是零误差。`rmse`、`asymmetric_loss` 是其他课程复用的指标，本课暂不要求解释，也不用拿它们代替 MAE。

## 新人数的结果在哪里

`stress_queue` 不会修改验证集。它只生成一个额外输入，因此不会改变比较表中的 MAE 或样本数。终端会显示新人数和三种预测；完整值位于 `summary.json` 的 `stress_test.metrics`：

- `queue_length` 是新人数；`predictions` 保存 baseline、rule、linear 的预测。
- `actual=null` 是没有真实等待标签，不能计算误差。
- `measured_intervention_effect=null` 是没有测量提醒的实际效果。

## 其他结果与保存

`summary.json` 的 `metrics` 对应 `primary_model` 指定的方法，`comparison` 保存其余方案，均不表示程序建议采用哪一种。`details.by_period` 是可选的时段检查；每组样本很少，不能直接推广。`provenance` 中的哈希帮助核对数据、配置和代码是否变化，不证明来源真实。

每次试验用新的 `--output` 目录，保留配置和命令。失败后旧文件可能仍在，不能当本次结果。`submission.json` 中的完成状态由你在实际完成后填写，不通过修改结果中的 `example_only` 完成作业。

数据生成入口为 `mlcourse/foundations_data.py` 的 `example_data`；批量生成脚本仅输出到新的空目录。入门学习不需要运行生成脚本或修改原数据。

## 现场背景字段

每条记录另有 `staff_count`（窗口可工作人数）、`weather`（晴、阴或雨）和 `event_flag`（是否处于课程预设的忙碌日）。默认模型只使用 `queue_length`；这些字段用于冷读时检查“为什么相同人数可能不代表相同等待”，不是程序已经拟合的特征。若要使用它们，必须明确修改代码、保存新配置并重新评价，不能只在报告中说模型已经考虑了现场条件。
