# S01 入门支持：先算一条预测，再比较提醒

这是 [第三课](README.md) 的详细路径，不是额外作业。使用现成代码和配置也可以完成必做任务；不用再重复 README 的自主路径。本节先沿用“给准备排队的同学显示预计等待分钟数”的用途，你只需做一个有理由的个人选择，不必一开始另想大项目。

## 1. 第一项小任务：不用开电脑也能开始

历史记录 **B05** 是窗口 B、第 5 天的一次排队。开始时前面有 **1 人**，结束后实际等了 **8 分钟**。人工规则为“预计分钟数 = 1 + 2 × 人数”。

先在草稿写三行：输入是几人？规则预测几分钟？预测与实际相差几分钟？再读 [LEARN.md](LEARN.md) 第 1–4 节的解释，或往下用程序核对。这就是今天的第一项任务。

**特征**是预测时使用的输入，本例是人数；**标签／目标值**是实际等待时间；**预测值**是规则或模型算出的估计。`B05` 只是编号，不是第五位同学的姓名。

打开 `lesson-03/report.md`，先写使用者、输入、输出和用途。例如可以沿用“只给大致分钟估计”，再用自己的话写为什么需要它。先保留预计，其他部分拿到结果后再填。不需要现在读懂全部配置字段。

## 2. 不改代码，先找到一次成功运行

在学生仓库根目录执行，那里有 `scripts` 和 `lesson-03`。不清楚终端或根目录时，使用 [第一次运行指南](../docs/FIRST_RUN.md)；不要在 Python 的 `>>>` 后输入命令。只能识别 `python3` 时，把下面的 `python` 换成 `python3`。

```bash
python scripts/course.py start 03
python lesson-03/analysis.py --config lesson-03/config-start.json --output lesson-03/artifacts/support-start
```

第一条只记录开始，不会训练模型。第二条才运行实验：`--config` 指定现成配置，`--output` 指定输出目录；本课数据默认来自 `lesson-03/data/base.json`。先不改 `config-start.json`。

看到“结果写入”后，在 `lesson-03/artifacts/support-start/` 打开 **`records.csv`**。CSV 是逗号分列的表格，可用编辑器或表格软件查看。先找下面点名的一行，不必看懂全部输出。

## 3. 核对一条，再比较同一批六条

在 `records.csv` 同时找 `id=B05`、`method=rule`。三种方法对同一记录分别计算，所以一个编号会出现三次，不是新增了三条独立样本。

| 列名 | 含义 | 这一行的核对值 |
|---|---|---:|
| `queue_length` | 输入人数 | 1 人 |
| `actual` | 实际等待时间 | 8 分钟 |
| `prediction` | 人工规则的预测 | 3 分钟 |
| `absolute_error` | 预测与实际的绝对差 | 5 分钟 |
| `alert` | 是否发提醒 | False，即不提醒 |

核对 `1 + 2 × 1 = 3`，以及 `|3 − 8| = 5`。默认阈值是 8 分钟，但规则根据**预测的 3**决定不提醒，不能用事后知道的 8 替换预测。`True` 表示提醒，`False` 表示不提醒。

接着打开同目录的 **`comparison.csv`**。本课先看 `method_name`（方法名）、`n`（样本数）、`mae`（MAE，分钟）、`alerts`（提醒条数）。`baseline`、`rule`、`linear` 分别是均值基线、人工规则、一元线性回归的代号。

逐方法核对编号都是 **A05、A06、B05、B06、C05、C06**，不只是数出各有 6 行。按 LEARN 的六条小表手算规则 MAE：绝对误差相加为 26，除以 6，约 4.333 分钟。分母既不是全部数据的 24，也不是 CSV 的 18 行。

| 方法 | 验证样本数 | MAE（分钟，约） | 阈值 8 时的提醒数 |
|---|---:|---:|---:|
| 均值基线 | 6 | 3.889 | 0 |
| 人工规则 | 6 | 4.333 | 0 |
| 一元线性回归 | 6 | 2.556 | 3 |
| 不提供预测也不提醒 | 6 | 没有定义 | 0 |

这些只是原始数据和起始配置的自查值，不是评分目标或采用建议。四舍五入的小差异正常。最后一行的 MAE 空白或 `null` 不是零；只显示预测而不提醒的工具仍可计算误差，不要混淆两种“不提醒”。

把自己的计算及三种方法的比较填入报告第 2 节。其他兼容指标、分组统计和哈希暂时不用逐项解释，含义可按需查 [数据说明](data/DATA.md)。

## 4. 先预计，再跑准备好的对照

`config-support.json` 只把 `alert_minutes` 从 8 改为 10，其他字段不变。它是**提醒阈值**，不是回归系数。

运行前先问自己：B06 的回归预测约为 8.333 分钟。阈值从 8 变成 10，提醒会怎样？预测与 MAE 会不会跟着改变？把预计写到草稿，再运行：

```bash
python lesson-03/analysis.py --config lesson-03/config-support.json --output lesson-03/artifacts/support-compare
```

并排查看两次 `records.csv` 中 B06 的 `linear` 行，再比 `comparison.csv` 的 `linear` 行。输出放在不同目录，不覆盖起始结果。

<details>
<summary>运行后展开核对</summary>

B06 的预测仍约为 8.333，`alert` 从 True 变 False。回归的 MAE 仍约为 2.556，提醒数从 3 变为 1。两次都会执行拟合，但阈值没有参与拟合，训练数据和方法也没有变，所以回归系数与预测不变。

只看 B05 的规则行，两次都不提醒，也不说明阈值修改失败；那一行的预测 3 低于两个阈值。应核对指定方法、指定样本和实际配置。
</details>

## 5. 做一次自己的选择，不照抄采用结论

从 `config-start.json` **另存为 `lesson-03/config-mine.json`**。自己选一个适合所述用途的提醒阈值，例如 9 或 12 分钟；只改 `alert_minutes` 后面的数值，其他字段不动。例子不是标准答案，要先解释你的用途、为什么选它，以及预计哪条记录会变。

另存时保留英文双引号、逗号和冒号，数字不用引号，文件名不要多出 `.txt`。先检查格式，再运行：

```bash
python -m json.tool lesson-03/config-mine.json
python lesson-03/analysis.py --config lesson-03/config-mine.json --output lesson-03/artifacts/my-check
```

格式检查成功只说明 JSON 能读，不说明实验完成。第二条成功后，核对一条记录的预测与提醒状态，以及总提醒数。即使没有变化，也可以根据预测与阈值解释原因，不必为了让结果变好继续改参数。

可以让 AI 解释一列数据，或提出两种提醒办法及各自的取舍；仍由你选一项、运行并说明理由。

在报告第 3–4 节保留自己的预计、实际结果和建议。你可以选择继续研究、只提供分钟数、暂不提醒或暂停；要引用结果说明理由，不能把提醒条数写成节省的等待时间。

也可以改做新人数检查：另存一个配置副本，只改 `stress_queue`，仍使用上面的运行方式。新人数不追加到验证集，因此比较表的 MAE 不会因此变化；新预测在终端“新输入检查”及 `summary.json` 的 `stress_test.metrics.predictions` 中。`actual=null` 表示没有真实等待时间，不是误差为零。每次检查使用新的输出目录。

## 6. 写完报告，保存后再参加概念检查

按 `report.md` 五节回答，运行条件统一写在最后一节，不要在每个问题下重复一遍文件清单。至少有任务定义、一项手算、同样本比较、个人选择及检查、有限的建议。示范数值不代替个人试验。

将最后保留的配置复制到本课 `config.json`。`primary_model` 只是汇总重点：`linear` 表示回归、`rule` 表示规则、`baseline` 表示均值基线；所有方法仍会计算。可以先保留它的原值，报告明确写自己的建议。暂不采用时无需编造一个 `none` 参数。

`contract.json` 是任务说明，保留 `lesson`，其余六项用自己的话填写：`question` 写问题，`user` 写使用者，`data_source` 写人工数据来源，`metric` 写指标与单位、分母，`split_plan` 写训练／验证／测试用途，`initial_expectation` 写实验前预计。完成实际工作后再把 `submission.json` 的 `status` 改为 `complete`，不要改程序结果的 `example_only`。
