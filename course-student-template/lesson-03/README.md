# 第 03 课（S01）：怎样把模糊需求变成可研究的问题

## 本课要解决什么问题

“用 AI 让同学少排队”是一个愿望，还不是可以检查的任务。本课把它缩小成一个能运行的小实验：**同学准备加入取餐队伍时，程序根据当时看到的排队人数，估计还要等几分钟；如果估计时间达到某个值，再决定是否显示提醒。**

这里有两个不同的问题：预测值和实际等待时间相差多少？提醒是否真的让人少等？本课的数据只记录排队人数、实际等待时间和程序提醒，没有记录谁看到了提醒、谁改变了行动，所以本课只能检查预测和提醒数量，不能证明提醒带来了更短的等待。

如果你第一次做这类作业，直接按 [入门支持](SUPPORT.md) 的顺序完成。它会告诉你先算哪一行、在哪个目录运行命令、成功后打开哪个文件，以及怎样只改一个设置做比较。你仍要自己选择阈值或新输入，并把实际结果写进报告。

## 本课要学会什么

| 概念 | 本课结束时你能做什么 |
|---|---|
| 任务定义（task definition） | 写清使用者、做预测时已经知道的输入、程序输出和使用目的 |
| 特征（feature）与标签（label / target） | 区分开始排队时知道的前面人数，与结束后才知道的实际等待分钟数 |
| 预测值（prediction）与提醒 | 用预测值决定是否提醒，不把事后知道的实际值当成输入 |
| 基线模型（baseline model）和比较 | 在同一批验证样本上比较均值基线、人工规则和一元线性回归 |
| 平均绝对误差（MAE）与因果效应 | 重算 MAE 的单位和分母，并说明预测更准不等于提醒让等待变短 |

第一次出现的术语会在 [LEARN.md](LEARN.md) 中用例子解释。你不需要先会写训练算法，也不需要先读完整术语表。

## 90 分钟安排

- **0–15 分钟：先写任务。** 在报告和 `contract.json` 中写使用者、输入、输出、用途和预计结果。
- **15–30 分钟：运行起点。** 从仓库根目录运行命令，打开一条 `records.csv` 记录，核对预测和绝对误差。
- **30–50 分钟：比较方法。** 只看同一批 6 条验证记录，核对三种方法的 MAE、单位和分母。
- **50–65 分钟：做一次个人检查。** 只改提醒阈值，或者另设一个没有标签的新人数，先写预计再运行。
- **65–78 分钟：写报告并保存。** 说明实际结果、选择的办法、失败检查和限制。
- **78–90 分钟：完成概念检查。** 按教师通知进入 ml-check，完成 A、学习和 B 阶段，最后检查提交清单。

如果第 30 分钟还没有生成结果，先回到 SUPPORT 的小表，记录已执行的命令和报错，再修复或请教师协助。手算结果要在报告中标成“尚未运行”，不能冒充程序结果。

## 完成步骤

所有命令都在学生仓库根目录运行。根目录是能同时看到 `scripts`、`lesson-03`、`mlcourse` 和 `requirements.txt` 的文件夹。电脑只识别 `python3` 时，把下面命令中的 `python` 换成 `python3`。

### 1. 先写任务和预计

打开 `lesson-03/report.md`，先填写第 1 节：谁会使用结果？做预测时能看到什么输入？输入的单位是什么？要预测的标签是什么？结果准备用来做什么？最后写下你预计三种方法的误差和提醒数量会怎样不同。

再打开 `lesson-03/contract.json`。这是一个 JSON 文件，也就是用大括号保存字段和值的文本。只填写下面六个空字段，保留 `"lesson": "lesson-03"`：

- `question`：你要预测什么，以及结果给谁看？
- `user`：谁会在什么时候使用结果？
- `data_source`：数据从哪里来，一行数据代表什么？
- `metric`：用什么指标比较，单位和分母是什么？
- `split_plan`：训练集、验证集、测试集分别做什么？
- `initial_expectation`：运行前预计哪个方法会怎样，为什么？

### 2. 运行起始实验

先在根目录执行：

```bash
python scripts/course.py start 03
python lesson-03/analysis.py --config lesson-03/config-start.json --output lesson-03/artifacts/original
```

第一条命令只把本课标成“进行中”。第二条命令读取 `lesson-03/data/base.json` 的 24 条人工记录和 `config-start.json` 的参数，生成三个结果文件：

- `lesson-03/artifacts/original/records.csv`：每条记录、每种方法的输入、预测、实际值和误差；
- `lesson-03/artifacts/original/comparison.csv`：三种方法在同一批验证记录上的汇总；
- `lesson-03/artifacts/original/summary.json`：程序使用的配置、数据划分和汇总说明。

终端出现“结果写入”后，**先打开 `records.csv`，不要先看汇总分数。**找 `id=B05` 且 `method=rule` 的一行，按 SUPPORT 第 3 节的表格核对一次计算。

### 3. 比较同一批验证记录

打开 `comparison.csv`，确认 `baseline`、`rule`、`linear` 三种方法的 `n` 都是 6。`n` 是评价样本数；三种方法必须使用同样的 6 个编号。用 [LEARN.md](LEARN.md) 的 6 行表重算人工规则的 MAE，并在报告第 2 节写出加法、分母和单位。

`no_action` 表示不提供分钟预测，也不发提醒，因此 MAE 是空白或 `null`，不是 0。不要只比较提醒数量，也不要把较小的 MAE 写成“每个人少等了几分钟”。

### 4. 只改一个设置做对照

先打开 `config-support.json`，确认它只把 `alert_minutes` 从 8 改为 10，其他设置和 `config-start.json` 相同。在报告第 3 节先写预计：预测值会不会变？提醒数量会不会变？然后运行：

```bash
python lesson-03/analysis.py --config lesson-03/config-support.json --output lesson-03/artifacts/trial
```

把 `original` 和 `trial` 两个输出目录中的 `comparison.csv` 并排查看，再找 `B06` 的 `linear` 行。说明为什么阈值改变会改变提醒状态，却不会改变已经拟合出的预测和 MAE。

### 5. 做自己的检查

从 `config-start.json` 复制出 `lesson-03/config-mine.json`，只选择一种检查：

- **改提醒阈值：**只改 `alert_minutes`，说明这个阈值适合什么使用场景；
- **换一个新人数：**只改 `stress_queue`，说明这是一个没有实际标签的新输入，所以只能看预测，不能计算误差。

先把预计写进报告，再检查 JSON 格式并运行：

```bash
python -m json.tool lesson-03/config-mine.json
python lesson-03/analysis.py --config lesson-03/config-mine.json --output lesson-03/artifacts/my-check
```

输出目录必须与 `original` 和 `trial` 不同。打开 `records.csv` 或终端中的“新输入检查”，写下一个实际数字和它的含义。若新输入没有标签，报告中写“没有足够信息计算误差”，不要填 0。

### 6. 保存报告和提交文件

完成 `report.md` 的 5 节：任务与预计、同样本比较、个人检查、建议与限制、运行命令和输出目录。然后把最后一次选择写入 `config.json`，填写 `contract.json` 的六个字段，并在确认所有结果都已保存后，把 `submission.json` 的 `status` 改为 `complete`。

运行最终检查：

```bash
python scripts/course.py run 03
python scripts/course.py check 03
```

检查暂存文件：

```bash
git add lesson-03
git add -f lesson-03/artifacts
git diff --cached --name-only
```

清单中应有报告、任务说明、配置、程序生成的结果和实际运行所需的代码。不要只提交截图。

### 7. 完成概念检查

按教师通知进入 [ml-check](https://hblu.top/ml-check/)，选择第 03 课（S01）场次。A 版 5 题约 4 分钟；学习阶段只显示知识点和学习说明；B 版 5 题约 4 分钟。每题先读完情境再选择，不确定时如实选择把握程度。提交后不能返回修改。

## 必须提交什么

必须提交以下内容：

- 能从仓库根目录重新运行的程序和配置；
- `contract.json` 中完整的任务说明和运行前预计；
- `report.md` 中的一条手算、同一批验证记录上的方法比较、个人检查、实际建议和限制；
- `artifacts/` 中与报告数字对应的 `records.csv`、`comparison.csv` 和 `summary.json`；
- `submission.json` 中正确的课次、报告路径、结果路径、运行命令和完成状态。

报告必须说明：你改了哪个设置，改动前预计什么，实际改变了什么；提醒数量和 MAE 能支持什么，不能支持什么；别人怎样按你的命令重新得到主要结果。

## 不同起点怎么做

### 必做任务（Core）：完成一条有证据的比较

定义一个具体预测用途，运行起始实验，核对 B05，比较同一批 6 条验证记录，完成一次只改一个设置的检查，并根据证据写出继续研究、缩小用途或暂不采用的理由。

### 入门支持（Support）：按 SUPPORT.md 逐步完成

适合第一次使用命令行或还不熟悉训练集、验证集的同学。SUPPORT 提供现成配置、完整命令、一行手算、输出位置和报告提示。它是完成必做任务的一条路径，不需要再重复做一份 Core，也不会因为使用它而降低要求。

### 提高任务（Upgrade）：改变使用标准

固定三种预测方法，另为一种使用者设计提醒阈值，比较误报、漏报或提醒容量的取舍。必须说明改变了什么，不能只换一个数字。

### 换数据重测（Transfer）：换场景再检查

把问题换成配送时间或打印制作时间，重新说明特征何时可用、标签是什么、单位和分母是什么，再运行或记录不能运行的部分。不能只替换字段名后直接沿用原结论。

### 自选拓展（Open extension）：研究提醒是否真的有用

设计一份能比较“收到提醒”和“没有收到提醒”的新数据记录，说明需要记录谁、何时、采取了什么行动以及实际等待多久。本课不执行真实干预。

## 运行限制

需要 Python 3.10 以上、已安装的 NumPy 和仓库内的离线数据；24 条人工记录可在普通 CPU 上运行，不需要显卡、付费 API 或课堂下载大模型。单次运行目标不超过 3 分钟，从头重跑目标不超过 5 分钟。在线概念检查需要网络，实验本身不需要网络。

如果命令报错，先确认当前目录、配置文件名、输出目录和 Python 版本；保留完整报错和已经生成的文件。环境暂时无法修复时，可以先完成 SUPPORT 中的手算，并在报告中明确标注“仅手算，尚未运行”，再请教师协助补跑。

> 数据提醒：`base.json` 还保存了 `staff_count`、`weather` 和 `event_flag`。它们可能帮助解释现场差异，但起点模型只使用排队人数。请在报告中写一个可能影响等待、但尚未验证的因素。
