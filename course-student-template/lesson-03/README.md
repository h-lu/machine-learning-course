# S01 · 这件事值得交给模型吗

## 本课要解决什么问题

一个服务团队想减少重复劳动，提出“做个智能助手”。这句话可能指查找已有信息、判断下一条请求、把相似请求放在一起，也可能只是执行一条已有规则。你要把需求改写成可评价的小任务，并用离线数据检验一种简单方案。

请提交任务说明、能运行的最小方案及采用建议。无法得到可靠标签或任务没有清楚用途时，允许建议先整理数据或使用规则；必须用本课的实际试验说明原因。

### 由你选择的用途与方案

可以为分配人员选择“下一条请求交给谁”，为资料维护者选择“找到可能相关的历史记录”，或根据数据自拟任务。由你选择预测、检索、分组或规则处理的路线，但要说明输出为何帮助使用者。不要把不同任务的分数直接排成同一榜单。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **任务说明（task specification）**：把笼统需求写成谁在什么时刻，拿什么输入，得到什么输出。
- **预测与检索（prediction / retrieval）**：前者估计未知结果，后者寻找已有材料，评价问题不同。
- **无模型基线（non-model baseline）**：先看规则、排序或人工处理能否达到目的。
- **做预测时已知的信息（prediction time information）**：确定哪些列能使用，避免事后信息带来虚假的好结果。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—15分钟拆解笼统需求；15—27分钟比较任务类型；27—52分钟实现两条路线；52—66分钟检验失败情形；66—75分钟写采用建议；75—90分钟概念检查与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 先读数据说明，删去需求中无法由本数据检查的承诺；把留下的问题写进 contract.json。
2. 在 report.md 预计简单办法会做好的地方和会失败的地方，再让AI帮助实现。
3. 按用途修改 config.json 或程序；默认实验只是一个起点，可改为自己的输入与输出。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-03/analysis.py
```

默认结果保存为 `lesson-03/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`threshold` 控制规则分界，`false_negative_cost` 表示漏报后果的假设。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-03/analysis.py --output artifacts/S01-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 从可选用途或自拟用途选一个，写清一行数据代表什么、输入取得时刻和输出后的行动。
2. 给出与该任务一致的评价办法，并运行一条简单规则或最小模型；若选择检索，检查找到的资料是否真正有用。
3. 比较一条有实质区别的路线，例如规则与学习，或检索与预测；说明为什么可比较或只能分别评价。
4. 找一个任务表述或数据条件会使方案失效的例子，根据结果决定建模、保留规则或先补资料。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

可以执行的任务定义；简单方案和合理替代路线的结果；一条不该交给当前方案的请求；给团队的下一步建议。合格标准是目标、数据、输出和评价相互对应，即使最终决定不训练模型。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

从一种给定用途开始，使用规则方案；把复杂度留给需求与评价是否对应的判断。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较信息需求不同的两条路线，说明增加输入是否值得。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

把相同技术用于另一使用者，重新定义评价与行动。

### 自选拓展（Open extension）：提出本课问题之外的新探索

自拟一个非预测任务，例如检索或分组，并说明它的评价依据。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
