# 第 03 课（S01）：怎样把模糊需求变成可研究的问题

## 本课要解决什么问题

“用 AI 让同学少排队”还不够具体。今天先研究一个能核对的小问题：**加入队伍前，根据前面的人数预测等待分钟数，再讨论是否显示提醒**。预测准不准、提醒多少次、提醒有没有帮助，要分别判断。

**基础还不稳时，直接从 [入门支持：逐步做一遍](SUPPORT.md) 开始**。那里给出准备好的配置、完整命令、指定样本和报告填写提示，不要求先会写训练代码。完成这条路径中的比较、自己的检查和解释，就是完成必做任务，不必重复做两套流程。

你将提交任务说明、运行结果与简短报告。可以让 AI 协助分析、编程和写作，但要核对结果并解释自己的选择。打不开终端或找不到文件时，先用 [第一次运行指南](../docs/FIRST_RUN.md) 检查目录和环境；暂时不能运行时，也能先完成本课的手算练习。

## 本课要学会什么

| 知识点 | 本课结束时能做什么 |
|---|---|
| 任务定义 | 写清谁在什么时候使用、输入、输出和用途 |
| 特征与标签 | 说明哪些信息预测时已知，哪些是事后结果 |
| 预测与行动 | 根据预测值判断是否提醒，不用真实值代替预测 |
| 基线比较 | 核对三种方法是否使用同一批样本，并重算 MAE |
| 相关与因果 | 说明预测误差和行动效果为什么不是同一个量 |

[LEARN.md](LEARN.md) 有术语解释、六条记录的计算表和两道小练习。这里只复用 C01–C02 学过的简单模型，不要求推导或手写新的训练算法。

## 90 分钟安排

0–20 分钟：阅读情境、讲解一条预测并做纸面小练习；20–30 分钟：运行起始配置、找到 B05；30–55 分钟：运行对照、做自己的检查；55–75 分钟：核对比较、写报告并保存文件；75–90 分钟：A 版 4 分钟、AI 学习 5 分钟、B 版 4 分钟，最后 2 分钟核对提交。

第 30 分钟仍未找到结果时，先做入门指南的小表计算，记录命令与报错并请教师帮助，修复后补跑。不要因此跳去做提高任务，也不要把手算写成已经运行的结果。以上是课堂安排，不是已经经真人试教证实的完成时间。

## 完成步骤

下面是可以自行安排实验的路径。需要更细指导时，只做 [SUPPORT.md](SUPPORT.md) 即可。

### 1. 写下任务和预计，再运行起点

在 `report.md` 的第一节写使用者、可用输入、输出和用途。例如先研究“给准备加入队伍的同学提供大致分钟估计”，不承诺减少等待。再写一句你预计三种方法会有什么差别。

所有命令在学生仓库根目录执行，那里能同时看到 `scripts` 和 `lesson-03`。只识别 `python3` 的电脑，把下面的 `python` 换成 `python3`。

```bash
python scripts/course.py start 03
python lesson-03/analysis.py --config lesson-03/config-start.json --output lesson-03/artifacts/original
```

程序读取本课的人工数据 `data/base.json` 和起始配置。先打开 `artifacts/original/records.csv` 找一条结果，再读 `comparison.csv`；`summary.json` 保存完整信息。文件和列名见 [数据说明](data/DATA.md)。

### 2. 比较方法，不只比较一个数字

在 `records.csv` 同时找到 `id=B05`、`method=rule`：人数为 1，真实值为 8，规则预测为 3，绝对误差为 5 分钟。然后读 `comparison.csv` 中均值基线、人工规则和回归的 MAE。

对每种方法核对验证编号都是 `A05、A06、B05、B06、C05、C06`。每种方法的分母为 6，不能用总数据量 24 或 CSV 行数 18。`no_action` 是“不提供预测也不提醒”，不能把它空白的 MAE 当作零误差。

### 3. 先预计阈值变化，再运行对照

对照配置只把 `alert_minutes` 从 8 改为 10。先写预计：哪些预测可能变化，哪些提醒可能变化？再运行，不要先照抄一个采用建议。

```bash
python lesson-03/analysis.py --config lesson-03/config-support.json --output lesson-03/artifacts/trial
```

并排核对两次的同一方法、同一条记录。两次都会运行训练代码，但阈值不进入拟合，所以训练条件不变时系数、预测和 MAE 应保持一致。

### 4. 做一次自己的检查，给出有限的建议

把 `config-start.json` 另存为本课的 `config-mine.json`。选一个适合你所述用途的提醒阈值，只改 `alert_minutes`；或只改变 `stress_queue`，检查一个没有真实标签的新输入。先说明理由和预计，再运行：

```bash
python -m json.tool lesson-03/config-mine.json
python lesson-03/analysis.py --config lesson-03/config-mine.json --output lesson-03/artifacts/my-check
```

阈值检查要说明预测和提醒是否分别改变；新输入检查要说明输出在哪里，以及为什么没有标签就不能算误差。结果没有变化也可以分析，不能为了让数字变好而修改结果文件。可以继续研究、只提供分钟估计、不提醒或暂不使用，但要说明证据支持到哪一步。

本课只用验证集开发比较，先保留测试集。另换用途、数据或模型时可以修改代码，但要保留同样本比较和自己能解释的检查。

### 5. 整理并核对提交

在报告保留原始与试验的配置、结果路径和运行命令。将最后保留的参数写回 `config.json`；`primary_model` 只是决定汇总重点，不会替你选择用途，也不会停止其他方法的计算。决定暂不采用时直接写在报告里。

填写 `contract.json` 的六个文字字段，完成实际工作后才把 `submission.json` 的 `status` 改为 `complete`。结果中的 `example_only` 不要手改。

```bash
python scripts/course.py run 03
python scripts/course.py check 03
```

`artifacts/` 默认被 Git 忽略，必须显式保存报告引用的结果。详细命令见 [本课入门指南](SUPPORT.md) 和 [模块提交说明](../docs/FOUNDATIONS.md)。本地检查通过不等于文件已经上传。

## 必须提交什么

保留程序与配置、三份主结果 `summary.json`／`comparison.csv`／`records.csv`、任务说明和报告；报告引用的配置副本、原始结果和个人试验结果也要保存，且给出重算命令。

报告至少解释任务、输入与标签、三种方法在相同六条样本上的 MAE、自己改了什么，以及哪些结论还不能得出。选择题参与情况按教师指定场次记录，不需要把教师答案放进报告。

## 不同起点怎么做

### 入门支持（Support）：照详细步骤完成同一任务

使用 [SUPPORT.md](SUPPORT.md) 和现成配置。从一行数据开始，完成比较、一次自己的选择和解释。操作上可以请求帮助；不因使用支持材料限制分数，不以代码量评分。

### 必做任务（Core）：所有路径共同完成的内容

定义预测任务；比较同一验证集上的基线、规则和回归；核对一项手算；完成自己的阈值或输入检查；说明预测效果不能证明提醒的因果效果。入门路径已经覆盖这些要求。

### 提高任务（Upgrade）：加深一个有用的比较

为另一类使用者设计提醒标准，用相同预测比较两种用途的取舍，不必新增模型。

### 换数据重测（Transfer）：用新数据重新检查

换成配送时间预测，重新说明特征何时可用、标签和单位，连同程序和评价一起调整，不只替换字段名。

### 自选拓展（Open extension）：提出下一步研究

设计研究提醒效果的数据收集方案，说明如何形成可比较条件；本课不执行真实干预。以上三项均为选做，不要求全部完成。

## 运行限制

使用 Python 3.10 以上和已安装的 NumPy。24 条人工样本可在普通 CPU 上离线运行，不需要显卡或付费 API；单次运行目标不超过 3 分钟，从头重跑目标不超过 5 分钟。AI 学习和在线概念检查另按教师安排。数据只用于教学，不证明真实食堂里的预测效果或提醒收益。
