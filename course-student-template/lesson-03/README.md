# 第03课（S01）：把预测作品变成可研究的使用方案

**2026-10-09 新版教材；已完成前七次作业无需重交。**

## 本课要解决什么问题

“让共享单车更方便”还不是可检查的任务。你要把前两课的作品写成**用途、可用信息、输出与行动边界一致的方案**，并用真实记录检验。可以给分析员显示当小时条件估计，可以研究提醒，也可定义日历信息下的前一天简单估计；不足时可以暂不采用。

你交用途与信息审查说明，自己选择方案及对照。第一个可开始动作是写一句“谁在何时知道什么、得到什么、准备用来做什么”，再与数据字典核对。默认程序只读取并核对数据与字段，不替你决定提醒阈值（触发提醒的数值分界）或模型。卡住按需查 [SUPPORT](SUPPORT.md)，保留失败证据，先做学习页其他情境例题再补运行。

## 本课要学会什么

| 概念 | 掌握表现 |
|---|---|
| 任务定义 | 使用者、时点、输出和目的相互匹配 |
| 预测时可用信息 | 区分实际当小时天气与前一天已知信息 |
| 数据泄漏 | 识别目标组成项与不可得字段，不因CSV已有就输入 |
| 预测与使用规则 | 分开数值输出、阈值提醒和真实行动，追踪具体记录 |
| 预测评价与因果效果 | MAE/提醒计数不能证明增放车辆或提醒导致改善 |

[LEARN](LEARN.md)提供其他情境的完整示例；正式可用输入清单、阈值、编号和建议由你决定。

## 课堂任务

教师给情境、关系和一段示范；学生自主定义用途、构建证据与比较、查失败并修改同一作品；最后按通知完成既有课堂选择题。基础/标准/提高是同一作品，不要求重复交三份。

## 完成步骤

以下是方案应具备的证据，**不规定统一模型、阈值或操作顺序**。

- **决定用途与已知信息**：写使用者、时点、输入清单、目标、输出与限制。表中有字段不等于使用时已知。casual/registered相加等于cnt，禁止用于预测cnt。自己定义一个其他用途，说明变化后可用信息与评价怎样不同。
- **决定怎样使用输出**：可以只显示数值、用自己选的阈值提醒、或说明为什么暂不输出。若选择暂不采用，仍需用可运行候选解释是什么证据使你暂停；“没有输出”不等于MAE=0。
- **构建实际对照**：选择另一条合理使用规则，固定预测比较两个自行确定阈值，或比较仅显示数值与提醒等方案。写预计，给同编号追踪和实际计数。若改时点/输入/模型多项，逐项列出，不称为只改一个因素。
- **自行检查失败与边界**：选三个正式记录，追踪输入→预测→使用判断→实际核对；自己选一种可能误用的条件或泄漏尝试，解释程序为何该拒绝或方案该缩小。提醒依据预测，不可用标签倒推。
- **判断证据支持什么**：预测误差和提醒数量支持哪些有限结论？为何不能说增加单车或发提醒使需求/体验改善？提出其他可能解释和新记录需求。

至少两项重要决策是：**任务时点与输入清单**和**使用规则及对照/失败检查**。阈值与正式编号由你决定。

所有命令在学生仓库根目录执行（能看到lesson-01、mlcourse、scripts、requirements.txt）。`analysis.py`是可编辑起点：默认只读取并核对数据，必要时给出基线，运行不会自动完成你的项目。共享`mlcourse/bike_course.py`保留可选例子，也可以借AI自己写读取、规则、拟合、分组与评价代码；不要求必须沿用它的菜单。方法应保持在本课已有概念范围，必要时请AI解释一条输入的计算，不突然引入不理解的新算法。

```bash
python3 lesson-03/analysis.py
```

默认产物只帮助核对数据、字段与开发期预览。你可复用自己前课代码或借AI构建新的可运行候选，程序须使用实际改动的信息。共享完整工具仅为可选示例：它将同一alert_threshold（提醒阈值）用于预测提醒和actual_high（实际次数是否达到高需求标准），因此改变阈值也改变实际标准；若你希望固定业务高需求标准，需自己分开定义并重计。

## 必须提交什么

用途与信息审查说明（[report.md](report.md)可改结构），包括自己的可用输入清单和规则、另一个用途、实际对照、三个自选追踪、失败检查、证据边界和可重跑文件。仅审计文件或把数据字段抄一遍不算完成。

目录工具与程序可由AI协助，但关键选择及结果解释由你承担。保存报告引用的数据版本、代码、配置、完整命令、逐条预测与汇总。

`contract.json`保存任务说明，字段名不改，填写六个空字符串（各字段的含义见 [SUPPORT](SUPPORT.md#卡点我想保存自己的作品)）；`submission.json`是提交清单，把`run`改为你自己的可重跑命令、`artifacts`列为实际证据文件，完成后将`status`改为`complete`。示范或基线文件齐全不等于项目完成。

`python3 scripts/course.py check 03`只检查文件，CI（自动检查）重新运行命令，检查清单中的结果文件是否逐字节一致，不替你判断推论；未列入清单的对照仍须保存并给独立命令。用`git add -f lesson-03/artifacts`保存可能被忽略的产物。

已有历史课次、线上场次和评分不变；新页是增强学习材料。

## 不同起点怎么做

**基础支持（Support）**：按卡点查看任务定义、阈值例题或环境说明，保留自己的用途与规则选择。

**标准任务（Core）**：完成用途/信息/使用规则一致的可检验方案，与另一合理方案比较并限定结论。

**提高任务（Upgrade）**：围绕同一作品研究固定真实高需求标准下阈值敏感性、使用条件或暂停标准；解释建议何时改变，不只增加提醒计数表。

**迁移与课后挑战（Transfer / Open extension）**：为医院预约或设备报修另写任务与字段可得性；设计研究提醒行动效果的新记录方案，不开展真实干预，不上传个人信息。

## 运行限制

标准任务使用共享的真实 [UCI Bike数据](../data/bike/LICENSE_AND_SOURCE.md)，17,379行、17列，CC BY 4.0。训练 `<2012-07-01` 13,003行；验证 `[2012-07-01,2012-10-01)` 2,208行；最后2,168行测试留到第08课，前七课不评价它。缺少的165个小时记录不能补成0需求；casual和registered相加等于cnt，禁止把这两列作输入。

实验离线；Python 3.10以上与NumPy即可，普通CPU约8GB内存，无显卡或付费依赖。环境已在本机Python3.14/NumPy2.5验证，不代表每台学生电脑具备同一环境。完整说明见 [ENVIRONMENT.md](../ENVIRONMENT.md)。下面命令用python3，学生沿用自己的python或py启动命令即可。AI辅助与课堂选择题按教师安排联网。运行时间只反映程序计算；项目完成还需选择、检查与解释。
