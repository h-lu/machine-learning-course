# 第03课 · 预测出来以后，能用它做什么？

预测一个数，与根据这个数采取行动，是两件事。

例如，程序估计打印订单要用14分钟。你可以把14显示给顾客，也可以约定“预计超过某个时间才发提醒”。提醒是否有帮助，还取决于顾客看没看到、采取了什么行动，以及行动后发生了什么。

本课用一个小例，把这些环节分开。

## 1. 先把任务说完整

“让服务更好”还不是一个能直接检验的预测任务。先说清五件事：谁使用、什么时候使用、当时知道什么、想估计什么、准备用结果做什么。

以单车为例：
- 已知当小时实际天气后，估计这个小时的租借次数。
- 前一天晚上，预测明天每个小时的租借次数。

这两个任务需要的信息不同。数据里没有天气预报，第二个任务不能直接使用明天才测到的天气。可以先缩小到当时已知的日历信息，或说明还缺什么数据。

把真实使用时不应知道的信息放进模型或评价，叫作**数据泄漏（data leakage）**。字段在历史表里存在，不代表预测时能得到。`casual+registered=cnt`，所以前两列不能作为预测cnt的合法输入。

## 2. 用一条打印规则，算预测与提醒

下面是人工编制的例子，不是正式单车任务。

我们给定规则：

**预计分钟数 = 2 + 3×页数。**

再作两个不同约定：
- 预测达到12分钟就发提醒，这是**提醒阈值（alert threshold）**。
- 实际达到12分钟就记为“实际耗时长”，这是事后核对用的标准。

|订单|页数|实际分钟|预测分钟|是否提醒|实际是否耗时长|
|---|---:|---:|---:|---|---|
|a|4|9|14|是|否|
|b|2|15|8|否|是|
|c|5|18|17|是|是|

以a为例：2+3×4=14，达到提醒阈值，所以提醒；但实际只用9分钟，没有达到实际长耗时标准，这次是误报。

b恰好相反：预测8分钟，没有提醒，实际却用15分钟，这是漏报。c提醒了，实际也确实耗时长。

三条绝对误差分别是5、7、1分钟，平均绝对误差（mean absolute error，MAE）为13/3分钟。MAE说明数值预测偏离多少，并不告诉我们一共发了几次提醒。

## 3. 四种结果，把每条订单都算进去

把“实际耗时长”叫作**正类（positive class）**，就是当前想找出的情况。

|最终行为|实际耗时长|实际耗时不长|
|---|---|---|
|提醒|真阳性（true positive，命中）|假阳性（false positive，误报）|
|不提醒|假阴性（false negative，漏报）|真阴性（true negative，正确未提醒）|

这种把预测判断与实际情况交叉摆放的表，叫作**混淆矩阵（confusion matrix）**。这里“真”“假”只表示判断是否吻合，不是说某条记录造假。

先看“提醒了没有”，再看“实际长不长”，每条订单都能放入一个格子。四格相加应等于全部评价记录数，不能只检查发了提醒的订单。

在上表中，命中1、误报1、漏报1、正确未提醒0，合计3条。

**精确率（precision）**问的是：“发出的提醒中，多少确实耗时长？”
本例是命中1÷提醒2=1/2。

**召回率（recall）**问的是：“实际耗时长的订单中，多少得到了提醒？”
本例是命中1÷实际耗时长2=1/2。

这次两个比例恰好相等，但分母不同。没有任何提醒时，精确率没有定义；没有实际长耗时订单时，召回率没有定义。不要把这种情况直接填成0或100%。

## 4. 改提醒阈值，预测会不会变？

保持刚才的三条预测不变，也保持“实际至少12分钟算长”的标准。只把提醒阈值提高到16分钟。

- a预测14，不再提醒。
- b预测8，仍不提醒。
- c预测17，仍提醒。

现在精确率变为1÷1=100%，召回率仍为1÷2=50%。精确率变高了，但b仍被漏掉，所以不能只凭精确率选择阈值。

重新数四格，得到命中1、误报0、漏报1、正确未提醒1。提醒数从2变成1，但预测仍是14、8、17，MAE也仍是13/3分钟。

这里改变的是使用预测的规则，没有重新训练模型。这个例子少了一次误报，却仍漏掉b，不能据此推断提高阈值在所有数据上都更好。第6课还会讨论提醒名额有限时怎样选择。

请留意代码的实际定义：共享示例`mlcourse/bike_course.py`把同一个阈值用于预测提醒和`actual_high`。直接改这个参数，会连“实际高需求”的标准也一起改变。若要像本节一样只研究提醒规则，应固定实际标准，另外设置预测阈值，再重新计数。

## 5. 更多提醒，为什么不等于效果更好？

顺着一次提醒想下去：

**可用输入 → 数值预测 → 是否发提醒 → 使用者是否行动 → 行动后的效果。**

打印小表记录了输入与耗时，可以核对预测和提醒是否命中；它没有记录顾客是否看到提醒，也没有记录提醒让等待减少了多少。

同样，单车数据没有提醒接收、调度行动、单站库存或新增车辆的干预记录。预测次数较准，不足以证明增加车辆就改善体验。

两个变量一起变化，叫作**关联（association）**；研究改变一个因素会使结果怎样变化，涉及**因果关系（causation）**。要研究提醒是否有效，需要补充行动及结果记录，并采用能作合理比较的设计。换更复杂的算法不能自动补上这些证据。

## 6. 回到自己的任务，写一句有边界的话

可以照下面的句式填写，内容由你决定：

“在____时，使用者已经知道____。模型据此估计____。当预测满足____时，系统会____。现有数据可以检查____，还不能检查____。”

然后对照实际代码：如果程序只用了temp，不能说也用了hr或workingday。若某个输入在使用时拿不到，应改输入、缩小用途，或暂时不采用方案。

“不采用”也需要理由，例如某个关键组错误较多，或所需信息缺失。没有产生预测的方案无法计算MAE，不能把它记为零误差。

## 7. 练习与不同完成程度

- **基础完成：**页数3、实际16分钟，按原规则计算预测，再分别判断“预测是否至少12”和“实际是否至少12”。把结果放入四格表，解释为什么。
- **完整完成：**按[任务页](README.md)给自己的单车方案写清任务和信息来源，用实际记录核对数值预测与使用规则，说明能评价与不能评价的效果。
- **扩展练习（选做）：**页数6、实际11分钟，分别用12和16作为提醒阈值，实际长耗时标准始终固定12。哪些量改变，哪些不变？再自编一条会因改阈值而从命中变成漏报的记录，并核对两次判断。

基础题核对：3页预测11分钟，没达到提醒阈值12；实际16分钟属于长耗时，因此是一次漏报。

最后把“发了两次提醒”与“帮助了两个人”各写一句解释。如果手里只有预测和实际耗时，你能确认的是哪一句？
