# 第 15 课（S13）：预训练模型的能力来自哪里

## 本课要解决什么问题

前几课已经用数据训练过模型。本模块从这一课开始设计一个“离线课程问答助手”，但先要弄清一件容易混淆的事：系统输出改变时，究竟是基础模型的参数变了，还是只改了输入，或只训练了后接的任务部件？如果把这些变化都称为“模型学会了”，后面就无法判断证据来自哪里。

**第一次做这类实验时，直接打开 [入门支持](SUPPORT.md)**。先运行三条路线，再在同样 6 条评价记录上核对一条分数。提交三条路线的比较、一次参数轨迹核对、一个自己选择的输入规则对照，以及哪些结论目前不能得到。运行失败时保留命令和报错，先用 [学习材料](LEARN.md) 的两条记录手算，修复后补跑。

本课的 `pretrained_score` 是课程准备的固定分数，不是真实预训练模型输出。微型训练只更新一个输出头。实验用于区分变化来源，不评价真实大模型能力。

## 本课要学会什么

- **预训练（pretraining）**：先在大规模任务上更新模型参数，形成可复用能力；本课没有执行预训练。
- **推理（inference）**：参数固定时，对新输入计算输出。给输入补充文字可以改变输出，但不等于更新参数。
- **任务微调（task fine-tuning）**：用当前任务的标注数据更新部分或全部参数。本课只训练微型输出头，不能称为完整微调。
- **偏好反馈（preference feedback）**：用人对候选结果的偏好调整输出行为。它可能改善表达或遵循要求，并不自动补充事实。
- **输出头（output head）**：把固定基础分数换成当前任务预测的小部件；必须说明它与基础部分谁被更新。

完成后，你应能根据参数轨迹和输入配置说明每条路线改变了什么，并限制结论。数值例子见 [LEARN.md](LEARN.md)，字段来源见 [数据说明](data/DATA.md)。

## 90 分钟安排

0–15 分钟辨认三种变化；15–25 分钟运行起点并找到 `ev-02`；25–40 分钟重算一条预测和训练轨迹；40–58 分钟比较一个输入规则；58–72 分钟完成自己的检查与建议；72–90 分钟完成概念检查和提交。第 25 分钟仍找不到文件时，按 SUPPORT 的表格先算并请教师检查路径。

## 完成步骤

下面的命令都在学生仓库根目录执行，也就是能同时看到 `scripts` 和本课目录的位置；不要在 Python 的 `>>>` 中输入。电脑只识别 `python3` 时，把命令开头的 `python` 换成 `python3`。

1. 在 `report.md` 先写预计：哪条路线会改变参数，哪条只改输入，以及什么结果会让你改变建议。
2. 从仓库根目录运行起点：

```bash
python scripts/course.py start 15
python lesson-15/analysis.py --config lesson-15/config-start.json --output lesson-15/artifacts/support-start
```

3. 先看 `routes.csv` 的 `changed_input`、`changed_parameters`、样本数和两项指标，再在 `records.csv` 找 `ev-02`。用 `parameter_trace.csv` 比较第 0 步和第 120 步，确认只有输出头的 `bias`、`weight` 被训练。
4. `config-support.json` 只把 `context_boost` 从 0.16 改为 0，运行到新目录：

```bash
python lesson-15/analysis.py --config lesson-15/config-support.json --output lesson-15/artifacts/support-compare
```

5. 从起点配置另存 `config-mine.json`，只改 `context_boost` 为 0.08、0.24 或另一个 0 至 0.3 的值。先预计 `ev-02` 分数是否越过 0.5，再运行到 `artifacts/my-check`。解释这是人为输入规则的效果，不能写成基础模型重新学会了课程知识。
6. 把最终采用的配置写回 `config.json`，完成报告和任务说明。`evidence.json` 是六课连续作品的第一份证据；下一课会引用它区分“输入改变”和“信息路径改变”。

## 必须提交什么

提交可重跑的配置与程序、`summary.json`、`routes.csv`、`records.csv`、`parameter_trace.csv` 和 `evidence.json`。报告必须包含：三条路线改变的部件；`ev-02` 在三条路线下的分数；训练前后至少一个参数和训练损失；个人规则对照；一项有依据的建议；至少两条证据不能支持的结论。

填写 `contract.json` 的问题、使用者、数据来源、指标、数据用途和最初预计。实际完成后将 `submission.json` 的 `status` 改为 `complete`，再运行：

```bash
python scripts/course.py run 15
python scripts/course.py check 15
```

## 不同起点怎么做

### 入门支持（Support）：沿详细路径完成同一必做任务

按 [SUPPORT.md](SUPPORT.md) 运行、核对和比较，不要求从零实现训练。得到教师帮助不降低完成标准。

### 必做任务（Core）：区分能力变化来源

所有人都要比较固定记录、输入规则和训练输出头，核对一条记录与一次参数更新，再写出结论限度。

### 提高任务（Upgrade）：检查任务头是否稳定

在相同数据上比较 60、120、240 步，观察训练损失与评价对数损失是否同方向变化。更多训练不自动更好。

### 换数据重测（Transfer）：改变请求类型

另加两条人工请求和明确标签，保持三条路线的评价条件一致，说明新标签如何得到。

### 自选拓展（Open extension）：研究偏好反馈

设计两个内容相同、表达不同的候选回答和偏好规则，说明它改变的是表达选择还是事实知识；不要把人工选择说成真实模型训练。

## 运行限制

Python 3.10 以上，只有标准库、12 条人工记录，普通 CPU 可在数秒内完成；不需要网络、显卡或付费服务。固定分数没有真实模型来源，因此只能观察已有材料。真实预训练或偏好训练超出本课资源，不作为必做任务。
