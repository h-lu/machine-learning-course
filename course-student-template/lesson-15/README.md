# 第 15 课 · 这次任务需要神经网络吗

## 本课要解决什么问题

分析小组发现简单模型漏掉了一些输入之间的关系，想试一个小神经网络。网络可以学到非线性，也可能只是增加训练和解释负担。你要选择一个用途，检查它相对简单基线是否带来值得采用的改善。

请提交网络与基线比较、训练过程、关键错误和建议。网络不胜出时可以保留简单模型；训练没有正常下降时先诊断计算与优化，再讨论模型能力。

开始前先写清楚四句话：谁会使用结果？输入在什么时候能得到？程序输出什么？结果变差时怎么办？这四句话会帮助你选择评价方法，也会帮助你写最后的建议。

### 由你选择的用途与方案

可以面向允许离线训练的分类任务，也可以面向资源更紧、希望保持简单输入处理的应用；可自拟用途。由你选择网络宽度、训练预算、评价办法和哪些改善值得复杂度。必须让简单模型与网络面对同样数据。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让 AI 编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **张量（tensor）**：以有明确形状的数组组织一批输入、权重与输出。
- **层与激活（layer / activation）**：逐步变换输入；非线性激活使多层不只是另一条直线。
- **前向计算（forward pass）**：从输入算出预测，用于核对网络实际做了什么。
- **损失与梯度（loss / gradient）**：损失表达训练目标，梯度说明局部怎样改变参数。
- **反向传播（backpropagation）**：按链式法则把损失变化传回各参数；可手写也可由自动求导工具计算。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

本课按下面的顺序进行：
- **0—12分钟确定网络要解决的不足。**
- **12—28分钟手算单元与形状。**
- **28—52分钟训练比较。**
- **52—66分钟错误与前向核查。**
- **66—75分钟建议和重跑。**
- **75—90分钟概念题与变式。**

遇到实现困难，可以让 AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 阅读网络配置与数据，先在 report.md 写预期；可以让 AI解释整个训练程序。
2. 修改 config.json 的 hidden、steps、learning_rate或l2时说明目的，保留与简单基线相同的数据划分。
3. 抽取一个隐层单元，列出它的加权和、激活与后续输出；核对实际程序而非只画概念图。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-15/analysis.py
```

默认结果保存为 `lesson-15/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`hidden` 控制隐层宽度，`steps`、`learning_rate`、`l2` 控制训练；增加规模需要用途理由。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-15/analysis.py --output artifacts/S13-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 说明用途与比较条件，先预计简单模型在哪类记录上不足，以及网络可能改善的关系。
2. 运行简单基线与小网络，核对输入、隐层、输出形状及训练预算，报告训练和验证过程。
3. 追踪一条记录的前向计算，解释激活、损失与参数更新怎样相连，不要求逐行手写代码。
4. 检查一类关键错误与自行设计的输入，判断改善是否稳定、成本是否值得，修改采用建议。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

同条件的网络与基线结果；训练和验证曲线或逐步数值；一次前向计算核对；一类错误与新测试；采用建议。合格标准是理解计算与比较依据，不以网络层数或参数量评分。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

沿用提供的小网络与基线，集中核对一个单元和一类关键错误。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较隐层宽度或正则化，解释改进与训练成本的变化。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换输入关系或群体分布，再检查网络优势是否仍在。

### 自选拓展（Open extension）：提出本课问题之外的新探索

用自动求导库重写同一小网络，核对与原计算是否一致。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
