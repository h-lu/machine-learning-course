# 第 27 课（S25）：反馈怎样帮助学习，又会遗漏什么

## 本课要解决什么问题

前六课已经形成一个校园设备服务台助手。本课不换作品，而是决定助手应该显示“简短回答”还是“带步骤回答”，再用使用者是否解决问题的反馈改进选择。程序提供的是离线反馈模拟，不是真实使用者实验。

**第一次接触这类实验时，从 [入门支持](SUPPORT.md) 开始。** 你会在五分钟内跑出第一份结果，看到系统每轮只观察被选回答的反馈。你要比较只选当前看来较好的方案，与偶尔尝试另一方案的结果；提交五个随机种子下的反馈、覆盖情况和采用建议。运行失败时保留完整命令和报错，先用 LEARN 的四轮小表继续计算，修复后补跑。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 利用（exploitation） | 选择目前证据中反馈较好的方案。 |
| 探索（exploration） | 有计划地尝试证据较少的方案，以获得新反馈。 |
| 反馈（feedback） | 采取选择后观察到的结果；本课用 0 或 1 表示请求是否解决。 |
| 选择偏差（selection bias） | 反馈只来自被选方案，因此观察到的数据不代表所有方案。 |
| 覆盖情况 | 实际尝试了多少种回答以及各尝试多少次。高反馈不能代替覆盖检查。 |

完成后，你应该能同时报告累计反馈和覆盖情况，并解释为什么没有被选的回答不能当作“反馈为 0”。

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–15 分钟 | 用四轮小表区分已观察反馈和未观察结果 |
| 15–30 分钟 | 运行探索率 0.10 的起点，核对一个种子的 16 轮 |
| 30–50 分钟 | 只把探索率改为 0.25，用五个相同种子公平比较 |
| 50–68 分钟 | 选择另一个探索率，先写预计，再运行并解释差异 |
| 68–75 分钟 | 写采用建议、遗漏的信息和下一项反馈实验 |
| 75–90 分钟 | 完成 A 版概念检查、AI 学习、B 版检查并提交 |

## 完成步骤

1. 从学生仓库根目录开始本课并运行起点：

   ```bash
   python scripts/course.py start 27
   python lesson-27/analysis.py --config lesson-27/config-start.json --output lesson-27/artifacts/start
   ```

2. 打开 `artifacts/start/rounds.csv`，先筛选 `seed=3` 和 `policy=epsilon`。核对共有 16 行；`chosen_response` 是实际显示的回答，`observed_feedback` 才是策略能学到的反馈，`other_response_feedback` 应为“未观察”。手算该组反馈总和除以 16。
3. 在 `report.md` 先写预计：探索率从 0.10 改为 0.25 后，两种回答的尝试次数、平均反馈可能怎样变化。然后运行现成比较：

   ```bash
   python lesson-27/analysis.py --config lesson-27/config-support.json --output lesson-27/artifacts/support
   ```

   两次运行使用相同五个种子和相同 16 轮，只有探索率不同。打开 `episodes.csv`，不要只挑一个有利种子。
4. 把 `config-support.json` 复制为 `config.json`，将 `exploration_rate` 改成你选择的第三个值并说明理由。运行 `python scripts/course.py run 27`，比较反馈和覆盖情况。探索方案不必胜出；你要说明它增加了什么信息，以及短期可能付出什么代价。
5. 在 `report.md` 写清一行数据代表一次实际选择，反馈的分母是每个策略每个种子的 16 轮。最后提出下一项更接近真实使用的反馈采集办法。

## 必须提交什么

- `config.json` 和程序生成的 `summary.json`、`rounds.csv`、`episodes.csv`。
- 对一个种子的反馈手算，写出分子、分母和单位“轮”。
- 五个种子下贪心选择与探索选择的反馈和覆盖比较。
- 你选择的探索率、看结果前的预计、实际差异及采用或限制使用的建议。
- 一项当前模拟遗漏的信息，不能把模拟反馈写成真实使用者证据。

## 不同起点怎么做

### 入门支持（Support）：沿完整路径完成同一核心任务

按 [SUPPORT.md](SUPPORT.md) 运行现成配置、核对 16 轮、改变探索率并写建议。使用支持路径不限制成绩。

### 必做任务（Core）：在反馈和覆盖之间作有证据的选择

所有人都要使用多个种子，比较至少两个探索率，并解释未选择方案为何没有当轮反馈。

### 提高任务（Upgrade）：按请求类型检查覆盖

分别统计借用期限、库存、费用和例外请求中两种回答被选多少次，判断总覆盖是否掩盖某类请求缺少证据。

### 换数据重测（Transfer）：改变一类反馈模式

复制为 `data/mine.json`，只改变一类请求的模拟反馈，说明这是条件变化，不是新收集的真实反馈，再运行相同策略。

### 自选拓展（Open extension）：设计较安全的反馈采集

提出退出探索、人工复核或最小样本数办法，并说明怎样避免长期只观察一个方案。

## 运行限制

实验使用 Python 标准库、普通 CPU 和小型离线模拟，通常数秒内完成，不需要显卡、网络或付费服务。AI 可以帮助读表和写程序，但报告必须引用自己的实际输出。概念检查需要按课堂安排联网；无法联网时保留本地实验，按教师安排补做。
