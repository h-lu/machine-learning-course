# 第 08 课（S06）：用一次实验区分失败解释

## 本课要解决什么问题

你已经学习提出预测问题、审查数据、划分训练／验证／测试、选择误差指标与检查泛化。现在要把这些知识用于一项自己设计的诊断：**当前方案为什么在某些条件下失败？什么实验能够区分至少两种解释？**

主要资源是 UCI Bike Sharing 的17,379条真实小时记录。你可以研究“给定当小时实际天气与日历信息，估计记录租借次数”这项用途，或者提出另一个数据能够支持的问题。可以继承自己前课的思路或方法；程序不会自动读取前课个人模型，换了数据必须在当前样本上重跑对照。

本课产物是一件有依据的分析作品：两种解释、一个自己设计的单因素实验、真实的对照结果、独立失败检查以及保留／修改／暂停的建议。**你至少作出两个会改变实验或结论的重要决定**，例如选择哪个失败解释，以及用什么表示、方法、主指标或分组检查它。例题与给定代码是资源，不是统一菜单；不要求全班得到相同分数或结论。

先读下面的作品要求即可开始。需要操作支持时按卡点打开 [SUPPORT](SUPPORT.md) 或 [HINTS](HINTS.md)；需要理解概念时用 [LEARN](LEARN.md) 的完整小例子。AI可以帮助提出方案、实现代码、计算与写作，你要解释选择与实际证据怎样连接。

## 本课要学会什么

| 知识关系 | 你应能展示的理解 |
|---|---|
| 假设与控制变量 | 至少两个可区分的解释；一项改动对应一项解释，其他条件保持一致 |
| 表示与模型能力 | 追踪一次输入表示或处理，解释它允许模型表达什么、仍遗漏什么 |
| 条件关系与交互 | 说明一个输入的预测关系是否随另一个条件不同；按需要决定是否引入组合输入 |
| 总体与分组误差 | 核对一条误差和正确分母，解释分组与总体为何可能支持不同选择 |
| 事前计划与最后评价 | 看本次验证结果前记录规则，验证后保存选择，测试后如实限定建议 |

小时指示变量与小时×工作日交互在学习页作为可选例子，帮助理解表示与条件关系；你可选择其他已学方法，如有依据的分段规则、特征增删或一项数据处理比较。选择其他路线仍需解释同样的知识关系，不需要先学习一串新算法。

## 课堂任务

完成一件由自己设计的诊断作品：提出竞争解释，构建一个有区分力的对照，核算并检查失败，依据证据提出建议。教师说明问题、知识关系和资料入口后，你自主安排阅读、设计、编程与检查；遇阻可按需获得帮助。

课堂末按教师安排完成A版选择题、AI学习和B版选择题，再核对提交。环境故障或实验未完成时保留实际进展与报错，明确待补，不用给定例子代替自己的实验。

## 完成步骤

### 定义你要诊断的失败

明确使用者、结果用途、目标、单位，以及做预测时知道什么。提出至少两种解释，选一项本次能够检查的改动，写它为什么有区分力。可从训练数据和前课作品形成解释，不先查看最后测试来挑问题。

例如，“小时连续表示无法描述峰形”与“工作日小时规律不同”对应不同表示实验；这些只是例子。你也可发现另一失败，选择其他已学的表示、规则或处理方案。若改问题或目标，连同评价、泄漏检查和实现一起调整。

### 保存自己的实验计划

在运行本次验证比较前，在自己的报告实验计划部分或 `plan.md` 记录两种解释、原方案与候选、唯一改变的因素、保持不变的条件、主要评价指标及分组、怎样据证据作选择、什么结果会限制使用。规则可以是合理的文字判断或数值条件，不强制统一阈值或JSON模板。记录至少两个重要决定与理由。

### 构建并公平比较

用提供的离线数据与现有Python／NumPy环境，自行构建一项对照。可编辑 `analysis.py` 的候选函数，或另写自己的入口。默认程序只做数据检查和训练均值基线，不一次完成正式实验，也不替你生成报告。

第一次查看数据可在学生仓库根目录执行：

```bash
python lesson-08/analysis.py
```

只有 `python3` 可用时替换首项；详见 [ENVIRONMENT](../ENVIRONMENT.md)。默认结果在 `lesson-08/artifacts/baseline/`，先看 `comparison.csv`，再核对 `records.csv` 的一行。起点只是可运行资源，**只运行基线不足以完成本课**。

固定Bike时间切分为训练 `<2012-07-01`（13,003行）、验证 `<2012-10-01`（2,208行）、其后测试（2,168行）。用同一训练／验证记录比较原方案和你设计的候选，只改一项重要因素。处理参数从训练学习，验证沿用。若自选其他数据，说明来源、可用信息与独立评价安排，避免课堂中安装下载。

### 用自己的检查解释结果

自选一条真实记录，追踪关键输入或预处理到预测，独立重算误差；再选一个与用途有关的失败组或条件变化，带分母核对至少5条记录或完整组。解释它为何比只看总体分数有信息，保留至少一个未排除的解释。你决定具体检查，不必使用示例的通勤组。

需要通勤时段作为检查时，可以使用统一示例定义：workingday=1且小时7、8、9、16、17、18、19；这不是实测通勤者身份。无样本的组写不可评估，稀少组指出不稳定性。

### 先选择，再最后评价

基于验证结果在自己的报告选择部分或 `decision.md` 保存方法、参数、评价、理由与验证证据路径，再只评价这个方法的测试结果。你可以选原方案或建议暂停，候选不必胜出。若据测试再改方法，当前测试成为开发证据，改后方法需新的独立数据评价。

完成自己的报告与代码后，更新 `submission.json` 的run和artifacts，使它重算自己的主验证证据；不能把默认基线清单当作已经完成自主实验。默认CI不打开测试，测试与选择证据另保留。操作支持见 SUPPORT。

## 必须提交什么

- 自己的实验计划与测试前选择记录（可放报告），任务说明 `contract.json` 与 `report.md`，体现至少两个重要决定。
- 自己的可重现程序、配置和同条件原方案／候选验证结果；至少包括比较表、逐条真实值与预测，以及失败检查证据。输出格式可适应自己的方案，报告需说明字段和分母。
- 测试前选择与最后测试结果、实际命令、数据来源和环境说明；保留被引用的旧证据与失败尝试，不能倒写过程。

作品应能回答：我在研究什么、为什么选这项实验、它能区分什么、核算是否正确、自己的检查改变了什么建议、哪些结论仍不成立。仅有运行成功、文件齐全或AI生成说明不构成完成。

## 不同起点怎么做

### 必做任务（Core）：自己设计一件诊断作品

按上述证据标准完成。使用现成代码、让AI帮助编程或保留基线，都不降低标准，也不按代码量评价。标准练习见 [EXERCISES](EXERCISES.md)，可依需要安排顺序。

### 入门支持（Support）：遇阻时补一项能力

SUPPORT按“启动环境／不知道怎样计划／不会实现比较／不能核算／不能提交”等卡点提供帮助。它保留自己的假设、评价和诊断选择，不要求每人顺序点完全部步骤，也不设分数上限。

### 提高任务（Upgrade）：把残余解释变成第二项实验

在第一项作品完整后，检验另一解释或结果稳定性。记录继续使用同一验证数据属于开发，不冒充新独立评价。

### 换数据重测（Transfer）：检验迁移边界

把用途改为提前一天调度或换有来源的新数据，检查输入能否事先取得、目标是否仍一致、怎样保留新测试。当前实际天气分数不能直接证明新用途。

### 自选拓展（Open extension）：课后继续自己的问题

围绕尚未排除的解释设计新数据、变量或实验矩阵。先说明它将提供什么新证据，避免仅增加模型数量。

## 运行限制

用课程现有Python与NumPy，不新增安装。Bike数据已离线附带，普通CPU与约8GB可用内存；运行资源、具体环境与已验证范围见ENVIRONMENT。无需显卡、付费模型或课中下载；AI学习及在线概念检查另按教师安排。

来源与CC BY4.0见 [LICENSE_AND_SOURCE](../data/bike/LICENSE_AND_SOURCE.md)。CSV无空字段但缺165小时，不能补成零需求；casual和registered相加等于cnt，不能泄漏进输入；season保留数字类别并说明标签来源冲突。默认任务只能说明2011–2012记录租借的当小时条件估计，不证明未来调度、未满足需求或因果效果。评分与历史成绩保持原规则。
