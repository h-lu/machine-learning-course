# 第 08 课（S06）：用一次实验区分失败解释

## 本课要解决什么问题

你已经学习提出预测问题、审查数据、划分训练／验证／测试、选择误差指标与检查泛化。现在要把这些知识用于一项自己设计的诊断：**当前方案为什么在某些条件下失败？什么实验能够区分至少两种解释？**

主要资源是 UCI Bike Sharing 的17,379条真实小时记录。你可以研究“给定当小时实际天气与日历信息，估计记录租借次数”这项用途，或者提出另一个数据能够支持的问题。可以继承自己前课的思路或方法；程序不会自动读取前课个人模型，换了数据必须在当前样本上重跑对照。

本课产物是一件有依据的分析作品：两种解释、一个自己设计的单因素实验、真实的对照结果、独立核算与失败分析以及保留／修改／暂停的建议。**你至少作出两个会改变实验或结论的重要决定**，例如先检查哪种失败解释，以及用什么特征表示、方法、主要指标或分组检查它。例题与给定代码是资源，不是统一菜单；不要求全班得到相同分数或结论。

先读下面的作品要求即可开始。遇到操作或理解问题时，查阅 [SUPPORT](SUPPORT.md) 或 [HINTS](HINTS.md)；需要理解概念时用 [LEARN](LEARN.md) 的完整小例子。AI可以帮助提出方案、实现代码、计算与写作，你要解释选择与实际证据怎样连接。

## 本课要学会什么

| 知识关系 | 你应能展示的理解 |
|---|---|
| 假设与控制变量 | 至少两个可区分的解释；一项改动对应一项解释，其他条件保持一致 |
| 特征表示与模型能力 | 追踪一次输入表示或处理，例如把小时数改成“是否为8点”的0/1列；解释模型能表达什么、仍遗漏什么 |
| 条件关系与交互 | 检查一个输入与预测值的关系是否随另一条件变化，例如8点的工作日与非工作日是否不同；按需要决定是否引入组合特征 |
| 总体与分组误差 | 核对一条误差和正确分母，解释分组与总体为何可能支持不同选择 |
| 事前计划与最后评价 | 看本次验证结果前记录规则，验证后保存选择，测试后如实限定建议 |

小时指示变量与小时×工作日交互在学习页作为可选例子，帮助理解表示与条件关系；你可选择其他已学方法，如有依据的分段规则、特征增删或一项数据处理比较。选择其他路线仍需解释同样的知识关系，不需要先学习一串新算法。

## 课堂任务

完成一件由自己设计的诊断作品：提出至少两种可能的失败解释，设计能检查其中一种解释的对照实验，核算结果并分析失败，依据证据提出建议。教师说明问题、知识关系和资料入口后，你自主安排阅读、设计、编程与检查；遇阻可按需获得帮助。

课堂末按教师安排完成A版选择题、AI学习和B版选择题，再核对提交。环境故障或实验未完成时保留实际进展与报错，明确待补，不用给定例子代替自己的实验。

## 完成步骤

### 定义你要诊断的失败

明确使用者、结果用途、目标、单位，以及做预测时知道什么。提出至少两种解释，选一项本次能够检查的改动，说明什么结果会支持或削弱这项解释，以及另一解释是否仍可能成立。可从训练数据和前课作品形成解释，不先查看最后测试来挑问题。

例如，“线性回归中单个小时项无法描述早晚高峰”与“工作日小时规律不同”对应不同表示实验；这些只是例子。你也可发现另一失败，选择其他已学的表示、规则或处理方案。若改问题或目标，连同评价、泄漏检查和实现一起调整。

### 保存自己的实验计划

运行本次验证比较前，在报告的实验计划部分或 `plan.md` 中记录：你准备检查的两种解释、原方案与候选方案、唯一改变的因素，以及保持不变的条件。另写清主要评价指标、要检查的分组、怎样依据结果作选择，以及什么结果会让你限制使用。选择规则可以是有依据的文字判断或数值条件，不强制统一阈值或JSON模板。说明至少两个重要决定及理由。

### 构建并公平比较

用提供的离线数据与现有Python／NumPy环境，自行构建一项对照。可编辑 `analysis.py` 的候选函数，或另写自己的入口。默认程序只做数据检查和训练均值基线，不一次完成正式实验，也不替你生成报告。

第一次查看数据可在学生仓库根目录执行：

```bash
python lesson-08/analysis.py
```

只有 `python3` 可用时替换首项；详见 [ENVIRONMENT](../ENVIRONMENT.md)。默认结果在 `lesson-08/artifacts/baseline/`，先看 `comparison.csv`，再核对 `records.csv` 的一行。起点只是可运行资源，**只运行基线不足以完成本课**。

Bike按时间划分：2012年7月1日之前的13,003条记录用于训练；2012年7月1日至9月30日的2,208条记录用于验证；其后的2,168条用于最后测试。用相同的训练／验证记录比较原方案与候选方案，只改一项重要因素。从训练集学习处理参数，并在验证集上沿用。若自选其他数据，说明来源、可用信息与独立评价安排，避免课堂中安装下载。

### 用自己的检查解释结果

自选一条真实记录，从关键输入或预处理追踪到预测，并独立重算误差。再选一个与用途有关的失败分组，或检查一项输入条件变化；核对至少5条记录或完整分组，写明用于计算的记录数。说明这项检查提供了总体分数没有呈现的什么信息，并保留至少一个尚未排除的解释。具体检查由你决定，不必使用示例的通勤组。

需要通勤时段作为检查时，可以使用统一示例定义：workingday=1且小时7、8、9、16、17、18、19；这不是实测通勤者身份。没有记录的组写“不可评估”；记录很少的组说明结果可能不稳定。

### 先选择，再最后评价

基于验证结果在自己的报告选择部分或 `decision.md` 保存方法、参数、评价、理由与验证证据路径，再只评价这个方法的测试结果。你可以选原方案或建议暂停，候选不必胜出。若据测试再改方法，当前测试成为开发证据，改后方法需新的独立数据评价。

完成自己的报告与代码后，更新 `submission.json` 的 `run`（运行命令）和 `artifacts`（结果文件列表），使运行命令能重新生成自己的主要验证结果；不能把默认基线清单当作已经完成自主实验。默认自动检查（CI）不运行最后测试；测试结果与测试前选择记录需另行保存。操作支持见 SUPPORT。

## 必须提交什么

- 自己的实验计划与测试前选择记录（可放报告），任务说明 `contract.json` 与 `report.md`，体现至少两个重要决定。
- 自己的可重现程序、配置和在相同条件下得到的原方案／候选方案验证结果；至少包括比较表、逐条真实值与预测，以及失败检查证据。输出格式可适应自己的方案，报告需说明字段和分母。
- 测试前选择与最后测试结果、实际命令、数据来源和环境说明；保留报告引用的旧结果与失败尝试，按实际先后顺序记录过程。

作品应能回答：我在研究什么、为什么选这项实验、它能区分什么、核算是否正确、自己的检查改变了什么建议、哪些结论仍不成立。仅有运行成功、文件齐全或AI生成说明不构成完成。

## 不同起点怎么做

### 必做任务（Core）：自己设计一件诊断作品

按上述证据标准完成。使用现成代码、让AI帮助编程或保留基线，都不降低标准，也不按代码量评价。标准练习见 [EXERCISES](EXERCISES.md)，可依需要安排顺序。

### 入门支持（Support）：遇阻时补一项能力

SUPPORT按“启动环境／不知道怎样计划／不会实现比较／不能核算／不能提交”等问题提供帮助。假设、评价与失败分析仍由你选择，不要求按顺序做完所有支持步骤，也不设分数上限。

### 提高任务（Upgrade）：检查另一种尚未排除的解释

在第一项作品完整后，检验另一解释或结果稳定性。记录继续使用同一验证数据属于开发，不冒充新独立评价。

### 换数据重测（Transfer）：检验迁移边界

把用途改为提前一天调度或换有来源的新数据，检查输入能否事先取得、目标是否仍一致、怎样保留新测试。当前实际天气分数不能直接证明新用途。

### 自选拓展（Open extension）：课后继续自己的问题

围绕尚未排除的解释设计新数据、变量或实验矩阵。先说明它将提供什么新证据，避免仅增加模型数量。

## 运行限制

用课程现有Python与NumPy，不新增安装。Bike数据已离线附带，普通CPU与约8GB可用内存；运行资源、具体环境与已验证范围见ENVIRONMENT。无需显卡、付费模型或课中下载；AI学习及在线概念检查另按教师安排。

来源与CC BY4.0见 [LICENSE_AND_SOURCE](../data/bike/LICENSE_AND_SOURCE.md)。CSV无空字段，但缺165个小时的记录，不能补成零租借。`casual` 和 `registered` 相加等于 `cnt`，不能用于预测 `cnt`。`season` 保留数字类别，文字标签的来源冲突见数据说明。默认任务只能说明2011–2012记录租借的当小时条件估计，不证明未来调度、未满足需求或因果效果。评分与历史成绩保持原规则。
