# 第 08 课（S06）：用对照实验诊断预测误差

## 本课要解决什么问题

**预测问题：** 已知当小时实际天气和日历信息，估计共享单车系统在这个小时记录的租借总次数 `cnt`。数据来自 UCI Bike Sharing，共 17,379 条真实小时记录。它不提供提前一天的真实天气，也不记录想租车却没有租到的需求。

**本次对照：** 找一个误差较大的情形，提出至少两种可能原因，选其中一种设计改动。将原方案与候选放在相同训练、验证记录上比较，只改变要检查的因素。例如，比较“小时数乘一个系数”和“每个小时有自己的加数”；也可检查工作日的差别是否随小时改变，或选择其他已学方法。一次比较提供支持或削弱某种解释的证据，通常不能确定唯一原因。

**需要交的结果：** 一份两方案比较、一次从输入到预测的核算、一个分组或输入变化检查，以及根据结果提出的建议。计划和最终选择可写在同一份报告里。方法、主要指标和重点检查由你决定，至少说明两个会影响实验或建议的选择及理由；AI 可以协助设计、实现和计算。

## 本课要学会什么

| 概念 | 你应能做什么 |
|---|---|
| 假设与控制变量 | 说明可能原因、本次改动和保持不变的条件 |
| 特征表示 | 追踪输入怎样变成模型使用的数，例如“是否为 6 点”的 0/1 列 |
| 交互特征 | 解释一个输入对预测的影响怎样随另一个输入改变 |
| 总体与分组误差 | 重算误差，按记录数合并分组，并解释指标为何可能支持不同选择 |
| 实验计划与最后评价 | 先定评价规则，用验证结果选方案，再评价选定方案的测试结果 |

[LEARN](LEARN.md) 用同一张四行小表逐步解释这些关系；[HINTS](HINTS.md) 提供算错或操作卡住时的提示。

## 课堂任务

1. **选问题，写计划。** 从训练记录或前课观察指出误差较大的情形，提出两种可能原因。写原方案、候选、唯一改动、控制条件、主要指标与重点分组，以及什么结果会支持改用候选。本地报告即可，无需向外部平台注册。
2. **实现两种匹配方案。** 用相同训练、验证记录作对照；处理参数从训练集计算，验证集沿用。如果检验小时编码，两种方案的算法、其他输入和处理规则应相同，只换小时表示。默认均值基线不是“线性小时原方案”。
3. **检查计算与误差。** 自选一条真实记录，追踪输入到预测并重算误差；再检查与用途有关的分组，或改变输入看看预测怎样变化。核算至少 5 条记录，或所选分组的全部记录；完整小组少于 5 条也可检查，说明结果可能不稳定。标明实际记录数，区分抽查和整组。
4. **选择后再测试。** 根据验证结果保存选定方法、参数和理由，只评价该方法的测试结果。最后建议可以是保留原方案、采用候选、缩小用途或暂停使用；候选不必胜出。

教师说明情境和一个小例子后，你自主安排阅读、设计与操作。课堂末按教师安排完成 A 版选择题、AI 学习和 B 版选择题。较快完成后可继续检查另一种可能原因或结果稳定性。

## 完成步骤

在学生仓库根目录运行：

```bash
python lesson-08/analysis.py
```

沿用已经成功的 Python 启动命令；只有 `python3` 可用时替换首项。默认结果在 `lesson-08/artifacts/baseline/`：`comparison.csv` 给方法、记录数和 MAE，`records.csv` 给逐条观测值、预测和误差。起点只检查数据并计算**训练均值基线**；自己的比较方案需要另行实现。

## 必须提交什么

- 问题说明 `contract.json`、报告、实验计划和测试前选择；计划与选择可以放在报告里。
- 程序、配置及主要验证结果：两方案比较、逐条观测值与预测、输入追踪和分组或输入变化检查。
- 选定方案的最后测试结果、数据来源、环境与实际命令，保存报告引用的结果。

把 `submission.json` 的 `run` 和 `artifacts` 改为自己的主要验证命令与其能重生成的文件；另存的测试结果在报告中给路径。默认清单只对应均值基线。详见 [SUPPORT 保存报告与提交清单](SUPPORT.md#保存报告与提交清单)。

报告要让读者看懂：检查了什么可能原因，为什么这样比较，核算是否正确，结果支持什么建议，还有什么原因未被排除。沿用原评价，不增加评分、统一表单或完整 AI 对话要求。

## 不同起点怎么做

提高任务可检查另一种可能原因、一个处理参数的影响，或不同小时／月份的稳定性。再次使用同一验证数据属于继续开发；若依据测试结果改了方案，改后方案需要新的独立数据评价。

课后可把问题改成提前一天的用途，列出那时能取得的信息，例如带时间戳的天气预报，再设计新的评价。也可提出需要额外收集什么变量来检查未排除的原因。问题和路线可以自选，保持当前数据能够支持的解释范围。

## 运行限制

Bike 按日期划分：2012-07-01 之前 13,003 条训练；2012-07-01 至 09-30 的 2,208 条验证；之后 2,168 条最后测试。CSV 无空字段，但缺 165 个小时的记录；缺记录不表示零租借。`casual + registered = cnt`，这两列是目标的组成项，不能用于预测 `cnt`。季节数字编码的标签来源冲突见[数据说明](data/DATA.md)。

使用课程现有 Python／NumPy、离线数据和普通 CPU，约 8GB 可用内存即可；具体环境见 ENVIRONMENT。来源与 CC BY 4.0 见 [LICENSE_AND_SOURCE](../data/bike/LICENSE_AND_SOURCE.md)。验证改善可为相似条件下的预测提供证据；用于其他年份、城市或提前调度前，还需检查输入可用性和数据分布，并重新评价。
