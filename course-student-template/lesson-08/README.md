# S06 · 换一批数据，处理流程还能用吗

## 本课要解决什么问题

数据接入小组要把下一批记录送进预测程序。新记录可能缺一项输入，数值范围也可能不同。你要设计从原始输入到预测的处理流程，使它能重新运行，并说明信息不完整时怎样处理。

请提交流程、训练时学到的处理参数、缺失输入测试和建议。遇到无法合理填补的记录，可以要求补资料或转人工；需展示程序怎样识别这些情形，而不是让它无声输出一个数。

### 由你选择的用途与方案

可以面向要求尽量连续服务的值班人员，也可以面向宁可少处理一些、但要求信息充分的审核人员。由你选择缺失值处理、数值缩放和拒绝处理条件；根据数据自拟用途也可以。填补方法的默认值不是教师推荐的答案。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **训练与应用（fit / transform）**：先从训练资料确定处理参数，再原样应用到新记录。
- **缺失值填补（imputation）**：为缺少输入的记录提供可计算替代，不能恢复未知事实。
- **特征缩放（scaling）**：改变数值尺度以支持模型计算，参数也只能从训练资料学习。
- **训练管道（pipeline）**：将预处理与模型按同一顺序运行，避免评价时偷偷使用其他资料。
- **交叉验证（cross-validation）**：多次内部划分比较方案，每次都要重新学习预处理参数。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟讨论缺失后的行动；12—26分钟手算填补泄漏；26—51分钟比较处理流程；51—65分钟测试不完整输入；65—75分钟重跑与说明；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 查看 data/base.json 中x2缺失的记录，先预计填补会对哪些记录影响更大。
2. 修改 config.json 的 imputation，比较现有可用方式；如采用暂不预测，修改程序并记录未处理数量。
3. 从输出追踪一个填补值来自哪批记录，再用新的输出目录重跑整个流程。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-08/analysis.py
```

默认结果保存为 `lesson-08/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`imputation` 选择填补方式；新增暂不预测路线时需在程序中实现并报告未处理数量。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-08/analysis.py --output artifacts/S06-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 确定缺失输入仍值得预测的条件，选择至少两种有理由的处理路线。
2. 让填补、缩放和模型只在训练资料中学习，再应用到评价资料，保存参数及数量。
3. 运行一种使用全部资料计算处理参数的对照，解释它为何不代表真实新数据使用。
4. 设计缺失或数值异常的输入，检查输出、报错或人工处理行为；据结果修改使用条件。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

能从原始数据重跑的完整处理程序；处理参数来源；两条路线的预测与覆盖数量；一条缺失输入测试；采用建议。合格标准是新资料没有参与学习参数，缺失处理的局限有证据。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

使用已有均值或中位数填补流程，完整核对参数来源和缺失组表现。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较缺失标记或人工补资料路线，解释增益与覆盖代价。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换成缺失比例不同的新批次，再跑整个流程。

### 自选拓展（Open extension）：提出本课问题之外的新探索

加入类别输入并处理从未见过的类别，说明默认处理的含义。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.5 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
