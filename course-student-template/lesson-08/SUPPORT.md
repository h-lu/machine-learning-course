# 第8课入门支持：按遇到的问题选择帮助

这些帮助不是人人必须顺序做的另一份作业。你可只读当前需要的部分；自己的假设、方法、评价和失败检查仍由你决定。先有尝试，再用提示补能力；完整作品的证据要求见README。

## 我还不能开始读取真实数据

在学生仓库根目录（能看见 `scripts` 和 `lesson-08`）运行：

```bash
python lesson-08/analysis.py
```

只识别python3的电脑替换命令首项，不为命令名称另安装一套环境。环境检查见 [ENVIRONMENT](../ENVIRONMENT.md)。成功后先看 `lesson-08/artifacts/baseline/comparison.csv` 的方法、验证记录数与MAE，再用 `records.csv` 核对一行。该起点只核对数据并计算训练均值基线，没有候选、没有测试分数、没有个人报告。读懂它以后你要构建正式对照。

JSON是带字段名的文本，CSV以逗号分开列；可用编辑器或表格软件打开。运行失败保留命令与完整报错，不把旧输出当新运行。需要追踪缺失处理可用短热身：

```bash
python scripts/lesson08.py warmup --output lesson-08/artifacts/warmup
```

它只读取人工数据中的12条训练记录，用给定规则 `等待分钟数=1+2×排队人数` 演示计算，不比较真实数据上的候选模型。结果字段为 `queue_length_raw`（原始人数）、`queue_length_used`（处理后的输入人数）、`fixed_rule_prediction`（规则预测的等待分钟数）。在C04找原值为空与填补值13/9，按LEARN完整例题核算：queue_length_used的单位是人，fixed_rule_prediction的单位是分钟。

## 我不知道怎样从问题设计实验

先写使用者、目标和使用时点，再从训练记录或前课作品指出具体失败。提出两个解释：若解释一成立，哪项改动可能改善哪个组？若解释二成立，哪项检查会给不同证据？你决定优先检查哪项，并在报告或自己的计划文件保存理由。

计划可以用自己的文字和结构，包含原方案、候选、唯一变化、控制条件、主要评价和分组，以及什么证据会改变使用建议。可以采用数值规则，也可以说明有依据的判断条件，不要求全班统一阈值。别把“我预计一定成功”当解释。需要AI帮助时，可请它提出几种解释，以及每次只改变一项因素的实验，自己取舍并指出各方案能说明什么。

## 我会说想法但不知道怎样实现

可在analysis.py的候选函数中实现自己的预测，或另写自己的入口。先画出“从训练集学习处理参数→处理训练输入→拟合模型→沿用处理参数并预测验证记录”的关系，说明每个参数来自哪里。用一行输入追踪代码，不从空白重写整个框架。

该函数也可返回一个字典，同时给出你自己实现的原方案和候选方案。默认均值 `baseline` 不一定是检验当前解释所需的原方案；怎样匹配对照，见 [README](README.md#构建并公平比较)。字典的每个值对应同一批评价记录，名称由你自定；最后测试的 `--selected-method` 填测试前已选定的那个名称。

你可以沿用已学的规则、线性回归或单项特征处理。若选择小时表示或条件差异，LEARN提供指示变量与交互的完整人工例题；它们解释关系，不替你完成真实实验。请AI帮助实现时，同时要求保存原始输入、预测、中间处理与误差，以便你核对。

`scripts/lesson08.py bike` 是**可选示例工具**，给出小时编码或工作日交互的已实现比较；你可阅读、改写或用于辅助理解。它的两项预设路线和JSON数值限制只是工具接口，不限制自拟方案，也不替代你的正式构建与独立检查。如果你使用了它，要说明给定部分与自己改变的部分，并实际完成有影响的设计。

工具操作资料见 [数据说明](data/DATA.md)。只有准备采用该工具接口时才需要preregister／decision命令；使用自写程序时报告或自己的计划／选择文件即可记录过程，配合自己的输出和命令。

## 我不理解模型的一项计算

先用LEARN不同的人工小表算指示列与交互，不把人工系数当Bike结果。带符号的误差＝预测值−真实值，绝对误差＝绝对差；MAE＝这批绝对误差之和÷实际记录条数。

自己程序若有标准化，保存训练均值、标准差和转换值；一列贡献＝转换值×系数，所有贡献与截距相加才是完整预测。若使用示例工具，models.json和feature_trace.csv提供这些中间值；先算再核对。若选择规则模型，就追踪规则条件和输出，不强制填写不适用的回归系数。

## 我只看得到总体分数，不知道怎样诊断

由你选择一个与用途有关的组或条件变化，例如特定小时、天气、月份、工作日或高租借时段。选择要有理由，不能看哪个好就只报哪个好。用逐条记录重算至少5条，注明核算子样本与整组是否不同；少于5条时如实说明样本不足并选择可核算的检查。

分组MAE合并时按记录数加权，不能直接平均大小不同的组。n=0写不可评估，不当作0误差。条件变化检查若固定标签与模型，只说明输入敏感性，不证明现实因果。你可以提出另一个仍未排除的解释，继续收集数据也是合理建议。

## 我已经比较好了，怎样保留最后评价

先在报告选择部分或自己的decision文件记录选中的方法、固定参数、评价规则、理由与验证证据路径，再只评价该方法的测试数据。默认起点不打开测试；自己的代码或示例工具必须保持先选再测。看完测试再改方法，这批测试数据就参与了方案开发，修改后的方案需要新的独立评价。起点程序提供以下调用方式：

```bash
python lesson-08/analysis.py --split test --decision lesson-08/report.md --selected-method 你的方法名 --output lesson-08/artifacts/test
```

把“你的方法名”换成自己 `comparison.csv` 中 `method` 列的实际名称；`report.md` 应已有测试前选择记录。代码只报告所选方法，不自动替你挑模型；没有实现候选时不能拿基线冒充。你也可在自己的入口调用load_test后按自己的方法评价，不必使用这一参数形式。


你可以保留原方案或暂停使用，不能为了表现“进步”强迫复杂模型胜出。若任务用途是提前一天调度，要处理实际天气在那时不可得的问题，不引用当小时条件分数证明提前预测。

## 我不知道哪些文件需要提交

把自己的程序命令和主要验证结果路径写入 `submission.json`：`run` 是按顺序列出的命令及参数，`artifacts` 是支持报告的结果文件列表。默认清单只对应基线，完成自主实验后必须改成自己的比较与检查证据；不要修改lesson课号。应固定必要的随机种子与输出格式，让主要结果能够重算；默认自动检查（CI）不运行最后测试。

`contract.json` 中保留课号 `lesson`。填写 `question`（问题）、`user`（结果使用者）、`data_source`（来源）、`metric`（指标及单位／分母）、`split_plan`（数据划分）、`initial_expectation`（事前预计）。报告结构可修改，但应保留计划、构建、对照、独立检查、选择与建议。完成本课要求后，才把 `submission.json` 的 `status` 改为 `complete`（已完成）。

```bash
python scripts/course.py run 08
python scripts/course.py check 08
git add lesson-08
git add -f lesson-08/artifacts
git diff --cached --name-only
```

确认准备提交的列表包括计划、选择、报告、代码、配置、对照、核算和最后测试；共享代码若改动也需保存。接着按 [WORKFLOW](../docs/WORKFLOW.md) 创建提交和本课v2-l08-final标签，不覆盖历史标签。这些操作不自动上传，不改线上场次。

不会JSON时在现有结构中改值，保持英文双引号、逗号和括号，可用 `python -m json.tool 文件路径` 检查。显式新结果目录不能覆盖旧证据；默认基线重跑只更新该目录中程序生成的结果文件。环境无法运行时继续手算与设计，明确未运行，交完整报错，修复后补跑。
