# C02 · 一个分数够不够支持使用

## 本课要解决什么问题

这一课要回答一个很具体的问题：**两个办法都给出了分数，怎样判断哪个办法真的值得使用？**

先看一个和程序无关的小例子。100 份申请中，只有 10 份确实需要人工复核。如果一个办法把 100 份申请都说成“不需要复核”，它的准确率是 90%，看起来很高；但它一份需要复核的申请也没有找出来。这个例子说明：分数必须和使用者真正关心的事情联系起来，不能只看一个好看的数字。

本课的程序处理的是一份小型教学数据。每行数据有输入和一个实际结果，程序要根据输入预测这个结果。你会比较两个办法：

1. **简单办法**：先用一部分数据算出实际结果的平均值，然后对每条新记录都预测这个平均值。它很简单，但可以作为公平比较的起点。
2. **候选办法**：只使用一列输入，拟合一条直线，再用这条直线给出预测。它可能比简单办法好，也可能没有增加实际帮助。

假设使用者每天只能处理有限数量的记录，或者特别担心某一类记录出错。你要检查：

- 两个办法是否在同一批没有参与形成办法的记录上比较；
- 平均误差到底有多大，单位是什么；
- 你关心的那一组记录是否也表现良好；
- 输入条件改变后，结论是否还成立。

最后，你要根据证据决定：继续小范围试用候选办法、保留简单办法、修改方案，还是暂时不用。候选办法没有胜出也可以完成本课。

本课数据是为了教学生成的合成数据，不代表真实机构、真实用户或真实业务。你可以使用 AI 写代码和解释公式，但报告里的数字必须来自你实际运行的程序。

## 本课要学会什么

- **形成办法的数据和检查办法的数据**：前一部分数据用来算平均值或拟合直线；后一部分数据不参与形成办法，只用来检查它面对新记录时的表现。两个办法必须在同一批检查数据上比较。
- **简单起点（baseline）**：一个容易算、容易解释的办法。本课的简单起点对每条记录都给出同一个平均值，用来判断候选办法到底增加了什么。
- **评价指标（metric）**：把预测值和实际值比较成一个数字。写指标时要说明数字的单位、怎样计算，以及这个数字要帮助使用者做什么决定。
- **平均绝对误差（MAE）**：每条记录先算“预测值和实际值相差多少”，不管高估还是低估都取正数，再求平均。MAE 越小，表示平均来看错得越少。
- **均方根误差（RMSE）**：先把每条误差平方，再求平均，最后开平方。大的错误会被它放大，所以它能提醒你检查少数特别严重的错误。
- **分组检查**：把一组有实际意义的记录单独拿出来计算。例如新用户、某种设备或某个时间段。总体平均值可能把这一组的严重错误藏起来。

先读[学习材料](LEARN.md)。它用很小的数字演示 MAE 和 RMSE 的区别；不需要先记住英文缩写。

## 90 分钟安排

- **0–15 分钟：看懂任务。** 打开数据说明，写清楚谁会看预测、预测结果出来后要做什么，以及哪一种错误最不能接受。
- **15–30 分钟：先写预计结果。** 手算一条记录，写下你预计简单办法和候选办法谁会更好，以及你的理由。此时先不要看程序输出。
- **30–50 分钟：运行程序。** 比较两个办法，确认它们使用相同数量的检查数据，并记录 MAE、RMSE 和数据条数。
- **50–65 分钟：检查一组记录。** 选择一个和用途有关的分组，查看这个分组有多少条记录、两个办法各错多少。
- **65–75 分钟：改变一个条件。** 使用程序自带的输入变化测试，或加入一条容易出错的记录，观察误差和建议是否变化。
- **75–90 分钟：修改判断并提交。** 把实际结果和最初预计作比较，写下最后建议，完成 `ml-check` 的 C02 A 版、AI 学习和 B 版。

## 完成步骤

### 1. 先把任务写成一句话

从学生仓库根目录打开下面四个文件：

- [字段和生成说明](data/DATA.md)：说明每列是什么；
- [原始记录](data/base.json)：程序实际会读取的数据；
- [任务说明](contract.json)：你要补充的任务信息；
- [报告](report.md)：你要记录预计、结果和判断的地方。

在 `contract.json` 中填写：

- `question`：你想用预测支持什么决定？例如“是否继续试用候选办法”。
- `user`：谁会看结果？这个人或小组每天最多能处理多少条记录？
- `data_source`：数据从哪里来？一行记录代表什么？结果是在什么时候知道的？
- `metric`：你准备看 MAE、RMSE 还是其他数字？这个数字的单位是什么？为什么能帮助使用者？
- `split_plan`：哪些记录用来算平均值或拟合直线？哪些记录最后才用来检查？两种办法必须使用同一批最后检查的记录。
- `initial_expectation`：运行前写下你预计的结果和理由，例如“我预计候选办法的 MAE 更小，但输入整体变化后可能变差”。

### 2. 运行起步程序

```bash
python3 lesson-02/analysis.py
```

如果你的电脑使用 `python` 命令，可以把 `python3` 换成 `python`。程序会生成：

```text
lesson-02/artifacts/summary.json
```

打开这个文件，按下面的顺序读：

1. `data.rows`：总共有多少行数据；
2. `metrics.n`：这次最后检查用了多少行；
3. `metrics.mae` 和 `metrics.rmse`：候选办法的两个误差；
4. `comparison.training_mean.mae` 和 `comparison.training_mean.rmse`：简单办法在同一批检查数据上的误差；
5. `stress_test.metrics`：输入条件改变后，候选办法的误差；
6. `details`：每条记录的实际结果和候选办法预测值，用来手算一条误差；
7. `provenance`：实际使用的数据、配置和程序信息，方便别人重新运行。

这里的误差数字越小通常越好，但不要只看谁的数字小。先确认两个办法的 `n` 相同，再确认这个数字确实回答了使用者的问题。

### 3. 手算一条记录

在 `details` 中选一条记录，找到它的实际结果（`actual`）和候选办法的预测值（`prediction`）。用“实际结果减去预测值，再取相差的绝对值”算这条记录的误差。例如实际结果是 4，预测值是 3，绝对误差就是 1。把这一步写进 `report.md`，让别人能检查你有没有读错数字。

### 4. 检查一个有理由的分组

选择一组你确实关心的记录，例如某个 `group`、某个时间段或输入值较大的记录。不要为了让候选办法看起来更好才挑分组。

在报告中写清楚：

1. 这组记录满足什么条件；
2. 这组一共有多少条记录；
3. 两个办法在这组各自的误差是多少；
4. 样本很少时，为什么不能把这几条记录说成所有人的情况；
5. 这组结果会不会改变你的建议。

### 5. 改变一个条件，再运行一次

程序自带一个检查：把检查数据中的输入整体增加 2，但暂时不改变实际结果，用来模拟“输入记录方式发生变化”。在新的输出目录运行：

```bash
python3 lesson-02/analysis.py --output artifacts/C02-demo
```

比较 `artifacts/summary.json` 和 `artifacts/C02-demo/summary.json`，写清楚改了什么、为什么这算是一个可能让模型出错的条件、哪个误差改变了多少，以及你的第一次建议是否需要修改。不要覆盖第一次生成的结果。

### 6. 完成必做任务（Core）

每位学生都要完成下面五件事：

1. 写清楚使用者、行动、评价数字和运行前预计；
2. 在同一批检查数据上比较简单办法和候选办法；
3. 手算并记录一条预测误差；
4. 检查一个有实际意义的分组和一次条件变化；
5. 根据总体结果、分组结果和条件变化，修改第一次写下的建议。

最后按照[仓库首页的环境说明](../../README.md)重新运行一次。报告只能写程序实际产生的数字；如果运行失败，保留完整命令、报错文字和你已经核对的部分。

## 必须提交什么

- `contract.json`：填写好的任务、使用者、数据来源、评价数字、数据划分和预计结果；
- `report.md`：一条手算过程、两个办法的比较、一个分组检查、一次条件变化、第一次建议和最后建议；
- `analysis.py`、`config.json`：你实际运行的程序和设置；
- `artifacts/summary.json` 和 `artifacts/C02-demo/summary.json`：两次运行得到的结果；
- `submission.json`：报告路径、结果路径和运行命令，并把 `status` 改为 `complete`。

合格不等于候选办法一定胜出。只要两个办法比较公平，数字能够重新算出，你能解释错误和限制，并根据证据作出决定，就完成了本课的核心任务。

## 不同起点怎么做

### 入门支持（Support）：先把程序跑通

只做默认运行，找出两个办法的 `n`、MAE 和 RMSE。手算一条记录，再写一句话解释为什么不能只看一个总体分数。可以请 AI 解释公式，但要自己核对数字。

### 必做任务（Core）：完成一次公平比较

完成上面的六个步骤：写任务，运行程序，手算一条记录，检查分组，改变条件后重跑，修改建议。

### 提高任务（Upgrade）：比较另一列输入

把 `config.json` 中的 `feature` 从 `x1` 换成 `x2`，重新运行并比较。说明输入列改变后，哪个误差变了，以及是否改变你的决定。

### 换数据重测（Transfer）：换一份相同含义的数据

准备一小份含义相同的新记录，重新运行两个办法。说明新数据有多少行、哪些条件发生变化，以及原来的建议是否仍然适用。

### 自选拓展（Open extension）：换一个实际行动

选择另一个使用者或行动，例如特别害怕少数大错，重新说明为什么 MAE 或 RMSE 更适合这个行动。不能只复制原来的分数。

## 运行限制

本课数据约 180 行、文件约 40 KB。必做任务只使用仓库内的离线数据、普通 CPU 和约 8 GB 可用内存，不需要 GPU、网络下载或付费 API。单次运行目标不超过 3 分钟，从原始数据重新运行目标不超过 5 分钟。

如果替换数据或增加依赖，请在报告中写明数据怎样得到、每行代表什么、依赖怎样安装，并保留一个不需要联网的必做版本。数据只是教学样例，不能据此声称真实机构或真实人群的表现。
