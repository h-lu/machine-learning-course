# 第02课｜比较基线与候选

## 学习顺序

先读[知识讲解](LEARN.md)，完成[练习](EXERCISES.md)，再设计正式项目；计算卡点看[提示](HINTS.md)，文件与命令查[运行帮助](SUPPORT.md)。已完成的作业无需重交。

## 标准任务

1. 保留由训练标签计算的均值基线，再选择一个有理由的简单候选，说明参数来源。
2. 用同一批验证记录评价两者，核对目标、单位、条数、MAE及允许的信息来源。
3. 自选一条预测独立复算，再选择两个相关条件组或一种有理由的分组方式检查失败，给出分组数量及具体编号。
4. 根据用途选择基线或候选，并说明可能遗漏的信息、其他解释与下一步验证。

至少自主决定候选及参数来源，以及怎样检查目标用途中的失败。沿用前课作品时重新在相同记录上计算，不直接比较不同样本的旧分数。

## 数据与可用信息

真实数据来自[UCI Bike](../data/bike/LICENSE_AND_SOURCE.md)，一行是系统一个小时的租借记录。字段与单位见[数据字典](data/DATA.md)：`cnt`不是单站库存，也不涵盖全部未满足需求；`temp`不是直接的摄氏度。

训练13,003条、验证2,208条，最后2,168条测试保留到第8课。训练标签用于确定参数，验证标签用于比较；`cnt`及其组成项`casual`、`registered`不作预测输入。使用实际当小时天气时，结论是已知天气下的条件估计，而非有天气预报支持的提前调度。

## 运行与提交

在学生仓库根目录运行：

```sh
python3 lesson-02/analysis.py
```

默认入口提供数据检查、开发预览或必要基线。根据自己的问题完善程序，并保存报告、配置、逐条与汇总结果。AI可辅助编程与分析，保留自己的方法选择和证据解释。

填写 `contract.json` 原有六个字段，不改字段名；在 `submission.json` 中登记实际报告、产物及能重建它们的命令参数列表，完成后设 `status=complete`。

```sh
python3 scripts/course.py check 02
```

本地检查核对文件；CI重新运行登记命令并比较产物字节。提交时保留原工作流与评分安排，可用 `git add -f lesson-02/artifacts` 保存被忽略的产物。运行环境见[环境说明](../ENVIRONMENT.md)。
