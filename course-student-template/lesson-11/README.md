# 第 11 课（S09）：数据怎样表示，模型才容易使用

## 本课要解决什么问题

**先按 [入门支持](SUPPORT.md) 运行起点，查看同一条记录在两种表示下找到了谁。** 本课继续判断哪些咨询记录需要人工复核，但固定使用 3 近邻方法：找到表示上距离最近的 3 条训练记录，用它们的多数标签预测。你只改变数据怎样表示，以便把结果变化归因于表示。

原始表示直接把数值放在一起；候选表示使用训练集统计量缩放数值，并明确表示缺失和渠道类别。你要检查普通验证记录以及三条挑战记录：缺失长度、新渠道、少见但正常。相似只表示输入接近，不保证标签相同。你要提交表示比较、一个缩放手算、挑战记录检查和测试前选择。运行失败时保留命令与报错，先用支持页的二维小计算继续，修复后补跑。

## 本课要学会什么

| 标准术语 | 学完后的表现 |
|---|---|
| 数据表示（representation） | 说明一条原始记录怎样变成模型实际计算的数值 |
| 特征缩放 | 解释为什么量纲较大的字段会主导距离，并只用训练集计算均值和标准差 |
| 缺失值与缺失指示 | 区分“用中位数填补”与“告诉模型这里原本缺失” |
| 未见类别 | 为训练中没有出现的新渠道保留明确处理办法 |
| 距离与近邻 | 核对最近记录，同时说明距离近不等于真实类别一定相同 |

先读 [LEARN.md](LEARN.md) 的二维距离和缩放例子；遇到陌生词再查 [术语表](../docs/TERMINOLOGY.md)。

## 90 分钟安排

0–15 分钟用二维小例子解释尺度与距离；15–30 分钟运行并追踪一条近邻；30–50 分钟比较两种表示；50–65 分钟检查缺失、新类别和少见正常记录；65–75 分钟整理提交；75–90 分钟完成概念检查。

## 完成步骤

### 1. 固定方法，只比较表示

在仓库根目录运行：

```bash
python scripts/course.py start 11
python lesson-11/analysis.py --config lesson-11/config-start.json --output lesson-11/artifacts/start
```

先打开 `comparison.csv`，确认两行都使用相同 `neighbors` 和相同 12 条验证记录。再打开 `records.csv`，找 C28 的 `nearest_ids` 和 `nearest_distances`。原始表示中“消息长度”的数值范围远大于其他字段，因此距离很容易被它主导。

### 2. 核对缩放所用的数据

打开 `summary.json` 的 `training_statistics`。这些均值、中位数和标准差只由 24 条训练记录计算。选择一个字段，用 LEARN 中公式把一条值换成缩放后的数值。验证集和挑战记录不能参与计算这些参数，否则会发生数据泄漏。

### 3. 检查三条不能靠平均分解释的记录

打开 `challenge.csv`：P01 缺少消息长度，P02 的渠道 `social` 在训练中未出现，P03 是少见但可能正常的记录。比较两种表示的预测与近邻。即使预测碰巧正确，也要判断处理方式能否在下一条类似记录上重复执行。

### 4. 做一次自己的表示选择

复制 `config-start.json` 为 `config-mine.json`。只把 `candidate_representation` 从 `scaled` 改为 `prepared`，保持近邻数不变；或者只把 `neighbors` 改为另一个正奇数，保持表示不变。先写预计，再运行：

```bash
python -m json.tool lesson-11/config-mine.json
python lesson-11/analysis.py --config lesson-11/config-mine.json --output lesson-11/artifacts/mine
```

说明这个实验改变的是尺度、缺失/类别处理还是近邻数量。将最终设置写回 `config.json`，先用验证集选择，再改为 `test` 运行 `python scripts/course.py run 11`。

### 5. 完成提交检查

填写任务说明和报告，将状态改为 `complete`，运行 `python scripts/course.py check 11`。下节课会在已经明确的数值表示上追踪参数更新，因此报告要保留所选表示和一条失败记录。

## 必须提交什么

提交程序、配置、任务说明、报告，以及 `summary.json`、`comparison.csv`、`records.csv`、`challenge.csv`。报告写出：每个字段怎样表示；一个缩放计算；两种表示的公平比较；P01、P02、P03 中至少两条的处理；一项个人选择；测试前结论及限制。

## 不同起点怎么做

### 入门支持（Support）：从一条距离计算开始

[SUPPORT.md](SUPPORT.md) 提供完整命令、点名记录和可核对的距离。完成这条路径和个人选择即可覆盖必做任务。

### 必做任务（Core）：在同一方法下比较表示

保持评价集和近邻规则一致，比较至少两种表示，核对训练统计量，并检查缺失、新类别或少见正常输入。

### 提高任务（Upgrade）：拆开候选表示

分别运行 `scaled` 与 `prepared`，判断改善主要来自尺度还是缺失与类别编码。一次比较只增加一组表示变化。

### 换数据重测（Transfer）：换一个距离敏感任务

在设备相似度或商品相似度情境中选择两个单位不同的数值字段，说明为什么直接距离可能失真，并设计新类别处理。

### 自选拓展（Open extension）：比较不同近邻数

比较 1、3、5 个近邻，记录验证表现和一条预测变化；不要因为验证分数最高就宣称所有场景最优。

## 运行限制

Python 3.10 以上与 NumPy；48 条主记录和 3 条挑战记录，普通 CPU 单次不足 1 秒。实验离线。人工标签与距离只验证表示机制，不能证明真实咨询记录中的相似关系。
