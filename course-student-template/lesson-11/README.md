# 第11课（S09）：把文字变成数字：人工特征、词袋与TF–IDF

## 本课要解决什么问题

只记字数、数字数，可能把意思不同的短信变成相同数字。本课比较不同的记录方式：自己选的几项特征，和逐词计数。把原文变成模型能用的一串数字，叫作输入“表示”。

## 本课要学会什么

- 说明自己的数字保留了什么、漏掉了什么。
- 按固定词表数词，解释普通词袋为何不记录词序。
- 只用训练文本选词表，处理新出现的词。
- 算一个词的IDF权重，说明统一向量长度在做什么。
- 固定其他条件比较两种文字记录方式。

## 课堂任务

从开发记录的错误中，选一个可能与文字记录方式有关的问题。比较自建或修改的人工特征与词袋/TF–IDF。使用相同训练和评价ID、分类模型、训练次数及复核设置。追踪一条原文怎样拆词、对应哪些数字、得到预测；再检查一条未知词、空文本或改词序的输入。

你决定检查哪类失败；再决定要保留哪种信息，例如词频、缩写或大小写。若分别调设置，给两方相同试验次数，不能只为一方反复选最好结果。 AI可帮助写代码、计算和分析；要核对关键数值，不能只交默认输出。允许自拟其他路线，只要有真实可运行材料、相同的比较条件、本课的计算追踪，并且最后评价数据没有参与方案选择。

中文释义只帮助阅读，不偷偷替换模型收到的英文。若研究译文，另存翻译输入与来源，把它明确当作一次新的文字记录方式比较。

## 完成步骤

在学生仓库根目录运行；已有环境是Python 3.10+和NumPy。

默认先运行一份TF–IDF结果。它只是比较的一方；用[SUPPORT](SUPPORT.md)换自己的配置或程序，构建另一方：

```bash
python3 lesson-11/analysis.py
```

结果在lesson-11/artifacts/baseline。再次运行请加`--output lesson-11/artifacts/新目录名`，保留旧结果。representation.json记录词表和词权重；prediction_trace.json记录一条开发短信的数字、系数和贡献；records.csv供同ID比较。拆词与计算完整示例见[LEARN](LEARN.md)。

阅读和实验顺序由你安排；[HINTS](HINTS.md)解决具体卡点，[EXERCISES](EXERCISES.md)检查能否换一个例子解释。

一份作品要包含：问题与两项重要选择、一条真实记录的计算、同记录的两方案比较、失败检查、建议和限制。填写contract.json，保存报告、代码、配置和结果；把submission.json的run改为自己的命令，artifacts列齐该命令生成的结果。只运行起点尚未完成任务，不另交额外报告或AI对话日志。

## 不同起点怎么做

先用完整小例看懂关系，再用可选程序或自己实现的方法完成比较。较快者可在同一作品多查一个分组或设置，但不要同时改许多条件后猜原因。有证据地保留原方案也合理。

## 运行限制

短信已固定分为train（训练）、dev（开发，供比较选择）和finalholdout（最终留出）。文字处理和模型参数只从train学；dev选方法、门槛、停止点和要检查的错误组。第14课选好方案后才第一次评价finalholdout。见[数据与英文支持](../data/sms/DATA.md)。

普通CPU、约8GB内存即可，无付费服务或GPU；安装和模型缓存由教师课前准备，课堂不下载大文件。作者运行成功不等于已经通过真人课堂试教。
