# S09 · 一棵树能否成为可执行的规则

## 本课要解决什么问题

审核人员希望从数据中获得一套能读懂的判断规则。小树可能容易执行，大树可能记住了少数历史记录；即使两棵树分数相近，实际要求检查的条件也可能不同。你要选定用途，判断一棵决策树是否适合作为规则建议。

请交规则、覆盖人数、预测比较和稳定性检查。发现某个分支只有很少记录或对轻微变化敏感时，可以删简分支、转人工或暂不采用，并给出依据。

### 由你选择的用途与方案

可以面向需要快速逐项判断的值班人员，也可以面向允许较复杂规则的专业审核组；可自拟用途。由你选择树的深度、叶节点最低人数、评价办法以及如何处理证据少的分支。不是越短越好，也不是越深越好。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **决策树分裂（decision tree split）**：通过一个输入条件把记录分开，形成逐步判断。
- **不纯度（impurity）**：度量节点中的类别混合程度，是训练规则的工具而非业务价值。
- **深度与叶节点（depth / leaf）**：分别影响规则长度与每个结论覆盖的记录数。
- **剪枝（pruning）**：删简证据不足或无助于新资料表现的分支。
- **稳定性（stability）**：训练资料稍变后规则是否大幅改变，帮助评估维护负担。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟明确规则使用者；12—27分钟小例理解分裂；27—52分钟比较复杂度；52—66分钟路径和稳定性检查；66—75分钟规则说明；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 先预计更深的树会改善哪一批记录，再运行默认实验。
2. 修改 config.json 的 max_depth 或min_leaf，每次保留比较结果；把你选定的一个分支译成日常中文。
3. 设计刚好位于分裂值两侧的输入，检查处理差异是否符合用途。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-11/analysis.py
```

默认结果保存为 `lesson-11/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`max_depth` 限制树深，`min_leaf` 限制每个叶节点最低训练人数。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-11/analysis.py --output artifacts/S09-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 明确谁执行规则、一次判断能接受多长流程，先写评价办法及规则限制。
2. 比较不同复杂度的树或树与简单规则，同时报告训练和评价表现以及叶节点人数。
3. 选一条具体记录沿树逐步解释，核对每项输入在使用时可得。
4. 改变少量训练记录或轻微改变输入，检查重要分支是否稳定；据结果决定简化、限用或采用。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

至少两种复杂度下的结果与叶节点人数；一条能照着执行的规则；一次稳定性或分界输入检查；采用建议。合格标准是预测与可执行性都有证据，不是把树图片导出来。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

比较两棵现有深度的树，并完整解释一条路径及其人数。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

重复抽样训练，检查最重要规则与群体结果的稳定性。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换测量精度或新群体，再看原阈值与叶节点覆盖。

### 自选拓展（Open extension）：提出本课问题之外的新探索

把规则写成供人执行的表格，实测一次判断需要哪些输入。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
