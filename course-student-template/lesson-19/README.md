# 第 19 课（S17）：该改提示、补上下文，还是改参数

## 本课要解决什么问题

同一个问答失败，可以改提示、在推理时补资料，或用标注样例更新任务参数。这三条路线改变的环节、需要的数据和维护成本不同。本课使用三条路线在相同六个案例上的固定候选输出，选择两条作公平比较。

**从 [入门支持](SUPPORT.md) 开始**。固定材料只覆盖 `prompt_revision`、`retrieval_context` 和 `parameter_adapter` 三个候选；它不是现场生成。新增问题或自写提示如果没有匹配的新输出，就必须报告没有证据，不能套用旧候选。提交两次路线比较、两个具体案例、成本核对和有条件的建议。若命令失败，保留报错、配置和已有结果，按 SUPPORT 先用指定两行完成手算并标明“尚未运行”，修复后补跑。

## 本课要学会什么

- **提示适配（prompt adaptation）**：改变任务说明或示例，不更新模型参数，准备快但不能自动补齐缺失事实。
- **上下文适配（context adaptation）**：把检索到的资料随请求加入输入，便于更新事实，但每次都依赖检索质量。
- **参数适配（parameter adaptation）**：用任务数据更新部分参数，需要标注、训练和版本维护。
- **相同评价条件**：三条路线必须面对同样案例和评分规则，才能把差别归因于路线。
- **数据与维护成本**：分数只是证据的一部分；还要核对资料更新、标注数量、准备时间和错误后果。本课的准备时间是课程设定的分钟数，不是实测开发工时。

## 90 分钟安排

0–15 分钟画出三条路线改变的位置；15–28 分钟比较提示与上下文；28–42 分钟检查逐案例差异；42–55 分钟把第二条路线换成参数适配；55–70 分钟选择自己的两条路线和使用条件；70–75 分钟整理六课证据；75–90 分钟概念检查和提交。

## 完成步骤

下面的命令都在学生仓库根目录执行，也就是能同时看到 `scripts` 和本课目录的位置；不要在 Python 的 `>>>` 中输入。电脑只识别 `python3` 时，把命令开头的 `python` 换成 `python3`。

1. 先写预计：对需要最新课程事实的问题，哪条路线更合适；对固定输出格式问题，哪条成本更低。不要先看总分再倒写理由。
2. 运行第一组路线：

```bash
python scripts/course.py start 19
python lesson-19/analysis.py --config lesson-19/config-start.json --output lesson-19/artifacts/prompt-vs-context
```

3. 先看 `route_comparison.csv` 的任务、支持、格式比例及 `setup_minutes`。这些分钟数是课程情境的人工假设，不是实测。再在 `case_scores.csv` 找 `case-01`、`case-02`，解释为什么补上下文能提供截止时间，而两条路线都应对无资料问题停止。
4. `config-support.json` 只把第二条路线换成参数适配：

```bash
python lesson-19/analysis.py --config lesson-19/config-support.json --output lesson-19/artifacts/prompt-vs-parameter
```

核对 `parameters_updated`、标注样例数和支持比例。`parameter_adapter` 的输出来自固定材料；本课没有重现训练，不能把它的分数称为实测训练收益。
5. 从三条候选中选择两条写入 `config-mine.json`，先说明用途和成本限制，再运行到 `artifacts/my-routes`。选择可以与默认不同，结论也可以是保留较便宜路线或暂缓适配。
6. 报告把 S15 的提示结果、S16 的检索结果和本课路线表连起来：明确每条建议引用哪一份文件，不能把不同数据上的分数直接相减。

## 必须提交什么

提交配置、程序、两组 `route_comparison.csv`、对应 `case_scores.csv` 和 `evidence.json`。报告写出：两条候选改变了什么、没有改变什么；相同案例上的三项比例及分母；两个关键案例；数据与维护成本；选择条件；固定材料不能支持的新路线结论。

填写任务说明、保存采用配置并改提交状态后运行：

```bash
python scripts/course.py run 19
python scripts/course.py check 19
```

## 不同起点怎么做

### 入门支持（Support）：使用已有三条候选做路线选择

按 [SUPPORT.md](SUPPORT.md) 的两组比较逐步完成，不要求训练模型或调用服务。

### 必做任务（Core）：比较两个合理替代方案

在相同案例上比较质量、数据需求和维护成本，解释采用、保留或暂缓的条件。

### 提高任务（Upgrade）：做成本敏感选择

自己给准备时间或标注样例设置预算，说明预算改变时建议怎样变化；不能把分钟与质量比例直接相加。

### 换数据重测（Transfer）：准备一套完整新候选

新增案例时，必须为每条被比较路线准备来源明确的新输出和参考资料；缺一条就报告无法公平比较。

### 自选拓展（Open extension）：重现微型参数适配

可以用小分类器训练输出头，但必须记录更新参数、训练数据和独立评价；不得把输出头训练称为完整预训练。

## 运行限制

标准库、18 份固定候选输出，普通 CPU 数秒内完成。结果只能比较已覆盖候选；不需要网络、GPU 或付费服务。固定候选不是实时生成，也不能证明真实参数适配效果。
