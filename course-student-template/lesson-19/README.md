# 第 19 课 · 一段话中，该看哪些信息

## 本课要解决什么问题

为一个短序列任务设计信息聚合方式：例如从多条记录中找到与当前问题相关的一条。你将改变查询、顺序或遮挡规则，看输出是否仍适合使用者。提交能复核的注意力计算、一个对照和干扰案例。输出不合适时，先检查能看见的信息和位置设计，再决定修改聚合方式或保留简单检索。

起步程序用短小的人工向量实际计算点积、归一化权重和加权输出，包含遮挡与换序检查。默认查询、键和值都取输入本身，即 Q=K=V，没有学习投影参数。向量的含义由教学数据设定，不是从自然语言模型学出的语义。你可以自定义小记录和向量，但要解释这些数怎样表达匹配关系。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **查询、键和值（query / key / value）**：分别表示要找什么、用什么参与匹配，以及匹配后汇总什么。
- **注意力（attention）**：按匹配程度给信息分配权重，再加权汇总。
- **遮挡（mask）**：禁止使用不应看见的位置，例如序列中尚未发生的内容。
- **位置信息（positional information）**：帮助区分内容相同但次序不同的序列。
- **多头注意力（multi-head attention）**：让不同的匹配与汇总方式并行工作，再合并信息；理解用途即可，不要求本课自行实现。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一个需要从序列取信息的问题，并说明顺序是否重要。你可以让相同内容在不同时间代表不同含义，也可以选择只关心集合内容的任务。确定正确输出应接近哪条记录或哪个数值。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-19/analysis.py
   cp lesson-19/config.json lesson-19/config-trial.json
   cp lesson-19/data/base.json lesson-19/data/trial.json
   ```

3. **做出有理由的比较。** 用同一组记录比较平均汇总和按查询加权汇总。明确哪些位置允许被查询看见。先手算两个键的相对得分，再运行程序；只改变查询、顺序或遮挡之一，观察权重与输出。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-19/analysis.py --config lesson-19/config-trial.json --data lesson-19/data/trial.json --output lesson-19/artifacts/trial
   ```

4. **核对数字和含义。** 核对每一行允许位置的权重之和，以及被遮挡位置是否获得零权重。默认 Q=K=V，换序也会换查询行；在无位置、无遮挡的比较里，要先把行对应回同一个查询，再检查输出变化，不能把行顺序变化当作理解了先后。解释权重最大项的值怎样影响输出；权重大不是该项对实际决策有因果作用的证明。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自己添加一条与查询很相似但内容不相关的干扰记录，或交换两条顺序有意义的记录。实际比较输出，检查你的表示能否辨别它们。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 画出或列出查询、键、值、权重与输出的对应关系；说明哪条信息本应被排除；报告平均汇总与注意力的差别，以及是否需要位置信息或其他检索方法。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-19/analysis.py --config lesson-19/config-trial.json --data lesson-19/data/trial.json --output /tmp/ml-s17-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

解释一次加权汇总的数字；比较简单汇总与注意力；实际检查遮挡或次序；设计干扰记录；依据任务判断这个聚合方式是否足够，并从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先用两条记录和二维向量，把权重与值写成表。AI 可以完成矩阵计算，你要核对汇总后的数值代表什么。

### 提高任务（Upgrade）：增加一种能改变判断的比较

增加两个关注不同特征的注意力头，检查不同关注点是否带来有用信息，而不只比较图形是否丰富。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一个次序含义不同的任务再跑一次，例如从无序标签检索换成按时间读取状态。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做序列长度不超过 16，每个向量不超过 32 维。只做小矩阵运算，无需训练语言模型。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
