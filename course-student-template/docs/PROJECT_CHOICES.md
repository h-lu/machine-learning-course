# 怎样选一个自己的问题

先想结果出来后谁会做什么，再选模型。题目可以小到“明天准备多少份物料”，也可以是“这条查询应返回哪份资料”。课堂目标是完成一次可信的判断，不是搭建完整产品。

## 三种起步办法

- 沿用本课小数据，换一个使用者或用途。例如，同一组分类分数用于提醒用户和安排人工复核，需要不同的评价办法。
- 沿用本课问题，换一份你能解释来源的数据。例如，先在合成数量数据上比较预测办法，再换到公开的每日客流小表。
- 自拟问题和实现。用三句话说明它需要本课哪个概念、你能拿到什么数据、90 分钟内准备检查什么。

不必为了独特而换题。认真发现示例中一个别人没有检查的问题，也是一项实质选择。改变颜色、文件名或模型称呼，不会改变实验支持的结论。

## 可以持续发展的作品

| 作品方向 | 前几课可以做什么 | 后面可以接着问什么 |
|---|---|---|
| 数量预测与资源准备 | 定义数量、比较均值与回归 | 低估更贵时怎样评价；新月份是否需要重测 |
| 信息提醒与复核安排 | 理解标签、比较阈值和排序 | 概率是否可靠；每天的处理名额变化后怎么办 |
| 小型资料检索工具 | 定义查询、整理文档和相关性 | 怎样切分；资料不足时怎样回答；新版本怎样处理 |
| 图像与序列实验 | 比较输入表示、训练小模型 | 哪种变化应保持输出；模型是否读到了不该知道的信息 |
| 模拟中的连续决策 | 明确状态、动作与奖励 | 如何探索；短期收益是否伤害长期结果 |

这些只是起点，不能当成必须从中挑选的菜单。你也可以在不同课使用不同作品。

## 换题后仍需完成的检查

先说明数据里一条记录表示什么，以及作判断时已经知道哪些信息。选择一个主要指标，解释它为什么符合用途。至少和一种合理的简单办法比较，并检查一种可能改变使用建议的情况。

最后测试数据应模拟将来的使用方式。按结果调过方案后，这份数据已经参与开发；不要继续称它为未见测试。数据很少时，可以把结论限定为探索性结果，说明下一步还需要什么。

使用自己的数据时，保留来源、字段含义和必要的处理命令。不能分发原数据的项目，可以提交一个能展示计算方法的小样例，并明确哪些实际结果暂时无法让同学重跑。

合成数据中的 `x1`、`x2` 没有现实单位，`target` 也可能为负。把它们用于某个业务情境时，先说明单位与变换，确认数值在那个情境下成立；不能直接给无量纲数字贴上“人数”或“金额”的名称。也可以把任务保留为机制实验，清楚说明还没有真实业务数据。
