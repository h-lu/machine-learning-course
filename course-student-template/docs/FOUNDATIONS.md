# S01–S06：问题、数据与评价

这六课接在 C01–C02 后面，沿用“根据排队人数预测等待分钟数”的情境。前两课介绍的样本、特征、标签、基线和 MAE 会继续使用；新概念在每课 LEARN 中就地解释，不用先背术语表。

第 01–04 课已经授课，其中 S01、S02 保留当时的材料和完成要求。本轮从 S03（lesson-05）继续使用本模块，不追溯增加前四课任务。S07–S30 也已按新学习地图成套更新；进入哪一课仍以教师当次通知和 ml-check 场次为准。

## 基础还不稳时从哪里开始

每课 README 首屏的“入门支持”都通向 `SUPPORT.md`。跟着这一条路径做即可，不用同时做另一套任务。两个现成配置先帮助你完成一次比较，再自己选择一个设置或检查并解释理由；提高、换数据重测和自选拓展是选做。

后续 S07（lesson-09）开始新的“学习、表示与泛化”模块，也提供同样的 SUPPORT 路径。它使用另一份咨询处理时间数据，并有自己的训练、验证和测试划分；只延续前面学过的关系，不直接读取本模块的产物。配置字段和命令以各课 README 为准，不能照搬本模块参数。

## 六课怎样连起来

| 课次 | 文件目录 | 本课做什么 | 留给后续的依据 |
|---|---|---|---|
| S01 | lesson-03 | 把愿望改成任务，比较预测与提醒办法 | 原用途、输入、比较及不能证明的结论 |
| S02 | lesson-04 | 审查代理标签、未知记录与标注分歧 | 哪些标签可用，哪些需要复核或补充 |
| S03 | lesson-05 | 按用途比较时间、分组和随机划分 | 验证对象、保留测试数据、泄漏反例 |
| S04 | lesson-06 | 比较误差后果、阈值与容量 | 明确的评价标准和工作量假设 |
| S05 | lesson-07 | 在相同预算下比较补数据策略 | 选中编号、标签来源、总体与分组结果 |
| S06 | lesson-08 | 返回原用途，用一个实验区分失败原因 | 原方案与候选的同样本比较及修订建议 |

默认实验是可以替换的起点。可以自选用途、换数据或改程序，但要用到本课关系，保留实质比较和自己的检查。程序能退出成功，不等于实验支持你使用模型。

## 数据既有联系，也有版本差异

S01、S03、S04 使用相同的 24 个排队编号与标签。S03 增加事后小票字段，仅供泄漏反例。S06 标签与编号不变，只隐藏部分人数，模拟记录缺失。S06 必须在新版本上重跑原方案和候选，不能直接拿旧分数比较。

S02 是 8 条标签审查样本，有延迟上传和一条始终未知的标签。S05 是一个有 4 条训练样本、12 条候选池样本的采集模拟，仍使用固定的 6 条验证和 6 条测试。它们都是人工编写的数据，不是实际采集或实际 AI 输出。

本模块默认不查看测试结果，S06 确定方案后再练习最后评价。若你已经在其他实验中看过同一批测试标签，必须如实注明，并换新数据再评价；不能称作未见测试。

## 文件怎样读，怎样改

操作不熟时先读 [第一次运行指南](FIRST_RUN.md)。所有命令从能看到 `scripts` 和 `lesson-03` 等目录的学生仓库根目录执行。

每课先读情境和学习卡，再运行默认实验。每次试验另存 `config-trial.json` 等副本并使用新的输出目录。`comparison.csv` 是方案汇总；`records.csv` 是逐条依据；S05 的 `added_samples.csv` 记录选中样本；`summary.json` 保存完整信息。空白或 `null` 不是零。

参数只改本课 DATA.md 解释过的字段；新模型、新字段需要一起改程序。程序报错时先修复再重跑，旧输出不能算新实验。复制 JSON 时使用英文标点，最后一个字段后没有逗号。

## 任务说明的六个字段

`contract.json` 是任务说明文件，不是新增的机器学习术语。保留 `lesson` 字段，用自己的话填写下面六项：

| 字段 | 写什么 |
|---|---|
| question | 本课要研究的问题，不只是“运行代码” |
| user | 谁会使用结果，或本次教学练习假定的使用者 |
| data_source | 数据怎样得到；人工数据、代理标签或合成样本必须说明 |
| metric | 使用哪个评价指标，单位和分母是什么 |
| split_plan | 哪些数据训练、验证、测试；S02 写标签截止日及统计范围 |
| initial_expectation | 实验前预计会怎样，以及为什么值得比较 |

报告用短段落回答提示并引用具体文件和命令，不写空泛结论。S06 还需指向 S01 的原用途和你保留的比较依据。只有真实完成后，才把 `submission.json` 的 `status` 改为 `complete`。

## 保存和提交：不要漏掉结果文件

先将保留的配置写回本课 `config.json`，运行本课的 `scripts/course.py run`，再用 `check` 检查清单。命令中的数字是目录编号，不是 S 后面的数字：S01 对应 03，S06 对应 08。

以 S01 为例，以下命令保存本课文件及你修改的共享程序。`artifacts/` 默认被忽略，因此需要 `-f` 显式加入报告引用的结果：

```bash
python scripts/course.py run 03
python scripts/course.py check 03
git add lesson-03 mlcourse
git add -f lesson-03/artifacts
git diff --cached --name-only
git commit -m "S01 完成任务与比较"
git tag v2-l03-final
git push origin HEAD
git push origin v2-l03-final
```

在 `git diff --cached --name-only` 中确认报告、任务说明、最终和试验配置、结果文件都出现，再提交。共享代码修改过时也需提交。若标签已经存在，不删除或覆盖，按 [课程提交步骤](WORKFLOW.md) 使用修订标签。

| 课次 | run/check 编号 | 要保存的课目录 | 首次完成标签 |
|---|---|---|---|
| S01 | 03 | lesson-03 | v2-l03-final |
| S02 | 04 | lesson-04 | v2-l04-final |
| S03 | 05 | lesson-05 | v2-l05-final |
| S04 | 06 | lesson-06 | v2-l06-final |
| S05 | 07 | lesson-07 | v2-l07-final |
| S06 | 08 | lesson-08 | v2-l08-final |

S02 的最终配置可以选择合适截止日，但 `later_day` 不能更早。S06 需要同时保存 `config-validation.json` 与其验证结果，测试输出放在主 artifacts 目录。所有报告引用的试验都要有重算命令；不要求上传完整 AI 对话。

检查脚本只检查文件与重跑条件，不替教师评价推理质量。概念题在教师指定的场次完成；仓库中的题库源码和教师实际开放的线上场次必须属于同一发布版本。
