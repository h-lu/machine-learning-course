# 前八课怎样衔接与提交

01数据字典（字段含义和单位）→02模型比较→03用途说明→04覆盖审计（哪些时段有记录）→05划分方案→06评价与行动→07补样计划→08诊断实验。前1–7课已上，新版可补学，不追改已完成要求。新实验与旧人工例子的数据不同，不能把两者的误差分数直接当作同一批样本上的改进。

各课给核心关系与证据要求。你可以沿给定问题探索，也可以说明理由后自拟等价路线。至少两个会影响分析的重要选择由你确定，例如输入信息与评价办法。看结果前保存预计；比较时说明使用的数据与条件；核对具体记录编号和指标的分母，并保存选择理由与失败分析。`SUPPORT.md` 提供按需支持，使用提示不降低评分；若其中的小例子已满足同一练习要求，不需要重复交一份。`EXERCISES.md` 提供练习，`HINTS.md` 在卡住时查阅。

完成时保存代码、最终配置、`contract.json`、`report.md`、`submission.json` 与报告引用的全部证据。提交清单的 `artifacts` 列出可由 `run` 命令重建的主结果；其他试验也要保存配置和结果，并在报告写出各自的重算命令。完成后检查：

```bash
python3 scripts/course.py check 08
```

将 `08` 换成本课号。只有完成本课要求后才设置 `status: complete`；检查通过不代表分析正确，也不代表已上传。`artifacts/` 目录通常被 Git 忽略，按[提交流程](WORKFLOW.md)显式加入要交的文件。保留既有 `v2-lNN-final` 标签与修订标签，不覆盖旧标签。第8课先根据验证结果选定方案，再评价测试数据；如果用测试结果修改方案，这份测试数据已参与开发，后续独立评价需要新的测试数据。
