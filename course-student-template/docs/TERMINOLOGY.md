# 机器学习术语：先看意思，再看例子

这不是开课前要背完的词表。遇到新词时再回来查即可。本课程使用机器学习中通用的名称，再用小例子解释。下面以“根据排队人数预测取餐等待时间”为例；英文供查资料时使用。

| 通用术语 | 通俗解释 | 本课程中的例子 |
|---|---|---|
| 样本（sample） | 一次被记录的观察 | 一次取餐排队经历，不是整家食堂 |
| 数据集（dataset） | 为一个任务整理的一组样本 | 记录多次排队人数与等待分钟数的表格 |
| 特征（feature） | 模型作预测时使用的输入信息 | 开始排队时，前面有多少人 |
| 标签／目标值（label / target） | 希望模型预测的真实结果 | 排队结束后才知道的实际等待时间；标签也可以是数值，不只是类别 |
| 预测值（prediction） | 规则或模型算出的估计结果 | 预计等 5 分钟，不是承诺一定等 5 分钟 |
| 回归（regression） | 预测数值的任务 | 预测等待多少分钟 |
| 分类（classification） | 预测类别的任务 | 预测“是否超过 10 分钟”，与直接预测分钟数不同 |
| 模型训练／拟合（training / fitting） | 用训练数据确定模型参数 | 根据历史排队数据计算一条直线的截距和斜率 |
| 推理／预测（inference / prediction） | 使用已经确定的模型处理新输入 | 把新的人数代入模型得到等待时间 |
| 参数（parameter） | 决定规则或模型怎样计算的数 | 直线中的截距和斜率；可由人指定，也可用数据拟合 |
| 绝对误差（absolute error） | 预测值与实际值的非负差值 | 预测 5 分钟、实际 4 分钟，绝对误差为 1 分钟 |
| 基线模型（baseline model） | 用来作比较的简单参照模型 | 不看人数，对所有样本都预测训练集等待时间的平均值 |
| 训练集（training set） | 用来学习模型参数的数据 | 计算平均值或直线参数的 8 条样本 |
| 验证集（validation set） | 开发时用来比较和选择方案的数据 | 比较规则、基线与线性回归的 4 条样本 |
| 测试集（test set） | 方案确定后，用来做最后评价的数据 | 另外 6 条未用于训练和选择的样本；公开示例不是真实业务的最终证明 |
| 平均绝对误差（mean absolute error，MAE） | 每条预测与真实值相差多少，取绝对值后再求平均 | 两条预测分别差 1 和 3 分钟，MAE 为 2 分钟；越小越好 |
| 泛化（generalization） | 模型在未见样本上仍有用 | 不只在已经用于训练的排队记录上误差小 |
| 数据泄漏（data leakage） | 不该参与训练或方案选择的信息混了进来 | 用测试集标签计算基线的平均值，或把排队结束后才知道的结果当特征 |
| 可复现性（reproducibility） | 别人按相同数据、代码、参数和环境能够复核主要结果 | 保存输入、程序、配置与运行命令，而不只交截图 |

C01 先学习样本、特征、标签、预测、训练和可复现性。C02 再使用基线模型、数据集划分和 MAE。表里的“泛化、数据泄漏”等词是后续查阅用的，不要求你在 C01 开始前掌握。

## 遇到新术语怎么办

先问“它指什么”，再找一个具体样本，最后问“混淆它会导致什么错误”。例如，标签不是模型自己写出的答案，而是本任务要预测并核对的结果。AI 可以解释概念，也可以帮助举例；仍需用数据或计算核对解释。

## 查阅来源

术语可对照 [Google 机器学习术语表](https://developers.google.com/machine-learning/glossary)；训练、验证和测试的区别可对照 [scikit-learn 交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)，数据泄漏可对照 [scikit-learn 常见错误](https://scikit-learn.org/stable/common_pitfalls.html)。不需要为了读术语安装这些工具。

## S01–S06 用到的补充术语

这些词随课使用，不是另一张需要预先背诵的清单。

| 通用术语 | 通俗解释 | 例子 |
|---|---|---|
| 代理标签（proxy label） | 用与目标相关的另一个量代替目标标签 | 用规则估计分钟数代替真实等待；两者是否接近要核对 |
| 标注分歧（annotation disagreement） | 不同标注对同一样本给出不同结果 | 两人计时相差三分钟，先核对起止点 |
| 选择偏差（selection bias） | 被记录或进入统计的样本可能不能代表目标人群 | 只收到空闲窗口的标签，就推断全部窗口 |
| 时间划分（time-based split） | 按先后日期安排训练和评价 | 早期记录训练，较晚记录评价未来使用 |
| 分组划分（group-based split） | 按人、设备或窗口等对象分开数据 | 新窗口用途下，训练和验证窗口不重叠 |
| 误报／漏报（false positive / false negative） | 把不需要提醒的样本提醒了／把需要提醒的样本漏掉了 | 必须先定义“需要提醒”的真实标准 |
| 合成数据（synthetic data） | 用程序或模型生成的数据 | 原回归模型给新人数生成分钟数；不是新增真实观察 |
| 缺失值填补（imputation） | 用明确规则替代没有记录的输入值 | 用训练集已知人数的均值替代缺失人数 |
| 指示变量（indicator variable） | 用 0/1 表示一个条件是否成立 | 晚间为 1，午间为 0，是特征，不是预测标签 |
| 流水线（pipeline） | 将预处理与模型连接成一致的计算步骤 | 训练集学填补值，训练和新输入都沿用该值 |

标签覆盖率在 S02 专指“截止日已知标签数 ÷ 待统计样本数”。它是本次审查的统计量，不是模型准确率。社区术语可继续对照上面的官方术语表与 scikit-learn 文档。

## 本轮阅读中需要区分的用语

“定向抽样”在 S05 指本课的具体规则：优先选缺少时段，组内按编号选取。它不自动等于分层随机抽样或主动学习；掌握这条操作规则不要求背更多算法名。“标签覆盖率”在 S02 明确定义为已收到标签数除以本批样本总数，不是准确率。

S07 使用两个特征，称多元线性回归；一个特征的系数解释要保持另一个特征不变。阅读表的残差采用“真实值减预测值”。岭回归指带 L2 正则化的线性最小二乘；正则化不是所有验证数据上更优的保证。术语请结合当课例子，不额外作为开课前的背诵要求。

可查阅 [scikit-learn 线性模型](https://scikit-learn.org/stable/modules/linear_model.html)、[缺失值填补](https://scikit-learn.org/stable/modules/impute.html)与[数据泄漏及一致预处理](https://scikit-learn.org/stable/common_pitfalls.html)。

## S07–S12：学习、表示与泛化

| 通用术语 | 通俗解释 | 本课程中的例子 |
|---|---|---|
| 模型假设（model assumption） | 模型预先限定输入与输出可以怎样关联 | 直线模型假设细节项每增加一个，处理时间按固定斜率变化 |
| 模型复杂度（model complexity） | 模型能够表达的变化有多灵活 | 二次项能表示弯曲关系，也更容易适应少量训练记录的偶然变化 |
| 外推（extrapolation） | 对训练数据范围以外的输入作预测 | 训练最多见过 10 个细节项，却预测 16 个时的处理时间 |
| 预测概率（predicted probability） | 模型对某个结果发生可能性的数值估计 | 0.7 表示模型估计需要人工复核的可能性为 70%，不是确定事实 |
| 概率校准（probability calibration） | 检查一组相近预测概率与实际发生比例是否接近 | 预测约 0.7 的记录中，长期是否大约七成真的需要复核 |
| 阈值（threshold） | 把连续分数或概率转成行动的界限 | 概率不低于 0.6 才进入人工复核 |
| 精确率（precision） | 被选中的记录中，真实正类所占比例 | 复核 10 条，其中 7 条真的需要复核，精确率为 7/10 |
| 召回率（recall） | 全部真实正类中，被找出的比例 | 实际有 8 条需要复核，找出 6 条，召回率为 6/8 |
| 数据表示（representation） | 把原始对象变成模型能够计算的特征 | 将类别写成独热向量，或把不同量纲的数值缩放后计算距离 |
| 损失函数（loss function） | 训练时用一个数表示当前预测偏离目标多少 | 调整参数，使训练记录的平均损失下降 |
| 梯度（gradient） | 损失对参数变化方向和大小的局部信息 | 梯度为正时，沿反方向小幅修改参数可使损失下降 |
| 学习率（learning rate） | 每次参数更新走多大一步 | 太大可能越过较好位置，太小可能在有限时间内变化很慢 |
| 欠拟合／过拟合（underfitting / overfitting） | 模型太简单而未学到稳定关系／过度适应训练记录 | 训练和验证都差可能欠拟合；训练很好、验证明显差可能过拟合 |

## S13–S18：预训练模型复用

| 通用术语 | 通俗解释 | 本课程中的例子 |
|---|---|---|
| 预训练（pretraining） | 先在大规模任务上更新参数，得到可复用的表示或能力 | 本课只分析固定分数，没有执行真实预训练 |
| 推理（inference） | 参数固定后，使用新输入计算输出 | 给问答助手补一段资料会改变输出，但没有更新参数 |
| 任务微调（task fine-tuning） | 用当前任务数据更新部分或全部参数 | 只训练一个小输出头时，要说明基础部分仍然固定 |
| 词元（token） | 模型处理文字时使用的基本单位 | 一个汉字、词片段或标点都可能成为词元 |
| 注意力（attention） | 根据当前计算位置，为可见信息分配不同权重 | 权重说明信息怎样参与本次计算，不等同于事实正确或因果解释 |
| 因果遮罩（causal mask） | 生成下一个词元时阻止当前位置看到未来词元的规则 | 修改未来词元不应改变更早位置在有遮罩时的结果 |
| 提示过拟合（prompt overfitting） | 提示只适合参与修改的例子，换问题后收益消失 | 根据开发题反复改提示后，要用未参与修改的问题评价 |
| 检索增强生成（retrieval-augmented generation，RAG） | 先检索相关资料，再让生成步骤依据资料回答 | 要分别检查资料是否找到，以及回答是否得到资料支持 |
| 参数适配（parameter adaptation） | 为当前任务更新一部分参数的适配办法 | 固定候选输出只能比较已有路线，不能证明现场训练效果 |
| 评价器偏差（evaluator bias） | 评分过程会受顺序、措辞或规则设计影响 | 交换候选顺序后，代理评分发生变化，需要人工抽查 |

## S19–S24：模型、程序与人的协作

| 通用术语 | 通俗解释 | 本课程中的例子 |
|---|---|---|
| 工作流（workflow） | 把输入依次交给多个步骤处理的可运行流程 | 先判断路线，再查规则或算费用，最后决定是否转人工 |
| 中间产物（intermediate artifact） | 一个步骤交给下一个步骤的实际结果 | 检索到的文档编号、工具返回值和交接状态 |
| 工具调用（tool call） | 用明确参数请求程序执行计算或查询 | 调用费用计算器时要检查天数和设备类型是否合法 |
| 动态路由（dynamic routing） | 根据当前输入或反馈选择下一步骤 | 分类器选择查资料、查库存、计算费用或转人工 |
| 停止条件（stopping condition） | 规定任务何时完成或何时不再重试 | 工具成功后停止；连续失败达到上限后转人工 |
| 指令注入（prompt injection） | 不可信资料中的文字试图改变系统原有职责 | 文档要求导出账户信息时，流程仍需按权限规则拒绝 |
| 最小权限（least privilege） | 每个步骤只获得完成任务所需的动作和数据 | 查规则步骤不能顺便修改账户或导出个人信息 |
| 故障注入（fault injection） | 有控制地让一个步骤出错，以观察错误怎样传播 | 让检索返回错误文档，再替换该步骤判断整体结果是否恢复 |
| 端到端评价（end-to-end evaluation） | 从原始输入到最终用途一起检查整个流程 | 局部步骤正确不保证最终请求已经完成 |

## S25–S30：反馈、运行与迁移

| 通用术语 | 通俗解释 | 本课程中的例子 |
|---|---|---|
| 探索／利用（exploration / exploitation） | 尝试证据较少的选择／使用当前看来较好的选择 | 偶尔显示另一种回答以获得反馈，同时控制短期损失 |
| 状态（state） | 连续决策时，作选择已经知道的信息 | 当前风险等级和人工队列长度 |
| 奖励（reward） | 用数值表达希望系统鼓励的结果 | 只奖励立即回答可能漏掉稍后纠错的后果 |
| 延迟回报（delayed return） | 一个动作的后果在之后才出现 | 自动答复当下看似成功，稍后却需要人工修正 |
| 数据漂移（data drift） | 运行中的输入分布或说法相对参考数据发生变化 | 新批次出现“续借”和“无障碍设备”等新表达 |
| 延迟标签（delayed label） | 真实结果要过一段时间才能获得 | 请求处理结束并完成人工复核后，参考路线才确定 |
| 恢复方案（recovery plan） | 出现报警后切回可用版本并限制风险的步骤 | 切回保存的 v1，并把低置信请求转人工 |
| 延迟（latency） | 从开始处理到得到结果所用的时间 | 本机哈希计算耗时只是教学测量，不是大模型推理时间 |
| 缓存（cache） | 对相同输入和设置复用已保存结果 | 输入或方案变了就不能把旧命中当作新计算 |
| 迁移（transfer） | 把已有方案带到新的数据、使用者或用途后重新评价 | 校园设备路由换到图书馆后，要按新请求和新用途重测 |
| 文件摘要（checksum） | 根据文件字节计算的标识，用于发现内容变化 | SHA-256 相同支持文件一致，不能证明数据真实或结论正确 |
