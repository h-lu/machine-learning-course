# 机器学习术语：先看意思，再看例子

这不是开课前要背完的词表。遇到新词时再回来查即可。本课程使用机器学习中通用的名称，再用小例子解释。下面以“根据排队人数预测取餐等待时间”为例；英文供查资料时使用。

| 通用术语 | 通俗解释 | 本课程中的例子 |
|---|---|---|
| 样本（sample） | 一次被记录的观察 | 一次取餐排队经历，不是整家食堂 |
| 数据集（dataset） | 为一个任务整理的一组样本 | 记录多次排队人数与等待分钟数的表格 |
| 特征（feature） | 模型作预测时使用的输入信息 | 开始排队时，前面有多少人 |
| 标签／目标值（label / target） | 希望模型预测的真实结果 | 排队结束后才知道的实际等待时间；标签也可以是数值，不只是类别 |
| 预测值（prediction） | 规则或模型算出的估计结果 | 预计等 5 分钟，不是承诺一定等 5 分钟 |
| 回归（regression） | 预测数值的任务 | 预测等待多少分钟 |
| 分类（classification） | 预测类别的任务 | 预测“是否超过 10 分钟”，与直接预测分钟数不同 |
| 模型训练／拟合（training / fitting） | 用训练数据确定模型参数 | 根据历史排队数据计算一条直线的截距和斜率 |
| 推理／预测（inference / prediction） | 使用已经确定的模型处理新输入 | 把新的人数代入模型得到等待时间 |
| 参数（parameter） | 决定规则或模型怎样计算的数 | 直线中的截距和斜率；可由人指定，也可用数据拟合 |
| 绝对误差（absolute error） | 预测值与实际值的非负差值 | 预测 5 分钟、实际 4 分钟，绝对误差为 1 分钟 |
| 基线模型（baseline model） | 用来作比较的简单参照模型 | 不看人数，对所有样本都预测训练集等待时间的平均值 |
| 训练集（training set） | 用来学习模型参数的数据 | 计算平均值或直线参数的 8 条样本 |
| 验证集（validation set） | 开发时用来比较和选择方案的数据 | 比较规则、基线与线性回归的 4 条样本 |
| 测试集（test set） | 方案确定后，用来做最后评价的数据 | 另外 6 条未用于训练和选择的样本；公开示例不是真实业务的最终证明 |
| 平均绝对误差（mean absolute error，MAE） | 每条预测与真实值相差多少，取绝对值后再求平均 | 两条预测分别差 1 和 3 分钟，MAE 为 2 分钟；越小越好 |
| 泛化（generalization） | 模型在未见样本上仍有用 | 不只在已经用于训练的排队记录上误差小 |
| 数据泄漏（data leakage） | 不该参与训练或方案选择的信息混了进来 | 用测试集标签计算基线的平均值，或把排队结束后才知道的结果当特征 |
| 可复现性（reproducibility） | 别人按相同数据、代码、参数和环境能够复核主要结果 | 保存输入、程序、配置与运行命令，而不只交截图 |

C01 先学习样本、特征、标签、预测、训练和可复现性。C02 再使用基线模型、数据集划分和 MAE。表里的“泛化、数据泄漏”等词是后续查阅用的，不要求你在 C01 开始前掌握。

## 遇到新术语怎么办

先问“它指什么”，再找一个具体样本，最后问“混淆它会导致什么错误”。例如，标签不是模型自己写出的答案，而是本任务要预测并核对的结果。AI 可以解释概念，也可以帮助举例；仍需用数据或计算核对解释。

## 查阅来源

术语可对照 [Google 机器学习术语表](https://developers.google.com/machine-learning/glossary)；训练、验证和测试的区别可对照 [scikit-learn 交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)，数据泄漏可对照 [scikit-learn 常见错误](https://scikit-learn.org/stable/common_pitfalls.html)。不需要为了读术语安装这些工具。

## S01–S06 用到的补充术语

这些词随课使用，不是另一张需要预先背诵的清单。

| 通用术语 | 通俗解释 | 例子 |
|---|---|---|
| 代理标签（proxy label） | 用与目标相关的另一个量代替目标标签 | 用规则估计分钟数代替真实等待；两者是否接近要核对 |
| 标注分歧（annotation disagreement） | 不同标注对同一样本给出不同结果 | 两人计时相差三分钟，先核对起止点 |
| 选择偏差（selection bias） | 被记录或进入统计的样本可能不能代表目标人群 | 只收到空闲窗口的标签，就推断全部窗口 |
| 时间顺序划分（time-based split） | 按先后日期安排训练和评价 | 早期记录训练，较晚记录评价未来使用 |
| 分组划分（group-based split） | 按人、设备或窗口等对象分开数据 | 新窗口用途下，训练和验证窗口不重叠 |
| 随机划分（random split） | 使用随机过程把记录分到训练集和验证集 | 同一人或设备没有多条相关记录，且实际用途没有时间先后要求时，才可能合适 |
| 随机种子（random seed） | 固定随机过程的起点，使同一次划分可重现 | 同一种子得到同一组编号，但不能因此证明可以泛化 |
| 目标泄漏（target leakage） | 输入包含了标签本身或几乎直接暴露标签的事后信息 | 用等待结束后的小票时间预测等待时间 |
| 非对称损失（asymmetric loss） | 给不同方向的预测误差不同权重，再对逐条分数求平均 | 低估 2 分钟、低估权重为 3 时，该条加权误差分数为 6，不等于真实损失了 6 分钟 |
| 正类（positive class） | 在二分类评价中需要找出的那一类 | 第 06 课把实际等待至少 8 分钟定义为需要提醒 |
| 误报／漏报（false positive / false negative） | 把不需要提醒的样本提醒了／把需要提醒的样本漏掉了 | 必须先定义“需要提醒”的真实标准 |
| 决策阈值（decision threshold） | 预测达到设定值才进入某种决定的候选 | 预测等待至少 8 分钟才进入提醒候选；单位是分钟 |
| 容量约束（capacity constraint） | 一轮最多能处理或选择的候选数 | 5 条达到阈值，但一轮只能提醒其中 2 条 |
| 合成数据（synthetic data） | 用程序或模型生成的数据 | 原回归模型给新人数生成分钟数；不是新增真实观察 |
| 缺失值填补（imputation） | 用明确规则替代没有记录的输入值 | 用训练集已知人数的均值替代缺失人数 |
| 指示变量（indicator variable） | 用 0/1 表示一个条件是否成立 | 晚间为 1，午间为 0，是特征，不是预测标签 |
| 流水线（pipeline） | 将预处理与模型连接成一致的计算步骤 | 训练集学填补值，训练和新输入都沿用该值 |

标签覆盖率在 S02 专指“截止日已知标签数 ÷ 待统计样本数”。它是本次审查的统计量，不是模型准确率。社区术语可继续对照上面的官方术语表与 scikit-learn 文档。

## 本轮阅读中需要区分的用语

“定向抽样”在 S05 指本课的具体规则：优先选缺少时段，组内按编号选取。它不自动等于分层随机抽样或主动学习；掌握这条操作规则不要求背更多算法名。“标签覆盖率”在 S02 明确定义为已收到标签数除以本批样本总数，不是准确率。


可查阅 [scikit-learn 线性模型](https://scikit-learn.org/stable/modules/linear_model.html)、[缺失值填补](https://scikit-learn.org/stable/modules/impute.html)与[数据泄漏及一致预处理](https://scikit-learn.org/stable/common_pitfalls.html)。


## 真实Bike数据与第8课

|术语|通俗解释|本课核对|
|---|---|---|
|指示变量（indicator）|某条件成立为1，否则0|hr_8在8点为1，其他为0|
|独热编码（one-hot encoding）|用指示列表示类别|以0点为参照，保hr_1至hr_23，避免把相邻数字当同一方向变化|
|交互（interaction）|一个输入与另一个条件一起影响预测|hr_8×workingday只在工作日8点为1|
|预登记|看验证结果前保存解释、改动和评价规则|先保存自己的理由和通勤定义，再运行验证|
|目标泄漏（target leakage）|输入含目标本身或直接组成它的信息|casual+registered=cnt，两列不能预测cnt|
|覆盖率|已记录数量除以应有或定义的人群数量|有小时记录不等于每个日历小时都记录|

数字列temp为官方归一化温度，不能直接当摄氏度；cnt为系统该小时租借次数，不能当人数、库存或未满足需求。通勤组由教学用途事先定义，不证明这些记录全来自通勤者。
