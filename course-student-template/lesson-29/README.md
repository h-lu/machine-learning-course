# 第 29 课 · 知道规则后，怎样规划下一步

## 本课要解决什么问题

在转移规则已知的小环境里计算策略，例如帮助送件机器人绕开危险格到达终点；你可以换成其他连续决策问题。比较它与一条直观规则，判断数学上最优是否符合使用者的目标。提交价值计算、策略轨迹和规则变化后的检查。若策略绕远、冒险或循环，检查奖励与转移假设，再决定修改规划或暂不采用。

起步程序在已知小网格转移上执行价值迭代，输出价值、策略、贝尔曼残差与轨迹。转移由教学规则给定，规划器可以读取；这与下一课只能从交互学习不同。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **状态价值（state value）**：从当前状态开始，预期还能得到多少折扣回报。
- **贝尔曼更新（Bellman update）**：用一步奖励加上下个状态的价值，反复修正当前估计。
- **价值迭代与策略（value iteration / policy）**：价值迭代逐步求解，策略根据价值选择动作。
- **收敛误差与模型误差（convergence error / model error）**：数值迭代接近解，和转移模型接近现实，是不同问题。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 给路径或资源流程选择实际目标，例如快到达、少经过危险位置或节约动作。说明折扣和一步奖励怎样对应使用者需要；可以认为最短路径规则已经足够。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-29/analysis.py
   cp lesson-29/config.json lesson-29/config-trial.json
   cp lesson-29/data/base.json lesson-29/data/trial.json
   ```

3. **做出有理由的比较。** 在同一环境下比较价值迭代策略与一条可解释规则。选一个状态手算候选动作的一步更新，再核对程序。查看迭代停止条件，但不要把残差很小等同于现实正确。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-29/analysis.py --config lesson-29/config-trial.json --data lesson-29/data/trial.json --output lesson-29/artifacts/trial
   ```

4. **核对数字和含义。** 沿最终策略走一次，核对价值与实际奖励序列；检查终止状态是否继续获得不应有的未来价值。记录是否成功、步数与危险后果，不只比较回报。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自己修改一个关键假设，例如移动代价、危险格位置或折扣；先用旧策略在新环境运行，再重新规划比较，判断原策略是否对这个变化敏感。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 交代转移假设与目标、一处贝尔曼手算、规则与规划策略的结果、旧策略在变化下的表现，以及是否重新规划或保留简单规则的理由。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-29/analysis.py --config lesson-29/config-trial.json --data lesson-29/data/trial.json --output /tmp/ml-s27-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

说明已知转移；核对一个状态的更新；比较规则与规划；实际让旧策略面对一个新条件并重新检查；分清收敛与现实有效；从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先使用确定性小网格和给定终点，从靠近终点的状态开始手算，再让 AI 完成全表迭代。

### 提高任务（Upgrade）：增加一种能改变判断的比较

加入随机滑动或比较策略迭代，检查预期回报、失败概率与数值收敛的关系。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一张地图或目标限制再跑一次，说明哪些转移与奖励需要重新估计。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做环境不超过 100 个状态、5 个动作；折扣控制在 0 到 1 之间且小于 1，其他设定需说明收敛条件。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
