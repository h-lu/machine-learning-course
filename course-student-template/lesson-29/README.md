# 第 29 课（S27）：运行条件变了，怎样发现并处理

## 本课要解决什么问题

设备服务台助手投入试运行后，新一批请求出现了“延长借期”“无障碍设备”和“预留设备”等说法。程序版本也从 `v1` 变为 `v2`。真实路线标签不会同时到达：当前 6 条请求中只有 4 条已经完成人工标注。

**第一次做时从 [入门支持](SUPPORT.md) 开始。** 你要比较参考批次与当前批次的输入、新条件、置信度和已有标签正确率，触发一次报警并检查恢复版本。提交报警依据、恢复检查和“现在还不能判断什么”。本课读取课程提供的固定预测日志，没有重新训练或调用模型。

## 本课要学会什么

| 标准术语 | 本课需要掌握的含义 |
|---|---|
| 数据漂移（data drift） | 运行中的输入分布发生变化；本课表现为请求说法或类型与参考批次不同。 |
| 模型版本（model version） | 能明确区分两套预测来源的版本标识，本课为 `v1` 和 `v2`。 |
| 延迟标签（delayed label） | 真实路线要等人工处理后才知道，当前不能立刻评价全部请求。 |
| 监测指标（monitoring metric） | 在运行中持续计算的新条件比例、低置信比例和已有标签正确率。 |
| 恢复方案（recovery plan） | 报警后切回已保存版本、增加人工处理并保留证据的步骤。 |

完成后，你应该能区分“不需要标签的早期信号”和“标签到达后的质量证据”。

## 90 分钟安排

| 时间 | 活动 |
|---|---|
| 0–15 分钟 | 读参考批次和当前批次，标出两条暂无标签的请求 |
| 15–32 分钟 | 运行 `v1` 起点，核对三个分母 |
| 32–52 分钟 | 只把候选版本换成 `v2`，比较报警信号 |
| 52–67 分钟 | 调整一个报警阈值，预计并检查是否误报或漏报 |
| 67–75 分钟 | 写恢复条件、仍未知的质量和后续标注安排 |
| 75–90 分钟 | 完成 A 版概念检查、AI 学习、B 版检查并提交 |

## 完成步骤

1. 在仓库根目录运行参考版本：

   ```bash
   python scripts/course.py start 29
   python lesson-29/analysis.py --config lesson-29/config-start.json --output lesson-29/artifacts/start
   ```

2. 打开 `records.csv`，找到 `M09` 和 `M11`。两行的 `label_available` 为 `False`，所以 `known_correct` 是“尚不能判断”。再打开 `batch_metrics.csv`，核对当前批次请求数为 6、已有标签数为 4、暂无标签数为 2。
3. 先预计 `v2` 在当前批次的低置信比例和已有标签正确率会怎样变化，再运行只更换候选版本的配置：

   ```bash
   python lesson-29/analysis.py --config lesson-29/config-support.json --output lesson-29/artifacts/support
   ```

4. 手算当前批次 `v2` 已有标签正确率：4 条已有标签请求中 2 条路线正确，所以是 `2/4=0.50`。不能写成 `2/6`，也不能给两条暂无标签请求补猜测。
5. 把支持配置复制为 `config.json`，只改一个报警阈值。先说明它可能增加误报还是漏报，再运行 `python scripts/course.py run 29`。结合早期信号和已有标签，写明何时切回 `v1`、哪些请求转人工，以及什么时候重新评价。

## 必须提交什么

- 最终配置、`summary.json`、`records.csv` 和 `batch_metrics.csv`。
- 当前批次的请求数、已有标签数、暂无标签数及 `2/4` 手算。
- 至少一项无需标签的报警依据和一项标签到达后的质量依据。
- 一个报警阈值的单因素检查，以及误报或漏报方面的影响。
- 恢复步骤和仍不能判断的两条请求，不得把恢复版本称为已经在全部当前请求上验证正确。

## 不同起点怎么做

### 入门支持（Support）：先从三个分母和一条报警开始

按 [SUPPORT.md](SUPPORT.md) 找到标签状态、核对 2/4，并比较 `v1`、`v2`。支持路径覆盖完整必做关系。

### 必做任务（Core）：监测、报警并验证恢复

所有人都要同时使用输入信号与已有标签，检查一个阈值，并说明恢复后的验证边界。

### 提高任务（Upgrade）：比较报警时间

分别只用早期信号和等待标签后的信号，说明各自能提前多少、可能错过什么。

### 换数据重测（Transfer）：加入一种新说法

复制数据加入一条当前批次请求，只提供预测而暂不提供标签，检查报警是否变化；不能自行编造正确率。

### 自选拓展（Open extension）：写运行处置表

为输入变化、低置信、质量下降和程序故障分别写观察对象、负责人、恢复动作和复核条件。

## 运行限制

本课只分析固定预测日志。`confidence` 是日志中的数值；本课没有核对“数值接近 0.8 的记录是否长期约有 80% 正确”，所以不能把它当作已经校准的概率。恢复比较只覆盖 4 条已有标签请求。实验离线、数秒内完成；概念检查按课堂安排联网。
