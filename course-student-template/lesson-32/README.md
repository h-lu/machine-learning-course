# 第 32 课 · 换一个场景，原来的方案还能用吗

## 本课要解决什么问题

选择本学期一个已有项目，把它交给新的使用者或放进不同的数据条件。你要判断哪些证据还能沿用、哪些必须重做，并决定迁移、改造还是不采用。提交能重新运行的完整项目、旧新场景比较和一页使用说明。若新条件推翻旧结论，可以保留失败并提出更合适的规则或停止方案。

可复用本学期任意一个项目及其合法数据。没有合适旧项目时，起步程序提供合成表格上的均值与线性方案、新场景代价比较及重新拟合，便于完成迁移分析。它是入口示例，你不必把自己的图像、检索或强化学习项目改成回归。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **分布与用途变化（distribution shift / task shift）**：数据变了和使用目的变了可能同时发生，需要分别辨认。
- **再评价与适配（re-evaluation / adaptation）**：先用旧方案检查新条件，再决定是否调整参数、数据或模型。
- **代价敏感评价（cost-sensitive evaluation）**：同样的误差在不同使用者那里可能产生不同后果。
- **可追溯交付（reproducible handoff）**：让接手的人找到数据、程序、主要数字和采用条件，并能重新运行。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一个旧项目和一个会改变判断的新条件：新使用者、新时间、新群体、错误后果或资源限制。用一句话说明两者的实际差别，避免只改项目名称或随机种子。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-32/analysis.py
   cp lesson-32/config.json lesson-32/config-trial.json
   cp lesson-32/data/base.json lesson-32/data/trial.json
   ```

3. **做出有理由的比较。** 先保存旧方案，在新条件下直接运行，再比较一种适配路线或简单替代方案。明确哪些新数据用于适配，哪些用于最后检查；先定好评测方法，最后测试数据只用一次。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-32/analysis.py --config lesson-32/config-trial.json --data lesson-32/data/trial.json --output lesson-32/artifacts/trial
   ```

4. **核对数字和含义。** 核对旧新结果的分母、指标和数据来源是否可比。起步实验比较适配收益时，要让原模型和适配模型都使用新批次的同一后半部分；前半部分用于适配。若目标已经变了，不直接把两个分数相减当作模型退化，分别说明数据变化与采用标准变化的影响。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 选出最可能推翻迁移决定的一种条件，自己构造或收集对应输入并实际运行。可以检查新群体、额外限制、失效文档或奖励变化，但要说明这个变化为什么可能影响新用途下的结果。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 用一页说明告诉接手者任务、运行命令、结果出来后怎么做、什么时候停止，以及还有哪些未知；附旧方案、迁移比较、实际失败和修改后的采用决策。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-32/analysis.py --config lesson-32/config-trial.json --data lesson-32/data/trial.json --output /tmp/ml-s30-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

保留可运行旧方案；选择真正影响使用的新条件；在新条件运行旧方案并比较适配或简单替代；实际测试一个关键失败；在干净环境重跑主要结果；交给别人能读懂的使用说明。

### 入门支持（Support）：用较小的起点完成同样的判断

使用给定线性与均值示例，把低估后果或目标群体改成你能解释的场景；必须说明合成数据只是实验载体。

### 提高任务（Upgrade）：增加一种能改变判断的比较

比较第二条适配路线、估计不确定性或研究长期更新，重点解释增加的收益是否值得资源。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

再换一份数据或一个使用者检验最关键结论，说明有哪些部分可以复用、哪些需要重做。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

复用项目仍遵守普通 CPU、约 8 GB 可用内存与离线运行要求。必做总数据不超过 100 MB；缩减重复实验以保证从头重跑不超过 5 分钟。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
