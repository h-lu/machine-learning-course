# S22｜资料很多，怎样找到有用的一段

## 本课要解决什么问题

为一个小知识库设计检索办法，让使用者能找到当前真正有用的资料。你要自己界定“相关”是什么，比较漏掉证据与返回杂乱资料的后果。提交查询、相关性判断、检索比较和失败记录。找不到正确资料时，区分资料缺失、表示不合适和版本筛选问题，再决定修改或停止给答案。

起步知识库使用人工主题向量、短文档、有效版本标记和带相关文档编号的查询。程序实际进行余弦排序与版本筛选。这些向量不是通用语言嵌入；修改查询文字而不更新向量，不会真实改变语义检索。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **文档切块（chunking）**：把长文分成可检索的小段；过短可能丢上下文，过长可能混入无关内容。
- **向量与余弦相似度（embedding / cosine similarity）**：用数值方向比较内容接近程度，不自动判断是否适合回答。
- **返回数量（top-k）**：决定给使用者多少候选，影响漏检与阅读负担。
- **元数据过滤、召回率与精确率（metadata filtering / recall / precision）**：前者按版本等条件排除不适用资料；后两者检查该找的有没有找到、找到的有多少有用。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一个读者和资料用途，例如查当前借阅规则、查某年的旧政策或检索设备说明。自己制定相关性标准：历史说明是否有用、需要一段还是几段共同回答、什么情况应说明找不到。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lesson-24/analysis.py
   cp lesson-24/config.json lesson-24/config-trial.json
   cp lesson-24/data/base.json lesson-24/data/trial.json
   ```

3. **做出有理由的比较。** 为几条不同问法判断相关文档，再比较返回数量或版本筛选。可增加关键词检索作为简单路线；若自己换文本，可以重写检索器或使用明确解释的人工特征，不能把手设向量冒充模型语义能力。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lesson-24/analysis.py --config lesson-24/config-trial.json --data lesson-24/data/trial.json --output lesson-24/artifacts/trial
   ```

4. **核对数字和含义。** 逐项核对召回率和精确率的分母；没有相关文档的查询单独检查，不能硬算不存在的召回率。打开返回原文，确认它回答的是当前问题而不是仅包含相同词语。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 设计一条关键词相似但版本或对象不同的查询，或一条知识库没有答案的问题。运行后检查高相似度结果是否仍然无用。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 提供查询及相关性理由、检索参数或方法、逐查询命中与漏掉的资料、失败记录，以及返回数量与筛选条件的采用理由。 把说明写进 `report.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lesson-24/analysis.py --config lesson-24/config-trial.json --data lesson-24/data/trial.json --output /tmp/ml-s22-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `report.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

自己定义相关性；比较两个检索设置或方法；核对一个查询的分母；实际检查版本或无答案问题；解释人工向量限制；从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先在给定短文中人工标出有用段落，再让 AI 帮你计算余弦距离。你仍需确定当前问题需要哪一版资料。

### 提高任务（Upgrade）：增加一种能改变判断的比较

研究切块边界、关键词与向量混合或重新排序，检查收益是否来自更好的证据覆盖。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一份文档或一个时间范围再跑一次；同时更新相关性判断和向量生成办法。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做不超过 1,000 个短段落；默认只使用人工低维向量，离线运行。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../docs/RUNTIME.md)。
