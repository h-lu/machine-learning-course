# 第 10 课（S08）：预测概率怎样转成合适的行动

## 本课要解决什么问题

**先打开 [入门支持](SUPPORT.md)，运行现成配置并数一组概率。** 上一课比较了模型假设；这一课继续研究“怎样使用预测”，但改用课前准备的另一份“需要人工复核”概率数据。本课不读取第 09 课的分钟预测，也不重新训练概率模型。咨询团队每天只能复核有限记录，因此你必须决定按概率阈值提醒，还是按固定名额选概率最高的记录。

你要先检查概率分组与实际比例是否大致相符，再比较精确率、召回率和复核人数。提交内容包括概率核对、提醒办法、一次个人阈值或名额检查，以及测试前的选择。程序失败时可先手算支持页点名的 6 条记录，注明尚未完成运行。

## 本课要学会什么

| 标准术语 | 学完后的表现 |
|---|---|
| 预测概率 | 把数值解释为模型对结果发生可能性的估计，不把它当作确定事实 |
| 概率校准 | 比较一组记录的平均预测概率与该组真实发生比例 |
| 阈值 | 说明概率达到多少时触发提醒，并预计改变阈值的影响 |
| 精确率 | 在被选中复核的记录中，真正需要复核的比例 |
| 召回率与容量 | 说明找回了多少真正需要复核的记录，以及团队最多能处理多少条 |

概率质量和行动效果是两个问题：概率可以排序良好，但提醒办法仍可能超过人员容量；同一个概率也会因漏报和误报代价不同而采用不同阈值。

先读 [LEARN.md](LEARN.md) 的概率分组与精确率、召回率小计算；陌生词再查 [术语表](../docs/TERMINOLOGY.md)。

## 90 分钟安排

0–15 分钟解释概率、分组和提醒办法；15–30 分钟运行并手算一个分组；30–50 分钟比较阈值与固定名额；50–65 分钟改变一个规则并写使用建议；65–75 分钟整理提交；75–90 分钟完成概念检查。

## 完成步骤

### 1. 先核对概率，而不是立刻挑阈值

在仓库根目录运行：

```bash
python scripts/course.py start 10
python lesson-10/analysis.py --config lesson-10/config-start.json --output lesson-10/artifacts/start
```

成功后先打开 `calibration.csv`。每行的 `count` 是该概率区间的验证记录数，`observed_positive_rate` 是其中真实标签为 1 的条数除以该组总数。空组不会伪造比例。手算 `[0.4, 0.7)` 这一组的分母和实际比例，再与文件核对。

### 2. 比较三种提醒办法

打开 `comparison.csv`。`original_threshold`、`candidate_threshold` 按阈值选择；`capacity_top_k` 按概率排序后只取前 `review_capacity` 条。比较 `selected_count`、`false_positive`、`false_negative`、`precision` 和 `recall`。这些指标都以当前评价集为分母，不能把复核人数当成召回率。

在 `records.csv` 找到因规则改变而被新增或移除的一条记录，写清它的概率、真实标签和行动是否改变。

### 3. 只改一个行动设置

复制 `config-start.json` 为 `config-mine.json`，选择下面一种做法：只改 `candidate_threshold`，或只改 `review_capacity`。先写预计：提醒数、误报或漏报会怎样变化。再运行：

```bash
python -m json.tool lesson-10/config-mine.json
python lesson-10/analysis.py --config lesson-10/config-mine.json --output lesson-10/artifacts/mine
```

如果结果没有改变，也要解释原因，例如阈值区间内没有记录。不要同时改阈值和名额后只归因于其中一个。

### 4. 确定规则后再看测试集

先在验证集上写下选择及理由，将选中的设置写回 `config.json`。把 `evaluation_split` 改为 `test`，运行 `python scripts/course.py run 10`。测试集只用于评价已经确定的规则；看过结果后再次调阈值，需要新的未见数据。

### 5. 完成提交检查

填完 `contract.json`、`report.md`，将 `submission.json` 标成 `complete`，运行 `python scripts/course.py check 10`。报告要区分“概率分组是否可信”和“提醒办法是否适合容量”，不能只说准确率高。

## 必须提交什么

提交程序、最终配置、任务说明和报告，以及 `summary.json`、`calibration.csv`、`comparison.csv`、`records.csv`。保留个人配置与对应输出。

报告回答：谁使用提醒；标签 1 表示什么；一个校准分组怎样计算；选择规则改变了哪条记录；误报和漏报分别带来什么后果；容量是多少；验证集上为何选择该规则；测试结果能支持到什么范围。

## 不同起点怎么做

### 入门支持（Support）：按现成记录完成同一判断

[SUPPORT.md](SUPPORT.md) 点名要数的记录、分母和结果文件。用支持路径完成全部必做要求后，不再额外重复 Core。

### 必做任务（Core）：把概率变成有容量约束的行动

核对至少一个概率分组，比较阈值和固定名额，改变一个设置并在测试前确定规则。

### 提高任务（Upgrade）：比较两种误报或漏报后果

分别假设漏掉一条需要复核记录的代价为误报的 2 倍和 5 倍，计算三种规则的总误报或漏报后果，并说明假设改变是否改变建议。

### 换数据重测（Transfer）：换一种容量

将每天复核名额改为原来的一半，保持概率不变，重新比较排序与阈值规则。说明这验证的是行动约束，不是模型重新训练。

### 自选拓展（Open extension）：设计分组方式

在样本量允许时提出另一组概率区间，并说明每组至少需要多少记录才避免只凭一两条下结论。

## 运行限制

Python 3.10 以上，无额外第三方依赖；48 条人工记录，单次运行通常不足 1 秒。实验离线；概率是固定教学输出，不代表在线模型或真实用户风险。A/B 概念检查需要网络时按教师安排处理。
