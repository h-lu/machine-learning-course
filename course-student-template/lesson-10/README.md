# S08 · 风险概率应该怎样使用

## 本课要解决什么问题

服务团队希望预测某条记录是否需要后续处理。有的使用者只需要排序，有的希望把风险概率用于估计工作量。你要训练一个小概率模型，判断它能支持哪一种用途。

请交模型结果、概率检查，以及结果出来后怎么做的说明。排序有用但概率不准时，可以限定用途；模型没有改善简单基线时，也可以保留基线并解释原因。

### 由你选择的用途与方案

可为复核人员排列优先顺序，或为班组长估计整体工作量；也可自拟用途。由你选择损失、正则化、阈值和需要检查的群体。不要把概率与标签混为一谈，也不要把所有人都放在0.5阈值下评价。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **逻辑回归（logistic regression）**：用输入的线性组合产生0到1之间的二类概率。
- **S形函数（sigmoid）**：把任意实数映射成概率范围，但不保证概率已经准确。
- **对数损失（log loss）**：评价概率预测，特别惩罚对错误结果过度确信。
- **概率与类别（probability / class）**：风险大小是模型输出，是否行动还需要规则。
- **正则化与校准（regularization / calibration）**：前者限制模型复杂度，后者检查概率与实际比例是否相符。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟确定概率用途；12—27分钟辨别概率与类别；27—52分钟训练和基线比较；52—66分钟校准与错误确信检查；66—75分钟使用说明；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 先在 report.md 写概率0.8对所选使用者意味着什么，再运行实验。
2. 按需要改变 config.json 的 l2、learning_rate、steps或threshold；训练配置与行动阈值应分别解释。
3. 抽取一组相近概率的记录，核对人数与真实正例数；不能仅靠曲线判断校准。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-10/analysis.py
```

默认结果保存为 `lesson-10/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`learning_rate`、`steps`、`l2` 控制训练，`threshold` 控制行动；两类选择应分开解释。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-10/analysis.py --output artifacts/S08-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 选择排序、工作量估计或其他明确用途，先写需要评价的概率或行动性质。
2. 训练逻辑回归，与不依赖输入的概率基线比较，检查训练过程及目标评价资料上的结果。
3. 查看不同分数组或群体的实际比例，区分排序表现、概率准确程度和阈值行动结果。
4. 构造一个模型过于确信或信息不足的输入，决定是否限制概率解释、增加人工处理或停止使用。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

概率基线与逻辑回归比较；一组概率的实际比例核对；对应用途的行动或汇总结果；错误确信案例；概率使用说明。合格标准是说明概率可以支持什么，不能只交准确率。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

保留已有训练程序，比较概率基线并手查一组概率的分母。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较正则化与校准办法，分别看排序和概率用途。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换基础率不同的新批次，检查概率与阈值是否还适合。

### 自选拓展（Open extension）：提出本课问题之外的新探索

把概率用于工作量区间或资源模拟，说明新增假设。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
