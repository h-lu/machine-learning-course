# S18｜微型 Transformer 怎样猜下一个词元

## 本课要解决什么问题

搭建并检查一个微型序列模型，例如帮维护人员根据短操作记录预测下一个设备状态。你可以换成其他短序列任务。本课重点是追踪信息从输入到概率的路径，以及训练究竟改了哪里。提交分层检查、训练前后比较和一次信息泄漏测试。模型没学会时，保留失败数字，区分信息不足、只训练了部分参数和评测设计问题。

起步程序真实计算微型 Transformer 的注意力、残差、归一化和前馈步骤，并对输出分类头做一次更新。它没有训练完整 Transformer，也没有进行大规模预训练。数据是短小教学序列，结果只能说明本实验的计算和更新。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **自注意力（self-attention）**：让序列中的各位置根据彼此内容汇总信息。
- **残差连接（residual connection）**：把原来的表示加回新计算结果，为信息和更新提供直接路径。
- **层归一化与前馈层（layer normalization / feed-forward network）**：前者调整每个位置的特征尺度，后者逐位置进行非线性变换。
- **因果遮挡与下一词元预测（causal mask / next-token prediction）**：只能根据当前位置及以前的内容预测下一项，防止提前看见答案。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择一种短序列预测问题，例如符号循环、操作记录的下一步或你自定的小词表。说明预测时已经知道哪些内容，哪些规律应当能从前缀推断，哪些下一项本来就不唯一。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lessons/S18/analysis.py
   cp lessons/S18/config.json lessons/S18/config-trial.json
   cp lessons/S18/data/base.json lessons/S18/data/trial.json
   ```

3. **做出有理由的比较。** 先使用未更新的输出头记录目标词元概率与损失，再执行起步更新并比较。保持评测前缀独立；若改写训练流程，列出实际更新的参数，不把训练输出头写成全部层都学会了。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lessons/S18/analysis.py --config lessons/S18/config-trial.json --data lessons/S18/data/trial.json --output lessons/S18/artifacts/trial
   ```

4. **核对数字和含义。** 选一个位置，追踪输入维度、注意力输出、残差相加、归一化、前馈层和输出分数。检查训练损失下降是否伴随独立序列改善；如果只看同一个样本，结论只能涉及这次更新。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 在一个前缀后接上不同未来词元，检查前缀位置的输出是否保持一致。再设计一条训练中没有的组合；前者检查未来信息是否泄漏，后者检查学到的规则能否迁移。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 用自己的话标出各层用途、哪些参数被更新、训练与独立序列的损失，以及未来词元替换测试。说明这个微型模型能支持什么结论，哪些能力尚未测试。 把说明写进 `update.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lessons/S18/analysis.py --config lessons/S18/config-trial.json --data lessons/S18/data/trial.json --output /tmp/ml-s18-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `update.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

追踪一次完整前向计算；比较输出头更新前后；运行未来词元替换和一条新组合；根据独立结果决定继续训练、修改任务或暂停使用；从新目录重新运行。

### 入门支持（Support）：用较小的起点完成同样的判断

先用给定小词表和序列，只跟踪一个位置的向量与目标概率。AI 可以解释矩阵，你需要指出每一步能看见哪些位置。

### 提高任务（Upgrade）：增加一种能改变判断的比较

在预算内训练更多层或比较去掉某一组件，说明不同路线的参数更新量与评测样本相同与否。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一种短序列规律再跑一次，例如从固定循环换成依赖更早位置的重复；观察原任务的低损失还能否说明新任务有效。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

短序列不超过 16 个词元，模型宽度不超过 32；必做只做微型前向与少量更新，无 GPU 或下载权重要求。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../../docs/RUNTIME.md)。
