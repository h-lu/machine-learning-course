# C02 · 一个分数够不够支持使用

## 本课要解决什么问题

课程活动小组想知道一个简单预测办法是否值得用于下一批安排。组织者可能关心总体估计，值班同学却可能更在意少数严重错误。你要选择其中一种用途，比较一个不依赖复杂学习的起点和一个候选办法，向使用者解释是否值得继续试用。

请提交比较程序、分组结果和修改后的建议。候选办法没有胜出时，保留基线或暂不使用都是可交的成果；要说明是哪项结果改变了判断。

### 由你选择的用途与方案

用途可选“减少总体误差”“避免某一类严重错误”，也可自拟。你决定评价量、值得单独检查的群体、接受标准以及比较办法。不得先看全部结果，再把最有利的指标说成最初目标。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **训练与测试（training / test）**：用一部分记录形成办法，用另一部分检查对新记录的表现。
- **简单基线（dummy baseline）**：不利用输入关系的预测办法，用来识别看似不错却没有增加价值的分数。
- **评价指标（metric）**：用数字表达哪种错误值得在意，必须说明分母和方向。
- **分组检查（slice evaluation）**：分别查看有实际意义的记录组，防止平均值掩盖重要错误。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟辨别使用目标；12—25分钟比较微型例子；25—50分钟运行候选办法；50—65分钟分组与错误检查；65—75分钟重跑和建议；75—90分钟概念题与变式题。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 在 contract.json 写用途、评价量与划分办法；在 update.md 写基线可能在哪些记录上失败。
2. 运行默认实验，从结果中找到两种办法使用的记录数；需要时修改 analysis.py，使比较对应你的用途。
3. 选择一条错误记录，追溯输入与真实结果，再增加一条相关的测试输入。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lessons/C02/analysis.py
```

默认结果保存为 `lessons/C02/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`feature` 指定一元预测使用的输入；可比较现有输入，也可修改程序加入另一种办法。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lessons/C02/analysis.py --output artifacts/C02-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 明确所选用途，先写接受标准和预期，再按记录编号划分用于开发和最后检查的资料。
2. 比较简单基线和候选办法；保证它们接受同一批输入、采用同一种评价。
3. 选择一个有实际理由的分组或错误情形，查看总体结论是否仍成立；不能只挑候选办法占优的组。
4. 依据结果决定使用候选办法、继续保留基线或暂不使用，并在新的目录重跑主要结果。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

一张能重新计算的候选办法比较表；一个有理由的分组检查；一条错误记录和一条自行设计的测试；说明原来预计什么、现在决定什么。合格标准是同一评价条件下的比较能支持你的建议，而不是选出最高分。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](update.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

使用提供的两种办法，重点核对分母和一个相关分组，保持完整比较。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

估计换一批记录时差异是否稳定，解释额外检查是否改变建议。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一种群体构成再跑，看看总体排名为什么改变。

### 自选拓展（Open extension）：提出本课问题之外的新探索

把同一预测结果用于另一种行动，重新定义评价办法。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
