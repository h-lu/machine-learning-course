# S21｜提示改好了，还是只记住了例子

## 本课要解决什么问题

选择一个需要稳定输出的文本任务，例如把借书、预约等请求归类给值班同学；题目也可以自己定。建立能区分提示方案的评价办法。你要发现改进是否只发生在已经看过的例子上。提交候选比较、独立检查和失败类型说明。如果没有足够的新样本或新提示的真实输出，就保留验证缺口，不把想象中的改善写成结果。

起步数据是人工编写的候选响应表，包含查询、允许答案、示例候选输出以及开发和评测划分。程序只评价表里已有的输出，不会运行语言模型。改变 candidate 只是在已有候选间切换；新增提示必须另外获得并如实标明输出来源，不能由你写好理想答案后称作模型效果。

数据字段和生成方式见 [数据说明](data/DATA.md)。你可以改问题、数据、方法和评价；必须说明至少一个选择怎样影响结果。示例的结论不是你的任务答案。

## 本课要学会什么

- **零样本与少样本提示（zero-shot / few-shot prompting）**：前者直接说明任务，后者加入示例；示例可能帮助理解，也可能形成偏向。
- **结构化输出（structured output）**：约定输出字段和类型，使结果能被程序检查。
- **开发数据与最终测试数据（development / test data）**：前者用于改方案，后者用于检查已经选好的方案。
- **失败分类（error taxonomy）**：区分格式无效、类别错误和信息不足，便于决定怎样修正。

读 [学习卡](LEARN.md)，先用里面的小例子理解计算，再决定本课实验怎样用这些概念。

## 90 分钟安排

| 时间 | 你要做什么 |
|---|---|
| 0–12 分钟 | 确定使用者和问题，写下预计会看到的结果 |
| 12–25 分钟 | 学习本课概念，核对学习卡的一处计算 |
| 25–52 分钟 | 用 AI 协助运行起点并实现自己的比较 |
| 52–65 分钟 | 核对主要数字，运行自己设计的失败或条件变化检查 |
| 65–75 分钟 | 在新输出目录重跑，写出结论并整理提交 |
| 75–90 分钟 | 先做概念检查，再用 AI 学习，最后判断一个不同情境 |

新环境在课前准备；课堂内留时间复跑。遇到技术故障，先保留错误信息，按 [故障处理](../../docs/TROUBLESHOOTING.md) 修复，并说明还有哪一步没有完成。

## 完成步骤

下面命令从学生仓库根目录运行。没有安装环境时，先按 [环境准备](../../docs/GETTING_STARTED.md) 完成准备。

1. **把问题写具体。** 选择接收输出的人或程序，说明类别和格式为何有用。决定格式失败与内容错误的后果；可以选规则分类器作为候选，也可以研究什么时候应返回“信息不足”。 在 `contract.json` 中填写任务说明（task specification）：问题、使用者、数据来源、主指标、评测划分与预计结果。先写下预计会看到的结果，再开始比较。
2. **读数据并运行起点。** 先读本课 `data/DATA.md` 和 `config.json`，确认每条记录及参数的含义；运行后打开生成的 `summary.json`，区分示例结果与自己的结论。

   ```bash
   python3 lessons/S21/analysis.py
   cp lessons/S21/config.json lessons/S21/config-trial.json
   cp lessons/S21/data/base.json lessons/S21/data/trial.json
   ```

3. **做出有理由的比较。** 先把起步表当作方法演示，按开发数据选择候选及评分办法。自己的项目另保留最终测试数据，先定好评测方法，最后测试数据只用一次。若只使用已有人工输出，你的结论必须限定为这张响应表上的方案比较。 可以让 AI 解释、修改代码并整理图表；在配置和数据副本中完成自己的改动，保留原始文件。若新任务超出接口，直接改写 `analysis.py`，并记录新的运行命令。

   ```bash
   python3 lessons/S21/analysis.py --config lessons/S21/config-trial.json --data lessons/S21/data/trial.json --output lessons/S21/artifacts/trial
   ```

4. **核对数字和含义。** 分别核对输出能否被读取和答案是否正确，并抽查评分脚本是否把无效格式悄悄算成某一类别。保留开发集和独立检查的分母，说明示例是否覆盖了全部类别。 不只复制汇总结果，要追踪至少一个样本、计数或计算过程。
5. **加入自己的检查。** 自己设计一种此前没有的推理情境，例如一句话有两种请求，或缺少决定类别的信息。可用它检查本地规则、格式校验或已有系统的真实响应；若没有模型可运行，只提交测试输入与待检验假设，不捏造输出，另完成一个能实际运行的评分器失败检查。 起步程序已有的条件变化帮助理解方法，但还需要你提出并实际运行一条与自己用途有关的检查；保留它支持或推翻原判断的结果。
6. **修改决定并重跑。** 记录任务与评分标准、候选实际输出来源、开发和独立数据上的分类与格式结果、失败类型及改动理由；没有运行的新提示明确列为待验证。 把说明写进 `update.md`，比较实际结果与原先预计。在课前准备的新环境或干净仓库副本中运行下面命令，确认程序不依赖旧输出；若尚未完成新环境验证，如实写出已验证到哪一步。

   ```bash
   python3 lessons/S21/analysis.py --config lessons/S21/config-trial.json --data lessons/S21/data/trial.json --output /tmp/ml-s21-recheck
   ```

   核对主要数字后，将最终结果留在仓库内，并更新 `submission.json` 的进度、运行命令和文件位置。它是提交清单；具体字段和正式结果保存办法见 [提交说明](../../docs/SUBMISSION.md)。

## 必须提交什么

- 程序、实际使用的数据或获取说明、参数与运行命令，让别人能重新得到主要结果。
- 写明用途与预计结果的 `contract.json`，以及包含主要指标和分母的程序输出。自己的结果不能只保留默认示例。
- 自己设计并实际运行的失败输入或条件变化、输出和解释；可引用单独文件，不要求固定图表数量。
- `update.md` 中的比较、与预计不同之处，以及采用、限制试用或停止使用的理由；`submission.json` 指向最终文件。

有依据地不采用模型可以完成本课。仍需提交已运行的比较、失败证据和可行的下一步，不能用“效果不好”替代分析。

## 不同起点怎么做

### 必做任务（Core）：完成所有人都要作出的关键判断

在已有响应上比较两个候选；检查内容错误与格式无效的不同后果；设计并实际运行评分或系统的失败检查；保留独立评测方法；明确证据能否支持采用；从新目录重跑。

### 入门支持（Support）：用较小的起点完成同样的判断

先用人工候选表学习计算，自己决定一次格式无效要按什么代价处理，再加入一条格式检查用例。

### 提高任务（Upgrade）：增加一种能改变判断的比较

在已有且允许使用的本地模型或服务上收集新提示的真实输出，保存模型、参数和输入来源，再检验提示改进。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一组类别或新写法再跑一次；如果缓存里没有对应输出，就先补足真实响应或换成可运行的规则方案。

### 自选拓展（Open extension）：课后探索自己提出的新问题

可以沿本课问题尝试更大数据、其他模型或已有服务。先写它比必做实验多回答什么，再报告实际资源与新增证据；未运行的能力写成待验证假设。

## 运行限制

必做响应表不超过 500 条短查询，无需 API。联网模型仅在自选拓展中使用，不能作为完成主任务的条件。 默认普通 CPU、约 8 GB 可用内存即可，课堂实验离线运行，不依赖付费 API、云 GPU 或临时下载大模型。单次目标不超过 3 分钟，从头重新运行目标不超过 5 分钟。超过预算时先缩小数据或重复次数，保留本课必须完成的比较与判断，并记录缩减影响。

所有起步数据都是教学合成数据或人工微型样例，不能当作真实机构、真实群体或实际线上效果。参数和输出接口见 [运行办法](../../docs/RUNTIME.md)。
