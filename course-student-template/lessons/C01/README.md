# C01 · 让别人重跑你的第一次预测

## 本课要解决什么问题

实验小组想用一张小表估计下一条记录的结果。负责接手的人需要知道：程序是否读对了数据，输出是否由这些数据算出，换台电脑能否得到同样的主要结果。你要选择一个用途，完成一次小预测，再写一份别人能照着运行的说明。

本课提交程序、计算结果和一段给接手者的说明。预测不准也可以完成：指出一条具体错误，解释它对所选用途意味着什么，再提出继续试验或停止使用的理由。环境出错时先保留报错和已完成的手算，修好后补跑，不必重新选题。

### 由你选择的用途与方案

可以面向需要估计一般需求的排班同学，也可以面向希望发现偏离常态记录的检查人员；还可以根据数据字典自拟用途。由你选择要预测的结果、可在使用时得到的输入，以及先用平均水平还是一条简单规则。给数据编故事不能改变字段本来的含义；示例数据只能支持教学场景。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **特征与标签（feature / label）**：分别是做预测时已知的输入和希望预测的结果，先分清两者再运行。
- **基线（baseline）**：用简单办法给出可比较的起点，判断复杂代码到底增加了什么。
- **环境与依赖（environment / dependency）**：说明程序靠哪些软件运行，让接手者能重新安装。
- **随机种子（random seed）**：让同一随机过程可以重跑；它不能保证模型一定可靠。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟看用途与数据；12—25分钟手算一次预测；25—52分钟运行与修改；52—66分钟检查错误输入；66—75分钟重跑和提交；75—90分钟做概念题、请AI解释并完成变式题。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 阅读 data/base.json 的说明和前几条记录；把你打算预测的字段与已经知道的字段分别写下。
2. 先在 update.md 写预计结果，再运行默认程序。请AI解释输出中一个数字怎样从原始记录得到。
3. 根据所选用途改 config.json 或 analysis.py，并保留你设计的错误输入及运行方法。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lessons/C01/analysis.py
```

默认结果保存为 `lessons/C01/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`missing_field` 指定用来演示缺项检查的字段；改变它应对应你关心的输入。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lessons/C01/analysis.py --output artifacts/C01-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 用一句话说明接手者想据预测做什么；选一个能从原始记录算出的评价量，并解释它为什么有用。
2. 运行起步程序，抽取一条记录，自己或让AI列出输入、真实结果和预测，核对计算。
3. 设计一条容易让这个简单办法出错的输入；解释错误是计算故障，还是办法本身的限制。
4. 在新的输出目录重跑，核对样本数和主要数值，修改第一次的使用建议。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

一份能重跑的小预测程序；支持说明的数值文件；一条手算或逐步核对的记录；一条错误输入；给接手者的使用建议。合格标准是别人能重算你的主要数字，并看懂这次错误是否妨碍所选用途，不要求预测分数漂亮。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](update.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

使用原有起步程序，只选一个输出数字完成逐步核对；可以请AI解释每一步。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

换一个合理的简单预测办法，说明两种误差对用途的不同影响。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换一小份同含义的记录，再跑一次并比较结论是否变化。

### 自选拓展（Open extension）：提出本课问题之外的新探索

自选小数据做第二个用途，但先说明一行记录和字段含义。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
