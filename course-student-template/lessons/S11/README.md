# S11 · 分成几组之后，准备怎样做

## 本课要解决什么问题

运营小组希望从没有现成类别的数据中找到便于安排工作的群组。算法总能给出几个簇，但分组可能只是单位、尺度或少数记录造成的。你要先选定分组后的行动，再判断聚类是否提供了有用信息。

请交分组方案、组内差异、稳定性检查与行动建议。找不到稳定且有用的分组时，可以建议使用连续指标或逐条处理；解释不分组的依据同样是成果。

### 由你选择的用途与方案

可以为资源分配者寻找需要不同安排的对象组，也可以为巡检人员缩小阅读范围；可自拟用途。由你选择距离所用的输入、尺度处理、簇数和分组后的不同动作。给簇取名字不能代替证明它值得用于行动。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **距离（distance）**：规定记录怎样算相近，输入单位会影响结果。
- **K均值（K-means）**：用若干中心把记录分组，偏向在所选距离下紧凑的簇。
- **特征尺度（feature scale）**：数值大的输入可能支配距离，需要与用途对应。
- **簇数（number of clusters）**：影响分组细度，应考虑可执行动作和稳定性。
- **聚类稳定性（cluster stability）**：轻微改变资料或初始化后分组是否仍相似，避免把偶然结果当自然类别。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—13分钟确定分组后动作；13—27分钟手算距离；27—51分钟比较尺度与簇数；51—66分钟稳定性与组间检查；66—75分钟建议与重跑；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 先预计哪项输入会影响距离最多，再运行默认实验。
2. 修改 config.json 的 k、standardize或scale_multiplier；每次说明该变化对应什么用途。
3. 选择一条组间记录核对距离，避免让AI仅凭簇均值给人贴标签。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lessons/S11/analysis.py
```

默认结果保存为 `lessons/S11/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`k` 控制簇数，`standardize` 控制是否缩放，`scale_multiplier` 用于检查量纲变化。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lessons/S11/analysis.py --output artifacts/S11-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 明确使用者会对不同组采取什么不同动作，选择与这些动作有关的输入和距离。
2. 比较不同尺度处理或簇数，查看每组人数、特征和组内差异，不只交低维散点图。
3. 改变初始化或少量记录检查稳定性，解释组号变化与成员变化的区别。
4. 设计一条位于组间或尺度异常的记录，检查行动是否对细小差异过于敏感；决定分组、改组或不分组。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

用途与分组后动作；两种合理方案的人数和组内特征；一次稳定性检查；组间案例及处理；是否采用分组的建议。合格标准是分组与行动有联系，不要求发现“真实类别”。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](update.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

比较原尺度与标准化后的分组，完整检查人数与一条组间记录。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

加入重复初始化或重抽样，评价成员稳定性与行动变化。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换单位或新群体再跑，说明原距离是否仍有意义。

### 自选拓展（Open extension）：提出本课问题之外的新探索

比较K均值之外的距离或分组方法，评价同一用途。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
