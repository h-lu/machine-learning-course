# S10 · 多一点性能值得多大成本

## 本课要解决什么问题

部署准备小组正在比较单树与多棵树组成的模型。运行更复杂的模型可能减少某些错误，也会增加计算、输入依赖和维护工作。你要为一个具体使用者确定值得付出的成本，并选择方案。

请提交同条件比较、实际运行开销、关键错误及替代方案。集成模型若没有足够改善，可以选择单树；若改善集中在重要记录，也可以有依据地接受更高成本。

### 由你选择的用途与方案

可以服务响应时间紧的现场终端，也可以服务可离线批量处理的分析组；可自拟用途。由你确定误差、预测耗时与输入代价怎样比较，选择模型规模和停止增加复杂度的条件。不要事先把集成模型指定为必须胜出的方案。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **装袋法（bagging）**：让不同重抽样训练的模型共同预测，主要帮助减少波动。
- **提升法（boosting）**：逐步改进已有预测，后续学习依赖前面的错误。
- **学习率（learning rate）**：控制每步改进幅度，与模型数量共同影响拟合。
- **早停（early stopping）**：根据开发资料决定何时停止增加训练，避免只追训练改善。
- **特征重要性（feature importance）**：描述模型使用输入的某种方式，不等于因果贡献或业务价值。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—12分钟确定资源预算；12—27分钟理解两类集成；27—52分钟比较性能和计时；52—66分钟检查增益来源与替代；66—75分钟采用建议；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 在 update.md 预计增加树数可能减少什么误差、增加什么开销。
2. 修改 config.json 的 n_estimators、max_depth或learning_rate，并用相同计时方式运行；记录机器与条件。
3. 核查一个所谓重要输入，如果移除它，重新训练和评价后结果如何变化。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lessons/S10/analysis.py
```

默认结果保存为 `lessons/S10/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`n_estimators` 控制树数，`max_depth` 控制单树复杂度，`learning_rate` 控制提升每步的改进幅度。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lessons/S10/analysis.py --output artifacts/S10-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 明确响应或批量处理用途，先写主指标、资源限制和哪些错误值得额外成本。
2. 在同一划分与评价方法下比较单树、装袋或提升中的合理候选，报告实际运行时间和规模。
3. 检查性能增益来自哪些记录，比较减少模型数量或少用输入后的损失。
4. 设计一个输入缺失或较难记录的测试，决定复杂模型不可用时使用什么办法；据结果选择方案。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

可重算的性能与开销比较；一项重要记录或输入成本检查；复杂方案不可用时的替代办法；采用建议。合格标准是增益和代价同时可见，不规定哪种模型应胜出。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](update.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

使用已有小模型比较，把精力放在相同计时条件和一类关键错误。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较树数与学习率，寻找继续增加规模已无实际帮助的位置。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换输入批量或少一项输入再跑，重新判断资源与效果。

### 自选拓展（Open extension）：提出本课问题之外的新探索

设计按记录难度分配简单或复杂模型的办法，并计算整体开销。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
