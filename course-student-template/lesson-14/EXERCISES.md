# 第14课｜练习

先独立作答，再查看[提示](HINTS.md)。前两部分用于理解，第三部分形成课堂作品，拓展为选做。

## 一、概念与手算

### 1. 相同输入能否靠多训练解决

两条标签相反的文本映射到完全相同的向量。

- 对固定参数的确定性分类器，两条概率能否不同？说明原因。
- 增加训练步数后，这两条概率之间能否出现差别？
- 若实际向量不同，但预测仍错误，能否断言表示没有保留信息？

### 2. 分清三种变化量

同一20条记录，原方案错6条，新方案错4条。

- 计算两次错误率、下降的百分点和相对下降比例。
- 进一步知道原有6条错误中有4条被改正，求新增错误数和两方案都错的条数。
- 仅知道总错误由6降到4，能否断言所有子组都改善，或改善具有统计显著性？

### 3. 设计能区分解释的证据

一组短信预测不理想，有两个解释：表示遗漏关键信息；分类头尚未训练充分。

- 固定表示、增加训练步数，分别可能观察到什么？
- 查看实际向量是否完全碰撞，能够支持或排除什么？
- 如果增加步数仍无改善，为什么还不能直接宣布第一种解释成立？

### 4. 冻结、定案与最终评价

- 冻结编码器与系统定案分别固定什么？
- 分类概率不变，只改门槛或容量，是否还是同一个完整系统？
- 看过最终留出后调整门槛，再换目录评价，是否恢复了独立性？

## 二、对齐真实记录

使用自己两个开发方案的输出：

1. 核对两个 `summary.json` 的数据身份、评价人数及 `partition=dev`。
2. 在两个 `records.csv` 中按ID匹配，不只按行号比较；确认标签相同。
3. 分别统计都对、原错新对、原对新错、都错四组。
4. 选择一条改正或新增的错误，追踪原文、表示、概率、阈值和容量后的行动。
5. 将变化与原先的两个解释对照，说明结果支持什么、还不能区分什么。

本课“对错”按送去复核的action与真实标签比较。讨论概率排序时应另说明评价量，不能把它与行动错误混在一起。

## 三、完成自己的诊断与定案

- 实验前写问题、两个解释、改变因素、共同设置及预期结果。
- 保存两个条件和开发结果，结合训练曲线、整体指标与具体记录判断。
- 根据dev选择完整系统，写理由后生成定案目录，核对文件指纹。
- 将目录交教师，保留首次最终评价的逐条记录与汇总。
- 在报告中分别写开发结论与最终评价，说明数据来源、成本及仍未解决的问题。
- 连续重建开发实验两次，再完成 `check` 与 `ci`。

## 四、选做

在开发资料上事先定义一个更能区分解释的子组，记录选择依据、分母和预期，再比较结果。若研究随机性，明确实际随机来源；同一确定性程序重复运行不是新的独立实验。
