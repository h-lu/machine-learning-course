# 第14课（S12）：检查失败原因，选好方案后做最后评价

## 本课要解决什么问题

同一批漏选可能有不同原因：文字变成数字时丢了信息，也可能训练还不够。为同一个失败提出两个解释，找一个能让它们产生不同预期的实验，再选好完整方案，第一次使用最终留出数据评价。

## 本课要学会什么

- 针对同一个失败写出两个可检查的解释。
- 让实验观察量能够区分这两个解释。
- 说明训练与开发结果不同，还不能确定唯一原因。
- 保存会影响预测和复核的全部设置。
- 最后评价后若再修改，承认原数据已经参与研究。

## 课堂任务

先在开发部分选定失败记录，写下两种解释以及各自预期。只改变要检验的一项，实际比较原方案与修改方案。按事先约定保存所有重复结果。依据开发结果选好方案，保存文字处理、模型参数、训练停止点、概率门槛与复核容量；随后才由教师入口做一次最终评价。

你决定优先研究哪个失败；再决定做什么实验、观察什么差别。结论可以是保留原方案，也可以是证据还分不开两种原因。 AI可帮助写代码、计算和分析；要核对关键数值，不能只交默认输出。允许自拟其他路线，只要有真实可运行材料、相同的比较条件、本课的计算追踪，并且最后评价数据没有参与方案选择。

如果没有说清实际使用能接受多少错判、错判代价多大，平均少错一些仍不足说明可以投入使用。最后评价后若据此修改，要用新的独立数据评价新版。

## 完成步骤

在学生仓库根目录运行；已有环境是Python 3.10+和NumPy。

已有第10–13课作品时继续用它，不必另起项目。下面仅提供一个可运行的TF–IDF起点，不会自动完成诊断或打开最终数据：

```bash
python3 lesson-14/analysis.py
```

结果在lesson-14/artifacts/baseline。再次运行请加`--output lesson-14/artifacts/新目录名`，保留旧结果。先用[LEARN小例](LEARN.md)检查两种解释是否真的有不同预期；完成比较后用[SUPPORT](SUPPORT.md)保存选定系统，再交教师最后评价。

阅读和实验顺序由你安排；[HINTS](HINTS.md)解决具体卡点，[EXERCISES](EXERCISES.md)检查能否换一个例子解释。

## 必须提交什么

一份作品要包含：问题与两项重要选择、一条真实记录的计算、同记录的两方案比较、失败检查、建议和限制。填写contract.json，保存报告、代码、配置和结果；把submission.json的run改为自己的命令，artifacts列齐该命令生成的结果。只运行起点尚未完成任务，不另交额外报告或AI对话日志。

沿用v2-l14-final和revision标签，[提交流程](../docs/WORKFLOW.md)与[评分](../docs/ASSESSMENT.md)不变：完成25、代表作品25、期末50，每六课取最好五次。课末A独立判断→AI学习→B换情境，按参与计分，不按正确率扣完成分。

## 不同起点怎么做

先用完整小例看懂关系，再用可选程序或自己实现的方法完成比较。较快者可在同一作品多查一个分组或设置，但不要同时改许多条件后猜原因。有证据地保留原方案也合理。

## 运行限制

短信已固定分为train（训练）、dev（开发，供比较选择）和finalholdout（最终留出）。文字处理和模型参数只从train学；dev选方法、门槛、停止点和要检查的错误组。第14课选好方案后才第一次评价finalholdout。见[数据与英文支持](../data/sms/DATA.md)。

普通CPU、约8GB内存即可，无付费服务或GPU；安装和模型缓存由教师课前准备，课堂不下载大文件。作者运行成功不等于已经通过真人课堂试教。
