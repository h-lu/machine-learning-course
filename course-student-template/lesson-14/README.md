# 第14课（S12）｜失败诊断与最终评价

第13课比较了自建表示与预训练表示。本课从一个实际失败出发，区分可能原因，依据开发证据选定系统，再进行首次最终留出评价。

## 本课要学会什么

- 区分输入表示、分类头训练与复核规则造成的失败。
- 提出两个竞争解释，设计能区分它们的观察或实验。
- 对齐同一批记录，分别查看改正的错误和新增的错误。
- 分清开发重建、系统定案和最终评价三个环节。

## 学习顺序

1. 阅读[知识讲解](LEARN.md)，先理解表示碰撞，再学习区分实验与成对比较。
2. 完成[概念与手算练习](EXERCISES.md)，用[分层提示](HINTS.md)核对。
3. 从自己的dev结果选择一个失败，写下两个解释及各自预期。
4. 按[运行帮助](SUPPORT.md)保存两个开发条件，完成记录追踪与公平比较。
5. 依据dev定案，将选定目录交教师，最后解释首次最终评价。

## 课堂任务

完成一份有证据的失败诊断与系统选择报告。

1. **找具体问题**：列出真实dev记录ID及原文，说明误选、漏选或复核成本为何值得研究。
2. **提出两个解释**：分别写出若解释成立，预计看到什么；不要只写两个模型名称。
3. **设计区分实验**：明确改变的因素，保存原、新方案配置，控制其他共同设置。
4. **核对记录与整体**：追踪一条真实计算，按ID比较两方案，报告改正与新增的错误及整体指标。
5. **作出选择**：说明采用新方案、保留原方案或暂缓的理由，保存完整系统。
6. **解释最终评价**：使用教师返回的首次评价，报告结果，并说明对哪些短信和使用条件有效，不据此回头调参后仍称独立检验。

问题、实验因素与系统选择由自己决定，至少包含两项影响结论的自主选择。可以沿用第13课结果，不要求再换一次模型，也不要求新方案必须更好。AI可辅助计算与写作，无需提交对话日志。

## 数据与运行

train3877条用于训练，dev807条用于开发。原文、ID及划分保持一致；最终留出由教师评价。若需要新起点，在仓库根目录运行：

```sh
python3 lesson-14/analysis.py
```

默认使用TF–IDF，结果在 `lesson-14/artifacts/baseline/`。预训练表示的缓存、本地模型和依赖沿用第13课。

## 成果与提交

- [报告](report.md)：问题与预期、真实追踪、成对比较、选择理由、首次最终评价及限制。
- `contract.json`：事先的实验计划；自己的配置及可重复运行脚本。
- 开发产物、选定系统目录、教师最终评价文件，分别保存并说明来源。
- `submission.json`：登记开发重建命令和对应产物，完成后设为 `complete`。

```sh
python3 scripts/course_l1314.py check 14
python3 scripts/course_l1314.py ci 14
```

标签沿用 `v2-l14-final`，评分要求不变。日常重建只计算开发实验，不反复定案或调用最终留出。课堂选择题按教师开放场次完成。
