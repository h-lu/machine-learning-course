# 第 14 课（S12）：下一项实验应该改数据、表示还是训练方法

## 本课要解决什么问题

**先打开 [入门支持](SUPPORT.md)，写出两种失败解释，再运行一项只改一个因素的实验。** 你已经比较过模型复杂度、提醒办法、数据表示、训练设置和借来表示。本课不再追求多跑模型，而是判断当前作品为什么不够好，以及下一项实验最该改什么。

给定起点使用扩展表示训练 80 轮。你可以检验训练轮数不足、复杂表示过拟合，或正则化不足等解释。程序会同时报告训练集与验证集损失。一次实验只能直接支持或削弱与所改因素相关的解释。你要提交两个失败假设、训练与验证证据、一次控制变量实验和下一步建议。运行失败时保留命令与报错，先用支持页给出的曲线数值继续判断，修复后补跑。

## 本课要学会什么

| 标准术语 | 学完后的表现 |
|---|---|
| 欠拟合 | 识别模型连训练数据中的关系也没有充分学到的迹象 |
| 过拟合 | 识别训练表现继续改善、验证表现却不再改善的迹象 |
| 失败假设 | 为同一现象提出至少两个可区分的原因 |
| 控制变量实验 | 一次只改表示、训练轮数或正则化强度中的一个因素 |
| 泛化诊断 | 根据训练和验证证据决定下一步，而不是把随机波动写成原因 |

先读 [LEARN.md](LEARN.md) 的欠拟合、过拟合与控制变量例子；陌生词再查 [术语表](../docs/TERMINOLOGY.md)。

## 90 分钟安排

0–15 分钟回顾 S09–S11 的证据；15–30 分钟写两个失败假设并运行起点；30–50 分钟完成一个诊断实验；50–65 分钟解释训练与验证差异；65–75 分钟形成下一步建议和提交；75–90 分钟概念检查。

## 完成步骤

### 1. 先写假设，再看结果

在 `report.md` 写至少两种解释，例如“训练轮数不够”和“扩展表示使模型过度适应少量训练记录”。说明哪种结果会更支持每个解释。然后在仓库根目录运行：

```bash
python scripts/course.py start 14
python lesson-14/analysis.py --config lesson-14/config-start.json --output lesson-14/artifacts/start
```

先看 `comparison.csv` 的训练和验证对数损失，再看 `learning_curve.csv`。起点与候选使用同一批数据；候选只把训练轮数从 80 增至 320。

### 2. 用数值判断，而不是给曲线贴标签

计算两种方法的“验证损失减训练损失”。这个差值不是统一的过拟合分数，但能帮助描述训练与验证是否朝不同方向变化。若训练损失下降、验证损失上升，更长训练并没有改善未见数据；这会削弱“只是轮数不够”的解释。

### 3. 选择另一个单因素实验

复制 `config-start.json` 为 `config-mine.json`，只把 `diagnostic_change` 改成以下一项：

- `more_epochs`：只增加训练轮数；
- `stronger_regularization`：只增加正则化强度，限制参数；
- `simpler_representation`：只去掉平方项和交互项。

先写预计，再运行：

```bash
python -m json.tool lesson-14/config-mine.json
python lesson-14/analysis.py --config lesson-14/config-mine.json --output lesson-14/artifacts/mine
```

比较训练损失、验证损失和验证准确率。小验证集只有 12 条；一条记录就会让准确率变化约 8.3 个百分点，因此不能把小幅变化直接归因于修改。

### 4. 决定下一步并最后评价

结合前几课报告，选择“补充更有代表性的数据”“修改表示”或“修改训练方法”中的一项，说明当前实验为什么支持这个优先级。先在验证集确定采用起点还是候选，再把同样配置的 `evaluation_split` 改为 `test`，运行 `python scripts/course.py run 14`。

测试结果用于评价事先确定的方案，不用于继续挑选。若结果不支持候选，可以有依据地保留原方案或暂停部署。

### 5. 完成提交检查

填完任务说明与报告，将状态标为 `complete`，运行 `python scripts/course.py check 14`。报告引用 S09、S10 或 S11 至少一项已有证据，并说明本程序没有自动读取个人旧文件；引用路径和结论由你核对。

## 必须提交什么

提交程序、最终和个人配置、任务说明、报告，以及 `summary.json`、`comparison.csv`、`learning_curve.csv`、`records.csv`。报告包括两个失败假设、预计结果、实际训练/验证证据、一次差值计算、被削弱的解释、下一步优先级、测试结果和仍不确定的部分。

## 不同起点怎么做

### 入门支持（Support）：按现成对照区分两个原因

[SUPPORT.md](SUPPORT.md) 用“只增加训练轮数”演示如何检验解释。完成后再选一个自己的诊断设置。

### 必做任务（Core）：用一次控制变量实验决定下一步

提出两个原因，运行一个能区分它们的实验，同时查看训练与验证，并据此选择下一步。

### 提高任务（Upgrade）：形成小型实验矩阵

分别运行三种 `diagnostic_change`，但每次仍只改一个因素。比较它们分别回答什么，不能把三项合并后只给一个原因。

### 换数据重测（Transfer）：检查样本波动

在保持方法不变时更换一个预先规定的数据划分，观察建议是否稳定。不要反复换划分直到出现喜欢的结论。

### 自选拓展（Open extension）：设计新的证据

提出一项收集数据或标注复核计划，说明它能区分哪两个原因、需要什么字段以及何时停止实验。

## 运行限制

Python 3.10 以上与 NumPy；48 条人工记录，单次不足 1 秒。小数据适合练习诊断关系，不足以支持真实部署。所有必做实验离线；在线概念检查另按课堂安排。
