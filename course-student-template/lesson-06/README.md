# S04 · 预测错多少，要看结果用来做什么

## 本课要解决什么问题

同一份需求预测要交给两位使用者：排班人员关心整体偏差，备料人员尤其担心少估造成短缺。你要选择一个用途，比较预测办法，并把误差换成使用者能够理解的后果。

请交预测结果、误差与后果的计算，以及采用建议。如果任何办法都达不到所需条件，保留失败结果，建议增加余量、限制用途或先不使用。

### 由你选择的用途与方案

可以服务一般需求估计、避免短缺或控制积压，也可自拟用途。由你选择主指标、低估与高估的后果、需要单独看的记录组和候选办法。成本数值若是你提出的假设，必须注明并检查变化后的结论。

本课随附数据是教学合成数据。先读[字段和生成说明](data/DATA.md)，再查看[原始记录](data/base.json)；示例中的使用者帮助比较用途，不代表真实机构的业务。你可以全程让AI编写代码、计算和起草文字；不需提交完整对话。提交前要核对数字及其支持的建议。

## 本课要学会什么

- **平均绝对误差（MAE）**：按原单位汇总偏离多少，便于说明常见规模。
- **均方根误差（RMSE）**：对大误差更敏感，帮助关注少数严重偏离。
- **残差（residual）**：真实结果减预测值，用方向追查系统低估或高估。
- **非对称损失（asymmetric loss）**：低估与高估带来不同后果时，不把两者当作同样错误。
- **分位数预测（quantile prediction）**：预测分布的某个位置，可服务对低估容忍度不同的用途。

[学习材料](LEARN.md)用一个小例子解释这些概念。它们应帮助你选择和检查方案，不能只出现在报告的术语表里。

## 90 分钟安排

0—13分钟讨论错误后果；13—27分钟手算两种误差；27—52分钟比较预测；52—66分钟改变成本或分组；66—75分钟建议与重跑；75—90分钟概念题与变式。

遇到实现困难，可以让AI提供更完整的代码，也可以复用现有程序。优先减少重复操作与排版时间，保留比较与判断。

## 完成步骤

1. 先在 report.md 写预计哪种办法会少估、什么错误更麻烦，再填写任务说明。
2. 运行实验；从输出中抽取一对真实值和预测值，核对残差与所选损失的计算。
3. 修改 config.json 中已有候选设置或程序中的损失计算，使比较回答你的用途。

### 运行与修改

从学生仓库根目录运行：

```bash
python3 lesson-06/analysis.py
```

默认结果保存为 `lesson-06/artifacts/summary.json`。打开[配置文件](config.json)与[程序](analysis.py)，结合数据说明修改：`underestimate_cost` 是低估代价假设，`prediction_shift` 是预测整体调整量；要说明改变它们的依据。 默认设置仅用于开始实验，不是评分答案。需要其他模型、指标或输出时，可以替换程序，写清依赖和运行命令。

在新的输出目录再运行一次，便于比较两次结果：

```bash
python3 lesson-06/analysis.py --output artifacts/S04-demo
```

`--output` 后面是目录。报告中引用实际生成的数值，写清两次运行各用了什么设置。设计的错误输入可保存在本课目录，写明如何通过程序检查；保留原始数据副本；另存你设计的输入，说明改了哪里和为什么。

### 必做任务（Core）：把本课问题回答完整

1. 选择使用者，先写出主要误差怎样影响行动，并说明评价量和接受标准。
2. 在同一批记录上比较至少一条简单基线和一个候选办法；同时查看误差方向与严重偏离，不能只抄主指标。
3. 选一个与用途相关的分组或成本变化，实际检查原先选择是否仍合适。
4. 设计一条容易低估或高估的输入，据此解释何时增加余量、人工处理或停止使用。

完成比较后，按[仓库首页](../../README.md)的环境说明在干净环境从原始数据重新运行，核对主要数值，保存实际输出。程序不能运行时记录命令、报错和已核对部分，修复后补跑；不要把估计的数字写成运行结果。

## 必须提交什么

同一批记录上的预测比较；可以核算的主指标和误差后果；一个分组或成本敏感性检查；一条错误输入；修改后的行动建议。合格标准是指标选择与用途一致，允许不同同学选不同办法。

- [任务说明](contract.json)：用已有字段写清问题、使用者、数据、指标、划分办法和最初预计；数据不需要划分时说明原因。
- [预计与结论](report.md)：先保留预计，再写实际选择、关键结果、错误案例、修改或保留的建议。可以按自己的问题组织，引用程序产生的文件。
- 程序、配置、支持结论的结果文件，以及[提交说明](submission.json)。若更换运行入口或结果路径，同步修改提交说明；完成后把 `status` 改成 `complete`。

自动检查可以帮助发现文件、字段或路径问题。方案是否合适仍要看本课的比较与解释，检查通过不替代这些判断。

## 不同起点怎么做

### 入门支持（Support）：借助现成工具完成同一个问题

用现有预测结果完成损失重算，重点在选择指标、核对方向和解释用途。

### 必做任务（Core）：完成上面的比较、检查和建议

所有人都要完成“完成步骤”中的四项判断，并交出“必须提交什么”中的具体成果。选择简单办法或有依据地暂不使用，都可以完成主任务。

### 提高任务（Upgrade）：对重要选择多做一次有用的检查

比较分位数预测或预测余量，说明增加保守性付出什么。

### 换数据重测（Transfer）：换一份数据或场景再跑一次

换成需求构成不同的一批记录，检查同一成本下的建议。

### 自选拓展（Open extension）：提出本课问题之外的新探索

自拟库存、时间或能耗用途，说明损失单位与假设。

## 运行限制

随课示例包含 180 条记录，数据文件约 39.6 KB。自带数据时先取能说明问题的小样本，建议不超过 100 MB，再按下面的时间目标控制实验规模。

必做部分使用本地数据、普通CPU和约8 GB可用内存，不需要GPU、网络下载或付费API。保留小数据和小模型；单次运行目标不超过3分钟，从原始数据重新运行目标不超过5分钟。新增依赖写入环境说明，课前准备好离线安装材料。更多数据、更大模型或联网服务可用于自选拓展，但必须有能离线完成必做判断的版本。

时间和资源要求是课程设计目标，真实耗时以你的记录为准。超出限制时先减少无关搜索、重复运行或模型规模，保留关键比较；不要省略需要解释的错误。
