# 第06课（S04）｜怎样评价预测与有限提醒

## 从哪里开始

平均误差较小，是否就能选出更有用的提醒？先在[学习页](LEARN.md)用四条记录算误差，再给提醒加上名额限制，看哪些真正需要关注的小时被漏掉。回到项目后，由你说明错误的后果和名额的依据。

本页说明正式项目要完成什么；[学习页](LEARN.md)讲概念和手算，[操作支持](SUPPORT.md)帮助读取数据、运行和保存结果。已完成的作业与评分仍按原安排。

## 本课要解决什么问题

同样大小的误差，可能带来不同后果。例如，低估高需求可能导致准备不足；发出过多提醒，又可能超出处理能力。本课要把“预测偏离多少”与“最后提醒了谁”分开检查。

你将沿用或修改前课预测，为使用者选择评价指标与提醒规则。在相同记录上比较两种合理方案，算清误报、漏报和名额限制怎样影响结果，再提出使用建议。

## 本课要学会什么

能按用途选择评价指标，说明不同错误的后果；能从预测和名额算出最终名单，再用正确的分母计算四格表中的比例。

[学习页](LEARN.md)提供完整手算例子；它们用于理解，正式任务仍使用你选定的数据与方案。

## 课堂任务

完成一份预测评价与提醒建议。至少自主决定两项，例如主要指标、低估的权重、提醒阈值、每日名额、排序方式或需要单独检查的记录组，并解释理由。

AI可以协助实现；你需要核对具体记录，并说明为什么这样选择、结果支持什么。

**基本任务**：用小例解释核心关系并使自己的程序实际读取数据。

**标准任务**：构建自己的预测与评价/容量规则，留一条真实样本的完整误差和一个同日批次的排序核算。用同记录比较合理替代指标或提醒条件，不规定人人采用300阈值/4名额。

**提高任务**：以另一种低估或误报带来的后果或通勤时段的记录子集重新评价，也可以依据结果保留原规则。本课用`workingday=1`且`hr`为7、8、9、16、17、18、19的记录作为通勤时段；这只是分析范围，不代表知道每个租赁者的通勤身份。 三类任务围绕同一件作品。使用支持材料不影响评价；不要求人人做完所有扩展或重复交三个作品。

## 完成步骤

1. **规定评价问题**：选择主要指标、低估惩罚、实际高需求标准、提醒阈值和每日容量，说明至少两项选择的理由。实际标准定义要找的事件，提醒阈值控制什么时候发提醒，二者可以不同。
2. **固定训练与评价记录**：沿用前课模型或实现一个基线，只用训练标签拟合，再保存同一验证集上的预测。默认起点不自动完成提醒排序。
3. **从误差到损失**：计算有符号误差、绝对误差和所选惩罚；抽一条真实记录逐项复算。低估误差乘权重后仍按参与评价的记录总数取平均。
4. **从候选到最终名单**：先按预测阈值形成候选，再按事先确定的排序与并列规则使用每日名额。选一天核对候选数、最终提醒数和容量。
5. **按最终行为评价**：保存 TP、FP、FN、TN、查准率与召回率；分母为零时标为未定义。比较提醒阈值时固定实际高需求标准，不同时改变事件定义。
6. **比较并建议**：保持模型不变比较容量，或保持提醒阈值、容量和排序不变比较模型。报告总体与重点记录组结果，说明采用或保留原方案的理由。这是同日完整预测后的离线比较，不等同于实时部署效果。

可参考[第3课的独立阈值核算示例](../lesson-03/SUPPORT.md)。第6课还要先执行每日容量筛选，再以最终名单计数。共享可选工具把提醒阈值同时用于实际高需求判断；若只研究提醒门槛，应在自己的评价代码中分开这两个参数。

## 必须提交什么

提交自己的分析程序、配置/任务说明、实际结果与报告；报告格式可改，但问题/用途、数据来源、至少两个重要选择、公平比较、失败检查、核算和适用限制不能省。保留原方案与比较试验，见[练习资源](EXERCISES.md)。

默认的`submission.json`只列出起点结果，**运行起点代码不等于完成项目**。完成自己的分析后，把结果文件路径写入`artifacts`，替换或补充原清单；把`run`改成实际能够重新生成这些文件的命令。

完成研究后，才把`status`改为`complete`。在学生仓库根目录运行`python3 scripts/course.py check 06`及`python3 scripts/course.py ci`。CI（自动检查）会重新运行命令，核对清单中结果文件的内容是否一致；它不判断结论是否正确。未列入清单的比较试验须另存重跑命令。

保留原来的提交标签。是否需要提交复习后的修订版，按教师通知执行。

## 不同起点怎么做

概念不清楚时，先看LEARN中的手算过程；程序或结果看不懂时，查SUPPORT对应问题，也可以看[提示页](HINTS.md)。先完成基础理解和标准任务，再选与自己作品有关的扩展。可以自行选择题目、数据、方法和呈现形式，但要回答本课核心问题并提供依据；不因模型更多、代码更长或AI对话更多而加分。

## 运行限制

使用已准备的Python与NumPy，命令示例为本机`python3`；你原环境若使用`python`或`py`，统一用已经成功的启动命令，不安装新环境。默认起点从学生仓库根目录的`data/bike/hour.csv`离线读取数据，只准备文件检查和样本预览，不能作为正式分析已完成证据。AI可帮助提出问题、写代码、核算和解释，不要求提交提示词记录、不要求所有人同路线或强制逐人答辩。

遇到数据或软件报错，保存执行的命令、当前目录和完整报错。可以先继续手算学习页例子，并在报告中写明程序尚未成功运行，排查后再补跑。用`--output`指定的目录若已存在，程序会拒绝覆盖；请换新目录保留旧结果。不指定`--output`时，默认的`artifacts/starter`允许重新生成。正式程序和输出由你决定；`submission.json`中的`run`必须能重新生成`artifacts`列出的分析结果。未列入清单的比较试验，另存配置和重跑命令。

误差单位为次租赁/小时。默认起点没有提醒排行或模型答案；学生可沿用前课作品，自选均值起点只是最小资源。 数据来源、字段/时间边界和许可见[data/DATA](data/DATA.md)。程序可在普通CPU上离线运行；课堂选择题和AI访问按教师安排。遇到资源无法使用的情况，请保留说明并向教师反馈。
