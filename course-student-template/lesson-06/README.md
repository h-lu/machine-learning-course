# 第 06 课（S04）：怎样评价等待时间预测与有限提醒

## 本课要解决什么问题

假设取餐窗口想提供两种服务：向同学显示预计等待时间，以及在值班人员每轮只能查看少数记录时，优先提醒可能等得很久的同学。同一个“预计等几分钟”会用于两种不同决定。低估（预测比实际少）可能耽误同学的安排，高估（预测比实际多）可能让同学放弃排队；发出错误提醒和漏掉真正长等的记录也各有代价。

本课使用 24 条人工编写的排队记录：12 条训练集记录用于确定模型参数，6 条验证集记录不参与训练、用于比较候选方案；另 6 条测试集记录要等方案确定后再用。程序给出本课的均值基线、线性回归模型，以及“在线性回归预测上加 4 分钟”的对照方案。它们是本课提供的起点，**没有读取或重跑你在第 05 课保存的模型**。为了练习有限名额怎样影响决定，我们暂把 6 条验证记录当作同一轮的候选；真实现场不一定如此。

你要先说明两种用途及可能的错误后果，再运行程序、核对一条记录、改变一次评价权重，并自己选择另一种提醒容量。最后分别给“显示分钟数”和“有限提醒”提出有证据的建议。提交报告、任务说明、配置和实际生成的结果；运行失败时保留命令与完整报错，按 [第一次运行指南](../docs/FIRST_RUN.md) 排查，修复后补跑。**第一次做可以直接按 [入门支持](SUPPORT.md) 逐步完成同一必做任务**，不需要另做一份作业。

## 本课要学会什么

| 标准术语 | 本课怎样理解和使用 |
|---|---|
| 平均绝对误差（MAE） | 每条预测与实际相差的分钟数取绝对值，再除以记录数；能核对整体偏差大小，不能区分高估与低估 |
| 非对称损失 | 给低估和高估的绝对误差不同权重；权重表达使用假设，不是已经测得的真实损失 |
| 二分类评价、误报与漏报 | 把“实际等待至少 8 分钟”定义为需要提醒的正类，再比较实际结果与提醒决定 |
| 决策阈值 | 预测至少达到多少分钟才进入提醒候选；本课默认是 8 分钟，不是概率 |
| 容量约束 | 一轮最多能处理几条候选；达到阈值不等于一定收到提醒 |

[LEARN.md](LEARN.md) 用小表解释这些关系，[数据说明](data/DATA.md) 解释文件和字段。遇到陌生词时先看本课解释，再按需查 [术语表](../docs/TERMINOLOGY.md)。

## 90 分钟安排

0–15 分钟：说明两个用途，先预计高估、低估和错误提醒的后果；15–30 分钟：运行起点，核对一条预测和比较表；30–48 分钟：只改变低估权重，判断方案排序为什么变；48–65 分钟：只改变提醒容量，先预计再核对实际提醒编号；65–75 分钟：分别写两条建议及其代价；75–90 分钟：完成 A 版、AI 学习、B 版概念检查并提交。

到第 30 分钟仍不能运行时，先按 [入门支持](SUPPORT.md) 手算一条记录，记录“尚未运行”和报错，请教师协助修复后补跑。手算不能当作程序结果。

## 完成步骤

### 1. 先写用途，再运行本课起点

在 `report.md` 写下：谁会看预计分钟数，谁会处理提醒？如果预测偏低、偏高或提醒错了，各会怎样？低估权重 3、每轮最多 2 条提醒都是本课的**假设设置**，不是从这些数据测得的现实成本。运行前先预计哪种方案更适合哪种用途，以及什么结果会使你改变看法。

以下命令在学生仓库**根目录**执行，也就是同时看得见 `scripts/` 和 `lesson-06/` 的目录。电脑只有 `python3` 时，把命令中的 `python` 换成 `python3`。

```bash
python scripts/course.py start 06
python lesson-06/analysis.py --config lesson-06/config-start.json --output lesson-06/artifacts/support-start
```

程序读取 `lesson-06/data/base.json` 中的人工数据和 `config-start.json` 中的设置，写出 `comparison.csv`（每个方案一行）、`records.csv`（每条记录在各方案下的预测）和 `summary.json`。成功后先打开 `lesson-06/artifacts/support-start/records.csv`，找 `id=B05` 且 `method=linear` 的一行；具体字段和核对数值见 [入门支持](SUPPORT.md)。

### 2. 核对误差，再只改变评价权重

B05 实际等了 8 分钟，线性回归预测约 6.333 分钟，因此低估约 1.667 分钟。低估权重为 3 时，这条记录的加权误差约为 5。再从 `records.csv` 找一条高估记录手算。到 `comparison.csv` 核对 `method`、样本数 `n=6`、MAE 和平均加权误差 `asymmetric_loss`；这两个指标可能把方案排成不同顺序。

`config-support.json` 是已经准备好的对照，只把低估权重从 3 改成 1。两次使用同一批预测，结果保存到不同目录，不能把预测改变误写成权重改变。

```bash
python lesson-06/analysis.py --config lesson-06/config-support.json --output lesson-06/artifacts/support-compare
```

并排比较两份 `comparison.csv`：哪些分数变了？哪些预测、提醒数和误报漏报没有变？在报告中结合用途回答，不能只写“分数更小”。

### 3. 自己选择一种提醒容量

本课把“实际等待至少 8 分钟”和“预测至少 8 分钟”分开：前者用于事后判断提醒是否正确，后者只决定当时谁进入候选名单。候选多于名额时，程序按预测分钟数从高到低选；预测相同按编号排序，**不会用实际等待时间挑人**。

从 `config-start.json` 在编辑器中“另存为” `lesson-06/config-mine.json`，只改 `capacity`：选 `1` 表示一轮只能处理 1 条，或选 `4` 表示一轮最多处理 4 条。先写你预计漏报或误报怎样变化、什么结果会改变你的建议；保持权重、阈值和数据不变。JSON 中的英文双引号、逗号、冒号不能删，文件名不要多出 `.txt`。

```bash
python -m json.tool lesson-06/config-mine.json
python lesson-06/analysis.py --config lesson-06/config-mine.json --output lesson-06/artifacts/my-check
```

在新的 `comparison.csv` 逐个核对 `linear` 和 `buffered` 的候选数 `eligible`、实际提醒数 `alerts`、`tp/fp/fn/tn`；在 `records.csv` 列出 `alert=True` 的编号。四类计数之和应为 6，提醒数不能超过容量。`tp/fp/fn/tn` 的中文意思和逐条读法见 [LEARN.md](LEARN.md)。

### 4. 给两个用途分别下结论

本课只用验证集比较，不提前打开测试集。你可以保留线性回归、采用加 4 分钟的候选方案，也可以因证据不足而限制或暂停提醒；两种用途不必选同一个方案。每条建议要说明一项支持证据、一项代价和仍缺少什么现实信息。

把最终要保留的设置写回 `config.json`，再运行下面的主结果命令。它生成 `lesson-06/artifacts/` 下的正式结果；之前的起点、权重对照和个人容量结果仍要保留，不能覆盖。

```bash
python scripts/course.py run 06
```

### 5. 检查并提交

把 `report.md` 的提示替换成自己的回答，在 `contract.json` 填写任务说明。完成实际工作后把 `submission.json` 中的 `status` 改为 `complete`，不要修改课号。运行：

```bash
python scripts/course.py check 06
```

检查通过只说明文件齐全，不等于分析正确，也不等于已经上传。`artifacts/` 默认被 Git 忽略；提交前按 [操作与提交步骤](../docs/WORKFLOW.md) 显式加入报告引用的结果，并检查暂存文件列表。

## 必须提交什么

提交本课程序、`config.json`、你使用的配置副本、实际生成的 `summary.json`、`comparison.csv`、`records.csv`、`contract.json`、`report.md` 和 `submission.json`。报告引用的起点、权重对照及个人容量结果也要保留。报告要能回答：两种用途分别需要什么；B05 和一条高估记录怎样手算；权重从 3 变成 1 为什么只改变评价；你选的容量改变了哪些提醒编号、误报和漏报；最后两条建议各有什么依据与代价。

## 不同起点怎么做

### 入门支持（Support）：沿一条完整路径完成必做任务

按 [SUPPORT.md](SUPPORT.md) 使用准备好的 `config-start.json` 和 `config-support.json`。你仍要自己决定容量、先写预计、核对结果并解释选择。使用支持材料或 AI 帮忙理解命令，不会降低任务的完成标准。

### 必做任务（Core）：所有路径都要完成

明确两个用途，运行并核对一条低估和一条高估；比较低估权重 3 与 1；只改容量 1 或 4 做个人检查；分别给显示分钟数和有限提醒写有证据的建议。完成入门路径后，无需重复做一次 Core。

### 提高任务（Upgrade）：有余力再比较

固定真实长等待定义和预测，依次试容量 0–6，记录提醒数、误报和漏报。再单独改变预测提醒阈值，观察“谁进入候选”和“最终提醒谁”分别怎样变化；每次只改一个条件，不能用事后真实结果排序。

### 换数据重测（Transfer）：换一种真实问题

例如把“每轮最多复核几条”用于客服请求。重新定义要找出的正类、数据单位、预测阈值和容量；修改数据与程序并重新运行，不是只改名称。

### 自选拓展（Open extension）：估计实际后果

调查低估、高估和错误提醒在真实场景中的后果，再与本课假设权重比较。以上选做任务不替代必做任务。

## 运行限制

需要 Python 3.10 以上及已安装的 NumPy；本课使用 24 条人工教学样本，普通 CPU 和约 8 GB 可用内存即可。单次运行目标不超过 3 分钟，从头重跑目标不超过 5 分钟。必做实验离线运行，不调用付费模型；AI 学习和在线概念检查的接入或补做按教师安排。人工数据只能说明本课的评价与决策机制，不能证明真实人群的等待情况或提醒效果。
