# S04 实验报告

把下面提示替换成自己的回答。保留运行前的预计和改变建议的条件，再写实际结果；不要拿给定核对数字冒充自己的程序运行。

## 1. 两个使用问题、后果与运行前预计

分别说明“向同学显示预计分钟数”和“值班人员每轮只能处理少数记录时，优先查看哪些可能长等的记录”由谁使用、用来做什么。低估和高估各会带来什么后果？默认低估权重 3、容量 2 是现实测量还是用途假设？你预计原回归与缓冲方案分别适合哪一种问题？什么结果会使你改变建议？

## 2. 逐条计算与同条件比较

从同一份 `records.csv` 选择一条低估和一条高估，分别写出绝对误差与加权误差的算式。再列出 linear、buffered 的 MAE 和低估权重为 3 时的非对称损失，写清单位、6 条样本的分母及结果路径。缓冲方案改变了什么，没有改变什么？

## 3. 改变评价权重后，建议为什么可能改变

比较低估权重为 3 和 1 的结果。填写 linear、buffered 在两种权重下的非对称损失，并说明预测值、MAE、提醒数和四类计数哪些保持不变。结合第 1 节的使用后果，解释你是否改变对两个方案的建议；不能只写“分数变小”。

## 4. 我的容量选择与实际提醒编号

写下你为什么把容量改为 1 或 4，以及运行前预计。分别列出 linear、buffered 的 `alerts`、`eligible`、`tp/fp/fn/tn` 和实际提醒编号，核对四类计数之和为 6、提醒数不超过容量。实际结果是否触发第 1 节写的改变条件？引用个人配置、结果文件和完整命令。

## 5. 两条建议、支持证据和代价

分别回答：若只显示预计分钟数，你保留什么方案，证据和主要偏差是什么；若按你的容量执行提醒，你保留什么方案，接受多少误报或漏报？每条建议至少写一项支持证据和一项代价。最后说明权重、容量和人工小数据还不能证明什么，以及下一步最需要补哪项现实证据。
