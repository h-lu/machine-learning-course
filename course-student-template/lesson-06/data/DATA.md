# 第 06 课数据、配置与结果怎样读

## 数据从哪里来，一行代表什么

`lesson-06/data/base.json` 是课程人工编写的数据，不是某个食堂的真实调查。JSON 是用“字段名：值”保存数据的文本格式；顶层 `rows` 是 24 条历史排队记录的列表。**一条记录代表某个虚构窗口在某一天的一次排队观察**，不表示同一天的所有人，也不表示验证集的 6 条真实地同时出现。程序仅把它们当作一个假想批次来练习有限提醒。

24 条记录已经标好用途：`split=train` 的 12 条用于拟合给定模型，`validation` 的 6 条用于本课比较，`test` 的 6 条留到方案确定后再评价。本课默认只读取验证集作为评价对象；不要把测试集改成挑方案的数据。

| 原始字段 | 这列是什么 | 本课怎么用 |
|---|---|---|
| `id` | 记录编号，例如 `B05` | 找到同一条记录；不是模型输入 |
| `queue_length` | 加入队伍时前面有多少人，单位是人 | 本课线性回归模型的唯一预测特征 |
| `wait_minutes` | 事后记录的实际等待时间，单位是分钟 | 要预测的标签；在评价时核对，不能提前用于提醒排序 |
| `period` | 午间或晚间 | 查看分组结果；不是本课模型输入 |
| `site` | 虚构窗口 A、B、C | 标识窗口；不是本课模型输入 |
| `day` | 第几天 | 说明记录的日期顺序；不是本课模型输入 |
| `staff_count` | 这条记录中的工作人员数 | 仅描述情境；不是本课模型输入 |
| `weather` | 人工设定的天气 | 仅描述情境；不是本课模型输入 |
| `event_flag` | 当天是否设定有活动，`true` 为是、`false` 为否 | 仅描述情境；不是本课模型输入 |
| `split` | `train`、`validation` 或 `test` | 决定记录用于拟合、比较还是保留评价 |

人数为非负整数，等待时间为非负分钟数。`source.type=synthetic` 说明这是人工教学数据；不能据此推断真实用户的等待分布或提醒成效。

## 配置文件里的设置

`config-start.json` 是不能覆盖的入门起点；`config-support.json` 只把低估权重从 3 改为 1；`config.json` 是完成本课后主结果使用的设置。个人容量检查先从起点“另存为” `config-mine.json`，只改 `capacity`。每次对比使用独立输出目录，防止旧文件冒充新结果。

| 配置字段 | 含义和默认值 |
|---|---|
| `seed` | 随机步骤的固定起点，默认 7；本课按既定划分运行，没有随机步骤，改它不会改变本课结果 |
| `evaluation_split` | 本次评价读取哪一组记录，默认 `validation`；本课不要改成 `test` 来挑方案 |
| `primary_model` | 在 `summary.json` 中重点汇总哪种方法，默认 `linear`；它不是自动推荐 |
| `buffer_minutes` | 给 `linear` 的每个预测加多少分钟，默认 4；不重新拟合模型 |
| `underestimate_weight` | 低估的绝对误差乘多少，默认 3；高估乘 1，是评价假设而非测得的现实成本 |
| `long_wait_minutes` | **事后真实类别**的界限：实际等待至少 8 分钟算需要提醒的正类 |
| `alert_threshold` | **当时进入候选**的界限：预测至少 8 分钟才进入提醒候选；单位是分钟，不是概率 |
| `capacity` | 一轮最多发出多少条提醒，默认 2；个人检查只改这一项 |
| `stress_capacity` | `summary.json` 的附加容量检查所用值，默认 1；它不改变主比较的 `capacity` |

`capacity` 与 `stress_capacity` 是两项不同设置。首次做个人检查时只改 `capacity`，避免看错结果。未知字段或不合适的数值会触发程序报错，不要用整份其他课配置覆盖本课文件。

## 成功运行后先打开哪份文件

程序在 `--output` 指定的目录写出三份结果。`records.csv` 是**逐条表**：同一 `id` 会因 `baseline`、`linear`、`buffered` 三种方法各出现一次，不是三条独立记录。先找 `id=B05` 且 `method=linear`；`actual` 是真实分钟数，`prediction` 是预测分钟数，`absolute_error` 是两者之差的绝对值。`weighted_error` 是这条记录按低估权重算出的分数；`long_wait` 是事后真实类别，`alert` 是按预测和容量实际发出的提醒。

`comparison.csv` 是**方法汇总表**，一行一种方法。`method_name` 是中文名称；`n` 是这一行评价使用的记录数，本课默认应为 6；`mae` 是 6 条绝对误差的平均，单位分钟。`asymmetric_loss` 是 6 条 `weighted_error` 的平均加权误差分数，不是现实中真的损失了多少分钟。`eligible` 是达到**预测阈值**的候选数，`alerts` 是容量限制后的实际提醒数。`tp/fp/fn/tn` 依次为正确提醒、误报、漏报、正确不提醒，四类计数之和应为 6。`rmse` 是另一种误差指标，本课必做任务暂时不需要用它排序方案。

`summary.json` 保存配置、输入和程序的摘要，以及完整的比较结果。里面的 `metrics` 只重复 `primary_model` 指定方法的汇总，`comparison` 包含各方法，`stress_test` 只把容量临时换为 `stress_capacity` 以供附加检查。JSON 的 `null` 或 CSV 的空白单元格表示没有可用数值，不要自行写成 0。摘要哈希可以帮助发现文件变化，不能证明数据真实或结论正确。

运行失败后，旧输出目录可能仍有文件；它们不能作为这次成功的证据。修好后换一个新目录运行，看到终端的“结果写入”，再打开该目录下的文件。程序不会自动把 `submission.json` 改成已完成状态。
