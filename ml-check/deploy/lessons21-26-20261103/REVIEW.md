# 第21—26课题库审阅版

六课各有五个概念、五对 A/B 迁移题，共60题；内部 ID S19—S24 与教材第21—26课一一对应。题目使用青禾图书馆案例，检查流程契约、工具调用、反馈循环、权限、失败诊断和人机分工。

## S19 怎样设计一个协作流程

- **S19-01 输入输出契约**：让每一步写清输入、输出字段和缺失处理，避免相邻步骤误读同一值。
- **S19-02 步骤依赖**：按依赖安排步骤，后一步只使用前一步已经交出的结果。
- **S19-03 证据覆盖**：回答要逐项对应问题要求，资料未说明的部分要明确标出。
- **S19-04 固定流程与直接回答**：先用明确流程建立可检查基线，再考虑让模型选择步骤。
- **S19-05 协作边界**：自动步骤、工具步骤和人工步骤要有清楚的交接。

## S20 模型怎样调用工具

- **S20-01 调用证据**：工具名、参数、状态、返回值和来源共同构成可核对记录。
- **S20-02 参数校验**：执行前检查类型、范围、单位和允许值。
- **S20-03 返回值、单位与来源**：解释数字时同时保留成功状态、单位、来源和适用时间。
- **S20-04 工具失败处理**：失败时停止、有限重试、修正参数或转人工，并保留错误。
- **S20-05 副作用与确认**：写入、删除、导出等动作要单独检查权限和人工确认。

## S21 智能体怎样根据反馈选择下一步

- **S21-01 观察—动作—反馈**：循环每一步都记录当前观察、采取的动作和工具反馈。
- **S21-02 停止条件**：证据覆盖问题或确认资料缺口时停止，避免无界循环。
- **S21-03 预算与循环**：调用次数、处理条数和延迟都是循环预算；预算变化要记录。
- **S21-04 固定与动态选择**：固定流程更易检查；动态选择可适应变化，但需要比较错误、成本和交接。
- **S21-05 可见轨迹**：记录状态、动作、结果和停止原因即可核对，不要求暴露隐藏思维。

## S22 怎样处理不可信资料与越权请求

- **S22-01 资料与指令分层**：检索到的文字是待核对资料，不会自动改变系统规则。
- **S22-02 最小权限**：只给系统完成任务所需的最小工具和数据范围。
- **S22-03 提示注入识别**：外部文本中的“忽略规则”“泄露秘密”等要求不能改变职责。
- **S22-04 敏感动作确认**：删除、导出、写入和账户操作应由授权人员确认。
- **S22-05 安全拒答路径**：拒绝时说明边界，并给出安全、可行动的替代路径。

## S23 怎样定位整个系统的失败原因

- **S23-01 第一处错误**：沿轨迹找最早不符合契约的步骤。
- **S23-02 局部与端到端**：单步正确不等于整体完成；最终结果需要覆盖任务要求。
- **S23-03 一次改动**：诊断实验一次只改一个环节，保留原轨迹和结果。
- **S23-04 轨迹证据**：日志要保留输入、输出、版本、错误和运行条件。
- **S23-05 修复范围**：根据失败环节选择局部修复，不把格式错误升级为无关的模型重训。

## S24 何时自动完成、拒答或交给人

- **S24-01 低风险且证据充分**：只读、低风险且有资料支持的请求可以自动回答并给依据。
- **S24-02 证据缺口**：资料不足时先检索或明确缺口，不把不确定变成事实。
- **S24-03 人工接手**：涉及写入、个人信息、不可逆后果或复杂例外时，交给授权人员。
- **S24-04 拒答与转交的区别**：不允许的动作要拒答或转授权；资料缺口可以说明、检索或提供安全替代。
- **S24-05 质量、风险与人工负担**：选择策略要同时看正确性、风险、覆盖、延迟和人工量，不能只看模型信心。
