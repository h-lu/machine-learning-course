# S09 参考分析与评价要点 · 一棵树能否成为可执行的规则

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lesson-11/analysis.py --output /tmp/ml-reference-S09
```

查看 `/tmp/ml-reference-S09/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`max_depth` 限制树深，`min_leaf` 限制每个叶节点最低训练人数。

## 需要核对的计算与含义

1. 明确谁执行规则、一次判断能接受多长流程，先写评价办法及规则限制。
2. 比较不同复杂度的树或树与简单规则，同时报告训练和评价表现以及叶节点人数。
3. 选一条具体记录沿树逐步解释，核对每项输入在使用时可得。
4. 改变少量训练记录或轻微改变输入，检查重要分支是否稳定；据结果决定简化、限用或采用。

课堂核算可先使用[学习材料](../../../course-student-template/lesson-11/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：选择浅树作为现场规则

预测差异小而现场需要短流程；较大的叶节点支持稳定解释，保留困难对象人工处理。

### 路线2：保留较深树作专业辅助

重要小群体确有可重现差异，审核人员可获得所需输入；复杂分支需要独立证据和维护说明。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：至少两种复杂度下的结果与叶节点人数；一条能照着执行的规则；一次稳定性或分界输入检查；采用建议。合格标准是预测与可执行性都有证据，不是把树图片导出来。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 把训练集纯度提高当成新资料可靠性提高。
- 报告规则没写叶节点人数，无法判断少数记录造成的偶然结构。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
