# S01 参考分析与评价要点 · 这件事值得交给模型吗

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lessons/S01/analysis.py --output /tmp/ml-reference-S01
```

查看 `/tmp/ml-reference-S01/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`threshold` 控制规则分界，`false_negative_cost` 表示漏报后果的假设。

## 默认配置的作者运行核算（2026-09-06）

默认规则在60条评价记录中找到24个正例、误报5个、漏报6个。按漏报代价4、误报代价1的假设，总损失为6×4+5=29；固定概率基线在同一行动规则下损失120。这只支持该分类用途与代价下的比较，不能据此判定所有“智能助手”需求都应训练模型。

本次核算使用Python 3.14.4、NumPy 2.5.2，数据摘要前12位 `428c864bd28e`，配置摘要前12位 `ec63f62e48df`。这些数值仅用于检查参考计算与解释，学生改变合理方案后无需匹配它们；没有进行真实学生90分钟试教。

## 需要核对的计算与含义

1. 从可选用途或自拟用途选一个，写清一行数据代表什么、输入取得时刻和输出后的行动。
2. 给出与该任务一致的评价办法，并运行一条简单规则或最小模型；若选择检索，检查找到的资料是否真正有用。
3. 比较一条有实质区别的路线，例如规则与学习，或检索与预测；说明为什么可比较或只能分别评价。
4. 找一个任务表述或数据条件会使方案失效的例子，根据结果决定建模、保留规则或先补资料。

课堂核算可先使用[学习材料](../../../course-student-template/lessons/S01/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：采用清楚的规则或检索

任务的正确结果由已有条文或明确条件决定，规则能够覆盖所需情形；维护规则比训练模型更直接。

### 路线2：尝试学习型预测

任务涉及尚未知的结果，已有输入与随后结果可对应，规则遗漏了有价值的关系；先按真实用途评价再决定是否试用。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：可以执行的任务定义；简单方案和合理替代路线的结果；一条不该交给当前方案的请求；给团队的下一步建议。合格标准是目标、数据、输出和评价相互对应，即使最终决定不训练模型。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 把“模型能生成文本”当作任务需求；追问使用者如何据输出行动。
- 预测相关性被写成改变输入的效果，必须拆开两种问题。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
