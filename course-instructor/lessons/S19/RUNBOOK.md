# S19 教师运行单：怎样把任务拆成模型、程序和人的协作

## 主要关系与前置知识

主要关系是：分步流程会保存路线、资料或工具返回值，使错误可以定位；透明的一步基线步骤少，但固定默认值可能不适合当前请求。前置只用到 S16 的资料检索、S18 的评价维度，以及输入、输出、比例和基线；不要求智能体框架。

一步基线不是语言模型：借用统一回答 7 天、库存统一回答 1 件、费用按 1 元/天估计。分步流程也是确定性教学程序。课堂结论只能说明当前人工数据上的步骤和记录方式，不能声称验证了真实模型协作能力。

## 最小资源与课前准备

普通 CPU、Python 3.10 以上、仓库内离线数据。课前从学生仓库根目录运行：

```bash
python lesson-21/analysis.py --config lesson-21/config-start.json --output /tmp/s19-initial
python lesson-21/analysis.py --config lesson-21/config-support.json --output /tmp/s19-later
```

确认两个目录都有 `summary.json` 和 `traces.csv`。W01 两条方案同为 7，但只有分步流程记录 `loan-student-current`；W02 一步基线为 1 件，分步流程为 2 件。

## 90 分钟组织

- 0–15 分钟：公开一步规则，让学生预计 W01、W02。
- 15–35 分钟：运行初始批次，沿一行读输入、路线、资料或工具、结果。
- 35–50 分钟：分开自动结果、未覆盖与转人工，明确各自分母。
- 50–68 分钟：运行后一批开发请求，再让学生增加一个会改变轨迹的请求。
- 68–75 分钟：形成采用、限制使用或停止建议。
- 75–90 分钟：A 题、AI 学习和 B 题。

## 巡视问题与失败支持

问“这个数来自固定规则还是当前资料”“最后数值相同能否证明过程相同”“转人工后是否已经知道结果”。运行不通时核对仓库根目录、JSON 逗号、路线所需字段和输出路径；保留报错，用 W01/W02 小表继续，再修复补跑。不要替学生指定唯一边界请求。

## 课堂证据

至少看到一条完整轨迹、一步与分步的相同分母比较、一个自拟请求的预计与实际差异。初始批次有 4 条自动请求和 2 条适当转人工；一步基线自动正确 1/4，分步流程 4/4。W07–W12 是后一批开发证据，后课复用时不能称为新最终测试。
