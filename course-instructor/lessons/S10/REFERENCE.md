# S10 参考分析与评价要点 · 多一点性能值得多大成本

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lesson-12/analysis.py --output /tmp/ml-reference-S10
```

查看 `/tmp/ml-reference-S10/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`n_estimators` 控制树数，`max_depth` 控制单树复杂度，`learning_rate` 控制提升每步的改进幅度。

## 需要核对的计算与含义

1. 明确响应或批量处理用途，先写主指标、资源限制和哪些错误值得额外成本。
2. 在同一划分与评价方法下比较单树、装袋或提升中的合理候选，报告实际运行时间和规模。
3. 检查性能增益来自哪些记录，比较减少模型数量或少用输入后的损失。
4. 设计一个输入缺失或较难记录的测试，决定复杂模型不可用时使用什么办法；据结果选择方案。

课堂核算可先使用[学习材料](../../../course-student-template/lesson-12/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：保留单树

误差差异不足以抵偿时延或输入维护成本，简单规则满足用途；报告其严重错误和处理办法。

### 路线2：采用有限规模集成

改善集中在后果重的记录，实际运行满足预算；选择已足够的规模而非自动使用最大模型。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：可重算的性能与开销比较；一项重要记录或输入成本检查；复杂方案不可用时的替代办法；采用建议。合格标准是增益和代价同时可见，不规定哪种模型应胜出。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 不同机器或输入规模下计时，误把不可比结果当倍数结论。
- 重要性解释为因果或遗漏重新训练条件。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
