## 主要关系与前置知识

主要关系是开发选择与最后评价必须分开。学生先在开发数据上比较原校园方案与图书馆适配方案，固定候选、指标和停止条件，之后才显式读取最后评价。交付还要保存可重跑命令、文件摘要、已知限制和下一项实验。前置为 S29 的迁移比较，以及开发数据与最后评价用途不同这一概念。

默认 `analysis.py` 和默认 `submission.json` 只读取 `data/base.json`。程序的 `--final-data` 默认值必须为 `None`；只有学生复制 `submission-final.json` 后，`course.py run 32` 才会传入 `data/final.json` 和 `config-final.json`。不得用输出目录名代替阶段判断；以 `summary.json` 和 manifest 的 `evaluation_stage` 为准。

## 最小资源与课前准备

开发数据 8 条，原方案 6/8、适配方案 8/8，变化为 T01、T02。最后评价另有 8 条，原方案 5/8、适配方案 8/8，变化为 D01、D02、D06。学生材料不得提前给出后一组数字和编号。

课前完成三项检查：

1. 临时删除或破坏 `data/final.json`，直接运行 `analysis.py` 和默认 `course.py run 32`，两者仍应生成 `development` 结果；
2. 显式传入 `--final-data`，结果应变为 `final_evaluation`，且所选候选与固定配置一致；
3. 从两个不同输出目录运行相同最终命令，summary、records 和 manifest 应逐字节一致。manifest 的输出目录固定写 `<OUTPUT_DIR>`。

## 90 分钟组织

0–18 分钟运行开发比较；18–33 分钟追踪变化请求并固定候选、指标和停止条件；33–48 分钟复制最终配置与提交清单并运行最后评价；48–62 分钟手算与重跑；62–75 分钟写决定、限制和下一实验；75–90 分钟概念检查和提交。

## 巡视问题与失败支持

巡视时先问：“现在的 `evaluation_stage` 是什么？”“终端命令有没有 `--final-data`？”“你的候选和停止条件是在什么时候写下的？”“manifest 能证明参考路线正确吗？”

若学生开发阶段已经看到 D 编号，立即停止，把这批结果视为已见开发证据，检查其 `submission.json` 是否被提前替换。若最终命令缺少 `final_data_sha256`，说明提交的仍是开发运行。无法重跑时先核对 manifest 中的完整参数和文件摘要，不用截图代替。

## 课堂证据与验收

必须看到：开发结果；打开最后数据前的候选、指标和停止条件；固定的 `config-final.json`；显式最终命令；同分母手算；严重条件核对；至少一条变化解释；干净目录重跑；摘要的能力边界；继续、修改或停止的决定；可执行的下一实验。

不强制选择适配方案。若学生看过最后评价后修改方案，需把该批次降为开发证据，不能继续声称它是未见的最后评价。
