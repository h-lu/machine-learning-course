# C02 参考分析与评价要点 · 一个分数够不够支持使用

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lesson-02/analysis.py --output /tmp/ml-reference-C02
```

查看 `/tmp/ml-reference-C02/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`feature` 指定一元预测使用的输入；可比较现有输入，也可修改程序加入另一种办法。

## 需要核对的计算与含义

1. 明确所选用途，先写接受标准和预期，再按记录编号划分用于开发和最后检查的资料。
2. 比较简单基线和候选办法；保证它们接受同一批输入、采用同一种评价。
3. 选择一个有实际理由的分组或错误情形，查看总体结论是否仍成立；不能只挑候选办法占优的组。
4. 依据结果决定使用候选办法、继续保留基线或暂不使用，并在新的目录重跑主要结果。

课堂核算可先使用[学习材料](../../../course-student-template/lesson-02/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：保留简单基线

候选办法整体增益很小，却在关键组上更差或需要额外输入；保留基线能够符合所选用途。

### 路线2：限于部分记录使用候选办法

候选方法在数据充分的组上改善明显，而新对象不稳定；限定使用条件并保留其他处理办法。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：一张能重新计算的候选办法比较表；一个有理由的分组检查；一条错误记录和一条自行设计的测试；说明原来预计什么、现在决定什么。合格标准是同一评价条件下的比较能支持你的建议，而不是选出最高分。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 用各自不同的测试资料比较两个分数，需追查记录编号。
- 先挑赢家再换指标；允许修订目标，但应明确新的评价是后续分析。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
