# S02 教学运行单 · 记录下来的结果就是好标签吗

## 本课的教学重点

学生不是要复述方法清单，而是回答：记录下来的结果就是好标签吗。以[学生任务](../../../course-student-template/lesson-04/README.md)中的两种用途进入讨论，让学生先明确使用者再选指标。自拟用途只要能用资料检验，并保留本课的知识判断，就可以采用。

## 课前准备

1. 阅读学生 `data/DATA.md` 与 `config.json`，确认字段含义和现有参数。`observation_day` 控制已经观察到哪一天，`agreement_threshold` 是提示需要进一步检查的一致性标准；它不是标签正确的保证。
2. 在准备好的Python环境运行学生入口，核对输出文件存在、记录数可追溯。将关键结果与本课微型例子分开；后者不是正式数据答案。
3. 备好两种用途的简短说明，选择一条正式记录用来核对输入、结果和算法输出。准备展示一条不支持原先建议的记录，不规定学生必须得到同样结论。
4. 打开本目录 `questions.json`，先做A两题，允许学生向AI学习，再做B两题；题目结果用于反馈概念，不用来识别AI代答。

## 90分钟安排

0—15分钟辨别真实目标与代理；15—28分钟手算标签差异；28—52分钟生成与检查标签；52—65分钟比较等待和样本代价；65—75分钟重跑与建议；75—90分钟概念题与变式。

巡视时优先查看学生的用途、原先预计和一个关键数字。实现困难可提供现成代码或让AI直接实现；不要要求通过手写代码或提交对话证明参与。提前完成者研究关键替代方案，不增加无关文件来消耗时间。

## 必做成果的具体检查

1. 明确真正关心的结果与目前记录的结果，列出两者可能不一致的原因。
2. 根据用途选择纳入记录和标签生成规则；实际计算代理标签差异或延迟观察的影响，并写出分母。
3. 比较另一条合理的标签路线，说明样本量、等待时间与错误风险怎样变化。
4. 构造一条“还没观察到”和“确认没有”容易混淆的记录，检查流程如何处理；据此修改建议。

一份标签说明、可重跑的生成或筛选流程、两条标签路线的数量与差异、一个未观察完整的案例，以及允许用于哪些对象的建议。关键是说明标签代表什么，不能只交一致率。

当学生选择暂不使用时，检查其结论是否有实际运行和错误分析支持；当学生选择采用时，检查声明的条件是否超出评价资料。两种方向都不能只凭态度或措辞得分。

## 两条可能都合理的路线

### 路线1：用投诉记录安排投诉响应

任务就是处理将出现的投诉；明确不能把结果解释成故障发生率，标签等待相对较短。

### 路线2：等待完整观察预测故障

使用者关心真实故障；愿意牺牲样本数量和时效，以减少标签误解与未完成观察造成的偏差。

两条路线服务的用途、错误后果或资料条件不同。本课没有一个对所有使用者都最好的参数或结论。教师可提供第三条路线，但不能把自己偏好的模型设为唯一完成标准。

## 巡视与反馈

- 把模拟真值当现实随时可见的输入，需区别教学对照与使用条件。
- 只报总体一致率，忽略正例少时多数一致很容易。

从学生成果中选择两个采用建议不同、依据却都清楚的片段，比较“哪项用途或条件造成分歧”。反馈到具体数字、分母、输入时刻或方法假设；不要把风格差异判成分析错误。

## 发布与试教记录

本课教材按普通CPU、离线小数据设计。作者的程序运行与文件检查不能证明真实学生能在90分钟内完成；实际试教后记录读题、计算、判断与提交分别耗时，再调整支持材料。
