# S02 参考分析与评价要点 · 记录下来的结果就是好标签吗

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lesson-04/analysis.py --output /tmp/ml-reference-S02
```

查看 `/tmp/ml-reference-S02/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`observation_day` 控制已经观察到哪一天，`agreement_threshold` 是提示需要进一步检查的一致性标准；它不是标签正确的保证。

## 默认配置的作者运行核算（2026-09-06）

观察到第10天时可用标签62个，占180条的约34.4%；这些记录的正例比例约46.8%。模拟最终所有标签可见时正例比例约59.4%。延后7天有134个可见标签。可见子集与全体差异值得讨论，但“最终真值”只在教学对照里可见，不能作为真实部署时可以直接取得的资料。

本次核算使用Python 3.14.4、NumPy 2.5.2，数据摘要前12位 `86e5eaf85df5`，配置摘要前12位 `4d101f700dfa`。这些数值仅用于检查参考计算与解释，学生改变合理方案后无需匹配它们；没有进行真实学生90分钟试教。

## 需要核对的计算与含义

1. 明确真正关心的结果与目前记录的结果，列出两者可能不一致的原因。
2. 根据用途选择纳入记录和标签生成规则；实际计算代理标签差异或延迟观察的影响，并写出分母。
3. 比较另一条合理的标签路线，说明样本量、等待时间与错误风险怎样变化。
4. 构造一条“还没观察到”和“确认没有”容易混淆的记录，检查流程如何处理；据此修改建议。

课堂核算可先使用[学习材料](../../../course-student-template/lesson-04/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：用投诉记录安排投诉响应

任务就是处理将出现的投诉；明确不能把结果解释成故障发生率，标签等待相对较短。

### 路线2：等待完整观察预测故障

使用者关心真实故障；愿意牺牲样本数量和时效，以减少标签误解与未完成观察造成的偏差。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：一份标签说明、可重跑的生成或筛选流程、两条标签路线的数量与差异、一个未观察完整的案例，以及允许用于哪些对象的建议。关键是说明标签代表什么，不能只交一致率。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 把模拟真值当现实随时可见的输入，需区别教学对照与使用条件。
- 只报总体一致率，忽略正例少时多数一致很容易。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
