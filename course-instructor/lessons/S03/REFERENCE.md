# S03 参考分析与评价要点 · 怎样测试才像将来的使用

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lesson-05/analysis.py --output /tmp/ml-reference-S03
```

查看 `/tmp/ml-reference-S03/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`split_strategy` 选择划分方式，`train_fraction` 控制训练资料比例；先按用途选择，再查看分数。

## 需要核对的计算与含义

1. 选择将来的使用对象与时刻，画出数据使用顺序，说明哪些数据用于开发、哪些留作最后检查。
2. 执行至少两种有解释意义的划分，比较对象重叠、时间关系、样本量和结果；不把不同问题强行排为同一榜单。
3. 核查一列特征的生成时刻，演示一种泄漏或不合适划分如何改变评价。
4. 最后检查前写清评价方法；检查后如继续修改，把已看过的数据标明为开发资料，更新可支持的结论。

课堂核算可先使用[学习材料](../../../course-student-template/lesson-05/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：选择时间划分服务已有对象

部署目标只涉及已记录对象的未来；保留对象历史是合理条件，但要阻止未来字段进入训练。

### 路线2：选择对象隔离服务新对象

接入团队面对陌生对象，随机分行结果不足；接受较低分数并限制可承诺的性能。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：可重建的划分程序及记录编号；两种划分的用途说明和结果；一个泄漏或重复对象案例；对未来使用的限定建议。合格标准是评价能回答你声明的问题，不以最低误差为准。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 把划分方式当成可调超参数，按高分选择。
- 用同一测试资料反复改模型后仍称独立测试。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
