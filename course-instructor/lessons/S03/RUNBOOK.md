# S03 运行单：怎样比较才接近未来使用

状态：已随 `ml-v13-course-map-2026-09-21` 于 2026-09-21 发布；本次没有真人 90 分钟试读。学生目录为 `lesson-05`。

## 本课关系与前置支持

C02 的训练/验证/测试和 S01 的可用输入。先画用途，再画日期或窗口，不从 API 开始。

主要关系：模型将用于熟悉窗口的未来日期，还是一个从未用于训练的新窗口？本课保持模型类型不变，比较时间、分组和随机划分，检查它们究竟在回答哪个问题。

## 90 分钟组织

前 12 分钟让学生先写“已有窗口未来”和“新窗口”两个用途；16 分钟运行并找到编号、分母与一项 MAE；20 分钟完成 time/group 两行证据表；18 分钟先写改变建议的条件，再运行日期边界或多随机种子检查；9 分钟整理支持证据、反面证据与泄漏限制；最后 15 分钟按 A 4 分钟、AI 学习 5 分钟、B 4 分钟和提交 2 分钟组织。题库源码包含对应时长，但生产服务未自动切换。

起步程序只提供机制。学生必须先选主要用途，再决定检查日期边界还是随机划分波动；不要以“照教师参数得出同样分数”评价完成。检查必须有机会改变建议：学生在运行前写出什么结果会使其限制或暂停，运行后再引用一项支持证据和一项反面证据。参数示例不是唯一菜单，自选实现只要保留关键关系和独立核对即可。

## 观察与提问

- 模型将预测老窗口未来，还是新窗口？
- 正常输入和小票输入有什么时间差？
- 三个分数的验证编号是否相同，能否直接排高低？
- 你在运行前写的哪一种结果会使你改主意？实际结果触发了吗？

学生答不上来时先退到一条记录或一个分母，不增加新的术语或表单。代码可以由 AI 完成；判断必须能联系实际结果解释。

## 失败支持与验收

先核对运行目录、配置字段、输入单位和输出时间；错误退出后的旧结果不是新实验。不会 JSON 或提交的学生使用 FIRST_RUN 与 FOUNDATIONS 指南。确认报告引用的配置、CSV 和命令都保存，包括被 Git 忽略的 artifacts。

每位学生提交两个用途的证据表、一项 MAE 手算、泄漏反例、运行前写下的改变条件、自设计检查，以及分别面向两个用途的建议。报告至少引用一条支持证据和一条反面证据。原方案可以胜出，也允许限制用途或暂停使用；不能只交最低 MAE 所在的一行。

## 基础较弱学生的详细支持与分层

让学生直接打开 [本课入门支持](../../../course-student-template/lesson-05/SUPPORT.md)，不要求先自己选大项目或从零写算法。第一次操作巡视时，只问学生能否找到“time 与 group 的数量”：12/6 与 6/6；共有窗口分别 3 与 0，测试编号不进开发。

入门支持、自己设计的必做路径使用相同完成标准：能先选使用对象再解释划分，同时否定事后小票的虚假高分。入门路径用训练截止日 2 作具体检查；应让学生先写改变建议的条件，不能先展示参考 MAE。使用现成配置或教师帮助不设置分数上限；提高、换数据重测和自选拓展不是全部必做。每个学生仍需说明自己的用途选择、检查理由和检查是否改变结论。

找不到结果时先核对目录、配置和方法名；环境故障先用指南表格继续算并记录未运行部分，修复后补跑，不直接判已完成。别让学生在陌生字段中无目的翻找；报告按当课提示写短回答即可。模拟冷读和命令成功不是学生已掌握的证据，仍需真实学生试读。
