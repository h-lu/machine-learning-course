## 最小计算

默认数据为人工教学样本，配置见学生目录。下列数值只用于独立核对起步实现，不是学生评分目标：

```json
{
  "n": 6,
  "mae": 2.5555555556,
  "rmse": 2.6874192494,
  "asymmetric_loss": 6.1111111111,
  "alerts": 2,
  "eligible": 3,
  "tp": 2,
  "fp": 0,
  "fn": 2,
  "tn": 2
}
```

先从原始样本及 `records.csv` 重算对应数量，再和汇总比较。参考脚本对本课采用不同配置，并检查训练隔离、统计分母或实际选择；不能只调用被测函数，再用其自身返回值证明正确。

只把低估权重从 3 改为 1 时，linear 与 buffered 的预测、MAE、提醒编号和四类计数都不变；`asymmetric_loss` 分别变为各自 MAE，即约 2.556 与 3.000，因此按该评价的顺序反转。教师应追问学生改变的是用途权重还是模型预测，不能只让学生抄两行分数。

容量个人检查的独立核对如下。真实长等待共 4 条，非长等待 2 条；排序不读取这些真实类别。

| 容量 | 方法 | 实际提醒编号 | TP / FP / FN / TN |
|---:|---|---|---|
| 1 | linear | C06 | 1 / 0 / 3 / 2 |
| 1 | buffered | C06 | 1 / 0 / 3 / 2 |
| 4 | linear | C06、B06、C05 | 3 / 0 / 1 / 2 |
| 4 | buffered | C06、B06、C05、A06 | 3 / 1 / 1 / 1 |

容量 4 的 buffered 中，A06 与 B05 的预测同为约 10.333，固定规则按编号先选 A06，所以出现 A06 误报而 B05 仍漏报。这里用于说明容量、排序和实际类别不同；不能据此推断真实系统应使用编号打破并列。学生若发现这一限制并提出在部署前明确合理的并列规则，应视为有根据的诊断。

## 两条合理路线

**分钟预估用途**。以 MAE 为主，同时解释高估低估和小组表现。

**有限提醒用途**。给出实际类别、预测阈值及容量，报告误报漏报，不只讲平均误差。

学生可以更换这些路线。同一个学生可以合理地在分钟预估中保留 linear，同时在低估后果较重的假设下考虑 buffered；也可以因权重缺少现实依据或容量下的误报漏报而暂停提醒。评价的是用途、比较、失败检查和结论的关系，不奖励采用参考模型，也不因候选没胜出而扣学习质量分。

## 容易误判的地方

- 权重改变后是预测改变了，还是评价改变了？
- 阈值单位是分钟还是概率？
- 达到阈值有 5 条但只有 2 个名额时，谁决定排序？
- 报告是否列出实际提醒编号，并解释容量 4 下 buffered 的误报与漏报？
- 两个用途的建议是否各有支持证据与代价，而不是共用一句“分数最好”？
