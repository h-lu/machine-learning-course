# C01 参考分析与评价要点 · 让别人重跑你的第一次预测

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lesson-01/analysis.py --output /tmp/ml-reference-C01
```

查看 `/tmp/ml-reference-C01/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`missing_field` 指定用来演示缺项检查的字段；改变它应对应你关心的输入。

## 默认配置的作者运行核算（2026-09-06）

默认资料有180条记录，训练120条、评价60条。全部预测为负类时正确30条、漏掉30条；全部预测为正类同样正确30条，但漏报变成0、误报变成30。相同0.5准确率对应相反后果。缺少x2的测试被识别为输入不完整。这个例子适合引出“算得出来、重跑一致与适合用途是不同检查”。

## 需要核对的计算与含义

1. 用一句话说明接手者想据预测做什么；选一个能从原始记录算出的评价量，并解释它为什么有用。
2. 运行起步程序，抽取一条记录，自己或让AI列出输入、真实结果和预测，核对计算。
3. 设计一条容易让这个简单办法出错的输入；解释错误是计算故障，还是办法本身的限制。
4. 在新的输出目录重跑，核对样本数和主要数值，修改第一次的使用建议。

课堂核算可先使用[学习材料](../../../course-student-template/lesson-01/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：用均值做一般需求估计

需要者关心许多次预测的总体误差，允许单次偏差；优先核对单位与均值计算，暂只作为计划参考。

### 路线2：拒绝用均值承诺单次供应

需要者要求很少发生缺货，而样本无法说明尾部需求；提交能重跑的均值结果，同时建议先收集更多资料或采用人工上限。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：一份能重跑的小预测程序；支持说明的数值文件；一条手算或逐步核对的记录；一条错误输入；给接手者的使用建议。合格标准是别人能重算你的主要数字，并看懂这次错误是否妨碍所选用途，不要求预测分数漂亮。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 把标签当作可用输入，需请学生指出“什么时候知道这一列”。
- 把演示成功写成实际业务有效；所有案例数字都只能说明教学实验。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
