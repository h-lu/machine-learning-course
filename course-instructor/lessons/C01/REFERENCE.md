# C01 参考分析：从样本到预测

这是教师核对材料，不是学生必须选择的答案。起步数据人工构造，不能支持真实食堂中的效果声明。

## 独立核对默认例子

训练样本共 8 条，排队人数依次为 `0、1、2、3、0、1、2、3`，标签为 `2、2、4、8、0、4、6、6` 分钟。规则 `1+2×人数` 的预测为 `1、3、5、7、1、3、5、7`，每条绝对误差都为 1 分钟。

以 `train-03` 为例：特征为人数 2，标签为实际 4 分钟，预测为 5 分钟。平均绝对误差为 1 分钟，但 C01 的最低理解证据是这一条计算，不要求提前掌握全部评价指标。

规则参数是人为设定，不通过训练样本拟合。AI 生成这段程序，也没有在任务数据上训练模型。训练集在这里是与 C02 共用的数据标记。

## 两条合理路线

**路线一：保留给定线性规则。**它便于说明和手算。学生可以自行选择人数 6 检查预测 13 分钟，指出这超出样例 0–3 人的区间，没有新标签时无法计算误差。理由不能是“程序可运行，所以真实可靠”。

**路线二：修改规则或换简单方法。**例如改为 `1+1.5×人数`，该参数下 `train-03` 的预测为 4 分钟，但不能因为这一条恰好正确就声称总体更好。可以把斜率设为 0、截距设为 4，形成恒定预测，为 C02 的基线比较铺垫。换其他合理参数或自选题同样可以。

两条路线都要有自己的理由、实际运行与输入检查。原方案可以保留，错误可以成为发现数据需求的依据，不以拟合更复杂的模型加分。

## 反例与输入检查

人数 -1 或 1.5 不符合人数含义，应明确报错；样本编号重复也要报告。人数 10 合法但超出训练人数范围，默认预测 21 分钟；它没有对应真实标签，`stress_test.metrics.mae` 必须为 `null`，不能编造误差。

删除 `wait_minutes` 会使本课的有标签数据检查失败；这不代表所有推理都必须带标签。预测函数只需要人数，脚本需要标签是因为它还负责核对历史样本。

## 数值与软件验收

在完整工作区运行：

```bash
python course-instructor/scripts/validate_reference_coverage.py --lesson C01
cd course-student-template
python -m unittest discover -s tests -p test_intro.py -v
```

教师变体改变人工斜率并测试一个新人数，独立核对预测与误差。单元测试还检查输入、参数来源与输出文件。数值通过不证明学生已经理解，也不代表真实课堂已试教。

五个知识点和 A/B 题见同目录 `questions.json`。B 版改变情境，学习说明不复述题干。学生报告重点看样本含义、特征与标签、预测来源、一次核对和结论限度。
