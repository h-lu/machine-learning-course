# S05 参考分析与评价要点 · 复核名额应该给谁

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lessons/S05/analysis.py --output /tmp/ml-reference-S05
```

查看 `/tmp/ml-reference-S05/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`threshold`、`capacity` 和 `false_negative_cost` 分别对应分界、可用名额与漏报代价。

## 需要核对的计算与含义

1. 选择用途与复核容量，先写评价办法及接受标准；明确误报漏报分别会发生什么。
2. 用开发资料比较阈值或排序规则，计算每种规则的复核人数、找到数量、遗漏数量和相关损失。
3. 检查一种重要群体或基础率变化，并查看分数能否当作概率理解。
4. 设计一条接近规则分界或信息不足的输入，说明如何处理；最后用未参与选择的记录检查选定规则。

课堂核算可先使用[学习材料](../../../course-student-template/lessons/S05/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：按容量排序查前若干条

每日名额固定，目标是尽可能多找到重要对象；明确名单之外仍可能有风险，检查群体后果。

### 路线2：按风险标准筛选并允许空余或请求增援

使用者认为低风险记录不值得复核，高风险记录不应仅因名额而忽略；需要明确溢出时的人工安排。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：可执行的复核规则；同一批记录上的人数和错误比较；容量与群体检查；一条边缘输入及处理办法；采用、限用或暂缓建议。合格标准包括人数算得对且方案能实施。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 只报精确率或召回率，不写人数。
- 把未进入自动名单称作安全；只是未被当前规则选中。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
