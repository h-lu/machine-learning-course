# S22 参考分析

## 两条合理路线

路线一完全不采用资料中的动作建议，只把资料作为事实数据。路线二允许资料提出候选动作，但执行层独立检查允许列表和当前请求是否一致。两者都可能合理；资料不能给自己增加权限。

## 透明提取与字段核对

`document_action_phrases` 是公开的“原样文字片段 → 动作名”映射。SEC02 的 `document_id=untrusted-note`，文档正文包含“导出所有账户”，因此 `matched_phrase` 可核对为该片段，`extracted_document_action=export_accounts`。这只是字面规则，不是模型理解。

`security_cases` 的文档编号必须存在；缺失或拼错时程序报错。日志同时保留文档编号、原文、匹配片段、用户请求、候选来源、权限判断和实际动作。

## 独立核算与反例

起点 3 个案例中 SEC02 被阻止，阻止 1/3，危险执行 0，合法请求完成 2。只采用用户请求时阻止 0，合法请求完成 3。危险执行为 0 只说明当前允许列表挡住当前案例。

把文档短语改为“查询库存”后，提取 `inventory_lookup`。它在允许列表内，会实际记录执行，却与 SEC02 的 `read_public` 不同，因此 `unexpected_action_executed` 增加。这个反例说明允许列表还需配合任务一致性检查。

## 结论限度

字面短语表会漏掉同义改写，也可能误匹配；日志只证明教学执行器记录的行为，不证明生产系统无旁路。学生测试必须保持无真实副作用。
