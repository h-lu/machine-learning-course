# S06 运行单：一次小实验能否改变最初的问题

状态：成套候选材料，未指定班级启用，也未部署线上题库。学生入口见[本课任务](https://github.com/h-lu/machine-learning-course/blob/course/foundations-s01-s06/course-student-template/lesson-08/README.md)；本地目录为 `lesson-08`，不能把 S 编号直接传给数字课次脚本。

## 本课关系与前置支持

S01–S05 的报告或等价练习；不会流水线术语也可开始，先画“填补→拟合→预测”。

主要关系：回到 S01 的任务：当前问题到底出在数据记录还是遗漏的特征？本课先写出两种可能解释，选择一次只改变一个因素的实验，再用同一批样本比较原方案和候选。

## 90 分钟组织

20 分钟以 LEARN 的小表解释概念；35 分钟让学生运行、核对并设计自己的方案；20 分钟比较、排查并写建议；最后 15 分钟按 A 4 分钟、AI 学习 5 分钟、B 4 分钟和提交 2 分钟组织。题库源码包含对应时长，但生产服务未自动切换。

起步程序只提供机制。让学生自己选择用途、日期、阈值、采样或诊断假设；不要以“照教师参数得出同样分数”评价完成。参数示例不是唯一菜单，自选实现只要保留关键关系和独立核对即可。

## 观察与提问

- 这次只改变了哪一项，哪些保持不变？
- 1.444… 个人的填补值和真实人数不是整数是否矛盾？
- 测试不支持候选时，是否允许保留原方法或暂停？

学生答不上来时先退到一条记录或一个分母，不增加新的术语或表单。代码可以由 AI 完成；判断必须能联系实际结果解释。

## 失败支持与验收

先核对运行目录、配置字段、输入单位和输出时间；错误退出后的旧结果不是新实验。不会 JSON 或提交的学生使用 FIRST_RUN 与 FOUNDATIONS 指南。确认报告引用的配置、CSV 和命令都保存，包括被 Git 忽略的 artifacts。

每位学生提交主要比较、自设计检查和有理由的建议。原方案可以胜出，也允许暂停使用。必须引用 S01 原用途，并保留同一数据版本的前后比较；不是另外做一件无关作品。

## 教师备课验证

在完整工作区的 `course-instructor` 目录运行：

```bash
python scripts/validate_reference_coverage.py --lesson S06
```

检查验证的数值性质，再读 [REFERENCE.md](REFERENCE.md)。自动通过不证明新生能在 90 分钟内完成，仍需按[模块发布说明](../../releases/foundations-2026-09-19.md)试教。普通 CPU、离线小数据，不要求学生购买服务；网络和概念场次故障按原评分规则安排支持。

## 基础较弱学生的详细支持与分层

让学生直接打开 [本课入门支持](../../../course-student-template/lesson-08/SUPPORT.md)，不要求先自己选大项目或从零写算法。第一次操作巡视时，只问学生能否找到“A05 填补后的输入”：原人数缺失，填 0 与训练均值 13/9 不同；不能用验证均值。

入门支持、自己设计的必做路径使用相同完成标准：能引用原用途、提出两个解释，分别与同一原方案比较，再保存测试前选择。 使用现成配置或教师帮助不设置分数上限；提高、换数据重测和自选拓展不是全部必做。每个学生仍需说明一项自己的选择及其检查结果。

找不到结果时先核对目录、配置和方法名；环境故障先用指南表格继续算并记录未运行部分，修复后补跑，不直接判已完成。别让学生在陌生字段中无目的翻找；报告按当课提示写短回答即可。模拟冷读和命令成功不是学生已掌握的证据，仍需真实学生试读。

## 原方案的来源检查

本程序不会读取 S01 的个人配置。这里的 `original` 专指本课提供的“缺失人数填 0 后拟合一元线性回归”，不一定是你在 S01 选择的模型。入门路径可以用它作为本次改进的起点，但报告要说明这个起点与 S01 方案是否相同；若不同，不能把本次差异说成自己原方案的提升。按入门路径完成给定原方案到候选的改进即可覆盖本课要求，不另加“从零实现个人模型”的隐含要求。学生声称延续自己的 S01 模型时，则需核对实际代码、参数和当前评价样本，不能只核对原用途相同。
