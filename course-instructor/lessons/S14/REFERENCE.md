# S14 参考分析与评价要点 · 训练没有变好，应该先改什么

## 参考核算入口

在包含学生仓库的工作目录运行：

```bash
python3 course-student-template/lessons/S14/analysis.py --output /tmp/ml-reference-S14
```

查看 `/tmp/ml-reference-S14/summary.json`，同时核对学生的数据说明、原始记录与配置。默认实验为一种可重算的比较起点。教师应保存实际配置和数值，不能把这份文件的例子或一条预期关系直接写成已运行结果。

`comparison_learning_rate` 提供另一学习率对照，其余参数控制宽度、训练时长、学习率和正则化。

## 需要核对的计算与含义

1. 根据实际训练与验证过程提出一个诊断，列出另一个也可能解释现象的原因。
2. 固定资料划分、模型与随机条件，一次改变一个关键因素，比较前后完整过程而非只看最好一步。
3. 核对该改动是否真正检验了诊断，并用一次额外检查排除关键混淆，例如输入尺度或训练代码错误。
4. 在最后评价前选好版本，检查自行设计的困难输入；提出继续训练、换方案或停止的具体理由。

课堂核算可先使用[学习材料](../../../course-student-template/lessons/S14/LEARN.md)中的具体数字，再抽一条正式记录复核。核算时检查人数、单位、训练和评价资料的用途，以及输出是否真的回答学生选定的问题。相近数值允许因合理实现与随机条件有差异，不能按最后一位小数或默认模型评分。

## 可接受但方向不同的分析

### 路线1：降低学习率修复更新不稳定

训练与验证共同震荡，控制其他条件后较小步长使过程稳定；仍需单独检查泛化。

### 路线2：减少训练或加强正则化

训练持续改善而验证退步，主要问题是对新资料无益的拟合；接受更高训练损失以改善用途结果。

这些路线是条件式参考，不是标准答案：用途、信息条件或代价改变后，推荐也可能相反。学生可提出其他路线，只要能解释为何与相同问题相符，并提供可复核的比较。

## 最低合格与更有说服力的成果

最低合格：原始与修改后的训练、验证过程；诊断假设与替代解释；一次控制条件的比较；困难输入测试；后续建议。合格标准是试验能区分原因，允许结论是证据尚不足。

更有说服力的分析会指出哪项结论依赖重要选择，并通过与用途相关的替代或条件变化说明依赖程度；不会靠增加模型、图表和篇幅获取质量分。补充的业务假设必须标明，合成数据不代表真实机构效果。

## 常见误判

- 同时改多个因素后给唯一原因结论。
- 声称曲线包含验证而输出只有训练；发布前必须检查实际数值。

程序能够运行只说明计算链条可检查。不要把固定数值、指定关键词或与参考同样的推荐作为机器自动判定分析正确的条件。
