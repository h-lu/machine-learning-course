# 怎样读一件学生作品

先看它试图回答什么问题，再看计算。相同的结果，可能支持小规模人工辅助，也可能不足以支持自动处理。评价应依据学生明确说明的用途和限制。

| 维度 | 需要看到的证据 | 常见不足 |
|---|---|---|
| 问题与用途 | 说清使用者、输入和结果出来后的动作 | 只写“提高准确率”，没有人要用这个结果 |
| 数据与方法 | 数据来源、开发与测试安排、合理基线 | 预测时未知的信息进入特征；只挑有利比较 |
| 选择与检查 | 一项影响结果的自主选择、替代比较、自己设计的失败案例 | 直接交示例；只改图表外观；只报告平均分 |
| 结论与限制 | 建议由具体结果支持，保留最初判断及修订理由 | 把合成数据结论推到真实业务；把相关当因果 |
| 重跑与表达 | 清楚的入口、生成的结果、能追踪的一条计算 | 手写指标；缺数据；报告和程序不是同一个版本 |

“完成”表示覆盖本课必要概念与检查；“做得好”表示选择有理由、证据足够支持结论、文字让人能核对。运行示例只完成环境起步，不能作为全部项目。暂时不采用模型的结论可以获得高评价，但必须有实验和比较。

模型大小、代码数量、采用多少工具、AI 对话长度和结果是否优于教师示例，不单独计分。使用自己的数据和原有数据都可获得相同评价。

每课保留项目反馈和概念误区反馈。开课前由教师公布成绩权重、补交办法、代表作品数量和考试安排；本地重建不自动替课程决定这些政策。试教时重点记录：学生是否理解问题、在哪一步停住、支持材料是否让他仍能完成关键判断。
