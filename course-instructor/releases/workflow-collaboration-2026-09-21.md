# 第 21–26 课模型、工具与人协作模块发布记录：2026-09-21

## 范围与版本边界

本记录适用于学生 `lesson-21` 至 `lesson-26`，对应 S19–S24。第 01–04 课已授课并冻结，本模块不改变历史学生要求或旧场次解释。

六课复用一个设备借用服务流程，依次加入分步处理、本地工具、受限动态流程、权限边界、步骤故障定位和端到端改进。所有动作都发生在无真实副作用的离线环境。汇集题库已经以 `ml-v13-course-map-2026-09-21` 发布。

## 学生路径与产物

[S19–S24 冷读与运行记录](../reviews/s19-s24-cold-read-2026-09-21.md)只按学生页面前进，并在普通 CPU 上实际执行六课各自的 start/support 命令、个人条件和提交收尾。12 条 start/support 命令及一条 S24 final 命令均返回 0，生成 `summary.json` 与相应 CSV；每课自拟条件都实际改变了轨迹或结论。

S19–S23 在一次性学生副本中依次完成 `course.py start`、采用配置、`course.py run`、状态改为 `complete` 和 `course.py check`。S24 先运行 development 并确认默认提交不读取 holdout，再显式切换到 final 提交清单；两阶段及最终检查均通过。

S24 的 W01–W12 是开发数据，F01–F06 单独位于 `data/holdout.json`。默认 `scripts/course.py run 26` 只读取 `base.json + config.json` 并生成开发结果；学生固定候选后才显式使用 `submission-final.json`、`config-final.json` 和 holdout。公开仓库中的 holdout 仍依赖操作顺序，不能当作高风险评价中的保密数据。
