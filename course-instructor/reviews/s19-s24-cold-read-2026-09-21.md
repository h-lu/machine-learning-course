## 检查方式和证据边界

本次完成了两类检查：

1. **模拟学生冷读**：只按 README 首屏、SUPPORT 第一项、当前步骤所需 LEARN、数据说明、命令结果和报告提示前进，没有打开教师参考寻找操作答案。
2. **真实命令运行**：在本机 Python 3.11、普通 CPU 环境中，从学生仓库根目录执行每课 start/support 命令、S24 独立 final 命令及每课一项自拟条件。当前主机没有 `python` 命令，因此按学生总 README 和 FIRST_RUN 的明确说明，把命令首项换为 `python3`；`submission.json` 中的 `python` 会由 `scripts/course.py` 替换成当前解释器。

没有真人学生首次试读，也没有课堂 90 分钟计时。模拟冷读和命令成功只能证明页面形成完整路径、程序可运行，不能证明所有学生无需教师支持或能在规定时间完成。

六课复用同一个作品。`data/base.json` 的 W01–W12 全部是开发数据；`initial` 和 `later` 只是两批开发请求。S24 的 F01–F06 单独放在 `data/holdout.json`，开发命令不读取也不生成这些结果。公开仓库无法技术性隐藏文件，因此教学 holdout 还依赖“先固定配置、后打开文件”的操作顺序；正式高风险评价需在配置固定后另发未公开数据。

## 自拟条件的真实运行

每课还运行了一项不依赖预烘焙必胜的条件变化：

- S19 新增投影仪库存为 1 件的 W13，一步固定值也答对，使一步自动正确从 1/4 变为 2/5；这会缓和“分步只因分数更高才有价值”的结论。
- S20 新增库存为 1 件的录音笔请求，一步正确从 1/5 变为 2/6，工具为 6/6；结论需要同时讨论当前查询证据。
- S21 把 W09 的重试上限改为 0；首次失败后转人工，自动错误仍为 0，不必要转人工变为 1。
- S22 把文档短语改成“查询库存”；允许列表放行动作，但它偏离用户的公开读取请求，`unexpected_action_executed` 变为 1。
- S23 选择 route 故障与 route 替换；故障实际改变自动处理、转人工和多个局部字段，替换后恢复。
- S24 只把 W09 改写成“设备超过期限一天怎么收费”，保持 1 天与 2 元参考值；模型路线变化使原/候选各增加一个自动错误，说明来源过滤不能修复路线表达问题。

这些自拟运行证明学生可改变真实轨迹或结论，而不是只改报告文字。
