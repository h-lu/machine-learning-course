## 发现与修正

| 障碍 | 修正 |
|---|---|
| 目标、实际记录、代理估计、复核值混在一起，似乎写作“真实”就不必复核 | 先约定计时起止，指出第一份实际记录只是本练习参照，第二份不自动覆盖；代理有用不等于同一目标 |
| 通用数据说明仍提到 C 窗口和后课操作 | 改成本课 A/B 各四条；明确不是第三课24条数据，不沿用其分母 |
| 发生日、上传日和截止日容易混淆，原逐条表无法就地查日期 | 添加日期、窗口及两类绝对差阅读列；说明当天上传也计入、未来值仅用于离线模拟 |
| 日期对照像是在比较两天服务效果 | 强调固定八条已经结束的经历，只是可见标签逐渐增加；上传慢的原因仍待核查 |
| “标注一致”误当“标签准确”，缺第二份可能被算为一致 | 明确配对分母、严格大于容差及无配对时比例无定义；保留零值与未知的区别 |
| 改容差后终端看不到分歧变化 | 新增 S02 专用显示：主截止日、已知/总数、均值分母、配对、容差、分歧和一致比例；不叫模型性能 |
| 报告反复填写同一文件信息，入门任务缺少具体复核计划 | 集中运行记录；保留先预计、运行、核对与个人选择，说明应查哪个编号的什么原始信息 |
| 原选择题干扰项明显，缺少真实零值、配对缺失和等号的检查 | 重写十题和学习说明，保留五概念 ID 和全部时长；两题均带真实零值，配对题检查明确分母 |
| 反馈页只展示 B 解析，答错 A 后无对应解释 | 共用反馈页增加 A/B 各自题干、所选项、参考项和解析，仅在反馈阶段提供；不修改评分与提交接口 |

本次没有新建训练算法，原数据、默认配置、入口、任务字段与提交清单不变。S02 的数值计算规则不变，只增加结果阅读字段与终端说明。共用反馈页显示得到改善，其他课题目不因此变化。

## 实际做练习

先运行原起点和第7天配置；第4天已知 A01/A02/A04/B02，和为20，均值5，覆盖4/8，代理 MAE 为1。第7天再收到 A03/B01/B03，和为43，均值43/7，覆盖7/8；全程仍是八条，B04 未知。

个人检查先预计：容差3时 A04 的差异恰好3，不再被标为超过，但两列原值和覆盖不变。实际符合：分歧1→0、一致比例75%→100%，不据此宣称准确率提高。再单独选截止日5，实际新增 B01，均值27/5=5.4，覆盖5/8。所有结果分别保存，不覆盖起点。

纸面成绩练习：真实值0/60/90，均值50，覆盖3/6；错误填零得25。维修配对练习：差异0/1/2，容差1时1对分歧，一致2/3；容差2时3/3，但不能证明正确。

在单独模拟仓库填写明确标注“模拟练习”的报告、任务和个人配置，实际执行 SUPPORT 中的 Python 和本地 Git 命令，再从新的本地克隆执行 `scripts/course.py ci` 重跑成功。另做截止日5的检查，总计21条本地命令。没有推送模拟学生作业或创建课堂标签。

## 选择题与反馈

旧题先仅显示题干选项，记录 A：A/D/C/D/B，B：B/B/A/C/A，再与答案核对，十题相符；没有发现旧答案算错，但这不说明题目区分度好。新题逐项推演后，固定选择为 A：C/D/B/A/C，B：D/B/A/C/B；同一作者的修订与复核不是独立被试盲测。

本地 FastAPI TestClient、测试账号和临时 SQLite 走完教师创建 S02 场次、A五题、学习完成、B五题和反馈。专门让 A02 选择错误的“把缺失当零”答案，以检验 A 错题解析：A得4/5，B得5/5，十条提交、学习状态、结果显示和CSV导出对应一致。这里的4/5与5/5是测试输入结果，不是学习提升证据。测试提交用固定已推演的选择，不在运行时读取答案字段来选。

还检查：重复提交和跨阶段提交被拒绝；作答页没有解析，学习页不复述题干，两个公开读取接口仍只有题干选项；全部32课未作答状态的A/B反馈均正常。没有完成生产 Gitea 登录、浏览器视觉、复制按钮或倒计时的完整验收。
