## 一次课怎样进入生产

完整课包必须同时具备学生 README、LEARN、SUPPORT、数据、配置、程序与报告提示，教师 RUNBOOK、REFERENCE、五个知识点和十道 A/B 题，以及与该版本对应的题库汇集文件。必须实际运行起点、支持配置、个人单因素修改、提交检查和确定性重跑。

结构检查只证明目录、链接和格式；专项测试证明它覆盖的计算；模型模拟冷读检查页面顺序和操作停顿；真人试读才支持“初学者可以独立完成”或“90 分钟可完成”的判断。发布记录必须将这些证据分开，未做的真人试读如实写明。

学生至少完成一个会影响实际结果或结论的选择。入门支持是完成同一必做任务的可执行路径，不是更低分的另一份作业。最后评价只在方案和评价规则固定后使用；已经看过的记录改称开发证据。

## 整仓验证

在完整工作区根目录运行：

```bash
python3 tools/validate_course.py
PYTHONPATH=ml-check pytest -q ml-check/tests
```

统一验证先从教师源文件生成 `ml-check/app/question_bank/lessons.json`，再运行学生实验、教师参考独立核算、检查器/API 测试和三个材料目录的严格检查。最终报告写入 `validation/latest.json`；它记录作者本机环境，不等同于真人课堂试教。

题库同步后必须人工核对：

- 仍有 32 个课次，每课五个知识点、A/B 各五题；
- A/B 同编号检查同一知识点，B 使用不同情境；
- AI 学习页只有知识点和学习说明，不显示题干或答案；
- 第 01–04 课的已结束场次仍读取历史题目快照；
- 第 05–32 课标题、材料和概念题对应同一目标；
- 健康接口报告本轮题库版本和 32 课。

## 历史场次与题库切换

服务从本轮起在创建场次时保存该课完整题目快照和题库版本。查看历史统计、学生反馈或解释时读取场次快照，不再按当前题库重新解释。部署前先用旧镜像中的题库为现有场次回填快照，再切换镜像。

原位更新前依次执行：

1. 确认当前场次已经进入 `result` 或 `closed`，没有 A、学习或 B 阶段正在进行。
2. 备份 SQLite 主文件及 WAL/SHM、旧题库、compose 配置和当前镜像标识。
3. 对备份运行 `PRAGMA integrity_check`，记录用户、场次、作答和学习完成数量。
4. 使用 `deploy/backfill_session_snapshots.py` 和正在生产使用的旧题库回填旧场次。
5. 构建新镜像，在本机或隔离端口检查登录、建场次、A/学习/B/结果、历史场次和 CSV 导出。
6. 切换生产容器，回读健康接口、题库版本、数据库数量和旧场次题目。
7. 保留旧镜像、旧题库和数据库备份，直到至少完成一次新课场次。

数据库备份和学生记录不提交到仓库。恢复时同时恢复旧镜像、题库与数据库，不能只换其中一项。
