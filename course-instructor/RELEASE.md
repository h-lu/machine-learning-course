## 区分三类变更

| 变更 | 可以声明的完成 | 不能自动发生的事 |
|---|---|---|
| 规范、索引或规划修订 | 文件在受检提交下已对齐 | 切换班级任务、重新解释旧题号、改变成绩要求 |
| 完整课包发布 | 所列课次的任务、实验、参考、题库与课堂条件已验收 | 未覆盖模块自动完成、历史作业适用新规则 |
| 服务部署 | 指定镜像、题库和配置在验收环境中正常运行 | 推送仓库即上线、旧场次自动兼容新题库 |

先以 C01–C02 为完整入门批次，再按五个正式模块推进。允许在开发分支分步编辑，但未齐全的批次不开放为新课堂要求。

## 新课包的发布检查

发布记录应列出目标课次、新旧材料对应、前置知识、已覆盖与待补部分。确认运行单、学习卡、数据、程序、教师参考、五知识点及 A/B 题都支持相同主要关系。所有学生可见文字应面向初学者，使用机器学习通用术语并在首次出现时解释；以具体例子、单位和可核对计算检查表达，不以关键词数量认定通俗易懂。两条合理路线不能因模型名称或结论不同而被检查器拒绝。

学生必须能实际改变并运行方案，完成必要比较与自设计检查；五个正式模块保留一次持续改进。C01 的入门核对与 C02 的第一次比较成对验收。小模型、固定响应、实际生成和工具轨迹明确区分；缺少新输入对应输出不能视为新提示或新流程验证成功。

记录实际测量的环境、数据量、运行时间与内存，不以作者高配机器或旧报告代替新课预算检查。普通 CPU、约 8 GB 可用内存、单次目标 3 分钟、从头目标 5 分钟仍为必做预算。AI 辅助及 Gitea 概念练习的网络支持、故障补做另行安排，不要求临时购买服务。

核对前置知识是否随批次可获得。不能只凭相同编号拼接新旧模块；不足时补支持或继续使用原课包。软件通过后还应试教并记录学生能否在 90 分钟内理解、选择、运行、检查与解释。

## 测试与验收证据

在受信任的完整工作区根目录、依赖准备好后运行：

```bash
python3 tools/validate_course.py
PYTHONPATH=ml-check pytest -q ml-check/tests
```

统一验证包含题库汇集、学生实验测试、教师参考覆盖、教师状态测试和三个材料目录的严格检查。它会生成题库汇集文件及本地验证报告，运行后要核对差异，不能无意把旧题重新发布。另为新目标补相应数值、输入变化、缓存失配或评价独立性的专项测试。

验证记录至少包括受检提交、完整命令、依赖与系统环境、退出码、结果摘要及未运行项。结构检查只证明结构；已有数值测试只证明其覆盖的计算；教师阅读和试教分别检验实质选择、理解与课堂可完成性。

纯文档批次可以做链接、编号、索引对应与文案检查，明确未运行的整仓测试；不能为得到通过结果创建空链接目标、绕开检查，或把旧验证记录标为本次通过。未知学生代码不得在带生产凭据的环境中执行。

## 题库同步与当前服务限制

以下同步操作仅在包含 `tools/`、教师材料与 `ml-check/` 的完整工作区执行；独立 Gitea 教师仓库不能直接运行这些跨目录命令。题库源文件在 `lessons/ID/questions.json`。从完整工作区的教师目录执行 `python3 ../tools/sync_question_bank.py` 生成服务题库；修改概念和课次含义时还需审查 `ml-check/app/questions.py` 的题库版本及相关测试。同步脚本不是新旧版本隔离或生产部署工具。

当前 `ml-check/app/questions.py` 加载单份 `question_bank/lessons.json`，按 `lesson_id` 查找。它没有按课程版本选择题库的接口，因此只在发布记录中写版本号，不能使同一服务同时支持同课号的新旧含义。

在支持按版本保存与读取题目快照的功能完成并验收前，不将新旧课程题库同时投放到同一服务。需要并行授课时应先另行配置并验证独立实例、数据库和入口；这是发布前置工作，不是当前已提供的自动能力。

原位切换前暂停新场次并结束活动场次，备份数据库、原题库、镜像与配置，保存旧场次的题目、解释和成绩依据，核对恢复路径。新版本先在隔离环境测试登录、教师阶段控制、学生作答、解释与导出；确认旧班级不再依赖该入口后才切换。不得用新题库重新解释旧答题记录，必要时保留原服务只供旧班级访问。

## 每个发布批次记录什么

在发布说明或教师课堂记录中保存下列信息，不新增学生提交清单字段：

| 记录项 | 必须明确的内容 |
|---|---|
| 采用者与生效时机 | 班级、目标模块、正式启用日期；开发计划不能填作已启用 |
| 内容版本 | 完整材料提交 SHA、题库版本与题库文件 SHA、部署镜像标识 |
| 内容对应 | 目标课次、旧材料来源、已补缺口、前置支持与未发布课次 |
| 验收依据 | 软件与专项检查、教师阅读、资源实测和试教结果；未做项如实列出 |
| 保留与恢复 | 原材料、题库与成绩依据的保存位置，数据库备份，恢复责任与步骤 |

发布后回读实际部署版本并核对场次，不把计划版本当作线上版本。材料、题库与评价必须来自该班明确采用的同一发布包。

保留原课次提交与 `v2-lNN-final` 等标签，不覆盖历史提交，不追溯改变已经完成的作业要求。GitHub 与 Gitea 更新继续保留历史并采用可快进方式；生产凭据、数据库和学生记录不提交到公开仓库。仓库导出不含嵌套 `.git`、本机环境、临时产物与完整旧压缩包。

概念服务的生产运行按 `ml-check/deploy/README.md` 另行配置和验收。本批入门与问题评价模块候选不部署服务、不改数据库，也不代表 32 课已完成重写。
